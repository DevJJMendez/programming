# Structured Query Language
Es un lenguaje de programación estándar utilizado para administrar y manipular bases de datos relacionales. Fue desarrollado en la década de 1970 por IBM y se ha convertido en el lenguaje estándar para interactuar con sistemas de gestión de bases de datos relacionales (RDBMS) como MySQL, PostgreSQL, Oracle Database, Microsoft SQL Server, entre otros.

SQL se utiliza para realizar diversas operaciones en una base de datos, incluyendo:

- **Consulta de datos**: Permite realizar consultas para recuperar información específica de una base de datos, como seleccionar registros de una tabla, filtrar datos según criterios específicos, y realizar operaciones de agregación como sumas, promedios, etc.

- **Manipulación de datos**: Permite insertar nuevos registros en una tabla, actualizar registros existentes para modificar información, eliminar registros que ya no sean necesarios, y realizar operaciones de transacción para asegurar la consistencia de los datos.

- **Definición de datos**: Permite definir la estructura de la base de datos mediante la creación de tablas, la especificación de claves primarias y foráneas para establecer relaciones entre tablas, y la definición de restricciones de integridad para garantizar la consistencia de los datos.

- **Control de acceso**: Permite gestionar los permisos y privilegios de acceso a  la base de datos, estableciendo quién puede realizar qué operaciones en las tablas y los datos.


## Data Definition Language
El lenguaje de Definición de Datos (DDL) se utiliza para definir la estructura de la base de datos y los objetos dentro de ella.

Algunos comandos comunes de DDL son:

  - `CREATE`: Se utiliza para crear nuevos objetos en la base de datos, como tablas, índices, vistas, procedimientos almacenados, entre otros.
  - `ALTER`: Permite modificar la estructura de los objetos existentes en la base de datos, como añadir o eliminar columnas de una tabla.
  - `DROP`: Se usa para eliminar objetos de la base de datos, como tablas, vistas, índices, etc.
  - `TRUNCATE`: Elimina todos los registros de una tabla, pero no la estructura de la tabla misma.

## Data Manipulation Language
El lenguaje de Manipulación de Datos (DML) se utiliza para manipular los datos dentro de la base de datos.

Algunos comandos comunes de DML son:

  - `INSERT`: Se utiliza para insertar nuevos registros en una tabla.
  - `UPDATE`: Permite actualizar los datos existentes en una tabla.
  - `DELETE`: Se usa para eliminar registros de una tabla.
  - `SELECT`: Aunque es parte de DML, SELECT se usa principalmente para consultar y recuperar datos de la base de datos.
  
## Bases de datos Relacionales
Las bases de datos SQL, o bases de datos relacionales, son sistemas de gestión de bases de datos (DBMS) que utilizan el lenguaje SQL (Structured Query Language) para almacenar, manipular y recuperar datos. Estas bases de datos organizan la información en tablas relacionadas entre sí mediante claves primarias y claves foráneas, siguiendo el modelo relacional.

**¿Cuando usarlas?**

  - Aplicaciones de propósito general: Las bases de datos SQL son adecuadas para una amplia variedad de aplicaciones, desde sistemas de gestión de contenido hasta aplicaciones empresariales.

  - Requerimientos de integridad y consistencia: Cuando se necesite mantener la integridad y la consistencia de los datos mediante restricciones como claves primarias, claves foráneas y reglas de integridad.

  - Consultas complejas: Para aplicaciones que requieran realizar consultas complejas que involucren múltiples tablas y relaciones.

**¿Cuando no usarlas**

- Escenarios de alto rendimiento y escalabilidad extrema: En algunos casos de aplicaciones que requieran un rendimiento extremadamente alto y una escalabilidad masiva, es posible que las bases de datos NoSQL sean más adecuadas debido a su capacidad para distribuir y procesar grandes volúmenes de datos de manera eficiente.

- Estructuras de datos no relacionales: Si la estructura de los datos es no relacional o semiestructurada, como en el caso de bases de datos de grafos o documentos, puede ser más conveniente utilizar bases de datos NoSQL especializadas en ese tipo de datos.

- Flexibilidad extrema en el esquema: Si se necesita una flexibilidad extrema en el esquema de la base de datos, donde los campos y estructuras de datos pueden cambiar con frecuencia, las bases de datos NoSQL pueden ofrecer una mejor adaptabilidad.

## Bases de datos NoSQL
Las bases de datos NoSQL (Not Only SQL) son sistemas de gestión de bases de datos que se diferencian de las bases de datos relacionales (SQL) en su enfoque de modelado y almacenamiento de datos. A diferencia de las bases de datos SQL, que utilizan un modelo relacional con tablas y relaciones, las bases de datos NoSQL adoptan modelos de datos no relacionales o semi-estructurados, como documentos, grafos, clave-valor o columnas.

**¿Que son?**

  - Son sistemas de gestión de bases de datos que no utilizan exclusivamente el lenguaje SQL y no siguen el modelo relacional.

  - Utilizan modelos de datos alternativos, como documentos (ejemplo: MongoDB), grafos (ejemplo: Neo4j), clave-valor (ejemplo: Redis), y columnas (ejemplo: Apache Cassandra).

  - Están diseñadas para escenarios con requisitos de escalabilidad horizontal, flexibilidad en el esquema de datos, y manejo eficiente de grandes volúmenes de información no estructurada o semi-estructurada.
  
**¿Cuando usarlas?**

  - Escalabilidad y rendimiento: Las bases de datos NoSQL son ideales para aplicaciones que requieren escalabilidad horizontal, es decir, la capacidad de manejar grandes volúmenes de datos distribuidos en múltiples servidores.

  - Datos no estructurados o semi-estructurados: Son adecuadas cuando se trabaja con datos no estructurados o semi-estructurados, como documentos JSON, XML, datos de grafos, etc.

  - Flexibilidad en el esquema: Son útiles en casos donde se necesita una flexibilidad extrema en el esquema de datos, ya que permiten agregar, modificar y eliminar campos sin afectar la integridad de los datos existentes.
    
  - Alta velocidad de lectura/escritura: Son eficientes para aplicaciones que requieren altas velocidades de lectura y escritura, como sistemas de análisis en tiempo real, redes sociales, juegos en línea, etc.

**¿Cuando no usarlar?**

  - Aplicaciones transaccionales complejas: Para aplicaciones que involucran transacciones complejas y necesitan garantías de integridad ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad), las bases de datos relacionales SQL son más adecuadas.
  
  - Consultas complejas que requieren JOINs: Si las consultas de la aplicación dependen en gran medida de JOINs complejos entre múltiples tablas, las bases de datos NoSQL pueden no ser la mejor opción debido a la falta de soporte para JOINs complejos en algunos modelos de datos NoSQL.
  
  - Integridad y consistencia estrictas: Si la aplicación requiere una integridad y consistencia estrictas de los datos, especialmente en entornos con múltiples transacciones concurrentes, las bases de datos relacionales SQL suelen ofrecer mejores garantías.
