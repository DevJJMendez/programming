# Modificadores
En PostgreSQL, los tipos de datos pueden tener varios modificadores y argumentos que permiten definir su comportamiento, restricción y características. 

1. `PRIMARY KEY`

   * **Uso**: Se utiliza para definir una columna como clave primaria.

   * **Propósito**: Garantiza la unicidad de los valores en esta columna y no permite valores nulos.

   * **Ejemplo**: `user_id SERIAL PRIMARY KEY`

2. `UNIQUE`

   * **Uso**: Asegura que todos los valores en la columna sean únicos.

   * **Propósito**: Permite tener un índice único en la columna, evitando duplicados.

   * **Ejemplo**: `email VARCHAR(255) UNIQUE`

3. `NOT NULL`

   * **Uso**: Indica que la columna no puede contener valores nulos.

   * **Propósito**: Asegura que siempre se debe proporcionar un valor para esta columna.

   * **Ejemplo**: `name VARCHAR(100) NOT NULL`

4. `DEFAULT`

   * **Uso**: Proporciona un valor predeterminado para la columna si no se especifica un valor al insertar.

   * **Propósito**: Facilita la inserción de registros sin tener que especificar todos los valores.

   * **Ejemplo**: `created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`

5. `CHECK`

   * **Uso**: Define una restricción para asegurar que los valores en la columna cumplen con una condición específica.

   * **Propósito**: Garantiza que los datos son válidos según las reglas definidas.

   * **Ejemplo**: `age SMALLINT CHECK (age >= 0)`

6. `FOREIGN KEY`

   * **Uso**: Define una relación con otra tabla, especificando que los valores en esta columna deben coincidir con valores en una columna de otra tabla.

   * **Propósito**: Mantiene la integridad referencial entre las tablas.

   * **Ejemplo**: `user_id INTEGER REFERENCES users(user_id)`

7. `AUTOINCREMENT (o SERIAL)`

   * **Uso**: Se utiliza para crear un número único automáticamente para cada fila.

   * **Propósito**: Facilita la creación de identificadores únicos sin tener que especificarlos manualmente.

   * **Ejemplo**: `id SERIAL PRIMARY KEY`

8. `ARRAY`

   * **Uso**: Permite almacenar múltiples valores del mismo tipo en una sola columna.

   * **Propósito**: Facilita el manejo de colecciones de datos relacionados.

   * **Ejemplo**: `tags TEXT[]`

9. `JSON y JSONB`

   * **Uso**: Almacena datos en formato JSON.

   * **Propósito**: Permite el almacenamiento y la consulta de datos no estructurados.

   * **Ejemplo**: `data JSONB`

10. `ENUM`

    * **Uso**: Define un tipo de dato con un conjunto fijo de valores.

    * **Propósito**: Proporciona validación de valores y ahorra espacio en comparación con VARCHAR.

    * **Ejemplo**: `status ENUM('pending', 'shipped', 'delivered')`

11. `SET STORAGE`

    * **Uso**: Define cómo se almacenan los datos en la columna (por ejemplo, PLAIN, EXTERNAL, MAIN).

    * **Propósito**: Controla la forma en que se manejan los datos para optimizar el rendimiento.

    * **Ejemplo**: `data BYTEA SET STORAGE EXTERNAL`


## Ejemplo de Definición de Tabla Usando Modificadores
```sql
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(user_id),
    order_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    order_total NUMERIC(12, 2) NOT NULL CHECK (order_total >= 0),
    payment_method ENUM('credit_card', 'paypal', 'bank_transfer') NOT NULL,
    order_status ENUM('pending', 'shipped', 'delivered') NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
