# Seguridad
La seguridad en bases de datos se refiere a las técnicas y políticas que se implementan para proteger los datos almacenados contra accesos no autorizados, corrupción, pérdida o violaciones de integridad. Esto incluye la gestión de usuarios, permisos y privilegios que definen qué operaciones puede realizar cada usuario dentro del sistema.

## Permisos y privilegios en PostgreSQL
1. **¿Qué son permisos y privilegios?**
   
   * **Permisos**: Son derechos que los usuarios tienen para realizar acciones específicas sobre objetos de la base de datos, como tablas, vistas, secuencias, etc. Los permisos incluyen operaciones como `SELECT`, `INSERT`, `UPDATE`, `DELETE`, entre otras.

   * **Privilegios**: Son un conjunto de permisos que se otorgan a los usuarios o roles para controlar lo que pueden y no pueden hacer dentro del sistema de bases de datos.

2. **¿Para qué sirven?**
   * Los permisos y privilegios sirven para controlar el acceso a los datos de la base de datos y asegurar que solo los usuarios autorizados puedan realizar ciertas operaciones. Implementar estos controles es clave para:

     * Proteger los datos sensibles.

     * Limitar las acciones que pueden dañar la integridad de los datos.

     * Cumplir con las normativas de seguridad que muchas organizaciones deben seguir.

## Visualización de usuarios, permisos y privilegios
* **Ver usuarios en PostgreSQL**: Para listar los usuarios y roles en PostgreSQL
   
   ```sql
   \du
   ```
   Esto muestra una tabla con todos los usuarios y roles, junto con sus atributos (como si son superusuarios, si pueden crear bases de datos, etc.).

## Ver permisos y privilegios de un usuario en PostgreSQL sobre tablas
Para ver los permisos que tiene un usuario o rol sobre las tablas, bases de datos o cualquier otro objeto, puedes usar los siguientes comandos:

* Para ver los permisos sobre tablas:

   ```sql
   \z tableName
   ```
   Esto te muestra los permisos de cada usuario sobre una tabla en particular.

   ---
   ```sql
   SELECT grantee, privilege_type 
   FROM information_schema.role_table_grants 
   WHERE table_name = 'nombre_tabla';
   ```
   Esto muestra qué usuarios tienen qué privilegios sobre una tabla específica.

---
* **Otorgar privilegios a un usuario**: Para otorgar privilegios a un usuario sobre una tabla, por ejemplo:

   ```sql
   GRANT SELECT, INSERT ON nombre_tabla TO nombre_usuario;
   ```
   Esto otorga los privilegios **SELECT** e **INSERT** a nombre_usuario sobre la tabla **nombre_tabla**.

---
* **Revocar permisos**: Para quitar ciertos privilegios a un usuario:

   ```sql
   REVOKE INSERT ON nombre_tabla FROM nombre_usuario;
   ```
   Esto revoca el permiso de **INSERT** para nombre_usuario sobre la tabla **nombre_tabla**.

---
* **Para otorgar todos los privilegios sobre una tabla**:

   ```sql
   GRANT ALL PRIVILEGES ON nombre_tabla TO nombre_usuario;
   ```
   Esto le otorga a nombre_usuario todos los permisos (**SELECT**, **INSERT**, **UPDATE**, **DELETE**, etc.) sobre la tabla **nombre_tabla**.

## Tipos de permiosos / privilegios en PostgreSQL
PostgreSQL permite otorgar permisos individuales a los usuarios sobre diferentes objetos de la base de datos. Los principales privilegios son:

* `SELECT`: Permite leer los datos de una tabla o vista.

* `INSERT`: Permite insertar datos en una tabla.

* `UPDATE`: Permite modificar datos existentes en una tabla.

* `DELETE`: Permite eliminar datos de una tabla.

* `TRUNCATE`: Permite eliminar todos los registros de una tabla sin necesidad de usar una transacción.

* `REFERENCES`: Permite crear claves foráneas que referencian la tabla.

* `TRIGGER`: Permite definir y usar triggers sobre la tabla.

* `EXECUTE`: Permite ejecutar funciones.

* `USAGE`: Permite usar esquemas, secuencias, y tipos de datos.

* **Revocar todos los permisos**

   ```sql
   REVOKE ALL PRIVILEGES ON DATABASE nombre_base_de_datos FROM nombre_usuario;
   ```

## Roles en PostgreSQL
En PostgreSQL, los roles son una forma más flexible de manejar permisos. Un rol puede ser un usuario o un conjunto de permisos que pueden ser asignados a uno o más usuarios.

En PostgreSQL, un "usuario" es realmente un tipo de rol con la capacidad de autenticarse (login). Los roles pueden tener privilegios y ser utilizados para gestionar permisos en bases de datos, tablas, vistas, etc.

**Permisos (Privilegios)**: Controlan qué acciones puede realizar un usuario en objetos como bases de datos, tablas, esquemas, funciones, etc. Ejemplos de permisos son: SELECT, INSERT, UPDATE, DELETE, EXECUTE, ALL PRIVILEGES.

`GRANT`: Comando para asignar permisos a un usuario/rol sobre un objeto.

`REVOKE`: Comando para revocar (quitar) permisos asignados a un usuario/rol.

* **Crear un rol**
   ```sql
   CREATE ROLE nombre_rol;

   CREATE ROLE nombre_usuario WITH LOGIN PASSWORD 'contraseña';
   ```
   * **WITH LOGIN**: Permite que el rol se autentique.

  * **PASSWORD**: Establece una contraseña para el rol.

También puedes otorgar privilegios adicionales al crear el usuario, como:

  * **SUPERUSER**: Concede todos los privilegios (evitar en la mayoría de los casos).

  * **CREATEDB**: Permite al rol crear bases de datos.

  * **CREATEROLE**: Permite al rol crear nuevos roles.
---

* **Asignar permisos a un rol**: Puedes asignar privilegios a un rol igual que lo haces con un usuario:

   ```sql
   GRANT SELECT, INSERT ON nombre_tabla TO nombre_rol;
   ```

* **Asignar roles a usuarios**: Una vez que tienes un rol con ciertos privilegios, puedes asignarlo a un usuario:

   ```sql
   GRANT nombre_rol TO nombre_usuario;
   ```

* **Ver roles de un usuario**: Para ver qué roles tiene un usuario:

   ```bash
   \du nombre_usuario
   ```

## Buenas prácticas de seguridad en PostgreSQL
1. **Principio de menor privilegio**
   
   * Asegúrate de que los usuarios solo tengan los privilegios necesarios para hacer su trabajo. Evita otorgar permisos de superusuario si no es necesario.

2. **Uso de roles**

   * Agrupa permisos en roles y asigna esos roles a los usuarios. Esto facilita la gestión de permisos, especialmente en entornos con muchos usuarios.

3. **Revocación de acceso cuando sea necesario**

   * Revoca los privilegios cuando un usuario o rol ya no necesite acceso a ciertos datos u operaciones.

4. **Acceso a la base de datos mediante autenticación fuerte**

   * PostgreSQL admite autenticación con contraseña (md5 o scram-sha-256), certificados SSL, y autenticación basada en sistemas externos (como LDAP). Usa la autenticación más segura posible para tu entorno.

## Gestión avanzada de permisos y seguridad
1. **Permisos de objetos específicos**

   * Puedes otorgar o revocar permisos no solo sobre tablas, sino también sobre otros objetos de la base de datos como vistas, secuencias, funciones y esquemas.

   * Ejemplo para otorgar permisos sobre una secuencia:

   ```sql
   GRANT USAGE, SELECT ON SEQUENCE nombre_secuencia TO nombre_usuario;
   ```

2. **Revisar permisos de todos los objetos de la base de datos**

   * Para obtener información detallada de los permisos asignados a los objetos dentro de una base de datos, puedes ejecutar esta consulta sobre el esquema **information_schema**:

   ```sql
   SELECT grantee, privilege_type, table_name 
   FROM information_schema.role_table_grants 
   WHERE grantee = 'nombre_usuario';
   ```

## Auditoría y monitoreo
1. **Registrar consultas y actividades**

   * Puedes habilitar la auditoría de PostgreSQL para registrar todas las consultas y actividades de los usuarios. Esto es útil para rastrear quién ha accedido o modificado ciertos datos.

   * Para habilitarlo, edita el archivo **postgresql.conf**:

   ```sql
   log_statement = 'all'
   ```
   Esto registrará todas las consultas ejecutadas en la base de datos.

## Auditoría más avanzada con pgAudit
PostgreSQL tiene una extensión llamada pgAudit que permite hacer auditoría a nivel de detalle de las actividades de los usuarios. Puedes configurarla para registrar tipos específicos de eventos como cambios de datos o acceso a tablas sensibles.

## Creación de Usuarios y Permisos
Al crear usuarios y definir permisos en PostgreSQL, puedes utilizar roles para gestionar el acceso. Aquí hay un ejemplo básico:

```sql
-- Crear roles
CREATE ROLE superadmin;
CREATE ROLE admin;
CREATE ROLE client;
CREATE ROLE seller;

-- Asignar permisos al rol superadmin
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO superadmin;

-- Asignar permisos al rol admin
GRANT SELECT, UPDATE, DELETE ON products TO admin;
GRANT SELECT, UPDATE, DELETE ON orders TO admin;

-- Asignar permisos al rol client
GRANT SELECT ON products TO client;
GRANT INSERT, UPDATE ON orders TO client;

-- Asignar permisos al rol seller
GRANT INSERT, SELECT, UPDATE ON products TO seller;
GRANT SELECT ON orders TO seller;

-- Crear usuarios y asignarles roles
CREATE USER alice WITH PASSWORD 'password';
GRANT superadmin TO alice;

CREATE USER bob WITH PASSWORD 'password';
GRANT admin TO bob;

CREATE USER charlie WITH PASSWORD 'password';
GRANT client TO charlie;

CREATE USER dave WITH PASSWORD 'password';
GRANT seller TO dave;
```
### Mejora de la Seguridad
1. **Principio de Mínimos Privilegios**:

   * Cada usuario debe tener solo los permisos necesarios para realizar su trabajo. Esto minimiza el riesgo de que un usuario pueda realizar acciones no autorizadas.

2. **Prevención de Errores**:

   * Limitar los permisos ayuda a prevenir errores humanos, como la eliminación accidental de registros o la modificación de datos críticos.

3. **Auditoría y Control**:

   * Al tener roles bien definidos, es más fácil realizar auditorías y controlar quién tiene acceso a qué datos y funciones. Esto es crucial para cumplir con regulaciones de seguridad y privacidad.

4. **Aislamiento de Fallos**:

   * Si un usuario es comprometido, los permisos limitados pueden ayudar a contener el daño. Por ejemplo, un atacante que obtiene acceso a una cuenta de cliente no podrá acceder a la gestión de productos.
