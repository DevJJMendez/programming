### Tipos Numéricos
PostgreSQL ofrece varios tipos numéricos dependiendo de si los números son enteros, decimales, grandes o pequeños. Estos tipos se seleccionan según los límites y el espacio en memoria.

| Tipo               | memoria  | Rango                                                  |
| ------------------ | -------- | ------------------------------------------------------ |
| `smallint`         | 2 bytes  | -32,768 a 32,767                                       |
| `integer`          | 4 bytes  | -2,147,483,648 a 2,147,483,647                         |
| `bigint`           | 8 bytes  | -9,223,372,036,854,775,808 a 9,223,372,036,854,775,807 |
| `decimal(p,s)`     | Variable | Precisión arbitraria                                   |
| `numeric(p,s)`     | Variable | Precisión arbitraria                                   |
| `real`             | 4 bytes  | Números decimales de simple precisión                  |
| `double precision` | 8 bytes  | Números decimales de doble precisión                   |
| `serial`           | 4 bytes  | Entero autoincremental                                 |
| `bigserial`        | 8 bytes  | Entero grande autoincremental                          |

Buenas Prácticas:

* Usa smallint cuando los números sean pequeños y el espacio en memoria sea crítico.

* Usa integer como tipo predeterminado para enteros, ya que cubre la mayoría de los casos.

* Usa bigint solo si esperas números grandes.

* Para precisión en cálculos financieros, utiliza numeric(p,s) o decimal(p,s) ya que ofrecen una precisión arbitraria.

* Evita real y double precision para cálculos monetarios, debido a su falta de precisión exacta en decimales.

### Tipos de Texto
PostgreSQL tiene tipos de texto flexibles que permiten almacenar desde pequeñas cadenas de texto hasta grandes volúmenes de datos textuales.

| Tipo       | Tamaño en memoria           | Caracteristicas                                   |
| ---------- | --------------------------- | ------------------------------------------------- |
| char(n)    | n bytes + 4 bytes           | Cadena fija de longitud n                         |
| varchar(n) | Longitud variable + 4 bytes | Cadena de longitud variable (máximo n caracteres) |
| text       | Longitud variable + 4 bytes | Cadena de longitud variable ilimitada             |

Buenas Prácticas:

* Usa text para datos textuales grandes o si la longitud máxima no es un requisito estricto.

* Usa varchar(n) si tienes restricciones de longitud, como correos electrónicos o números de teléfono.

* Evita char(n), ya que se almacena en una longitud fija, lo que puede causar desperdicio de espacio.

### Tipo Booleano
| Tipo    | Tamaño en memoria | Valores                 |
| ------- | ----------------- | ----------------------- |
| boolean | 1 byte            | `true`, `false`, `NULL` |

Buenas Prácticas:

* Usa boolean cuando el campo solo puede tener dos valores (true o false), como en banderas de activación o estatus.

### Tipos de Fecha y Hora
PostgreSQL tiene un conjunto robusto de tipos para manejar fechas y horas.

| Tipo        | Tamaño en memoria | Rango                           |
| ----------- | ----------------- | ------------------------------- |
| date        | 4 bytes           | 4713 AC a 5874897 DC            |
| time        | 8 bytes           | Hora del día (sin zona horaria) |
| timetz      | 12 bytes          | Hora del día (con zona horaria) |
| timestamp   | 8 bytes           | Fecha y hora sin zona horaria   |
| timestamptz | 8 bytes           | Fecha y hora con zona horaria   |
| interval    | 16 bytes          | Intervalo de tiempo             |

Buenas Prácticas:

* Usa timestamp si no necesitas la zona horaria y timestamptz si sí la necesitas.

* Usa date para almacenar solo fechas (sin tiempo).

* Usa interval cuando necesites almacenar duraciones o diferencias de tiempo.

### Tipos Monetarios

| Tipo  | Tamaño en memoria | Rango                                         |
| ----- | ----------------- | --------------------------------------------- |
| money | 8 bytes           | -92233720368547758.08 a +92233720368547758.07 |

Buenas Prácticas:

* Aunque money existe, se recomienda usar numeric(p,s) para cálculos financieros, ya que proporciona mayor flexibilidad y precisión.

### Tipos de Datos Binarios
| Tipo  | Tamaño en memoria | Rango          |
| ----- | ----------------- | -------------- |
| bytea | Longitud variable | Datos binarios |

Buenas Prácticas:

* Usa bytea para almacenar datos binarios como imágenes o archivos.

### Tipos Geométricos
PostgreSQL soporta una variedad de tipos geométricos para almacenar datos espaciales.
| Tipo    | Tamaño en memoria | Rango                                 |
| ------- | ----------------- | ------------------------------------- |
| point   | 16 bytes          | Un punto en el plano                  |
| line    | 32 bytes          | Línea infinita en el plano            |
| lseg    | 32 bytes          | Segmento de línea                     |
| box     | 32 bytes          | Rectángulo definido por dos puntos    |
| path    | Variable          | Secuencia de puntos                   |
| polygon | Variable          | Polígono (cualquier número de puntos) |

### Tipos JSON
PostgreSQL ofrece soporte completo para almacenar y consultar datos en formato JSON.

| Tipo  | Tamaño en memoria | Rango                       |
| ----- | ----------------- | --------------------------- |
| json  | Variable          | Datos JSON en formato texto |
| jsonb | Variable          | Datos JSON en formato texto |

Buenas Prácticas:

* Usa jsonb si necesitas realizar consultas frecuentes o indexación en campos JSON.

* Usa json si solo necesitas almacenar el dato en su formato original y no realizar consultas complejas.

### Tipos Enumerados
| Tipo | Tamaño en memoria | Rango                            |
| ---- | ----------------- | -------------------------------- |
| enum | Variable          | Conjunto de valores predefinidos |

Buenas Prácticas:

* Usa enum cuando los valores posibles de un campo sean limitados y conocidos, como estado o tipo.

### Tipos de Array
PostgreSQL permite definir columnas que pueden almacenar múltiples valores del mismo tipo.
| Tipo  | Tamaño en memoria | Rango            |
| ----- | ----------------- | ---------------- |
| array | Variable          | Arreglo de datos |

Buenas Prácticas:

* Usa arrays para almacenar listas de valores que no requieren normalización. Sin embargo, evita su uso excesivo, ya que puede dificultar las consultas.

### UUID
El tipo UUID permite almacenar identificadores únicos globales.
| Tipo | Tamaño en memoria | Rango                      |
| ---- | ----------------- | -------------------------- |
| uuid | 16 bytes          | Identificador único global |

Buenas Prácticas:

* Usa uuid como clave primaria si necesitas identificadores globales únicos, como en sistemas distribuidos.

## Buenas Prácticas para Estructurar una Base de Datos en Función de los Tipos de Datos
Optimización de Espacio:

Usa el tipo de dato más pequeño que cumpla con los requisitos. Ejemplo: Usa smallint en lugar de integer si los valores siempre estarán en el rango de smallint.
Integridad de los Datos:

Usa tipos específicos como boolean, date, o uuid en lugar de tipos más generales como text o varchar para garantizar la precisión y validación implícita de los datos.
Evitar Uso Extensivo de Tipos de Texto:

No uses text o varchar para almacenar datos que tengan un formato específico o restricciones. Por ejemplo, usa date para fechas y boolean para valores de verdadero/falso.
Pensar en el Futuro:

Aunque integer es suficiente para muchas claves primarias, considera usar bigint o uuid en proyectos que puedan escalar y requerir grandes cantidades de datos.
Normalización vs Desnormalización:

Usa tipos de array o json cuando los datos no requieren normalización y sea más eficiente para consultas específicas. Sin embargo, en general, sigue los principios de normalización para evitar redundancia y problemas de integridad.
