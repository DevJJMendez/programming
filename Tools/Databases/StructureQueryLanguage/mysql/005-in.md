# `IN`
El operador **IN** en SQL se utiliza para comparar un valor con una lista de valores. Permite verificar si un valor está presente dentro de un conjunto específico de valores o resultados. Es una manera eficiente de realizar múltiples comparaciones de igualdad en una sola consulta.

## ¿Para qué se utiliza **IN**?
* **Comparación múltiple**: **IN** se utiliza cuando necesitas verificar si un campo tiene un valor que coincide con cualquiera de los valores de una lista. Esto simplifica consultas que, de otro modo, requerirían múltiples condiciones **OR**.

* **Subconsultas**: También puede utilizarse con subconsultas para verificar si un valor está presente en el resultado de otra consulta. Esto es útil cuando trabajas con relaciones entre tablas.

## Sintaxis
```sql
SELECT column1, column2
FROM table_name
WHERE column IN (value1, value2, ...);
```
## Ejemplo de uso básico:
Supongamos que tienes una tabla llamada users y quieres seleccionar todos los usuarios que viven en cualquiera de tres ciudades específicas: "Madrid", "Barcelona", o "Sevilla".

```sql
SELECT first_name, last_name
FROM users
WHERE city IN ('Madrid', 'Barcelona', 'Sevilla');
```
Este ejemplo devolverá todos los usuarios cuya ciudad coincida con cualquiera de las ciudades mencionadas en la lista.

## ¿Qué resuelve **IN**?
1. **Simplificación de consultas**: En lugar de escribir múltiples condiciones **OR**, puedes usar **IN** para simplificar la consulta.

   * En lugar de escribir

    ```sql
    SELECT first_name, last_name
    FROM users
    WHERE city = 'Madrid'
    OR city = 'Barcelona'
    OR city = 'Sevilla';
    ```
   * Usando **IN**

    ```sql
    SELECT first_name, last_name
    FROM users
    WHERE city IN ('Madrid', 'Barcelona', 'Sevilla');
    ```
  
2. **Claridad y legibilidad**: Hacer la consulta más legible y fácil de mantener. Cuando tienes que hacer comparaciones con muchos valores, IN reduce la redundancia.

3. **Consulta dinámica**: Permite utilizar listas dinámicas de valores mediante subconsultas, donde el conjunto de valores de comparación es el resultado de otra consulta.

## Uso de IN con subconsultas:
Puedes usar IN junto con una subconsulta para comparar un valor contra el resultado de otra consulta.

* Ejemplo: Supongamos que tienes dos tablas: `orders` y `customers`, y deseas encontrar todos los pedidos realizados por clientes de una región específica.

  ```sql
  SELECT order_id, customer_id, order_date
  FROM orders
  WHERE customer_id IN (
    SELECT customer_id
    FROM customers
    WHERE region = 'Europa'
  );
  ```
  En este ejemplo:
  
  * La subconsulta selecciona todos los `customer_id` de clientes que están en la región de "**Europa**".
  
  * La consulta externa selecciona todos los pedidos realizados por esos clientes.

## Diferencia entre `IN` y `=`:
El operador **IN** se puede ver como una versión compacta de múltiples comparaciones de igualdad. La diferencia clave es que **IN** permite hacer comparaciones con múltiples valores al mismo tiempo, mientras que `=` solo permite comparar con un valor.

* `=`: Se utiliza para comparar un campo con un solo valor.

* `IN`: Se utiliza para comparar un campo con una lista de valores.

# `NOT IN`
El operador **NOT IN** es la contraparte de **IN**. Se utiliza para excluir los valores de la lista especificada.

## Ejemplo
Supongamos que quieres seleccionar a todos los usuarios que no viven en **Madrid**, **Barcelona** o **Sevilla**.

```sql
SELECT first_name, last_name
FROM users
WHERE city NOT IN ('Madrid', 'Barcelona', 'Sevilla');
```
Este ejemplo excluye a los usuarios que viven en cualquiera de esas tres ciudades.

# Consideraciones de rendimiento:
1. **Pequeñas listas estáticas**: Para listas pequeñas de valores estáticos, IN es bastante eficiente.

2. **Grandes subconsultas**: Si estás usando **IN** con una subconsulta que devuelve una gran cantidad de resultados, el rendimiento puede verse afectado, especialmente si la base de datos necesita recorrer muchas filas. En esos casos, es mejor optimizar las subconsultas y asegurarse de que las columnas involucradas tengan índices adecuados.

3. **Índices**: Usar IN en una columna indexada mejora considerablemente el rendimiento, ya que el motor de la base de datos puede buscar los valores más rápido.

4. **Evitar NULL en subconsultas**: Si la subconsulta devuelve valores **NULL**, **IN** puede no comportarse como esperas. Es recomendable gestionar explícitamente los valores **NULL** en las subconsultas o en la lista de valores.

# `IN` vs. `EXISTS`:
A veces, es más eficiente utilizar **EXISTS** en lugar de **IN** cuando trabajas con subconsultas grandes. **EXISTS** solo verifica si hay algún resultado en la subconsulta, mientras que **IN** debe recopilar y comparar todos los resultados de la subconsulta.

**Ejemplo**
```sql
SELECT order_id, customer_id, order_date
FROM orders
WHERE EXISTS (
  SELECT 1
  FROM customers
  WHERE customers.customer_id = orders.customer_id
  AND region = 'Europa'
);
```
En este ejemplo, `EXISTS` podría ser más rápido si la subconsulta devuelve muchos resultados.
