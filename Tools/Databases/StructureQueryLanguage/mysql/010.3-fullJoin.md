# `FULL JOIN`
Un **FULL JOIN** o **FULL OUTER JOIN** en SQL es un tipo de operación de unión que combina los resultados de un **LEFT JOIN** y un **RIGHT JOIN**. Devuelve todas las filas cuando hay una coincidencia en una de las tablas. Si no hay coincidencia, las filas de la tabla sin correspondencia tendrán valores `NULL` en las columnas de la otra tabla.

En esencia, un `FULL JOIN` incluye:

* Todas las filas de la tabla izquierda (primera tabla) y las filas coincidentes de la tabla derecha (segunda tabla).

* Todas las filas de la tabla derecha y las filas coincidentes de la tabla izquierda.

* Filas sin coincidencias en ambas tablas tendrán `NULL` en las columnas de la tabla opuesta.

## ¿Para qué se utiliza el FULL JOIN?
El **FULL JOIN** se utiliza para:

1. **Combinar datos completos de dos tablas**: Incluye todas las filas de ambas tablas, proporcionando una vista completa de los datos relacionados y no relacionados.

2. **Identificar registros faltantes**: Facilita la identificación de registros que no tienen correspondencia en una de las tablas.

3. **Generar informes exhaustivos**: Útil en escenarios donde se necesita una visión integral de todas las entidades, independientemente de sus relaciones.

## ¿Qué problemas resuelve el FULL JOIN?
1. **Fusión completa de datos**: Permite combinar datos de dos tablas sin perder información de ninguna de ellas, incluso si algunas filas no tienen coincidencias.

2. **Detección de discrepancias**: Ayuda a identificar y analizar diferencias entre dos conjuntos de datos, como registros presentes en una tabla pero ausentes en otra.

3. **Consolidación de información**: Facilita la consolidación de información dispersa en múltiples tablas, ofreciendo una vista unificada.

## ¿Cómo lo resuelve el FULL JOIN?
El **FULL JOIN** compara cada fila de la primera tabla con cada fila de la segunda tabla usando la condición de unión especificada. Cuando encuentra una coincidencia, combina los datos de ambas filas en una sola fila de resultado. Si una fila en una de las tablas no tiene una coincidencia en la otra tabla, aún así se incluye en el resultado con los valores de la tabla sin coincidencia rellenados con `NULL`.

## Sintaxis
```sql
SELECT table1.column1, table1.column2, table2.column3, table2.column4, ...
FROM table1
FULL OUTER JOIN table2
ON table1.common_column = table2.common_column;
```
* `SELECT`: Especifica las columnas que deseas recuperar.

* `FROM table1`: Indica la primera tabla (izquierda).

* `FULL OUTER JOIN table2`: Especifica la segunda tabla (derecha) y el tipo de unión.

* `ON table1.common_column = table2.common_column`: Define la condición de unión basada en columnas comunes.

## Ejemplo
Supongamos que tienes dos tablas: `clientes` y `pedidos`. Quieres obtener una lista completa que muestre todos los **clientes** y todos los **pedidos**, indicando si un **cliente** no ha realizado **pedidos** o si un **pedido** no está asociado a ningún **cliente**.

`clientes`
| cliente_id | nombre |
| ---------- | ------ |
| 1          | Juan   |
| 2          | María  |
| 3          | Pedro  |
| 4          | Ana    |

`pedidos`
| pedido_id | cliente_id | producto |
| --------- | ---------- | -------- |
| 101       | 1          | Laptop   |
| 102       | 2          | Teléfono |
| 103       | 1          | Monitor  |
| 104       | NULL       | Tablet   |

**Consulta**
```sql
SELECT c.nombre, p.pedido_id, p.producto
FROM clientes c
FULL OUTER JOIN pedidos p
ON c.cliente_id = p.cliente_id;
```
**Salida**
| nombre | pedido_id | producto |
| ------ | --------- | -------- |
| Juan   | 101       | Laptop   |
| Juan   | 103       | Monitor  |
| María  | 102       | Teléfono |
| Pedro  | NULL      | NULL     |
| Ana    | NULL      | NULL     |
| NULL   | 104       | Tablet   |

**Análisis del Resultado:**
* Juan tiene dos pedidos (101 y 103).

* María tiene un pedido (102).

* Pedro y Ana no tienen pedidos, por lo que pedido_id y producto son NULL.

* Existe un pedido 104 que no está asociado a ningún cliente (cliente_id es NULL), por lo que nombre es NULL.

## Compatibilidad de SQL Dialects
Es importante notar que no todos los sistemas de gestión de bases de datos (DBMS) soportan FULL JOIN de forma nativa. A continuación, se detalla la compatibilidad en algunos DBMS populares:

* **PostgreSQL**: Soporta `FULL JOIN` nativamente.

* **SQL Server**: Soporta `FULL JOIN` nativamente.

* **Oracle**: Soporta `FULL OUTER JOIN`.

* **MySQL**: No soporta `FULL JOIN` directamente. Para lograr un efecto similar, se puede combinar `LEFT JOIN` y `RIGHT JOIN` con `UNION`.

* **SQLite**: No soporta `FULL JOIN` nativamente a partir de versiones anteriores. A partir de SQLite 3.33.0, `FULL JOIN` fue introducido.

## Alternativa para MySQL: Emular un FULL JOIN
Dado que MySQL no soporta FULL JOIN directamente, puedes emularlo combinando un LEFT JOIN y un RIGHT JOIN usando UNION.

```sql
SELECT c.nombre, p.pedido_id, p.producto
FROM clientes c
LEFT JOIN pedidos p ON c.cliente_id = p.cliente_id

UNION

SELECT c.nombre, p.pedido_id, p.producto
FROM clientes c
RIGHT JOIN pedidos p ON c.cliente_id = p.cliente_id;
```
Este método combina los resultados de ambos JOINs, asegurando que se incluyan todas las filas de ambas tablas, similar a un FULL JOIN.

## Consideraciones de Rendimiento
1. **Índices Adecuados**:
   * Para mejorar el rendimiento de las consultas con FULL JOIN, es crucial que las columnas utilizadas en las condiciones de unión estén indexadas. Esto facilita la búsqueda y combinación de filas coincidentes.

2. **Tamaño de las Tablas**:
   * Las uniones entre tablas muy grandes pueden ser costosas en términos de tiempo y recursos. Considera optimizar las tablas mediante la normalización y el uso de índices adecuados.

3. **Uso de Filtros**:
   * Aplicar condiciones en la cláusula WHERE puede reducir la cantidad de datos que necesita ser procesada, mejorando así el rendimiento.

4. **Evitar Uniones Innecesarias**:
   * Asegúrate de que realmente necesitas todas las uniones en la consulta. Uniones innecesarias pueden ralentizar significativamente la ejecución de la consulta.
