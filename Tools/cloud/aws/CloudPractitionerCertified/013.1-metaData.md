## Metadata
La Metadata en Amazon EC2 se refiere a la información acerca de una instancia de EC2 que puede ser accedida desde dentro de la misma instancia. Esta metadata incluye detalles sobre la configuración de la instancia, como la dirección IP, los ID de seguridad, las claves SSH, y otros atributos de la infraestructura. Los usuarios o aplicaciones pueden acceder a esta información para automatizar configuraciones, realizar ajustes dinámicos, o controlar características del sistema.

La metadata en EC2 es un conjunto de datos que describe la instancia en ejecución y su entorno. Se almacena de forma local en el hipervisor de EC2 y se puede consultar a través de solicitudes HTTP sin salir de la instancia.

La metadata incluye:

* Información básica sobre la instancia.

* Detalles de configuración de red.

* Datos sobre los volúmenes de almacenamiento.

* Claves de seguridad asociadas.

* Roles y credenciales temporales de IAM.

Se accede a la metadata de una instancia a través de una URL especial disponible desde dentro de la propia instancia:

```bash
http://169.254.169.254/latest/meta-data/
```

### Estructura de la Metadata
La metadata está organizada en diferentes categorías que pueden ser consultadas. Algunos de los elementos más relevantes incluyen:

1. **Atributos Generales**:

   * Instance ID: Identificador único de la instancia.

   * AMI ID: Identificador de la Amazon Machine Image (AMI) usada para lanzar la instancia.

   * Instance Type: Tipo de instancia (por ejemplo, t2.micro).

   * Launch Time: Fecha y hora de lanzamiento de la instancia.

2. **Configuración de Red**:

   * Local IP: Dirección IP privada asignada a la instancia dentro de la red VPC.

   * Public IP: Dirección IP pública, si está asignada.

   * MAC Address: Dirección MAC de la interfaz de red.

3. **Seguridad**:

   * IAM Roles: Si la instancia tiene un rol de IAM asociado, las credenciales temporales pueden obtenerse a través de la metadata.

   * Security Groups: Lista de grupos de seguridad asociados a la instancia.

4. **Almacenamiento**:

   * Block Devices: Detalles sobre los dispositivos de almacenamiento, como los volúmenes de EBS o Instance Store.

   * Root Device Type: Tipo de dispositivo raíz (EBS o Instance Store).

5. **Datos de Usuario (User Data)**:

   * Es un script o datos que puedes definir al lanzar una instancia. Estos datos se pueden usar para inicializar o configurar automáticamente la instancia en el primer arranque.

### Ejemplos de Uso de Metadata
1. **Obtener el ID de la Instancia**: Puedes obtener el ID de la instancia accediendo a la siguiente URL dentro de tu instancia:

    ```bash
    curl http://169.254.169.254/latest/meta-data/instance-id
    ```

2. **Obtener la Dirección IP Pública**: Para obtener la IP pública de la instancia:

    ```bash
    curl http://169.254.169.254/latest/meta-data/public-ipv4
    ```

3. **Acceder a Credenciales Temporales de IAM**: Si la instancia tiene un rol de IAM asociado, puedes obtener credenciales temporales:

    ```bash
    curl http://169.254.169.254/latest/meta-data/iam/security-credentials/<role-name>
    ```

4. **Leer el User Data**: El User Data es un script que se puede ejecutar al inicio de la instancia. Para acceder a él:

    ```bash
    curl http://169.254.169.254/latest/user-data/
    ```
    Esto es útil si se configuró un script para ejecutar tareas de inicialización.

### Metadata de IAM Roles
Si la instancia de EC2 tiene un rol de IAM asociado, la metadata también puede proporcionar credenciales temporales. Esto es importante para aplicaciones que necesitan acceso a otros servicios de AWS sin almacenar credenciales directamente en la instancia.

Ejemplo de acceso a las credenciales temporales:
```bash
curl http://169.254.169.254/latest/meta-data/iam/security-credentials/<role-name>
```
Este comando te devuelve un JSON con:

* Access Key ID

* Secret Access Key

* Token de sesión temporal

* Tiempo de expiración

Estas credenciales permiten a las aplicaciones ejecutar acciones permitidas por el rol IAM sin necesidad de credenciales estáticas.

## User Data
El User Data es parte de la metadata que permite proporcionar un script o una configuración personalizada cuando se lanza una instancia. Esto es útil para automatizar la configuración de servidores, como la instalación de software, actualizaciones de paquetes, o la configuración de servicios.

Por ejemplo, si al lanzar una instancia EC2 proporcionas un script de User Data que instala Apache, el servidor instalará automáticamente Apache al iniciarse.

```bash
#!/bin/bash
yum update -y
yum install httpd -y
service httpd start
```

### Best Practices para Usar Metadata
1. **No Almacenar Información Sensible en User Data**:

   * Aunque el User Data puede ser útil para iniciar configuraciones automatizadas, es recomendable no almacenar datos sensibles como claves o contraseñas, ya que cualquier usuario que tenga acceso a la instancia puede leerlo.

2. **Monitorear y Limitar Acceso a la Metadata**:

   * Para evitar accesos no autorizados a la metadata, es importante que las aplicaciones corriendo en la instancia no expongan rutas hacia la metadata a través de aplicaciones web o API vulnerables.

3. **Utilizar IAM Roles**:

   * Cuando una instancia necesita interactuar con otros servicios de AWS (como S3 o DynamoDB), es preferible usar roles de IAM para obtener credenciales temporales mediante la metadata, en lugar de incrustar credenciales estáticas.

## Acceso a Metadata desde AWS CLI
También puedes acceder a la metadata de la instancia usando la CLI de AWS mediante el comando `aws ec2 describe-instances`. Esto te permite ver muchos de los mismos detalles que podrías obtener accediendo a la URL de metadata, pero desde fuera de la instancia.
