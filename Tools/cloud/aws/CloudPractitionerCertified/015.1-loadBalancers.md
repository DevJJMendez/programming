## Balanceadores de Carga
Los balanceadores de carga son componentes esenciales en la arquitectura de sistemas distribuidos y en la computación en la nube, como AWS. Su función principal es distribuir eficientemente la carga de trabajo entre múltiples servidores o instancias para optimizar el rendimiento, mejorar la disponibilidad y garantizar la continuidad del servicio.

### ¿Qué es un Balanceador de Carga?
Un balanceador de carga (Load Balancer) es un dispositivo o servicio que distribuye automáticamente las solicitudes entrantes a varias instancias de servidores, aplicaciones o servicios. Actúa como un "proxy inverso", que recibe las solicitudes de los clientes y las distribuye a uno o más servidores backend según diferentes algoritmos o criterios.

### ¿Cuándo Usar un Balanceador de Carga?
El uso de un balanceador de carga es crucial en varios escenarios:

1. **Alta Disponibilidad**:

   * Cuando se desea asegurar que un sistema esté siempre disponible, incluso si uno o más servidores fallan, un balanceador de carga puede redirigir automáticamente el tráfico a servidores sanos.

2. **Escalabilidad Horizontal**:

   * En sistemas que requieren escalar horizontalmente, es decir, agregar más servidores para manejar más tráfico, un balanceador de carga distribuye la carga equitativamente entre ellos.

3. **Mejora del Rendimiento**:

   * Al distribuir las solicitudes de manera uniforme, se evita que un solo servidor se sobrecargue, lo que puede mejorar significativamente el rendimiento general del sistema.

4. **Tolerancia a Fallos**:

   * Si un servidor o instancia falla, el balanceador de carga puede detectar la falla y redirigir el tráfico a otras instancias sanas, minimizando la interrupción del servicio.

5. **Despliegue de Aplicaciones Multizona o Multiregión**:

   * En arquitecturas donde se implementan aplicaciones en múltiples zonas de disponibilidad (AZ) o regiones, un balanceador de carga es esencial para dirigir el tráfico de manera eficiente entre diferentes zonas o regiones.

6. **Gestión de Picos de Tráfico**:

   * Durante eventos de tráfico elevado, como promociones o lanzamientos de productos, un balanceador de carga puede ayudar a manejar la afluencia de usuarios sin comprometer el rendimiento.

### Tipos de Balanceadores de Carga en AWS
AWS ofrece varios tipos de balanceadores de carga bajo el servicio Elastic Load Balancing (ELB):

1. **Application Load Balancer (ALB)**:

   * Diseñado para balancear carga a nivel de aplicación (capa 7 del modelo OSI). Es ideal para aplicaciones web que requieren enrutamiento basado en contenido, como el enrutamiento de solicitudes a diferentes microservicios en función de la URL o el encabezado HTTP.

   * Soporta WebSockets y HTTP/2.

   * Ofrece reglas de enrutamiento avanzadas, como enrutamiento basado en la URL, en el host o en el método de solicitud HTTP.

2. **Network Load Balancer (NLB)**:

   * Diseñado para balancear carga a nivel de red (capa 4 del modelo OSI). Es ideal para aplicaciones que requieren una alta capacidad de procesamiento y baja latencia, como aplicaciones de alta demanda de datos o en tiempo real.

   * Puede manejar millones de solicitudes por segundo y ofrece estabilidad con tráfico volátil.

   * Adecuado para servicios que requieren IP fijas o que necesitan mantener conexiones persistentes.

3. **Classic Load Balancer (CLB)**:

   * Es el balanceador de carga original de AWS, que puede operar en las capas 4 (red) y 7 (aplicación) del modelo OSI.

   * Aún es utilizado en aplicaciones legacy, pero AWS recomienda migrar a ALB o NLB para aprovechar características más modernas y específicas.

### Algoritmos de Balanceo de Carga
Los balanceadores de carga utilizan diferentes algoritmos para decidir cómo distribuir las solicitudes entrantes:

1. **Round Robin**:

   * Las solicitudes se distribuyen de manera secuencial a cada servidor en la lista, uno después del otro.

   * Simple y efectivo para cargas uniformes.

2. **Least Connections**:

   * Las solicitudes se envían al servidor con la menor cantidad de conexiones activas.

   * Ideal para situaciones donde las solicitudes pueden tener tiempos de procesamiento variados.

3. **IP Hash**:

   * Las solicitudes se distribuyen en función de un hash generado a partir de la dirección IP del cliente.

   * Útil cuando se necesita mantener la sesión del usuario en un servidor específico (afinidad).

4. **Weighted Round Robin**:

   * Similar al Round Robin, pero permite asignar un peso a cada servidor, donde los servidores más potentes o menos cargados reciben más solicitudes.

### Características Adicionales de los Balanceadores de Carga en AWS
1. **Health Checks**:

   * Los balanceadores de carga en AWS realizan monitoreos regulares (Health Checks) para asegurarse de que las instancias de backend estén en buen estado. Si una instancia no pasa el chequeo de salud, el balanceador dejará de enviarle tráfico.

2. **SSL/TLS Termination**:

   * Los balanceadores de carga pueden manejar la terminación SSL/TLS, lo que significa que se encargan de desencriptar el tráfico seguro antes de enviarlo a los servidores backend, reduciendo la carga de estos.

3. **Auto Scaling Integration**:

   * AWS Elastic Load Balancing se integra con Auto Scaling, lo que permite ajustar automáticamente el número de instancias backend en función de la carga.

4. **Cross-Zone Load Balancing**:

   * Permite distribuir la carga equitativamente entre instancias en diferentes zonas de disponibilidad (AZ), mejorando la resiliencia y disponibilidad del servicio.

5. **Sticky Sessions (Session Affinity)**:

   * AWS ELB puede habilitar sesiones "pegajosas" donde un cliente específico siempre se conecta al mismo servidor backend durante la duración de una sesión, lo que es útil para aplicaciones que requieren mantener el estado del usuario.

6. **Access Logs**:

   * Los balanceadores de carga de AWS pueden generar registros de acceso detallados, que pueden ser utilizados para análisis de tráfico, seguridad y auditoría.

### Consideraciones al Usar Balanceadores de Carga
* **Costos**:

  * Utilizar balanceadores de carga introduce un costo adicional, por lo que es importante considerar si la carga de trabajo justifica este gasto.

2. **Configuración de Seguridad**:

   * Es fundamental configurar correctamente los Security Groups y las reglas de firewall para los balanceadores de carga y las instancias backend para proteger la infraestructura.

3. **Monitorización y Mantenimiento**:

   * AWS CloudWatch puede ser utilizado para monitorear la performance de los balanceadores de carga y tomar decisiones informadas sobre ajustes en la arquitectura.

4. **Geodistribución**:

   * Para aplicaciones globales, se pueden utilizar balanceadores de carga junto con AWS Global Accelerator o Route 53 para enrutar el tráfico a la región más cercana al usuario final, mejorando la latencia y la experiencia del usuario.
