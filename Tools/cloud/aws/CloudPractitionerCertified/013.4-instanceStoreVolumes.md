## Instance Store Volumes
Los Instance Store Volumes en Amazon EC2 son un tipo de almacenamiento temporal directamente asociado con la instancia de EC2. Estos volúmenes ofrecen almacenamiento de baja latencia y alto rendimiento, pero no persisten una vez que la instancia se detiene o termina.

Un Instance Store es un disco físico conectado directamente al servidor donde corre una instancia de EC2. Está basado en almacenamiento local (no en red) y ofrece un alto rendimiento en términos de entrada/salida (I/O), ideal para casos de uso donde el almacenamiento temporal y la velocidad son prioritarios.

### Características Clave de los Instance Store Volumes
1. **No Persistencia**:

   * Los datos almacenados en los Instance Store Volumes se pierden cuando:

     * La instancia se detiene (stop).

     * La instancia se termina (terminate).

     * La instancia falla.

   * Debido a esto, no es adecuado para almacenar datos críticos o que necesiten persistencia a largo plazo. Para almacenamiento persistente, AWS recomienda usar Elastic Block Store (EBS).

2. **Alto Rendimiento**:

   * El Instance Store ofrece un alto rendimiento, ya que es almacenamiento directo en hardware local del servidor. Es ideal para aplicaciones que requieren almacenamiento de baja latencia y alta capacidad de IOPS (operaciones de entrada/salida por segundo).

3. **Costo Eficiente**:

   * El Instance Store está incluido en el costo de algunas instancias EC2, lo que lo hace una opción económica cuando solo se necesita almacenamiento temporal.

4. **Capacidades y Tamaños Variables**:

   * El tamaño de los volúmenes del Instance Store varía según el tipo de instancia de EC2. Algunos tipos de instancias vienen preconfiguradas con múltiples volúmenes de Instance Store, mientras que otras no incluyen ningún Instance Store por defecto.

5. **Temporalidad**:

   * Es ideal para datos temporales, como archivos de caché, buffers intermedios, datos temporales de procesamiento y cualquier otra información que no sea crítica en caso de que se pierda.

### Casos de Uso Comunes
1. **Caché de Datos**:

   * Es excelente para almacenar caché de datos que se pueden regenerar fácilmente si se pierde, como caché de aplicaciones web o datos temporales que se procesan en tiempo real.

2. **Almacenamiento Intermedio**:

   * En escenarios de procesamiento intensivo, como bases de datos NoSQL o sistemas de análisis de big data, los Instance Store Volumes pueden ser utilizados como almacenamiento temporal para operaciones de entrada/salida de alta velocidad.

3. **Datos Temporales**:

   * Ideal para datos que se generan y procesan de forma temporal, como datos intermedios de procesamiento de archivos grandes o flujos de datos en aplicaciones de procesamiento masivo.

4. **Aplicaciones con Baja Persistencia de Datos**:

   * Los sistemas que no necesitan mantener un registro persistente de los datos, o que pueden volver a generarlos fácilmente, se benefician del uso del Instance Store debido a su rapidez y costo reducido.

### Tipos de Instancias con Instance Store
Algunas instancias de Amazon EC2 están equipadas con volúmenes de Instance Store por defecto, como las instancias de las familias "`d`", "`h`" y "`i`", que son especializadas para almacenamiento de alto rendimiento. Ejemplos:

* **i3 instances**:
  * Son optimizadas para almacenamiento en disco de alta IOPS, utilizando SSDs basados en NVMe.

* **d2 instances**:
  * Son ideales para grandes volúmenes de almacenamiento local y almacenamiento secuencial intensivo.

### Limitaciones del Instance Store
1. **No Persistente**:

   * La mayor limitación es la pérdida de datos al detener o terminar la instancia. Esto lo hace inapropiado para almacenar datos críticos.

2. **Limitado a Ciertas Instancias**:

   * No todas las instancias EC2 incluyen volúmenes de Instance Store. Es posible que tengas que elegir un tipo de instancia que soporte este tipo de almacenamiento si lo necesitas.

3. **Sin Respaldo Automático**:

   * A diferencia de EBS, que permite realizar snapshots (copias de seguridad automáticas), el Instance Store no tiene esta capacidad integrada.

4. **No Reconfigurable**:

   * Una vez que se asigna el almacenamiento del Instance Store a una instancia, no se puede cambiar su tamaño ni añadir más volúmenes de Instance Store sin lanzar una nueva instancia.

### Cómo Usar Instance Store
Cuando lanzas una instancia EC2, puedes elegir un tipo de instancia que incluya volúmenes de Instance Store. Estos volúmenes aparecerán como discos adicionales en tu instancia una vez que esté en ejecución.

Para almacenar datos en los volúmenes de Instance Store:

1. **Formatear el Volumen**: Al igual que con cualquier dispositivo de almacenamiento, primero debes formatear el volumen.

2. **Montar el Volumen**: Luego, puedes montarlo en el sistema operativo de la instancia para empezar a utilizarlo.

Si necesitas que los datos sean persistentes, es recomendable utilizar **Amazon EBS** o realizar copias de los datos almacenados en Instance Store a S3 o EBS regularmente.
