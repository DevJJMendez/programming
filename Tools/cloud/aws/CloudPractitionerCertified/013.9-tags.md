## Tags
En AWS, los Tags son etiquetas **clave-valor** que se pueden aplicar a los recursos de AWS, como instancias EC2, volúmenes EBS, grupos de seguridad, y más. Los **tags** ayudan a organizar, identificar, y gestionar los recursos dentro de una cuenta de AWS, especialmente cuando manejas una gran cantidad de recursos en diferentes regiones o entornos.

### Características Principales de los Tags en EC2:
1. **Estructura de los Tags**:

   * **Clave (Key)**: Es el identificador del tag. Cada recurso puede tener hasta 50 tags y cada clave debe ser única por recurso.

   * **Valor (Value)**: Es el valor asociado a la clave. Puede ser un valor descriptivo que varía según el propósito del recurso o una identificación específica.

* **Ejemplos de Uso Común**:
  
  * **Entorno (Environment)**: `Key: Environment, Value: Production` o `Key: Environment, Value: Development`.

  * **Propósito (Purpose)**: `Key: Purpose, Value: WebServer` o `Key: Purpose, Value: Database`.

  * **Propietario (Owner)**: `Key: Owner, Value: IT Team` o `Key: Owner, Value: John Doe`.

  * **Proyecto (Project)**: `Key: Project, Value: MobileApp` o `Key: Project, Value: Analytics`.

2. **Organización y Gestión**:

   * **Filtrado y Búsqueda**: Los tags permiten filtrar y buscar recursos de manera rápida en la consola de AWS. Esto es útil para encontrar todos los recursos relacionados con un proyecto específico, una aplicación, o un entorno.

   * **Automatización**: Se pueden usar tags para automatizar la gestión de recursos, como la ejecución de scripts que actúan sobre recursos etiquetados de manera específica.

   * **Cost Allocation Tags**: AWS permite utilizar ciertos tags para segmentar y asignar costos a diferentes proyectos, departamentos o equipos dentro de una organización. Estos se conocen como Cost Allocation Tags y son fundamentales para el seguimiento y la facturación detallada.

3. **Seguridad y Control de Acceso**:

   * **IAM Policies basadas en Tags**: AWS IAM permite definir políticas de control de acceso que restringen o permiten acciones en recursos basados en tags. Por ejemplo, podrías permitir que un usuario solo tenga acceso a instancias etiquetadas con su nombre o equipo.

### Mejores Prácticas para Tags:

* **Consistencia**: Es importante establecer una convención de nomenclatura para los tags a nivel de organización. Esto asegura que los tags sean consistentes y fáciles de entender.

* **Documentación**: Mantén un registro de los tags utilizados y sus significados, especialmente si hay múltiples equipos trabajando en la misma cuenta de AWS.

* **Mantenimiento**: Revisa y actualiza regularmente los tags para asegurarte de que siguen siendo relevantes y útiles para la organización.

### Herramientas de AWS Relacionadas con Tags:

* **Tag Editor**: AWS proporciona una herramienta llamada Tag Editor que permite buscar y administrar tags en todos los recursos de AWS dentro de una cuenta. Esto facilita la edición masiva y la aplicación de tags.

* **Billing Reports**: Los tags se pueden utilizar en los informes de facturación y costos de AWS para desglosar los costos por proyecto, departamento, o cualquier otra clave de tag que utilices para la asignación de costos.

### Aplicación de Tags a Instancias EC2:
Los tags pueden ser aplicados tanto al lanzar una nueva instancia EC2 como después de que la instancia esté en ejecución. Además, es posible aplicar los mismos tags a múltiples instancias simultáneamente.

Los tags también se pueden aplicar a otros recursos relacionados con EC2, como volúmenes EBS, IPs elásticas, y grupos de seguridad, lo que facilita la organización integral.

### Ejemplo de Tagging en EC2:
Supongamos que tienes múltiples instancias EC2 utilizadas en diferentes proyectos y entornos. Podrías aplicar los siguientes tags:

Instancia 1:

```ts
Key: Environment, Value: Production
Key: Project, Value: Website
Key: Owner, Value: Web Team
```

Instancia 2:

```ts
Key: Environment, Value: Development
Key: Project, Value: MobileApp
Key: Owner, Value: App Team
```
Con estos tags, podrías fácilmente filtrar todas las instancias que pertenecen al entorno de producción, identificar qué equipo es responsable de cada instancia, y analizar los costos asociados a cada proyecto.
