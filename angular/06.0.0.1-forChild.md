# `forChild`
Es un método utilizado para configurar módulos secundarios en Angular, principalmente en el contexto del enrutamiento. Permite definir rutas específicas para un módulo sin interferir con las rutas principales de la aplicación configuradas con forRoot.

Se encuentra en módulos secundarios (**feature modules**) que necesitan configurar su propio conjunto de rutas, pero sin volver a inicializar los servicios globales proporcionados por el módulo de enrutamiento.

## ¿Para qué sirve forChild?
* Definir rutas locales: Permite agregar rutas específicas para un módulo funcional (**feature module**).

* Mantener modularidad: Ayuda a separar la configuración de rutas por módulo, lo que facilita la escalabilidad y mantenibilidad de la aplicación.

* Evitar duplicación de instancias: A diferencia de `forRoot`, `forChild` no proporciona los servicios del enrutador nuevamente, evitando que se creen múltiples instancias de estos servicios.

## ¿Qué problemas resuelve forChild?
* Configuración de rutas en módulos secundarios: Permite definir rutas locales para cada módulo sin sobrecargar las rutas principales.

* Reutilización de servicios del enrutador: Se asegura de que los servicios del módulo de enrutamiento (como Router o ActivatedRoute) no se reinicialicen en los módulos secundarios.

* Separación de responsabilidades: Ayuda a organizar la lógica de rutas de manera modular, haciendo que las aplicaciones grandes sean más fáciles de mantener.

## ¿Cómo lo resuelve?
* Carga de rutas en el módulo local: forChild se usa dentro de módulos secundarios para configurar rutas específicas que solo afectan al módulo en cuestión.

* No inicializa servicios duplicados: Aprovecha los servicios ya configurados por forRoot en el módulo raíz.

* Permite Lazy Loading: Trabaja de manera eficiente con la carga diferida (lazy loading) para mejorar el rendimiento de la aplicación.

## Ejemplo con forChild
Supongamos que tenemos una aplicación con dos módulos:

* **`AppModule` (principal).**

* **`FeatureModule` (un módulo funcional con rutas propias).**

**Archivo de rutas principal (`AppRoutingModule`)**, `app-routing.module.ts`
```ts
import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { HomeComponent } from './home/home.component';

const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'feature', loadChildren: () => import('./feature/feature.module').then(m => m.FeatureModule) }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)], // Rutas principales
  exports: [RouterModule]
})
export class AppRoutingModule {}
```
**Archivo de rutas secundario (`FeatureRoutingModule`)**, `feature-routing.module.ts`
```ts
import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { HomeComponent } from './home/home.component';

const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'feature', loadChildren: () => import('./feature/feature.module').then(m => m.FeatureModule) }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)], // Rutas principales
  exports: [RouterModule]
})
export class AppRoutingModule {}
```
**Módulo secundario con rutas (FeatureModule) `feature.module.ts`**
```ts
import { NgModule } from '@angular/core';
import { CommonModule } from '@angular/common';
import { FeatureComponent } from './feature.component';
import { FeatureRoutingModule } from './feature-routing.module';

@NgModule({
  declarations: [FeatureComponent],
  imports: [
    CommonModule,
    FeatureRoutingModule // Incluye las rutas específicas del módulo
  ]
})
export class FeatureModule {}
```
**Comportamiento esperado**
  * Navegar a `/` muestra el `HomeComponent`.

  * Navegar a `/feature` carga el `FeatureModule` con su componente raíz `FeatureComponent`.

## Ventajas de usar forChild
* **Modularidad**: Mantiene las rutas organizadas y separadas por módulo, lo que es esencial en aplicaciones grandes.

* **Evita duplicación**: No inicializa los servicios globales del enrutador nuevamente, lo que mejora el rendimiento y evita errores.

* **Compatibilidad con Lazy Loading**: Permite cargar módulos bajo demanda, reduciendo el tiempo de carga inicial de la aplicación.

* **Facilita el mantenimiento**: Los cambios en un módulo no afectan las rutas de otros módulos.
