# Observables
Un Observable es un objeto que representa un flujo de datos que se emiten a lo largo del tiempo. Puede ser pensado como una fuente de datos que produce valores, los cuales pueden ser observados y manipulados por suscriptores. Los datos pueden ser de cualquier tipo: números, objetos, eventos, etc.

Un Observable es un flujo de datos que puede emitir tres tipos de eventos:

* **`next`**: Un valor es emitido.

* **`error`**: Se produce un error.

* **`complete`**: El flujo finaliza exitosamente.

Son parte de la librería RxJS (Reactive Extensions for JavaScript), que se utiliza ampliamente en Angular para manejar operaciones asíncronas, eventos y datos en tiempo real.

### Características Clave:
* **Asíncrono**: Los Observables pueden manejar operaciones asíncronas, permitiendo que los datos se emitan cuando estén disponibles, sin bloquear la ejecución del código.

* **Lazy (Perezoso)**: Un Observable no comienza a emitir valores hasta que alguien se suscribe a él. Esto significa que puedes definir un Observable sin que ejecute ningún código hasta que realmente se necesite.

* **Composición**: Los Observables pueden ser combinados, transformados y filtrados usando operadores de RxJS, permitiendo un manejo avanzado de flujos de datos.

## ¿Para qué sirven los Observables?
Los Observables son útiles para manejar flujos de datos asíncronos y operaciones reactivas. Sirven para:

* Manejar eventos: Escuchar clics, teclas presionadas o cualquier tipo de evento DOM.

* Operaciones asíncronas: Procesar respuestas de HTTP, temporizadores, o WebSockets.

* Reactividad: Reaccionar automáticamente a cambios en los datos, facilitando la comunicación entre componentes y servicios.

* Transformación de datos: Aplicar operaciones como filtros, mapas, combinaciones y otros en los datos emitidos.

## ¿Qué resuelven los Observables?
Resuelven problemas asociados a la gestión de operaciones asíncronas y a la necesidad de procesar flujos de datos complejos:

* Complejidad del manejo asíncrono:
  * Sustituyen múltiples callbacks anidados, conocidos como callback hell.
  
  * Son una mejora sobre las Promises, ya que permiten manejar flujos continuos de datos (no solo valores únicos).

* Control preciso sobre el flujo de datos: Permiten pausar, cancelar, transformar, combinar y manejar errores dentro de los flujos.

* Optimización del rendimiento: Reducen emisiones innecesarias mediante operadores como debounceTime, distinctUntilChanged, etc.

* Composición de flujos complejos: Con operadores, es fácil combinar múltiples fuentes de datos o aplicar lógicas avanzadas de manera declarativa.

## ¿Cómo lo resuelven?
Los Observables ofrecen un patrón basado en suscripción y reactividad:

1. **Suscripción**: Un consumidor (llamado **[`Observer`](09.1-Observer.md)**) se suscribe al Observable para recibir los valores emitidos.
```ts
const observable = new Observable(observer => {
  observer.next('Valor 1');
  observer.next('Valor 2');
  observer.complete();
});

observable.subscribe({
  next: value => console.log(value),
  error: err => console.error(err),
  complete: () => console.log('¡Finalizado!')
});
```

2. **Encadenamiento de [operadores](09.2.0-operators.md)**: Se utilizan operadores como `map`, `filter`, y `mergeMap` para transformar y combinar flujos de datos.
```ts
import { of } from 'rxjs';
import { map } from 'rxjs/operators';

of(1, 2, 3)
  .pipe(map(value => value * 2))
  .subscribe(value => console.log(value)); // 2, 4, 6
```

3. **Cancelación de flujos**: Los Observables permiten cancelar operaciones largas mediante el método [`unsubscribe`](09.8-unsubscribe.md).
```ts
const subscription = interval(1000).subscribe(value => console.log(value));

setTimeout(() => subscription.unsubscribe(), 5000); // Detener después de 5 segundos
```
