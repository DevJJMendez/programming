# Hot Observable
Un Hot Observable es un tipo de Observable en RxJS que **comienza a emitir valores inmediatamente, independientemente de si hay suscriptores o no**. A diferencia de los [Cold Observables](09.3-coldObservable.md), que inician la emisión de valores solo cuando se suscriben a ellos, los Hot Observables generan valores en su emisión de forma continua, incluso si ningún suscriptor está escuchando en ese momento.

En otras palabras, un Hot Observable **produce datos "en vivo"**, es decir, **se genera un flujo de datos de manera activa, sin importar cuántos suscriptores se hayan suscrito o cuándo se suscriben**. Si un suscriptor se suscribe a un Hot Observable después de que **algunos valores ya han sido emitidos, no recibirá los valores previos**, solo los valores que se emitan **después de su suscripción**.

## ¿Para qué sirven los Hot Observables?
Los Hot Observables son útiles cuando se trabaja con fuentes de datos en tiempo real, como:

* Eventos de usuario: Escuchar clics, desplazamiento o cualquier interacción del usuario.

* WebSockets: Comunicación bidireccional en tiempo real entre el cliente y el servidor.

* Streams de medios: Como video o audio en tiempo real, donde los datos continúan fluyendo sin detenerse.

* Streams de datos compartidos: Por ejemplo, un evento que debe ser compartido entre múltiples observadores.

* Streams con múltiples suscriptores: Los Hot Observables permiten que varias personas se suscriban a un mismo flujo de datos sin tener que reiniciar el flujo.

## ¿Qué resuelven los Hot Observables?
Los Hot Observables resuelven la necesidad de manejar fuentes de datos que no son estáticas y que deben ser compartidas entre múltiples suscriptores. Esto incluye:

* Emisión de datos en tiempo real: Permiten la transmisión continua de datos sin que cada suscriptor reinicie el proceso de emisión.

* Manejo de eventos asincrónicos y en vivo: Son ideales para aplicaciones donde se requiere responder a eventos en vivo, como clics o mensajes en tiempo real.

* Evitar la duplicación de esfuerzos: Evitan que cada suscriptor reciba una nueva instancia del flujo, lo que optimiza el rendimiento y la eficiencia.

## ¿Cómo lo resuelven?
Un Hot Observable resuelve estos problemas de la siguiente manera:

* Emisión activa y compartida: Los valores se generan de manera independiente de los suscriptores. No es necesario que un suscriptor inicie el flujo; este comienza tan pronto como el Observable se crea.

* Reemisión a suscriptores posteriores: Los suscriptores se "enganchan" al flujo activo y sólo reciben los valores emitidos después de haberse suscrito. No reciben valores previos.

* Uso de "Subjects": Un patrón común para crear Hot Observables es el uso de Subjects, que son tanto Observers como Observables. Esto permite que se emitan valores y, al mismo tiempo, se puedan suscribir otros Observers.

### Ejemplo básico de Hot Observable con [Subject](09.5-subject.md)
Un Subject en RxJS es un tipo especial de Observable que también puede ser utilizado como un Observer. Esto lo hace ideal para implementar Hot Observables, ya que puedes emitir valores de manera activa y permitir que múltiples suscriptores se "conecten" a ese flujo.

```ts
import { Subject } from 'rxjs';

// Crear un Hot Observable usando Subject
const hotObservable = new Subject();

// Suscribirse al Hot Observable
hotObservable.subscribe(value => {
  console.log('Suscriptor 1 recibió:', value);
});

hotObservable.subscribe(value => {
  console.log('Suscriptor 2 recibió:', value);
});

// Emitir valores desde el Subject
hotObservable.next('Valor 1');
hotObservable.next('Valor 2');
```
**salida**
```bash
Suscriptor 1 recibió: Valor 1
Suscriptor 2 recibió: Valor 1
Suscriptor 1 recibió: Valor 2
Suscriptor 2 recibió: Valor 2
```
Aquí, ambos suscriptores reciben los mismos valores porque se están "enganchando" al flujo de datos activo, pero ninguno de ellos recibirá valores que fueron emitidos antes de suscribirse.

## Ejemplo avanzado con [ReplaySubject](09.7-replaySubject.md)
Para obtener un comportamiento de Hot Observable, pero también reproducir valores previos a los nuevos suscriptores, puedes usar un ReplaySubject. Este tipo de Subject almacena una cantidad especificada de emisiones previas y las reproduce a nuevos suscriptores.

```ts
import { ReplaySubject } from 'rxjs';

// Crear un ReplaySubject que guarda los últimos 2 valores
const replaySubject = new ReplaySubject(2);

// Emitir algunos valores
replaySubject.next('Valor 1');
replaySubject.next('Valor 2');
replaySubject.next('Valor 3');

// Nuevo suscriptor recibe los últimos 2 valores emitidos
replaySubject.subscribe(value => {
  console.log('Nuevo suscriptor recibió:', value);
});
```
salida
```bash
Nuevo suscriptor recibió: Valor 2
Nuevo suscriptor recibió: Valor 3
```
En este caso, el ReplaySubject asegura que el nuevo suscriptor reciba los valores previos que ya han sido emitidos, lo cual es útil para casos donde quieras compartir datos pero también retener el historial para nuevos suscriptores.

## Uso de Hot Observables en Angular
En Angular, los Hot Observables se utilizan comúnmente en situaciones de comunicación en tiempo real y gestión de eventos, como:

* WebSockets: Los datos en tiempo real que se reciben desde el servidor.

* Eventos del DOM (por ejemplo, clics, desplazamiento): Utilizar un Subject para manejar eventos en tiempo real de la UI.
