# Constructor
El constructor en un componente de Angular es el primer método que se ejecuta cuando se crea una instancia de la clase del componente. Aunque no es un hook del ciclo de vida, juega un papel crucial en la configuración inicial del componente, especialmente en la inyección de dependencias.

## Estructura Básica del Constructor
```ts
export class ExampleComponent {
  constructor() {
    console.log('El componente ha sido instanciado.');
  }
}
```
En este ejemplo, el constructor se ejecuta cuando Angular crea el componente.

## ¿Para qué sirve?
El constructor sirve para:

* **Inyectar dependencias**: Angular utiliza el constructor para inyectar servicios u otros elementos requeridos en un componente, directiva o servicio.
  * El constructor se usa para recibir las instancias de servicios u otras dependencias necesarias para el funcionamiento del componente. Angular utiliza la inyección de dependencias para gestionar estas instancias de manera automática.

```ts
import { HttpClient } from '@angular/common/http';

export class ExampleComponent {
  constructor(private http: HttpClient) {
    console.log('HttpClient ha sido inyectado:', this.http);
  }
}
```

* **Configuración Inicial**: Aunque la lógica de inicialización suele colocarse en `ngOnInit`, a veces puede ser necesario configurar propiedades o realizar operaciones mínimas en el constructor. Sin embargo, esto debe hacerse con precaución, ya que no todas las propiedades del componente estarán disponibles en este punto.

```ts
@Component({
  selector: 'app-example',
  template: `<p>{{ greeting }}</p>`,
})
export class ExampleComponent {
  greeting: string;

  constructor() {
    this.greeting = '¡Hola, Angular!';
  }
}
```

* **Configurar propiedades internas**: Inicializar variables o propiedades que sean necesarias para que el componente funcione.

* **Crear instancias de clases**: El constructor actúa como punto de entrada para la creación de instancias de la clase.

## ¿Qué resuelve?
El constructor resuelve:

* **Inicialización de la clase**: Garantiza que el componente, directiva o servicio esté correctamente configurado antes de usarse.

* **Gestión de dependencias**: Facilita la inyección de dependencias usando los decoradores de Angular como `@Injectable()` o `@Component()`.

* **Preparación de datos iniciales**: Define un lugar claro para establecer valores predeterminados o configuraciones iniciales.

## ¿Cómo lo resuelve?
El constructor resuelve estos problemas al ser el primer método que Angular invoca cuando instancia la clase. A través de la Inyección de Dependencias, Angular proporciona automáticamente los valores requeridos en los parámetros definidos en el constructor.

## Limitaciones del Constructor
* **Sin lógica compleja**: No es el lugar para ejecutar lógica pesada como llamadas HTTP o inicialización que depende de datos de entrada.

* **Sin acceso a `@Input()`**: Las propiedades decoradas con `@Input()` no están disponibles en el constructor.

* **Se ejecuta antes que otros hooks**: No tiene información completa del ciclo de vida del componente.

## Buenas Prácticas al Usar el Constructor
* **Inyección de Dependencias Correcta**: Utiliza el constructor únicamente para inyectar dependencias. No realices tareas que deberían manejarse en otros hooks del ciclo de vida, como `**ngOnInit**`.

    ```ts
    constructor(private service1: Service1, private service2: Service2) { }
    ```

* **Evita Lógica Compleja en el Constructor**: El constructor no es el lugar para lógica compleja o para acceder a propiedades `@Input`. Estas propiedades no estarán inicializadas en este punto, lo que podría causar errores o comportamientos inesperados.

    ```ts
    constructor(private myService: MyService) {
      // Evitar lógica compleja aquí
    }
    ```

* **Mantenlo Ligero**: El constructor debe ser lo más simple y ligero posible. Su único propósito debería ser la configuración inicial y la inyección de dependencias.

    ```ts
    constructor(private myService: MyService) {
      // Solo configuración inicial y dependencias
    }
    ```

* **Uso de `@Inject`**: Aunque en la mayoría de los casos Angular puede inferir qué servicio se está inyectando en el constructor, puedes usar `@Inject` para especificar explícitamente el token de inyección, especialmente en casos de inyección de tokens personalizados o al inyectar algo que no es un servicio estándar.

    ```ts
    import { Inject } from '@angular/core';

    constructor(@Inject('API_URL') private apiUrl: string) { }
    ```

* **Evita Dependencias Circulares**: Las dependencias circulares ocurren cuando dos o más servicios se dependen mutuamente, lo que puede llevar a errores en tiempo de ejecución. Asegúrate de diseñar tus servicios y sus dependencias de manera que eviten estos ciclos.

### Ejemplo Completo
```ts
import { Component, Inject } from '@angular/core';
import { MyService } from './my-service.service';
import { LoggerService } from './logger.service';

@Component({
  selector: 'app-my-component',
  templateUrl: './my-component.component.html',
  styleUrls: ['./my-component.component.css']
})
export class MyComponent {

  // Inyectar múltiples dependencias
  constructor(
    private myService: MyService,
    private logger: LoggerService,
    @Inject('API_URL') private apiUrl: string
  ) {
    // Configuración inicial ligera
    this.logger.log('MyComponent creado.');
  }

  // El resto de la lógica debe ir en ngOnInit u otros hooks del ciclo de vida
  ngOnInit(): void {
    this.myService.getData(this.apiUrl).subscribe(data => {
      console.log('Datos recibidos:', data);
    });
  }
}
```
