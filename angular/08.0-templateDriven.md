# Template Driven
Los Template-Driven Forms son una forma de manejar formularios en Angular que utiliza el enfoque basado en plantillas (HTML) para crear y gestionar formularios. En este paradigma, se hace un uso extensivo de atributos y directivas proporcionadas por Angular para definir formularios y validaciones directamente en el archivo HTML.

Este método se caracteriza por su simplicidad y es ideal para formularios pequeños o proyectos que no requieren una gran cantidad de lógica compleja en los formularios.

## ¿Para qué sirven los Template-Driven Forms?
Sirven para crear y manejar formularios en aplicaciones Angular de manera simple y declarativa. Permiten:

* Gestión de formularios: Crear formularios dinámicos directamente en el HTML.

* Validación automática: Aplicar reglas de validación de manera declarativa.

* Enlace de datos bidireccional: Vincular los valores del formulario al modelo de datos de manera automática.

## ¿Qué resuelven los Template-Driven Forms?
* Simplificación del desarrollo: Facilitan la creación rápida de formularios sin necesidad de escribir una lógica compleja en el componente TypeScript.

* Validación declarativa: Permiten definir validaciones directamente en la plantilla HTML.

* Reducción de código en TypeScript: La mayoría de la lógica del formulario se gestiona desde el HTML.

* Sincronización automática de datos: Mantienen el modelo de datos sincronizado con los valores del formulario gracias al enlace bidireccional `[(ngModel)]`.

## ¿Cómo lo resuelven los Template-Driven Forms?
Los Template-Driven Forms utilizan:

* Directivas: Angular proporciona directivas como ngModel, ngForm, ngSubmit para manejar la lógica de los formularios.

* Validaciones integradas: Validaciones como `required`, `minlength`, `maxlength` se aplican directamente en el HTML.

* Enlace bidireccional: Usan `[(ngModel)]` para sincronizar el modelo de datos con el valor de los controles del formulario.

* Gestión automática de estados: Angular rastrea estados como pristine, dirty, touched, valid automáticamente.

## ¿Cómo se implementan los Template-Driven Forms?
* **Configuración inicial**, Importar el módulo: Antes de usar Template-Driven Forms, debes importar el módulo FormsModule en tu módulo principal.
```ts
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms';
import { AppComponent } from './app.component';

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule, FormsModule],
  bootstrap: [AppComponent],
})
export class AppModule {}
```

* Ejemplo práctico
HTML
```html
<form #userForm="ngForm" (ngSubmit)="onSubmit(userForm)">
  <div>
    <label for="name">Nombre:</label>
    <input 
      type="text" 
      id="name" 
      name="name" 
      [(ngModel)]="user.name" 
      required
    />
    <div *ngIf="name.invalid && name.touched">
      El nombre es requerido.
    </div>
  </div>

  <div>
    <label for="email">Correo:</label>
    <input 
      type="email" 
      id="email" 
      name="email" 
      [(ngModel)]="user.email" 
      required
    />
    <div *ngIf="email.invalid && email.touched">
      El correo es inválido.
    </div>
  </div>

  <button type="submit" [disabled]="userForm.invalid">Enviar</button>
</form>
```
TypeScript:
```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
})
export class AppComponent {
  user = {
    name: '',
    email: '',
  };

  onSubmit(form: any) {
    console.log('Formulario enviado:', form.value);
  }
}
```

### Estados y validaciones
Puedes verificar los estados de los controles de formulario usando:
```html
<div *ngIf="userForm.submitted">
  Formulario enviado correctamente.
</div>

<div *ngIf="userForm.controls.name?.invalid && userForm.controls.name?.touched">
  El campo nombre es obligatorio.
</div>
```

## Ventajas de los Template-Driven Forms
* Simplicidad: Ideales para formularios pequeños y aplicaciones sencillas.

* Legibilidad: Toda la lógica está directamente en la plantilla, lo que facilita el seguimiento del flujo.

* Menos configuración: No requiere definir explícitamente los controles en el componente TypeScript.

## Limitaciones de los Template-Driven Forms
* Dificultad con lógica compleja: No son adecuados para formularios grandes o con reglas de validación personalizadas avanzadas.

* Falta de control total: Es más difícil acceder y manipular dinámicamente los estados del formulario desde TypeScript.

* Menor escalabilidad: Los formularios reactivos son más adecuados para proyectos grandes.
