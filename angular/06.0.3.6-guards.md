# Guards
Un guard en Angular es una función o clase que implementa una interfaz específica para controlar la navegación de rutas. Los guards permiten decidir si una ruta puede ser activada, desactivada, cargada o si un usuario puede salir de una ruta determinada. Sirven para implementar reglas de acceso basadas en lógica personalizada.

## ¿Para qué sirve un Guard?
Los guards se utilizan para:

* Controlar el acceso a rutas protegidas: Aseguran que solo los usuarios autorizados puedan acceder a ciertas rutas.

* Proteger datos sensibles: Restringen la navegación hacia componentes que manejan información crítica.

* Evitar navegación no deseada: Por ejemplo, evitar que el usuario salga de un formulario sin guardar los cambios.

* Controlar la carga de módulos: Permiten cargar módulos solo bajo ciertas condiciones, como autenticación.

## ¿Qué problema resuelve un Guard?
* Acceso no autorizado: Evita que usuarios no autenticados o con roles incorrectos accedan a partes del sistema.

* Pérdida de datos: Protege a los usuarios de perder datos al salir de un formulario sin confirmación.

* Condiciones de carga: Bloquea la carga de módulos que no deberían estar disponibles en un contexto determinado.

## ¿Cómo lo resuelve?
Los guards se ejecutan antes de activar o desactivar una ruta, evaluando las condiciones configuradas. Dependiendo de la lógica del guard, Angular decide si permitir o bloquear la navegación.

1. **Guards implementados en rutas**: Los guards se configuran directamente en las rutas para verificar condiciones como autenticación, roles, o estados de la aplicación.

2. **Intercepción y redirección**: Si las condiciones del guard no se cumplen, el usuario es redirigido o se cancela la navegación.

## Tipos de Guards en Angular
Angular proporciona diferentes tipos de guards para manejar la navegación entre rutas y garantizar que ciertos requisitos se cumplan antes de permitir que un usuario acceda o abandone una ruta. Los cinco principales son:

* **`CanActivate`**: Determina si una ruta puede activarse.

* **`CanActivateChild`**: Verifica si las rutas hijas pueden activarse.

* **`CanDeactivate`**: Evalúa si el usuario puede salir de una ruta.

* **`CanLoad`**: Controla si un módulo cargado de manera diferida puede cargarse.

* **`Resolve`**: Obtiene datos antes de activar una ruta.

## CanActivate
**¿Qué es?**: CanActivate es un guard que controla si una ruta puede ser activada o no.

**¿Para qué sirve?**: Se utiliza para proteger rutas y asegurarse de que ciertas condiciones, como autenticación o roles específicos, se cumplan antes de acceder a una página.

**¿Qué resuelve?**: Evita que usuarios no autorizados accedan a rutas protegidas o privadas.

**¿Cómo lo resuelve?**: Evalúa la lógica definida en su método `canActivate`. Si devuelve `true`, la ruta se activa; de lo contrario, se bloquea la navegación.

```ts
@Injectable({
  providedIn: 'root',
})
export class AuthGuard implements CanActivate {
  constructor(private authService: AuthService, private router: Router) {}

  canActivate(): boolean {
    const isAuthenticated = this.authService.isLoggedIn();
    if (!isAuthenticated) {
      this.router.navigate(['/login']);
    }
    return isAuthenticated;
  }
}
```
Configuración en rutas
```ts
const routes: Routes = [
  { path: 'dashboard', component: DashboardComponent, canActivate: [AuthGuard] },
];
```

## CanActivateChild
**¿Qué es?**: `CanActivateChild` es un **`guard`** que verifica si una ruta hija puede activarse.

**¿Para qué sirve?**: Proporciona un control adicional sobre las rutas secundarias, como asegurar que solo usuarios con roles específicos puedan acceder a subrutas.

**¿Qué resuelve?**: Protege subrutas de acceso no autorizado, especialmente en secciones jerárquicas.

**¿Cómo lo resuelve?**: Evalúa la lógica en el método `canActivateChild`. Si devuelve `true`, la ruta hija puede activarse.

```ts
@Injectable({
  providedIn: 'root',
})
export class AdminGuard implements CanActivateChild {
  constructor(private authService: AuthService) {}

  canActivateChild(): boolean {
    const isAdmin = this.authService.isAdmin();
    return isAdmin;
  }
}
```
Configuración en rutas
```ts
const routes: Routes = [
  {
    path: 'admin',
    component: AdminComponent,
    canActivateChild: [AdminGuard],
    children: [
      { path: 'settings', component: SettingsComponent },
      { path: 'users', component: UsersComponent },
    ],
  },
];
```

## CanDeactivate
**¿Qué es?**: `CanDeactivate` es un guard que controla si el usuario puede salir de la ruta actual.

**¿Para qué sirve?**: Evita que el usuario pierda cambios no guardados al intentar salir de una página, como un formulario.

**¿Qué resuelve?**: Protege contra la pérdida de datos o navegación accidental desde páginas críticas.

**¿Cómo lo resuelve?**: Evalúa la lógica en el método canDeactivate. Si devuelve `true`, la navegación continúa; de lo contrario, se bloquea.

```ts
export interface CanComponentDeactivate {
  canDeactivate: () => boolean | Promise<boolean>;
}

@Injectable({
  providedIn: 'root',
})
export class UnsavedChangesGuard implements CanDeactivate<CanComponentDeactivate> {
  canDeactivate(component: CanComponentDeactivate): boolean | Promise<boolean> {
    return component.canDeactivate ? component.canDeactivate() : true;
  }
}
```
En el componente asociado
```ts
export class FormComponent implements CanComponentDeactivate {
  hasUnsavedChanges = true;

  canDeactivate(): boolean {
    return this.hasUnsavedChanges
      ? confirm('¿Deseas salir sin guardar los cambios?')
      : true;
  }
}
```
Configuración en rutas
```ts
const routes: Routes = [
  { path: 'form', component: FormComponent, canDeactivate: [UnsavedChangesGuard] },
];
```

## CanLoad
**¿Qué es?**: `CanLoad` es un guard que controla si un módulo cargado de manera diferida (lazy-loaded) puede cargarse.

**¿Para qué sirve?**: Evita que módulos protegidos se carguen en la aplicación si no se cumplen ciertas condiciones, como autenticación.

**¿Qué resuelve?**: Impide la carga innecesaria de módulos, mejorando la seguridad y optimizando el rendimiento.

**¿Cómo lo resuelve?**: Evalúa la lógica en el método canLoad. Si devuelve true, el módulo se carga.

```ts
@Injectable({
  providedIn: 'root',
})
export class AuthGuard implements CanLoad {
  constructor(private authService: AuthService, private router: Router) {}

  canLoad(): boolean {
    const isAuthenticated = this.authService.isLoggedIn();
    if (!isAuthenticated) {
      this.router.navigate(['/login']);
    }
    return isAuthenticated;
  }
}
```
Configuración en rutas
```ts
const routes: Routes = [
  {
    path: 'admin',
    loadChildren: () => import('./admin/admin.module').then(m => m.AdminModule),
    canLoad: [AuthGuard],
  },
];
```

## Buenas Prácticas
* Mantén la lógica sencilla: Evita incluir lógica compleja directamente en los guards, utiliza servicios para manejarla.

* Combina guards: Usa varios guards en una ruta para manejar diferentes casos.

* Prueba los guards: Escribe pruebas unitarias para validar la lógica de los guards.
