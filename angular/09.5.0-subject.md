# `Subject`
Un Subject es una clase de RxJS que actúa tanto como un Observable (una fuente de datos) como un Observer (un consumidor de datos). Es una combinación de ambos conceptos, lo que le permite recibir valores de múltiples fuentes y retransmitirlos a sus suscriptores.

En términos sencillos:
* Es un Observable: Los suscriptores pueden escuchar los valores emitidos por el Subject.

* Es un Observer: Puede recibir valores a través de métodos como next(), error() y complete().

```ts
import { Subject } from 'rxjs';

const subject = new Subject<number>();

// Suscribirse al Subject
subject.subscribe(value => console.log('Subscriber 1:', value));
subject.subscribe(value => console.log('Subscriber 2:', value));

// Emitir valores
subject.next(1);
subject.next(2);
```
salida
```bash
Subscriber 1: 1
Subscriber 2: 1
Subscriber 1: 2
Subscriber 2: 2
```

## ¿Para qué sirve un Subject?
* Compartir datos entre múltiples suscriptores: Permite que varias partes de tu aplicación se suscriban a los mismos datos emitidos, como una fuente compartida.

* Unir diferentes fuentes de datos: Puede actuar como un puente para combinar eventos o flujos de datos.

* Comunicación entre componentes: Ideal para transmitir datos o eventos entre componentes que no están directamente relacionados en Angular.

## ¿Qué resuelve un Subject?
* Emitir valores manualmente: A diferencia de un Observable puro, que generalmente define su lógica de emisión internamente, un Subject te permite emitir valores de forma explícita.

* Falta de compartición en Observables regulares: Un Observable regular es unicast, lo que significa que cada suscriptor recibe un flujo independiente. Los Subjects son multicast, lo que significa que todos los suscriptores reciben los mismos valores.

* Transmisión reactiva personalizada: Proporciona flexibilidad para crear flujos reactivos que no dependen directamente de una fuente específica, sino de datos emitidos manualmente.

## ¿Cómo lo resuelve?
Un Subject utiliza su naturaleza dual para:

* Emitir datos con el método next(): Cualquier valor pasado a next() se retransmite inmediatamente a todos los suscriptores.

* Actuar como un Observable: Permite que múltiples suscriptores escuchen los valores emitidos.

* Soporte para eventos reactivos: Combina su capacidad para observar y emitir valores en una herramienta poderosa para manejar datos en tiempo real.

## Casos de uso básicos
1. Comunicación entre componentes Angular: Un Subject puede servir como un servicio compartido para pasar datos entre componentes.
```ts
// En un servicio compartido
import { Subject } from 'rxjs';

export class DataService {
  private subject = new Subject<string>();

  sendMessage(message: string) {
    this.subject.next(message); // Emitir mensaje
  }

  getMessage() {
    return this.subject.asObservable(); // Proveer el Observable
  }
}
```
```ts
// Componente emisor
this.dataService.sendMessage('Hola desde el componente A');

// Componente receptor
this.dataService.getMessage().subscribe(message => {
  console.log('Mensaje recibido:', message);
});
```

2. Control de eventos personalizados: Puedes usar Subjects para emitir eventos y manejarlos en otras partes de la aplicación.
```ts
const eventSubject = new Subject<string>();

// Escuchar eventos
eventSubject.subscribe(event => console.log('Evento recibido:', event));

// Emitir un evento
eventSubject.next('click');
```

3. Agrupación de múltiples fuentes de datos: Combinar varias entradas en un único flujo reactivo que otros componentes pueden usar.

## Mejores prácticas
* Evita emitir valores innecesariamente: Usa Subject solo cuando necesites emitir manualmente valores o compartir flujos entre múltiples suscriptores.

* Gestiona la limpieza de suscripciones: Asegúrate de manejar correctamente la desuscripción de los observables creados con Subjects para evitar fugas de memoria.

* Usa el tipo adecuado: Según el caso de uso, considera si BehaviorSubject, ReplaySubject o AsyncSubject serían más apropiados.
