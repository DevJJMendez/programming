# Injection Tokens
Los Injection Tokens en Angular son identificadores únicos que el sistema de inyección de dependencias (DI) utiliza para resolver y proporcionar instancias de dependencias.

Un token puede ser:

* Una clase (lo más común).

* Una constante o valor primitivo.

* Una cadena de texto.

* Una instancia personalizada creada con `InjectionToken`.

Son fundamentales para indicar al inyector qué instancia se debe proporcionar cuando una clase o componente necesita una dependencia.

## ¿Para qué sirven?
Los Injection Tokens permiten:

* Resolver dependencias basadas en tokens únicos: Los tokens aseguran que el inyector de Angular pueda identificar correctamente una dependencia.

* Inyectar valores personalizados o servicios no basados en clases: Permite inyectar configuraciones, valores constantes, funciones o servicios que no están directamente asociados con una clase.

* Evitar conflictos de nombres: Si dos dependencias tienen nombres similares, los tokens proporcionan una forma única de diferenciarlas.

* Facilitar la personalización de servicios: Permiten modificar o sustituir servicios o valores en diferentes contextos.

## ¿Qué resuelven?
Problemas resueltos por los Injection Tokens:

* Confusión entre dependencias similares: Cuando hay múltiples servicios o valores similares, los tokens permiten diferenciarlos.

* Inyección de valores no basados en clases: Por ejemplo, inyectar un valor de configuración como una URL, tiempo de espera, etc.

* Reutilización y extensibilidad: Ayudan a reutilizar servicios en contextos diferentes al configurarlos con tokens personalizados.

* Modularidad: Posibilitan la provisión de diferentes implementaciones para un mismo token en diferentes partes de la aplicación.

## ¿Cómo lo resuelven?
Mecanismo de resolución:

* Provisión explícita: Los Injection Tokens se registran explícitamente en el sistema de Angular como providers.

* Identificación única: Cada token es único, lo que asegura que el inyector pueda resolver la dependencia correcta.

* Personalización con InjectionToken: Permite crear tokens personalizados con tipos fuertes y descripciones para facilitar el mantenimiento del código.

## Tipos de Injection Tokens en Angular
### Clase como Token
El método más común. El nombre de la clase es el token.
```ts
@Injectable({
  providedIn: 'root',
})
export class MyService {
  getMessage(): string {
    return 'Hola desde MyService';
  }
}

@Component({
  selector: 'app-root',
  template: '<h1>{{ message }}</h1>',
})
export class AppComponent {
  message: string;

  constructor(private myService: MyService) {
    this.message = myService.getMessage();
  }
}
```

### Tokens personalizados con `InjectionToken`
Cuando no hay una clase, usamos `InjectionToken`.
```ts
import { InjectionToken } from '@angular/core';

// Crear un token personalizado
export const API_URL = new InjectionToken<string>('API_URL');

// Registrar el token en un proveedor
@NgModule({
  providers: [
    { provide: API_URL, useValue: 'https://api.example.com' },
  ],
})
export class AppModule {}

// Usar el token en un servicio
@Injectable({
  providedIn: 'root',
})
export class ApiService {
  constructor(@Inject(API_URL) private apiUrl: string) {}

  getApiUrl(): string {
    return this.apiUrl;
  }
}
```

### Uso de valores primitivos
Cuando se necesita inyectar valores como números, booleanos o cadenas.
```ts
export const TIMEOUT = new InjectionToken<number>('TIMEOUT');

@NgModule({
  providers: [
    { provide: TIMEOUT, useValue: 3000 },
  ],
})
export class AppModule {}

@Injectable({
  providedIn: 'root',
})
export class ConfigService {
  constructor(@Inject(TIMEOUT) private timeout: number) {}

  getTimeout(): number {
    return this.timeout;
  }
}
```

# Provisión de funciones o clases específicas
Podemos usar `useClass`, `useExisting`, o `useFactory` para personalizar cómo se proporciona una dependencia.

En Angular, useClass, useExisting y useFactory son estrategias para registrar un proveedor (**`provider`**) en el sistema de **inyección de dependencias (DI)**. Estas opciones determinan cómo se resuelve una dependencia cuando se solicita a través de un token.

* **`useClass`**: Proporciona una nueva instancia de una clase específica.

* **`useExisting`**: Reutiliza una instancia existente registrada con otro token.

* **`useFactory`**: Genera un valor dinámico utilizando una función de fábrica.

### ¿Para qué sirven?
Usos principales:

* Customización de dependencias: Permiten ajustar cómo se resuelven las dependencias para servicios específicos o valores.

* Reutilización de servicios: `useExisting` evita duplicar instancias cuando varios tokens necesitan la misma dependencia.

* Creación dinámica: `useFactory` se usa cuando el valor o servicio necesita lógica para crearse en tiempo de ejecución.

* Pruebas: Facilitan la creación de simulaciones (mocks) para servicios en pruebas unitarias.

## ¿Qué resuelven?
Problemas resueltos:

* Control sobre las instancias: Deciden si se crea una nueva instancia (`useClass`) o se reutiliza una existente (`useExisting`).

* Dependencias dinámicas: Resuelven valores o servicios que dependen de variables dinámicas como configuraciones, valores del entorno, etc.

* Evitar duplicación: `useExisting` garantiza que diferentes tokens apunten a la misma instancia.

* Modularidad y personalización: Permiten registrar implementaciones específicas para diferentes contextos.

## ¿Cómo lo resuelven?
El sistema de inyección de Angular usa la configuración del proveedor para resolver dependencias según el token registrado. Dependiendo del método (`useClass`, `useExisting` o `useFactory`), se sigue un camino diferente para proveer la dependencia.

## Detalles de cada uno
###  `useClass`
* Descripción:
  * Especifica la clase que se debe usar para resolver el token.

  * Por defecto, si no se indica, Angular asume `useClass`.

* Casos de uso:
  * Registrar clases alternativas para un token.

  * Proveer diferentes implementaciones de un servicio en contextos distintos.

* Ejemplo:
```ts
export class ApiService {
  getData(): string {
    return 'Datos desde ApiService';
  }
}

export class MockApiService {
  getData(): string {
    return 'Datos desde MockApiService (pruebas)';
  }
}

@NgModule({
  providers: [
    { provide: ApiService, useClass: MockApiService } // Cambia la implementación
  ],
})
export class AppModule {}
```
Resultado:
  * Cuando se inyecta `ApiService`, se usa la implementación de `MockApiService`.

### useExisting
* Descripción:
  * Permite usar una instancia existente registrada con otro token.

  * Es útil para evitar duplicación de instancias cuando varios tokens comparten la misma dependencia.

* Casos de uso:
  * Reutilizar una dependencia en múltiples partes de la aplicación.

  * Definir alias para un servicio.

* Ejemplo:
```ts
@Injectable({
  providedIn: 'root',
})
export class LoggerService {
  log(message: string): void {
    console.log(message);
  }
}

// Reutilizar LoggerService con un alias
@NgModule({
  providers: [
    { provide: 'CustomLogger', useExisting: LoggerService },
  ],
})
export class AppModule {}

@Injectable({
  providedIn: 'root',
})
export class AppComponent {
  constructor(@Inject('CustomLogger') private logger: LoggerService) {
    this.logger.log('Mensaje desde CustomLogger');
  }
}
```
Resultado:
  * `LoggerService` y '`CustomLogger`' apuntan a la misma instancia.

### useFactory
* Descripción:
  * Proporciona una función que devuelve dinámicamente un valor o instancia.

  * Ideal para configuraciones o dependencias que dependen de valores en tiempo de ejecución.

* Casos de uso:
  * Crear dependencias basadas en el entorno (desarrollo/producción).

  * Proveer valores computados o configuraciones.

* Ejemplo:
```ts
export function apiUrlFactory(): string {
  return environment.production ? 'https://api.prod.com' : 'http://localhost:3000';
}

@NgModule({
  providers: [
    { provide: 'API_URL', useFactory: apiUrlFactory },
  ],
})
export class AppModule {}

@Injectable({
  providedIn: 'root',
})
export class ApiService {
  constructor(@Inject('API_URL') private apiUrl: string) {
    console.log(`API URL: ${this.apiUrl}`);
  }
}
```
Resultado:
  * Dependiendo del entorno, el token 'API_URL' tiene un valor diferente.

## Pruebas Unitarias
Estos métodos son útiles para pruebas al crear proveedores personalizados.

Ejemplo con useFactory en pruebas:
```ts
describe('ApiService', () => {
  let service: ApiService;

  beforeEach(() => {
    TestBed.configureTestingModule({
      providers: [
        ApiService,
        { provide: 'API_URL', useFactory: () => 'http://mock.api.com' },
      ],
    });
    service = TestBed.inject(ApiService);
  });

  it('debería usar la URL de prueba', () => {
    expect(service.apiUrl).toBe('http://mock.api.com');
  });
});
```
