# `paramMap`
`paramMap` es una propiedad de la clase `ActivatedRoute` que proporciona una API estructurada para acceder a los parámetros de la ruta en Angular. A diferencia de params, que devuelve un objeto simple, `paramMap` es una instancia de la clase **`ParamMap`**, la cual incluye métodos útiles para manejar parámetros de ruta.

Por ejemplo, en una ruta como `/products/:id`, el valor del parámetro `id` puede ser accedido usando `paramMap`.

## ¿Para qué sirve?
paramMap sirve para:

* Obtener valores de parámetros de ruta de forma segura y estructurada.

* Validar la existencia de parámetros opcionales.

* Proporcionar métodos adicionales para manejar los parámetros de forma más flexible, como el manejo de múltiples valores para una misma clave.

## ¿Qué resuelve?
paramMap resuelve los siguientes problemas:

* Acceso directo y seguro a parámetros de ruta. Evita errores comunes como acceder a claves inexistentes.

* Manejo de parámetros opcionales y múltiples valores. Permite verificar la existencia de parámetros y manejar escenarios complejos, como parámetros con múltiples valores.

* **API estructurada**: Proporciona una forma clara y programática de interactuar con los parámetros en lugar de depender de un objeto simple.

## ¿Cómo lo resuelve?
paramMap utiliza una instancia de la clase ParamMap, que ofrece métodos como:

* **`get()`**: Recupera el valor de un parámetro por clave.

* **`getAll()`**: Recupera todos los valores asociados a una clave.

* **`has()`**: Verifica si existe un parámetro.

Esto hace que el acceso a los parámetros sea más robusto y menos propenso a errores.

## Accediendo a `paramMap`
* **Usando la suscripción al `observable`**, `paramMap` está disponible como un `observable` en la clase `ActivatedRoute`. Esto permite reaccionar a los cambios en los parámetros de ruta:
```ts
import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';

@Component({
  selector: 'app-product-detail',
  template: `
    <h1>Product ID: {{ productId }}</h1>
  `
})
export class ProductDetailComponent implements OnInit {
  productId: string | null = null;

  constructor(private route: ActivatedRoute) {}

  ngOnInit(): void {
    this.route.paramMap.subscribe(paramMap => {
      this.productId = paramMap.get('id');
    });
  }
}
```

* **Usando `snapshot` para valores estáticos**, Si los parámetros de ruta no cambian mientras el componente está activo, puedes acceder a `paramMap` directamente desde `snapshot`:
```ts
ngOnInit(): void {
  this.productId = this.route.snapshot.paramMap.get('id');
}
```

### Configuración de rutas con parámetros
Para trabajar con `paramMap`, los parámetros deben estar definidos en las rutas. Ejemplo:
```ts
const routes: Routes = [
  { path: 'products/:id', component: ProductDetailComponent }
];
```
Aquí, `:id` es el parámetro dinámico que se mapeará a la clave `id` en `paramMap`.

## Métodos útiles de ParamMap
* **`get(key: string): string | null`**, Obtiene el primer valor asociado con la clave especificada.
```ts
const id = paramMap.get('id'); // "123"
```

* **`getAll(key: string): string[]`**, Recupera todos los valores asociados con una clave (útil para parámetros duplicados).
```ts
const tags = paramMap.getAll('tag'); // ["angular", "typescript"]
```

* **`has(key: string): boolean`**, Verifica si existe un parámetro con la clave especificada.
```ts
if (paramMap.has('id')) {
  console.log('ID está presente');
}
```

## Buenas prácticas al trabajar con paramMap
* Validar la existencia de parámetros: Siempre usa `paramMap.has()` para evitar errores al intentar acceder a parámetros inexistentes.

* **Desuscribirse** cuando sea necesario: Si utilizas `paramMap` como observable, recuerda desuscribirte en componentes que se destruyen frecuentemente.

* Usar `getAll()` para múltiples valores: Si esperas que un parámetro tenga múltiples valores, usa `getAll()` en lugar de `get()`.

* Evitar lógica extensa dentro de la suscripción: Extrae la lógica de manejo de parámetros a métodos dedicados para mantener el código limpio y legible.
