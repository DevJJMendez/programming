# Pages
El directorio pages es una carpeta en el proyecto Angular donde se agrupan los componentes de nivel superior que representan las vistas principales o las rutas de la aplicación. Cada archivo en este directorio se asocia típicamente con una ruta específica en el enrutador de Angular.

Estructura típica:
```plaintext
src/
 └── app/
     ├── pages/
     │    ├── home/
     │    │    ├── home.component.ts
     │    │    ├── home.component.html
     │    │    ├── home.component.scss
     │    │    └── home.component.spec.ts
     │    ├── about/
     │    │    ├── about.component.ts
     │    │    ├── about.component.html
     │    │    ├── about.component.scss
     │    │    └── about.component.spec.ts
     │    └── ...
     ├── shared/
     └── features/
```

## ¿Cuáles son las características del directorio pages?
* Organización lógica por vistas: Cada subcarpeta dentro de pages representa una página o vista completa de la aplicación, como **`home`**, **`login`**, **`dashboard`**, etc.

* Asociación directa con rutas: Los componentes dentro de pages suelen estar configurados en el archivo de rutas (`app-routing.module.ts`) para que correspondan a URL específicas.

* Componentes de nivel alto: Estos componentes suelen servir como contenedores de otros componentes más pequeños. Por ejemplo, la página dashboard puede incluir gráficos, tablas y formularios.

* Responsabilidad bien definida: Cada página se encarga de manejar la lógica y la representación visual de una sección principal de la aplicación.

## Integración con el sistema de rutas:
En el archivo `app-routing.module.ts`, puedes asignar componentes desde pages a rutas específicas:
```ts
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'login', component: LoginComponent },
  { path: 'dashboard', component: DashboardComponent }
];
```

## ¿Qué no es el directorio pages?
* No contiene componentes reutilizables: Si un componente puede ser reutilizado en varias páginas, debería colocarse en el directorio shared o features.

* No contiene servicios o lógica de negocio: Los servicios, modelos y utilidades deben estar en sus propias carpetas específicas como services o core.

* No es obligatorio en Angular: Es una convención organizativa, pero no es requerida para que una aplicación Angular funcione.
