# `@Output`
El decorador @Output en Angular es uno de los mecanismos fundamentales para la comunicación entre componentes. A diferencia de @Input, que se utiliza para pasar datos del componente padre al hijo, @Output permite al componente hijo enviar información al componente padre.

Este mecanismo se utiliza principalmente para emitir eventos desde el hijo hacia el padre. Usando @Output, el componente hijo puede emitir un evento (generalmente asociado a alguna acción o cambio de estado) que el componente padre puede escuchar y reaccionar a él. Esto establece una comunicación unidireccional de abajo hacia arriba, es decir, del hijo al padre.

### ¿Qué es @Output?
Es un decorador en Angular que marca una propiedad como un evento que puede ser escuchado desde el componente padre. Esta propiedad normalmente es un **`EventEmitter`** que permite emitir eventos desde el componente hijo hacia el padre.

**En resumen**:
* `@Output` hace que un componente hijo pueda emitir eventos.

* Los eventos emitidos pueden ser capturados por el componente padre y ejecutar alguna acción basada en ese evento.

### ¿Para qué sirve?
El propósito de `@Output` es **permitir la comunicación de los componentes hijos hacia el componente padre**. Mientras que @Input permite que los datos viajen en una dirección (del padre al hijo), `@Output` lo hace en la dirección contraria, del hijo al padre.

En un escenario típico, el componente hijo puede emitir un evento cuando algo cambia o cuando el usuario interactúa con él (por ejemplo, al hacer clic en un botón), y el componente padre puede reaccionar a ese evento para actualizar su propio estado o realizar alguna acción.

## ¿Qué resuelve?
@Output resuelve el problema de la comunicación entre componentes en situaciones donde un componente hijo necesita notificar o enviar información a su componente padre. Angular promueve una arquitectura unidireccional de flujo de datos, lo que significa que los datos fluyen de arriba hacia abajo (del padre al hijo) y los eventos fluyen de abajo hacia arriba (del hijo al padre).

## Casos típicos que resuelve:
* **Acciones del Usuario**: Cuando un usuario interactúa con un componente hijo (como hacer clic en un botón), es posible que desee que el componente padre actúe en función de esa interacción.

* **Cambio de Estado**: El componente hijo puede emitir un evento cuando su estado cambia, y el componente padre puede reaccionar a ese cambio.

* **Notificaciones**: El hijo puede notificar al padre que algo importante ocurrió, por ejemplo, el final de una tarea o un evento del ciclo de vida.

## ¿Cómo lo resuelve?
`@Output` se resuelve utilizando el siguiente proceso:

* Definir el @Output en el componente hijo. Esto se hace usando un EventEmitter.

* Emitir el evento desde el componente hijo en el momento en que ocurra alguna acción (por ejemplo, un clic).

* Capturar el evento en el componente padre usando la sintaxis de binding de eventos para que el padre pueda reaccionar a ese evento.

## Funcionamiento
1. Componente Hijo (HijoComponent)

```ts
import { Component, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-hijo',
  template: `<button (click)="enviarAlPadre()">Enviar al padre</button>`
})
export class HijoComponent {
  // Definir un EventEmitter para emitir el evento al componente padre
  @Output() eventoHijo = new EventEmitter<string>();

  // Método que emite un evento
  enviarAlPadre() {
    this.eventoHijo.emit('¡Mensaje desde el hijo!'); // Emitir un evento con un valor
  }
}
```
**En este código:**
   * La propiedad eventoHijo está decorada con `@Output()` y es un **`EventEmitter`**.

   * El método `enviarAlPadre()` emite el evento usando `this.eventoHijo.emit()`. El valor **'¡Mensaje desde el hijo!'** es el dato que se enviará al padre cuando el botón sea clickeado.

2. **Componente Padre (`PadreComponent`)**: En el componente padre, escuchamos el evento emitido por el hijo utilizando la sintaxis de binding de eventos de Angular (`$event`).

```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-padre',
  template: `
    <app-hijo (eventoHijo)="manejarEvento($event)"></app-hijo>
    <p>{{ mensaje }}</p>
  `
})
export class PadreComponent {
  mensaje: string = '';

  // Método que maneja el evento emitido por el hijo
  manejarEvento(dato: string) {
    this.mensaje = dato;  // Se actualiza la variable 'mensaje' con el valor recibido
  }
}
```
**En este código:**
   * Usamos (`eventoHijo`) para escuchar el evento emitido por el componente hijo.

   * El `$event` es el valor emitido desde el hijo y se pasa al método `manejarEvento()`, donde se puede procesar o almacenar en una variable.

   * El mensaje se actualiza con el dato recibido del hijo y se muestra en el template.

## Características clave de @Output y EventEmitter
* **Unidireccionalidad**: La comunicación sigue siendo unidireccional: el padre no puede modificar directamente el EventEmitter del hijo.

* **Transparencia de Eventos**: @Output permite que los eventos sean fácilmente capturados y manejados en el componente padre.

* **Reactividad**: El patrón de emisión de eventos es útil para crear aplicaciones reactivas donde las acciones del usuario o los cambios de estado en un componente hijo afectan a otros componentes.

## Combinación de @Output con @Input
A menudo, @Output y @Input se utilizan juntos para crear flujos de datos completos entre un padre y un hijo.

### Ejemplo:
Imagina que el componente padre envía un dato al hijo, y luego el hijo emite un evento que contiene una actualización de ese dato.

```ts
// Componente Hijo
@Component({
  selector: 'app-hijo',
  template: `
    <p>{{ mensaje }}</p>
    <button (click)="actualizarPadre()">Actualizar mensaje</button>
  `
})
export class HijoComponent {
  @Input() mensaje!: string;  // Recibe el mensaje del padre
  @Output() mensajeActualizado = new EventEmitter<string>();

  actualizarPadre() {
    this.mensajeActualizado.emit('Nuevo mensaje desde el hijo');
  }
}

// Componente Padre
@Component({
  selector: 'app-padre',
  template: `
    <app-hijo [mensaje]="mensaje" (mensajeActualizado)="manejarActualizacion($event)"></app-hijo>
    <p>{{ mensaje }}</p>
  `
})
export class PadreComponent {
  mensaje: string = 'Mensaje inicial';

  manejarActualizacion(nuevoMensaje: string) {
    this.mensaje = nuevoMensaje; // Actualiza el mensaje con el dato recibido del hijo
  }
}
```
Este flujo crea una comunicación bidireccional entre el padre y el hijo utilizando @Input y @Output:
  * El padre envía un dato al hijo.

  * El hijo emite un evento para actualizar el dato en el padre.
