# `reject`
En JavaScript, reject es la función que permite marcar una promesa como rechazada en una instancia de Promise, lo cual significa que la operación asíncrona que representa la promesa ha fallado o no se ha completado exitosamente. Junto a resolve, es uno de los dos parámetros que recibe una función ejecutora en una promesa y es clave para manejar errores y excepciones de manera estructurada en operaciones asíncronas.

## ¿Qué es reject?
reject es una función callback que se invoca en una promesa para indicarle que no se pudo completar satisfactoriamente. Cuando se llama a reject, la promesa cambia su estado a "rejected" (rechazada), y cualquier manejador .catch() asociado se activa para manejar el error o mensaje de rechazo.

## ¿Para qué sirve reject?
reject permite manejar errores y comunicar fallos en operaciones asíncronas. Sirve para devolver un valor de error a los manejadores .catch() adjuntos a la promesa, facilitando una gestión clara de errores en JavaScript.

Ejemplo básico
```js
const promise = new Promise((resolve, reject) => {
    const success = false;
    if (success) {
        resolve("Operación exitosa");
    } else {
        reject("Operación fallida");
    }
});

promise
    .then(result => console.log(result))
    .catch(error => console.log(error)); 
// Salida: "Operación fallida"
```

## ¿Qué resuelve reject?
reject resuelve la necesidad de manejar errores y excepciones en el flujo asíncrono de JavaScript. Antes de que existieran las promesas, manejar errores en callbacks asíncronos podía ser confuso y difícil de seguir. reject, en combinación con .catch(), permite una forma más intuitiva y estructurada de controlar los errores en operaciones asíncronas.

## ¿Cómo lo resuelve?
Cuando se llama a reject dentro de una promesa, su estado pasa a "rechazada" y cualquier bloque de .catch() en la cadena de promesas se activa, pasando el valor de error o mensaje a estos bloques de error.

* Uso de reject en una operación asíncrona
Es común utilizar reject para manejar errores o condiciones no deseadas en funciones asíncronas. Por ejemplo, una función que simula una solicitud de red puede rechazar la promesa si los datos no están disponibles:
```js
const fetchData = () => new Promise((resolve, reject) => {
    const success = false;
    setTimeout(() => {
        if (success) {
            resolve("Datos obtenidos");
        } else {
            reject("Error: No se pudieron obtener los datos");
        }
    }, 2000);
});

fetchData()
    .then(data => console.log(data))
    .catch(error => console.log(error));
// Salida: "Error: No se pudieron obtener los datos"
```

* reject y la propagación de errores
Cuando se llama a reject, el error se propaga a través de la cadena de promesas hasta que se encuentre un bloque .catch() para manejarlo. Esto permite una gestión centralizada de errores.
```js
const operation = () => new Promise((resolve, reject) => reject("Error en la operación"));

operation()
    .then(result => console.log(result))
    .catch(error => console.log(`Manejo de error: ${error}`));
// Salida: "Manejo de error: Error en la operación"
```

* reject y tipos de datos
El valor pasado a reject suele ser un mensaje de error o un objeto Error, proporcionando información sobre el motivo del fallo. Es recomendable utilizar objetos Error en vez de strings para ofrecer un contexto más rico y detalles específicos del error.
```js
const operation = () => new Promise((resolve, reject) => {
    reject(new Error("Ocurrió un error inesperado"));
});

operation()
    .catch(error => console.error(error.message));
// Salida: "Ocurrió un error inesperado"
```

* Múltiples rechazos en promesas
Si dentro de una promesa se llama a reject más de una vez, solo el primer rechazo es válido; cualquier llamada a reject posterior a la primera no tendrá efecto, ya que una promesa no puede cambiar de estado una vez que es resuelta o rechazada.
