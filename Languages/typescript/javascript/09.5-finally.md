# `finally()`
El método .finally() en JavaScript es una herramienta en el manejo de promesas que se utiliza para ejecutar lógica final, independientemente de si la promesa se resolvió o se rechazó. Es especialmente útil para realizar tareas de limpieza, actualización de estados, o cualquier operación que deba completarse una vez que una promesa ha terminado su ejecución, sin importar el resultado.

## ¿Qué es .finally()?
.finally() es un método que se agrega al final de una cadena de promesas y se ejecuta siempre, independientemente del resultado de la promesa. Es decir, se ejecutará ya sea que la promesa se haya cumplido con éxito (resolve) o que haya fallado (reject). Este método es muy útil en escenarios donde se requiere ejecutar código final de limpieza, como cerrar conexiones, detener animaciones, ocultar spinners, etc.

## ¿Para qué sirve .finally()?
.finally() es fundamental para garantizar que cierto código se ejecute después de una operación asíncrona, sin importar su éxito o fracaso. Este método permite asegurar que el flujo de la aplicación se complete de forma ordenada, manteniendo un control estructurado sobre tareas que deben ejecutarse al final de la cadena, como:

Limpiar recursos o conexiones.
Ocultar un loader o spinner después de una operación.
Restablecer valores temporales o estados.

## ¿Qué resuelve .finally()?
.finally() resuelve la necesidad de ejecutar un bloque de código final en una promesa sin duplicar la lógica en .then() y .catch(). Sin .finally(), sería necesario añadir tareas finales en ambos bloques (.then() y .catch()), lo cual redundaría en un código más extenso y menos mantenible.

Por ejemplo, si quisiéramos ocultar un spinner después de una operación de red, tendríamos que añadir esa lógica tanto en .then() como en .catch(). .finally() elimina esta redundancia.

## ¿Cómo lo resuelve .finally()?
.finally() lo resuelve al ejecutar su bloque de código independientemente del resultado de la promesa. Se añade al final de la cadena de promesas y siempre se ejecuta, permitiendo centralizar la lógica que debe ejecutarse al finalizar una operación asíncrona.

## Todo lo que necesitas saber sobre .finally()
* Sintaxis y uso básico de .finally()
La sintaxis básica de .finally() es bastante sencilla y sigue el patrón habitual de las promesas:
```js
const promesa = new Promise((resolve, reject) => {
    // Alguna operación asíncrona
    resolve("Operación exitosa");
});

promesa
    .then(result => console.log(result))    // Maneja el éxito
    .catch(error => console.log(error))     // Maneja el error
    .finally(() => console.log("Operación finalizada"));  // Siempre se ejecuta
// Salida:
// "Operación exitosa"
// "Operación finalizada"
```

* Ejemplo de .finally() en una solicitud de red
En aplicaciones web, .finally() es muy útil cuando se necesita ocultar un elemento de carga (spinner) una vez que la solicitud de red termina, sin importar si fue exitosa o no:
```js
// Mostrar spinner
console.log("Mostrando spinner...");

fetch('https://api.misitio.com/data')
    .then(response => response.json())
    .then(data => console.log("Datos recibidos:", data))
    .catch(error => console.log("Error:", error))
    .finally(() => {
        console.log("Ocultando spinner...");
    });
// Salida (si la operación falla):
// "Mostrando spinner..."
// "Error: (detalle del error)"
// "Ocultando spinner..."
```
En este caso, sin importar si fetch es exitoso o lanza un error, el mensaje "Ocultando spinner..." se mostrará al final.

* Comparación de .finally() con .then() y .catch()
.finally() no recibe ningún argumento ni resultado de la promesa, a diferencia de .then() y .catch(). Esto significa que el bloque de código en .finally() es completamente independiente del éxito o fallo de la operación.

Ejemplo
```js
let state = "inicial";

new Promise((resolve, reject) => {
    // Cambiamos el estado y resolvemos la promesa
    state = "en proceso";
    resolve("Proceso completado");
})
.then(result => {
    state = "finalizado";
    console.log("Resultado:", result);
})
.catch(error => console.log("Error:", error))
.finally(() => {
    console.log("Estado final:", state); // "finalizado"
});
// Salida:
// "Resultado: Proceso completado"
// "Estado final: finalizado"
```

* Uso en cadenas de promesas
.finally() se puede añadir a cualquier cadena de promesas, y siempre ejecutará su lógica final tras la última promesa en la cadena. Este comportamiento hace que .finally() sea ideal para procesos que se dividen en múltiples pasos, como en operaciones complejas de carga de datos:
```js
let datosProcesados = false;

const promesa = new Promise((resolve) => {
    setTimeout(() => resolve("Datos cargados"), 1000);
});

promesa
    .then(result => result + " y procesados")
    .then(data => {
        datosProcesados = true;
        console.log(data); // "Datos cargados y procesados"
    })
    .finally(() => console.log("Proceso completo. Estado:", datosProcesados));
// Salida:
// "Datos cargados y procesados"
// "Proceso completo. Estado: true"
```

* Diferencias entre .finally() y try...finally
Aunque .finally() en promesas se inspira en try...finally en código síncrono, existen diferencias:

Flujo de ejecución: try...finally se usa en bloques de código donde el flujo es síncrono y controlado, mientras que .finally() se usa en el contexto de promesas asíncronas.
Encadenamiento: .finally() es parte de una cadena de promesas, permitiendo múltiples operaciones asíncronas encadenadas, mientras que try...finally se aplica a bloques de código síncronos en un solo nivel.

Ejemplo de try...finally:
```js
try {
    console.log("Operación...");
    throw new Error("Error en operación");
} finally {
    console.log("Limpiando recursos...");
}
// Salida:
// "Operación..."
// "Limpiando recursos..."
```
