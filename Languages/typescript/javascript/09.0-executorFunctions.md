# Executor Functions
Las executor functions en JavaScript son funciones que se pasan como argumentos a una instancia de Promise para controlar cuándo y cómo se completa esa promesa. Este tipo de función se utiliza en el contexto de promesas y se ejecuta inmediatamente al crearse una promesa, manejando la lógica de la operación asíncrona y determinando su resultado (éxito o fallo).

## ¿Qué es una Executor Function?
Una executor function es la función que se pasa como argumento al crear una instancia de Promise, es decir, una función que recibe dos parámetros (usualmente llamados resolve y reject). Esta función maneja la operación asíncrona que la promesa debe completar y, basándose en el resultado de esta operación, invoca el método resolve si es exitosa o el método reject si falla.

Ejemplo básico de executor function:
```js
const promise = new Promise((resolve, reject) => {
    // Lógica de la operación asíncrona
    const operationSuccessful = true;
    if (operationSuccessful) {
        resolve("Operación completada");
    } else {
        reject("Operación fallida");
    }
});
```

## ¿Para qué sirve una Executor Function?
Una executor function permite encapsular operaciones asíncronas (como llamadas a APIs, operaciones de archivo, o temporizadores) y define claramente cuándo y cómo una promesa se cumple o es rechazada. Facilita el manejo de asíncronía al delegar a Promise la capacidad de controlar el flujo de código que depende de una operación futura.

## ¿Qué resuelve?
La executor function resuelve el problema de manejar la asíncronía en JavaScript de una manera estructurada. Gracias a las promesas y sus executor functions, el código asíncrono puede escribirse y leerse de una forma más ordenada, evitando la famosa “piramide de doom” o “callback hell” que resulta de anidar múltiples funciones de devolución (callbacks).

## ¿Cómo lo resuelve?
La executor function resuelve el problema al definir un mecanismo que separa la lógica asíncrona (dentro de la función de ejecución) y el control del flujo de código dependiente (con `.then()` y `.catch()`). Dentro de una promesa, la executor function se ejecuta inmediatamente y, cuando la operación completa, ejecuta `resolve` o `reject`, liberando al código dependiente para que proceda de acuerdo al estado final de la promesa.

## Detalles y Ejemplos de Todo lo que Necesitas Saber
* **Estructura básica de una Promise con Executor Function**: Una executor function siempre sigue esta estructura, permitiendo la creación de promesas personalizadas:
```js
const promise = new Promise((resolve, reject) => {
    // Lógica de la operación asíncrona
    const success = true;
    if (success) {
        resolve("Resultado exitoso");
    } else {
        reject("Ha ocurrido un error");
    }
});
```

* **Uso de `resolve` y `reject`**: resolve y reject son funciones callback internas que se invocan según el resultado de la operación. Por convención:

  * resolve(value): marca la promesa como completada y pasa value al siguiente .then().

  * reject(reason): marca la promesa como fallida y pasa reason al siguiente .catch().

Ejemplo de uso en una operación con temporizador:
```js
const delay = ms => new Promise((resolve) => {
    setTimeout(() => {
        resolve(`Completado después de ${ms}ms`);
    }, ms);
});

delay(2000).then(result => console.log(result));
```

* Manejando Errores dentro de una Executor Function
Al envolver la lógica asíncrona dentro de un try...catch, podemos capturar errores y rechazarlos explícitamente con reject:
```js
const fetchData = url => new Promise((resolve, reject) => {
    try {
        // Simulación de una operación asíncrona de obtención de datos
        if (!url) throw new Error("URL inválida");
        resolve(`Datos obtenidos de ${url}`);
    } catch (error) {
        reject(`Error en la operación: ${error.message}`);
    }
});

fetchData("http://example.com")
    .then(data => console.log(data))
    .catch(error => console.error(error));
```

* Asíncronía en la Executor Function
Una executor function puede incluir cualquier operación asíncrona (uso de setTimeout, solicitudes HTTP, etc.), pero el control final siempre se ejecutará cuando resolve o reject sea invocado:
```js
const fetchData = () => new Promise((resolve, reject) => {
    setTimeout(() => {
        const data = { id: 1, title: "Datos Simulados" };
        resolve(data);
    }, 3000);
});

fetchData().then(data => console.log(data));
```
