# Métodos Estáticos


Los `métodos estáticos` en la programación orientada a objetos (POO) son aquellos que se pueden llamar en una clase sin necesidad de crear una instancia u objeto de esa clase. Estos métodos se definen con la palabra clave `static` y se acceden utilizando el nombre de la clase, en lugar de utilizar un objeto instanciado de esa clase.

## Caracteristicas

- `No requieren una instancia`: Los métodos estáticos pueden ser llamados directamente desde la clase sin necesidad de crear un objeto de esa clase.

- `No tienen acceso a propiedades de instancia`: Al ser métodos que no están asociados a objetos, no pueden acceder a propiedades o métodos de instancia (no tienen acceso al `$this`).

## Ejemplo de un método estático:
```php
<?php
class MiClase {
    public static function metodoEstatico() {
        // Código del método estático
        echo "¡Este es un método estático!";
    }
}
?>
```

## Uso de métodos estáticos:

- Utilidades y funciones compartidas: Los métodos estáticos son útiles para implementar funciones que no dependen de una instancia específica de la clase y se utilizan comúnmente para implementar funciones de utilidad que pueden ser llamadas desde cualquier parte del código.

- Fabricación de objetos: En algunos casos, los métodos estáticos se utilizan como métodos de fábrica (`factory methods`) para crear objetos sin necesidad de instanciar la clase directamente.

- Mantenimiento de la coherencia: Se usan para agrupar funcionalidades relacionadas con la clase, pero que no necesitan acceder a variables de instancia específicas.

## Ejemplo de uso:
```php
class UtilidadesMatematicas {
    public static function sumar($a, $b) {
        return $a + $b;
    }
}

// Llamada a un método estático
$resultado = UtilidadesMatematicas::sumar(5, 3);
echo $resultado; // Imprimirá 8
```

Los métodos estáticos son útiles cuando necesitas definir funcionalidades que no dependen de la instancia de un objeto particular, sino que son comunes a toda la clase. Sin embargo, se deben utilizar con moderación, ya que su abuso puede llevar a un diseño poco claro y dificultar el mantenimiento del código.
