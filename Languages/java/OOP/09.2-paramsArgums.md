## Parámetros
Los parámetros son variables definidas en la firma del método, especificando los datos que el método espera recibir cuando se invoca. Los parámetros actúan como marcadores de posición en el método.

**Ejemplo de Parámetros**
```java
public class MyClass {
    // Método con dos parámetros
    public void greet(String name, int age) {
        System.out.println("Hello, " + name + ". You are " + age + " years old.");
    }

    public static void main(String[] args) {
        MyClass obj = new MyClass();
        obj.greet("Alice", 30);  // Llamada al método con argumentos
    }
}
```
En este ejemplo, `name` y `age` son parámetros del método `greet`.

## Argumentos
Los argumentos son los valores reales que se pasan al método cuando se invoca. Estos argumentos son copiados a los parámetros correspondientes definidos en el método.

**Ejemplo de Argumentos**
```java
public class MyClass {
    public void greet(String name, int age) {
        System.out.println("Hello, " + name + ". You are " + age + " years old.");
    }

    public static void main(String[] args) {
        MyClass obj = new MyClass();
        obj.greet("Alice", 30);  // "Alice" y 30 son los argumentos
    }
}
```
En este ejemplo, **"Alice"** y **30** son los argumentos pasados al método `greet`.

## Tipos de Parámetros

- **Parámetros Posicionales**: La forma más común, donde los argumentos se pasan en el mismo orden que los parámetros.
```java
public void greet(String name, int age) {
    // ...
}

obj.greet("Alice", 30);  // Orden posicional: name="Alice", age=30
```

- Parámetros de Varargs **(Argumentos Variables)**: Permiten pasar un número variable de argumentos al método.
```java
public void printNumbers(int... numbers) {
    for (int num : numbers) {
        System.out.println(num);
    }
}

public static void main(String[] args) {
    MyClass obj = new MyClass();
    obj.printNumbers(1, 2, 3, 4, 5);  // Pasando múltiples argumentos
}
```

- **Parámetros de Referencia**: Permiten pasar objetos al método, permitiendo que el método modifique el estado del objeto.
```java
public void updatePerson(Person person) {
    person.setName("Updated Name");
}

public static void main(String[] args) {
    MyClass obj = new MyClass();
    Person person = new Person("Original Name");
    obj.updatePerson(person);  // Pasando un objeto como argumento
    System.out.println(person.getName());  // Output: Updated Name
}
```

## Pasar Argumentos por Valor

En Java, todos los argumentos se pasan por valor. Esto significa que se pasa una copia del valor, no el valor en sí. Sin embargo, la forma en que se comportan las variables primitivas y los objetos es diferente.

- Tipos Primitivos: Se pasa una copia del valor primitivo. Los cambios dentro del método no afectan la variable original.
```java
public void modifyPrimitive(int x) {
    x = 10;
}

public static void main(String[] args) {
    int a = 5;
    MyClass obj = new MyClass();
    obj.modifyPrimitive(a);
    System.out.println(a);  // Output: 5
}
```

- **Objetos**: Se pasa una copia de la referencia al objeto. Los cambios en el estado del objeto dentro del método afectan al objeto original.
```java
public void modifyObject(Person person) {
    person.setName("Modified");
}

public static void main(String[] args) {
    Person person = new Person("Original");
    MyClass obj = new MyClass();
    obj.modifyObject(person);
    System.out.println(person.getName());  // Output: Modified
}
```

## Buenas Prácticas

- **Nombres Claros**: Usa nombres de parámetros que sean claros y descriptivos para mejorar la legibilidad del código.
```java
public void calculateSum(int firstNumber, int secondNumber) {
    // ...
}
```

- **Documentación**: Documenta los métodos y sus parámetros usando comentarios o JavaDoc para aclarar la intención y el uso.
```java
/**
 * Calculates the sum of two integers.
 *
 * @param firstNumber  the first integer
 * @param secondNumber the second integer
 * @return the sum of firstNumber and secondNumber
 */
public int calculateSum(int firstNumber, int secondNumber) {
    return firstNumber + secondNumber;
}
```

- **Evita el Exceso de Parámetros**: Si un método requiere muchos parámetros, considera crear una clase para agrupar esos parámetros.
```java
public class Order {
    private String product;
    private int quantity;
    private double price;

    // Constructor, getters y setters
}

public void placeOrder(Order order) {
    // ...
}
```

## Demasiados Párametros

Cuando una clase o un método tiene demasiados parámetros, puede resultar difícil de mantener y utilizar. Para mejorar la legibilidad y la manejabilidad del código, existen varias técnicas que puedes aplicar. A continuación, se describen algunas de las técnicas más efectivas:

- **Encapsulación de Parámetros en un Objeto**: Si un método tiene muchos parámetros que están relacionados, es posible encapsularlos en un objeto. Esto no solo reduce el número de parámetros, sino que también mejora la cohesión y el encapsulamiento.

**Ejemplo**
```java
public class Order {
    private String product;
    private int quantity;
    private double price;
    private String customerName;
    private String deliveryAddress;

    // Constructor, getters, y setters
}

// En lugar de:
public void placeOrder(String product, int quantity, double price, String customerName, String deliveryAddress) {
    // ...
}

// Usa:
public void placeOrder(Order order) {
    // ...
}
```

- **Builder Pattern**: El patrón Builder es útil cuando tienes una clase con muchos parámetros opcionales o configuraciones complejas. Este patrón permite la construcción de objetos de manera clara y flexible.

**Ejemplo**
```java
public class Order {
    private String product;
    private int quantity;
    private double price;
    private String customerName;
    private String deliveryAddress;

    private Order(OrderBuilder builder) {
        this.product = builder.product;
        this.quantity = builder.quantity;
        this.price = builder.price;
        this.customerName = builder.customerName;
        this.deliveryAddress = builder.deliveryAddress;
    }

    public static class OrderBuilder {
        private String product;
        private int quantity;
        private double price;
        private String customerName;
        private String deliveryAddress;

        public OrderBuilder setProduct(String product) {
            this.product = product;
            return this;
        }

        public OrderBuilder setQuantity(int quantity) {
            this.quantity = quantity;
            return this;
        }

        public OrderBuilder setPrice(double price) {
            this.price = price;
            return this;
        }

        public OrderBuilder setCustomerName(String customerName) {
            this.customerName = customerName;
            return this;
        }

        public OrderBuilder setDeliveryAddress(String deliveryAddress) {
            this.deliveryAddress = deliveryAddress;
            return this;
        }

        public Order build() {
            return new Order(this);
        }
    }
}

// Uso:
Order order = new Order.OrderBuilder()
                    .setProduct("Laptop")
                    .setQuantity(2)
                    .setPrice(1200.00)
                    .setCustomerName("John Doe")
                    .setDeliveryAddress("123 Main St")
                    .build();
```

- **Métodos Sobrecargados**: Puedes utilizar la sobrecarga de métodos para proporcionar diferentes versiones del método con diferentes números de parámetros, lo cual puede hacer que el uso sea más flexible.

**Ejemplo**
```java
public void placeOrder(String product, int quantity) {
    placeOrder(product, quantity, 0.0, "Unknown", "Unknown");
}

public void placeOrder(String product, int quantity, double price) {
    placeOrder(product, quantity, price, "Unknown", "Unknown");
}

public void placeOrder(String product, int quantity, double price, String customerName, String deliveryAddress) {
    // Implementación del método principal
}
```

- **Parámetros de Configuración con Objetos**: Si muchos parámetros son configuraciones opcionales, puedes encapsular estas configuraciones en un objeto de configuración.

**Ejemplo**
```java
public class PrintConfiguration {
    private boolean isColor;
    private boolean isDuplex;
    private int numberOfCopies;

    // Constructor, getters, y setters
}

public void printDocument(String document, PrintConfiguration config) {
    // Uso de config para acceder a las opciones de configuración
}
```

- **Usar Mapas o Diccionarios**: Para algunos casos, especialmente cuando los parámetros son dinámicos o desconocidos en tiempo de compilación, puedes usar un `Map` para pasar parámetros.

**Ejemplo**
```java
public void configureSettings(Map<String, Object> settings) {
    // Acceso a los valores en el mapa
    String theme = (String) settings.get("theme");
    Integer fontSize = (Integer) settings.get("fontSize");
    // ...
}
```

## ¿Dividir Clases?
El concepto de dividir clases cuando tienen demasiados parámetros se refiere a la técnica de descomponer una clase grande y compleja en varias clases más pequeñas y enfocadas. Esta técnica está alineada con los principios SOLID, particularmente con el **Single Responsibility Principle (SRP)**, que establece que una clase debe tener una única responsabilidad o motivo para cambiar. Dividir clases ayuda a mejorar la mantenibilidad, legibilidad y reutilización del código.

**¿Por qué dividir clases?**

- **Complejidad Reducida**: Al dividir una clase grande en clases más pequeñas, reduces la complejidad, haciendo el código más fácil de entender y mantener.
- **Mejor Cohesión**: Cada clase pequeña tiene una única responsabilidad, lo que aumenta la cohesión y hace que cada clase sea más enfocada y específica.
- **Reutilización**: Las clases pequeñas y específicas son más fáciles de reutilizar en diferentes contextos.
- **Testabilidad**: Las clases pequeñas son más fáciles de probar unitariamente.

**Ejemplo Práctico**

Supongamos que tienes una clase `OrderProcessor` que maneja muchos parámetros relacionados con la creación y procesamiento de una orden. Inicialmente, esta clase podría parecer algo así:
```java
public class OrderProcessor {
    private String product;
    private int quantity;
    private double price;
    private String customerName;
    private String deliveryAddress;
    private String paymentMethod;
    private boolean isGift;
    private String giftMessage;

    public OrderProcessor(String product, int quantity, double price, String customerName, String deliveryAddress,
                          String paymentMethod, boolean isGift, String giftMessage) {
        this.product = product;
        this.quantity = quantity;
        this.price = price;
        this.customerName = customerName;
        this.deliveryAddress = deliveryAddress;
        this.paymentMethod = paymentMethod;
        this.isGift = isGift;
        this.giftMessage = giftMessage;
    }

    public void processOrder() {
        // Lógica para procesar la orden
    }
}
```

## Dividiendo en Clases Más Pequeñas

**Paso 1: Identificar Responsabilidades**

Identificamos las diferentes responsabilidades en `OrderProcessor`:

- **Información del producto**.
- **Información del cliente**.
- **Información de entrega**.
- **Información de pago**.
- **Información del regalo**.

**Paso 2: Crear Clases Separadas**

Creamos clases separadas para cada responsabilidad.
```java
public class Product {
    private String name;
    private int quantity;
    private double price;

    // Constructor, getters y setters
}

public class Customer {
    private String name;

    // Constructor, getters y setters
}

public class Delivery {
    private String address;

    // Constructor, getters y setters
}

public class Payment {
    private String method;

    // Constructor, getters y setters
}

public class Gift {
    private boolean isGift;
    private String message;

    // Constructor, getters y setters
}
```

**Paso 3: Refactorizar la Clase Principal**

Refactorizamos `OrderProcessor` para usar las nuevas clases.
```java
public class OrderProcessor {
    private Product product;
    private Customer customer;
    private Delivery delivery;
    private Payment payment;
    private Gift gift;

    public OrderProcessor(Product product, Customer customer, Delivery delivery, Payment payment, Gift gift) {
        this.product = product;
        this.customer = customer;
        this.delivery = delivery;
        this.payment = payment;
        this.gift = gift;
    }

    public void processOrder() {
        // Lógica para procesar la orden utilizando las nuevas clases
    }
}
```
