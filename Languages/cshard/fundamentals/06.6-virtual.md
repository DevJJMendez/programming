# `override`
El modificador override en C# se utiliza para proporcionar una implementación específica de un miembro heredado de una clase base que ha sido marcado como virtual, abstract o definido en una interfaz. Este es un pilar fundamental de la programación orientada a objetos (POO), ya que permite el polimorfismo dinámico.

El modificador override indica que un método, propiedad, indexador o evento en una clase derivada sobrescribe el comportamiento definido en la clase base. Solo se puede usar para sobrescribir miembros marcados como virtual, abstract, o miembros heredados de interfaces.

## ¿Para qué sirve?
Sobrescribir comportamiento heredado: Permite que las clases derivadas proporcionen su propia implementación para los miembros heredados.
Soporte al polimorfismo dinámico: Asegura que el método sobrescrito sea invocado en tiempo de ejecución según el tipo del objeto.
Personalización de lógica: Facilita la creación de clases derivadas más específicas y con comportamientos personalizados.

## ¿Cómo lo resuelve?
Sobrescribiendo métodos virtual o abstract: Utiliza override para proporcionar una implementación específica para un miembro de la clase base.
Invocación polimórfica en tiempo de ejecución: Asegura que los métodos sobrescritos se llamen de acuerdo con el tipo real del objeto.

# `virtual`
El modificador virtual en C# es una característica clave en la programación orientada a objetos (POO) que se utiliza en métodos, propiedades, indexadores y eventos dentro de una clase para permitir que las clases derivadas los sobrescriban utilizando el modificador override.

## ¿Qué es virtual en C#?
El modificador virtual permite marcar un miembro de una clase (como un método, propiedad, evento o indexador) para que pueda ser sobrescrito por una clase derivada. Por defecto, los métodos en C# no se pueden sobrescribir a menos que se marquen como virtual.

## ¿Para qué sirve?
Extensibilidad de las clases: Permite que las clases derivadas personalicen el comportamiento de los miembros de la clase base.
Soporte al polimorfismo: Esencial para el polimorfismo dinámico, donde el comportamiento se determina en tiempo de ejecución basado en el tipo del objeto.
Flexibilidad en diseño: Habilita que los métodos de una clase base sean utilizados como una plantilla y puedan ser adaptados por las clases derivadas.

## ¿Qué problemas resuelve?
Falta de personalización en clases derivadas: Sin virtual, no es posible modificar el comportamiento de métodos heredados.
Falta de polimorfismo: Sin métodos virtual, no podrías sobrescribir el comportamiento para objetos de diferentes clases derivadas.
Rigidez en el diseño: Permite que una jerarquía de clases sea más flexible y extensible.

## ¿Cómo lo resuelve?
Marcando métodos, propiedades o eventos como virtual: Esto permite a las clases derivadas sobrescribirlos usando el modificador override.
Estableciendo un comportamiento predeterminado: La clase base puede proporcionar una implementación predeterminada que las clases derivadas pueden reutilizar o cambiar.

## Ejemplo básico del uso de virtual
Clase base con método virtual:
```c#
public class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("The animal makes a sound.");
    }
}

public class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Woof!");
    }
}

public class Cat : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Meow!");
    }
}

class Program
{
    static void Main(string[] args)
    {
        Animal animal = new Animal();
        animal.Speak(); // Output: The animal makes a sound.

        Animal dog = new Dog();
        dog.Speak(); // Output: Woof!

        Animal cat = new Cat();
        cat.Speak(); // Output: Meow!
    }
}
```
En este ejemplo:

El método Speak en la clase Animal está marcado como virtual.
Las clases Dog y Cat sobrescriben este método para proporcionar su propio comportamiento.

## Reglas importantes sobre virtual
Solo en clases no selladas: Un método virtual no puede estar en una clase marcada como sealed.
Acceso modificador debe coincidir o ser más permisivo: El acceso del método sobrescrito (override) debe coincidir con el del método base.
No aplicable a métodos estáticos: El modificador virtual no puede ser usado con métodos static, ya que estos no se relacionan con instancias.

## ¿Dónde usar virtual?
Cuando esperas personalización: Usa virtual en métodos que probablemente necesiten ser sobrescritos por clases derivadas.
En clases base de jerarquías: Si estás diseñando una jerarquía de clases extensible, usa virtual para permitir modificaciones en métodos clave.
Para habilitar polimorfismo dinámico: Si necesitas que los métodos sean invocados en tiempo de ejecución basados en el tipo real del objeto, usa virtual.
