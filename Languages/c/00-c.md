# `C`
El lenguaje **C** fue creado a principios de la década de 1970 por **Dennis Ritchie** en los laboratorios Bell, mientras trabajaba en el desarrollo del sistema operativo **Unix**. 

1. Antecedentes: Antes de **C**, existía un lenguaje llamado **B**, desarrollado por **Ken Thompson** (también en Bell Labs) para facilitar la programación del sistema operativo Unix en una máquina PDP-7. Sin embargo, **B** tenía limitaciones en cuanto a eficiencia y control sobre el hardware.

2. **Creación de C (1972)**: Dennis Ritchie creó el lenguaje **C** como una evolución de `B`, añadiendo funcionalidades cruciales como tipos de datos y mejor manejo de estructuras. Esto lo hizo más potente y eficiente para la programación de sistemas, lo que facilitó la escritura de **Unix** en **C**, permitiendo que el sistema operativo pudiera ejecutarse en diferentes tipos de hardware.

3. **Estándar y popularización (1980s)**: En la década de 1980, el lenguaje C ganó popularidad en la academia y la industria, lo que llevó a la creación de su primer estándar formal en 1989 por la ANSI (American National Standards Institute), conocido como ANSI C o C89. Luego, fue adoptado internacionalmente por la ISO (International Organization for Standardization) en 1990, consolidando su estatus.

4. **Influencia**: **C** ha influido en muchos otros lenguajes modernos, como **C++**, **Java**, **C#**, **JavaScript**, **PHP** y más, gracias a su eficiencia, simplicidad y control directo del hardware. Muchas de sus características fundamentales, como los punteros, estructuras de control y tipos de datos básicos, se encuentran en estos lenguajes.

## Estructura básica de un proyecto en C
Un proyecto en C puede ser simple o complejo dependiendo de su tamaño.

**Ejemplo básico**
```bash
mi_proyecto_c/
│
├── src/            # Código fuente (archivos .c)
│   └── main.c
│
├── include/        # Archivos de cabecera (archivos .h)
│   └── funciones.h
│
├── bin/            # Archivos binarios compilados (ejecutables)
│
└── Makefile        # Opcional: Archivo de configuración para automatizar compilación
```

## `main.c`
El archivo principal `main.c` puede tener una estructura simple como esta:
```c
#include <stdio.h>
#include "funciones.h"  // Incluir el archivo de cabecera

int main() {
    printf("Hola, Mundo!\n");
    saludar();
    return 0;
}
```
## `funciones.h`
Aquí puedes definir funciones auxiliares o declarar variables globales:
```c
#ifndef FUNCIONES_H
#define FUNCIONES_H

void saludar();

#endif
```
## funciones.c
El archivo donde defines las funciones:
```c
#include <stdio.h>
#include "funciones.h"

void saludar() {
    printf("¡Saludos desde una función!\n");
}
```

## Compilación y ejecución

1. **Compilar**

   * Para compilar tu proyecto, ve al directorio donde está el código y usa este comando en la terminal:
    ```bash
    gcc -o bin/mi_programa src/main.c src/funciones.c -Iinclude/
    ```

## header files
Los archivos de cabecera (o **header files**) en **C** son archivos que contienen declaraciones de funciones, macros, constantes, tipos de datos, y otras definiciones que pueden ser compartidas y reutilizadas en múltiples archivos fuente. Estos archivos tienen la extensión `.h` y juegan un papel crucial en la modularización y organización del código.

## ¿Qué son los archivos de cabecera?
* Son archivos con extensión `.h` que **contienen declaraciones** (no implementaciones) de funciones, variables, macros, y tipos de datos.

* **No contienen el código fuente completo**, solo especifican **qué es lo que existe** (funciones, variables, etc.), **pero no cómo funcionan**. La implementación de esas funciones generalmente se encuentra en archivos `.c`.

* Son incluidos en los archivos fuente `.c` utilizando la directiva `#include`.

## ¿Qué resuelven?
1. **Reutilización del código**: Permiten compartir la misma declaración de funciones, estructuras o macros entre diferentes archivos fuente sin duplicar código.

2. **Modularización**: Fomentan el diseño modular, donde las funciones y estructuras se declaran una vez en los archivos de cabecera y se implementan en los archivos fuente. Esto facilita la organización del código en proyectos grandes.

3. **Mantenimiento**: Si necesitas cambiar una declaración o estructura, solo modificas el archivo de cabecera, y todos los archivos que lo incluyan automáticamente verán la actualización. Esto reduce la duplicación y facilita el mantenimiento del código.

4. **Separación de interfaz e implementación**: Los archivos de cabecera separan la interfaz (lo que un módulo puede hacer) de la implementación (cómo lo hace). Otros archivos solo necesitan conocer la interfaz para utilizar el código.

## ¿Cómo lo resuelven?
1. **Declaraciones en archivos `.h`**: Las funciones y variables se declaran en los archivos de cabecera, pero no se implementan.

2. **Implementación en archivos `.c`**: Los archivos `.c` contienen la implementación de las funciones y pueden incluir archivos de cabecera para usar las declaraciones.

   * **Ejemplo**
     * `functions.h`
    ```c
    #ifndef FUNCTIONS_H
    #define FUNCTIONS_H

    // Declaración de la función
    void saludar();

    #endif
    ```

   * `functions.c`
    ```c
    #include "functions.h"
    #include <stdio.h>

    // Implementación de la función
    void saludar(){
      printf("hello from functions.c");
    }
    ```

   * `main.c`
    ```c
    #include "functions.h"

    int main(){
      saludar();
      return 0;
    }
    ```
  En este ejemplo, el archivo de cabecera `functions.h` contiene la declaración de la función `saludar()`. La implementación real está en el archivo `functions.c`, y el archivo principal `main.c` puede usar esa función porque incluye el archivo de cabecera.

## ¿Cuándo se utilizan?
Los archivos de cabecera se utilizan en varias situaciones:

1. **Declaraciones de funciones**: Cuando una función se utiliza en varios archivos `.c`, la declaración de esa función se coloca en un archivo de cabecera para que otros archivos puedan "verla".

2. **Estructuras y tipos de datos**: Si has definido una estructura o un tipo de dato que se necesita en varias partes del programa, lo defines en un archivo de cabecera.

3. **Macros y constantes**: Las macros (`#define`) y constantes globales a menudo se colocan en un archivo de cabecera para facilitar su reutilización en todo el proyecto.

4. **Declaración de variables globales**: Si necesitas una variable global compartida entre múltiples archivos, puedes declarar su existencia en un archivo de cabecera (aunque es preferible evitar variables globales cuando sea posible).

## Protección contra inclusiones múltiples
Cuando varios archivos incluyen el mismo archivo de cabecera, puede ocurrir una **inclusión múltiple**, lo que provoca errores de compilación por redefinición. Para evitar esto, se utilizan **`include guards`**.

## ¿Qué son los include guards?
Los include guards son una técnica que evita la inclusión múltiple de un archivo de cabecera utilizando las directivas preprocesadoras `#ifndef`, `#define` y `#endif`.

**Ejemplo**
```c
#ifndef FUNCIONES_H // IF FUNCIONES_H IS NOT DEFINED
#define FUNCIONES_H // DEFINE FUNCIONES_H 

// Contenido del archivo de cabecera
void saludar();

#endif
```

## Errores comunes al usar archivos de cabecera
* **Incluir archivos de cabecera innecesarios**: Evita incluir archivos que no se necesiten en el archivo .c actual.

* **Duplicación de definiciones**: Los archivos de cabecera no deben contener definiciones de variables o funciones, solo declaraciones. Las definiciones deben estar en los archivos .c.

* **No usar `include guards`**: No utilizar **include guards** puede provocar errores de múltiples inclusiones.

## archivo de implementación
El archivo de implementación de funciones en **C** es un archivo fuente con extensión `.c` donde se encuentra el código real que define cómo se comportan las funciones, estructuras, o cualquier otra lógica del programa. Este archivo complementa los archivos de cabecera (`.h`), que solo contienen las declaraciones de esas funciones o estructuras.

## ¿Qué es el archivo de implementación?
* Es un archivo con extensión `.c` que contiene las definiciones de funciones, es decir, el código que describe qué hace cada función.

* A diferencia de los archivos de cabecera, que solo declaran la existencia de funciones, las variables y las estructuras, el archivo de implementación contiene la lógica que las implementa.

* Estos archivos son compilados para generar el **código objeto** que luego puede ser **enlazado** con otros archivos para formar el programa ejecutable.

## ¿Qué resuelve?
* **Separación de interfaz e implementación**: El archivo de cabecera (.h) declara qué funciones y variables están disponibles, y el archivo de implementación (.c) especifica cómo se ejecutan esas funciones. Esto permite modularizar el código y hacer que sea más fácil de mantener.

* **Modularización**: Al dividir la declaración de la implementación, los desarrolladores pueden trabajar en diferentes módulos del programa de forma independiente, siempre y cuando las interfaces en los archivos de cabecera se mantengan consistentes.

* **Reutilización del código**: Las implementaciones pueden ser compartidas entre diferentes partes del proyecto o incluso reutilizadas en diferentes proyectos si están bien organizadas en módulos separados.
