# Setters
es un método que se utiliza para **modificar el valor** de un atributo privado o protegido de una clase. En la programación orientada a objetos, los atributos suelen ser privados para mantener el encapsulamiento y evitar el acceso directo e incontrolado desde el exterior de la clase. El setter actúa como un método controlado para permitir que el código externo cambie el valor de un atributo de manera segura.

**Ejemplo**
```java
public class Empleado {
    private String nombre;
    private double salario;

    // Constructor
    public Empleado(String nombre, double salario) {
        this.nombre = nombre;
        this.salario = salario;
    }

    // Setter para el atributo nombre
    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    // Setter para el atributo salario
    public void setSalario(double salario) {
        if (salario > 0) {
            this.salario = salario;
        } else {
            System.out.println("El salario debe ser mayor a 0");
        }
    }
}
```

## ¿Para Qué Sirve un Setter?
1. **Permitir la Modificación Controlada de Atributos**: Un setter permite modificar el valor de un atributo privado de manera segura y controlada, asegurando que el nuevo valor cumpla con ciertos criterios o reglas antes de ser asignado.

2. **Aplicar Validaciones o Lógica al Asignar un Valor**: Los setters pueden incluir lógica adicional, como validaciones, para asegurar que los atributos siempre tengan valores válidos. Por ejemplo, asegurarse de que un salario no sea negativo o que un nombre no esté vacío.

3. **Proveer una Interfaz Consistente**: Los setters proporcionan una interfaz estándar para modificar los atributos de un objeto, lo que permite extender o modificar la lógica de la clase sin afectar al resto del código que depende de ella.

## ¿Qué Problemas Resuelve un Setter?
1. **Control del Estado Interno del Objeto**: Al no permitir el acceso directo a los atributos, el setter se asegura de que cualquier cambio en el estado interno del objeto pase por un filtro o lógica específica. Esto ayuda a mantener el objeto en un estado válido y evita errores.

2. **Flexibilidad para Modificaciones Futuras**: Si se necesita cambiar la lógica de cómo se asigna un valor, el setter puede modificarse sin afectar al resto del sistema. Esto mejora la mantenibilidad y flexibilidad del código.

3. **Seguridad y Validación**: Los setters permiten implementar validaciones antes de aceptar un nuevo valor, asegurando que los atributos siempre estén en un estado válido. Esto protege la integridad del objeto y previene errores.

## ¿Cómo Resuelve Estos Problemas?
Uso de Métodos Públicos para Modificar Atributos Privados:

Los setters permiten que se modifiquen los atributos sin exponerlos directamente. De esta manera, el código externo no puede establecer valores inválidos o inapropiados sin pasar por el control que el setter impone.
Añadiendo Validaciones en el Setter:

Puedes añadir validaciones o lógica dentro del setter para asegurarte de que el valor que se asigna es correcto. Por ejemplo, puedes validar que un valor no sea nulo, que un número esté dentro de un rango aceptable, etc.
Ejemplo:
```java
public class Producto {
    private double precio;

    // Setter con validación
    public void setPrecio(double precio) {
        if (precio > 0) {
            this.precio = precio;
        } else {
            System.out.println("El precio debe ser mayor que 0");
        }
    }
}

Producto laptop = new Producto();
laptop.setPrecio(1200); // Correcto
laptop.setPrecio(-100); // "El precio debe ser mayor que 0"
```

3. Facilitando la Mantenibilidad:

Imagina que en el futuro necesitas agregar un impuesto o una comisión al precio de un producto. Si usas un setter, puedes modificar el método para incluir esta lógica sin afectar el código que ya existe y que utiliza ese setter.

## Consideraciones Adicionales
1. **Nomenclatura**: Los setters siguen una convención de nomenclatura que consiste en usar `set` seguido del nombre del atributo con la primera letra en mayúscula. Esto asegura consistencia y claridad en el código.

2. Compatibilidad con Frameworks:

Al igual que con los getters, muchos frameworks y herramientas dependen de los setters para poder modificar el estado de un objeto. Esto es común en frameworks de inyección de dependencias (como Spring), donde los valores se establecen a través de setters.
Control sobre Atributos Derivados:

A veces, un atributo no es simplemente un valor, sino que puede derivarse de otros valores. Los setters permiten incluir esta lógica para calcular o ajustar valores derivados de manera correcta y consistente.
Peligros del Uso Excesivo de Setters:

Aunque los setters son útiles, hay situaciones en las que tener demasiados setters puede ser una mala práctica. Por ejemplo, si el objeto está en un estado inválido mientras se están configurando todos sus atributos a través de setters, puede provocar errores inesperados. En estos casos, se recomienda usar constructores o patrones de diseño como el Builder para garantizar que el objeto esté completamente configurado antes de su uso.
