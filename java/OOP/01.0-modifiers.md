# Modificadores de Acceso
Los modificadores de acceso en Java son palabras clave que definen el nivel de acceso (visibilidad) de clases, métodos y variables. Estos permiten controlar qué partes del código pueden interactuar con ciertos elementos de una clase, asegurando que se mantenga la seguridad y encapsulamiento del software.

## ¿Para qué Sirven los Modificadores de Acceso?
Su función principal es controlar la accesibilidad de diferentes elementos en un programa para:

1. **Encapsular datos**: Ocultar los detalles internos de una clase y exponer solo lo necesario.

2. **Proteger la integridad de los datos**: Evitar el acceso no autorizado o no deseado a los datos.

3. **Mantener un diseño modular**: Permitir la separación de responsabilidades dentro de un sistema, limitando qué partes pueden modificar otras partes.

## ¿Qué Problemas Resuelven los Modificadores de Acceso?
1. **Acceso no autorizado a datos**: Evitan que se pueda acceder directamente a variables sensibles, protegiendo la información interna de la clase.

2. **Mantenimiento del código**: Permiten cambiar la implementación interna sin afectar a otras partes del código. Esto facilita la extensibilidad y el mantenimiento del software.

3. **Prevención de errores**: Reducen el riesgo de errores al restringir el acceso a métodos o variables que no deben ser usados desde fuera de su clase.

## ¿Cómo lo Resuelven?
1. **Encapsulamiento**: Los modificadores de acceso limitan qué partes de un programa pueden ver o modificar ciertos elementos, asegurando que la clase controle cómo se accede a sus datos.

   * Ejemplo: Usar `private` para una variable asegura que solo métodos dentro de la misma clase puedan acceder o modificar su valor. Esto permite que la clase defina reglas claras de cómo sus datos deben ser manipulados.

2. **Abstracción y Exposición Controlada**: Los modificadores permiten que una clase decida qué partes de su implementación son visibles y cuáles no, exponiendo solo los métodos necesarios para interactuar con ella.

   * **Ejemplo**: Usar public para métodos de la clase que deben ser accesibles para otras partes del sistema, mientras se mantiene private para métodos internos que manejan la lógica específica.

3. **Modularidad y Extensibilidad**: Facilitan el diseño modular del software, ya que se puede definir qué partes son extensibles (por ejemplo, a través de herencia usando `protected`) y qué partes deben permanecer inalteradas.

   * **Ejemplo**: Una clase base define ciertos métodos `protected` que las subclases pueden sobrescribir o extender, permitiendo la personalización sin romper la funcionalidad original.

# `public`
public es uno de los modificadores de acceso en Java que se utiliza para declarar clases, métodos, y variables. Este modificador indica que el elemento marcado como public es accesible desde cualquier otra clase, sin importar en qué paquete esté definido. Es el nivel de acceso más amplio que existe en Java.

## ¿Para qué Sirve public?
El modificador public sirve para:

1. **Hacer elementos accesibles globalmente**: Permite que métodos, variables y clases puedan ser utilizados desde cualquier parte del programa.

2. **Exponer funcionalidad**: Es ideal para definir métodos y clases que deben estar disponibles para ser utilizados por otras clases, módulos o bibliotecas externas.

3. **Crear API públicas**: Permite que otras partes de la aplicación o incluso aplicaciones externas puedan acceder a la funcionalidad que se necesita exponer.

## ¿Qué Problemas Resuelve?
1. **Interoperabilidad entre componentes**: Permite que diferentes componentes del sistema se comuniquen entre sí, exponiendo funcionalidad clave que debe ser accesible para otras partes del programa o módulos.

2. **Reutilización de código**: Facilita la creación de métodos y clases reutilizables que se pueden utilizar en diferentes proyectos o partes del mismo sistema.

3. **Definición de contratos y API**: Ayuda a crear interfaces públicas que otras partes del sistema (o aplicaciones externas) pueden utilizar sin necesidad de conocer los detalles internos de la implementación.

## ¿Cómo lo Resuelve?
1. **Exponiendo métodos y clases globalmente**: Al marcar un método, variable o clase como public, se asegura que estos puedan ser accedidos desde cualquier otro lugar del programa. Esto permite la interacción directa sin necesidad de restricciones adicionales.

2. **Permitiendo la visibilidad y acceso completo**: La visibilidad global permite que, por ejemplo, una clase pueda definir métodos públicos que otras clases pueden invocar para interactuar con ella.

3. **Estableciendo contratos de código claros**: Las clases public pueden contener métodos public que actúan como la interfaz oficial de la clase, definiendo cómo otras clases deben interactuar con ella.

## Ejemplos
1. **Método `public`**
```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}
```
* **Explicación**: El método `add` es **public**, por lo que puede ser llamado desde cualquier otra clase que tenga acceso a una instancia de `Calculator`. Esto es útil porque el método `add` forma parte de la funcionalidad principal que se debe exponer a otras partes del programa.

2.**Clase `public`**
```java
public class Main {
    public static void main(String[] args) {
        Calculator calc = new Calculator();
        int result = calc.add(5, 3);
        System.out.println("Resultado: " + result);
    }
}
```
* **Explicación**: La clase `Main` es **public**, lo que significa que puede ser ejecutada por la JVM desde cualquier lugar del proyecto. Es común que las clases que contienen el punto de entrada de una aplicación (el método main) sean públicas para que la JVM pueda acceder a ellas.

# `private`
**private** es uno de los modificadores de acceso en Java que restringe el acceso a clases, métodos, y variables. Cuando se declara un miembro (método, variable o constructor) como **private**, solo es accesible dentro de la misma clase en la que se define. Es el nivel de acceso más restringido en Java.

## ¿Para qué Sirve private?
El modificador **private** sirve para:

1. **Encapsular datos**: Permite ocultar los detalles internos de una clase, protegiendo el estado interno del objeto de modificaciones externas.

2. **Controlar el acceso**: Solo se puede acceder a los miembros **private** a través de métodos públicos de la misma clase, proporcionando un control estricto sobre cómo se accede y se modifica la información.

3. **Mantener la consistencia**: Al encapsular los datos, se puede asegurar que el estado del objeto permanezca consistente, evitando modificaciones accidentales o inapropiadas.

## ¿Qué Problemas Resuelve?
1. **Protección del estado interno de los objetos**: Restringe el acceso directo a los atributos, asegurando que solo métodos específicos de la clase puedan modificar el estado interno.

2. **Cumplimiento de principios de diseño**: Como el Principio de Encapsulamiento, que es fundamental para el diseño orientado a objetos, permite ocultar detalles internos y mostrar solo lo que es necesario a otras partes del programa.

3. **Control de comportamiento**: Los métodos privados pueden usarse para organizar y modularizar el comportamiento de la clase, sin exponer esa funcionalidad interna.

## ¿Cómo lo Resuelve?
1. **Ocultando la implementación interna**: Los atributos y métodos declarados como **private** no pueden ser accedidos directamente desde otras clases, lo que obliga a utilizar métodos públicos (getters y setters) para acceder o modificar los datos de forma controlada.

2. **Encapsulando la lógica interna**: Permite crear métodos que realizan tareas internas sin que estén disponibles para el uso externo, lo que facilita el mantenimiento del código, ya que los detalles de implementación pueden cambiar sin afectar a otras clases.

## **Ejemplos**
1. **Atributos `private`**
```java
public class BankAccount {
    private double balance;

    public BankAccount(double initialBalance) {
        this.balance = initialBalance;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
        }
    }
}
```
* **Explicación**: En este ejemplo, el atributo `balance` es **private**, por lo que no se puede acceder ni modificar directamente desde fuera de la clase. Esto asegura que el saldo solo pueda cambiarse a través de los métodos `deposit` y `withdraw`, que incluyen lógica para validar las operaciones y mantener la consistencia del estado.

2. **Métodos `private`**
```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    private void log(String message) {
        System.out.println("LOG: " + message);
    }

    public int subtract(int a, int b) {
        int result = a - b;
        log("Subtraction performed");
        return result;
    }
}
```
* **Explicación**: El método `log` es **private**, lo que significa que solo puede ser invocado desde dentro de la clase `Calculator`. Este diseño permite mantener la funcionalidad de logging sin exponerla a otras partes del programa.

# `protected`
**protected** es un modificador de acceso en Java que permite un nivel de acceso intermedio entre public y private. Cuando se declara un miembro (variable, método o constructor) como **protected**, puede ser accedido por:

1. La misma clase.

2. Clases dentro del mismo paquete.

3. Subclases (clases derivadas) en otros paquetes.
Este comportamiento hace que **protected** sea útil cuando necesitas permitir que las subclases accedan a miembros de la clase base sin exponerlos a todo el mundo (es decir, fuera del paquete).

## ¿Para qué Sirve protected?
**protected** es útil para:

1. **Permitir la herencia controlada**: Permite que las subclases accedan a métodos o atributos de la clase padre, facilitando la reutilización de código.

2. **Extender clases en otros paquetes**: Proporciona un acceso restringido que permite a las subclases ubicadas en diferentes paquetes interactuar con la clase padre.

3. **Controlar el acceso en el mismo paquete**: Los miembros **protected** están disponibles para todas las clases del mismo paquete, lo cual puede ser útil para compartir datos entre clases relacionadas sin hacerlos públicos.

## ¿Qué Problemas Resuelve?
1. **Facilita la Reutilización de Código**: Al permitir el acceso a miembros de la clase padre, las subclases pueden reutilizar código sin duplicación.

2. **Control de Acceso en Jerarquías de Herencia**: Proporciona una manera de exponer ciertos atributos y métodos a las subclases sin hacerlos públicos para todas las clases.

3. **Modularidad y Organización**: Permite organizar mejor el acceso entre clases relacionadas dentro del mismo paquete, sin necesidad de hacer públicos los detalles.

## ¿Cómo lo Resuelve?
1. **Permitiendo el Acceso a las Subclases**: Los métodos y atributos **protected** se pueden usar directamente en las subclases, incluso si estas se encuentran en paquetes diferentes. Esto promueve la herencia y la reutilización del código.

2. **Facilitando el Diseño Orientado a Objetos**: **protected** hace posible diseñar componentes que permiten la extensión y modificación de comportamiento sin exponer toda la funcionalidad interna al resto del sistema.

## Ejemplos
1. **Atributos y Métodos `protected`**
```java
package animals;

public class Animal {
    protected String name;

    protected void eat() {
        System.out.println(name + " está comiendo.");
    }
}
```
```java
package animals;

public class Dog extends Animal {
    public Dog(String name) {
        this.name = name; // Acceso permitido debido al modificador 'protected'
    }

    public void bark() {
        System.out.println(name + " está ladrando.");
    }
}
```
**Explicación**: En este ejemplo, la clase `Animal` tiene un atributo nam`e` y un método `eat`, ambos definidos como **protected**. La subclase `Dog` puede acceder a name directamente y también puede llamar al método `eat`. Esta es una forma de permitir que las subclases interactúen con ciertos aspectos de la clase padre sin exponer esos miembros al resto del sistema.

2. **Uso de `protected` en Diferentes Paquetes**: Supongamos que la clase `Animal` está en un paquete diferente del siguiente código:
```java
package zoo;

import animals.Animal;

public class Lion extends Animal {
    public Lion(String name) {
        this.name = name; // Posible gracias a 'protected', aunque está en otro paquete
    }

    public void roar() {
        System.out.println(name + " está rugiendo.");
        eat(); // Llamada permitida al método 'protected'
    }
}
```
**Explicación**: Aunque `Lion` está en un paquete diferente, puede acceder a los miembros `protected` `name` y `eat` de `Animal` porque es una subclase. Esto facilita la extensión de la funcionalidad de la clase `Animal` en diferentes contextos.

# `default`
El término `default` en el contexto de los modificadores de acceso en Java se refiere a la ausencia explícita de un modificador. Es decir, si no especificas ningún modificador de acceso (`public`, `private`, `protected`), el miembro (método, atributo o clase) será tratado como `default`. También se conoce como nivel de acceso de paquete o `package-private`.

## ¿Para Qué Sirve el Modificador default?
El modificador `default` se utiliza para:

1. **Controlar el acceso dentro del mismo paquete**: Los miembros de una clase declarados sin un modificador de acceso explícito solo son accesibles por otras clases que se encuentran en el mismo paquete. Esto puede ser útil para organizar el código y limitar el acceso de manera controlada.

2. **Encapsulación de nivel de paquete**: Permite que las clases relacionadas dentro del mismo paquete interactúen entre sí sin hacer públicos los miembros, pero también sin restringir el acceso tanto como private.

## ¿Qué Problemas Resuelve?
1. **Modularidad en Paquetes**: Facilita la organización modular del código al restringir el acceso a clases y métodos para que solo puedan ser utilizados dentro del mismo paquete. Esto es especialmente útil en aplicaciones grandes donde se necesita controlar quién tiene acceso a qué componentes.

2. **Control de Acceso Selectivo**: Permite controlar qué partes de una clase pueden ser accesibles por otras clases dentro del mismo paquete, evitando accesos accidentales desde clases que no deberían conocer esos detalles.

3. **Mantenimiento de la Encapsulación**: Proporciona un equilibrio entre private y protected. A diferencia de private, que restringe el acceso a la misma clase, y protected, que permite el acceso desde subclases y el mismo paquete, `default` limita el acceso solo a clases dentro del mismo paquete.

## ¿Cómo lo Resuelve?
1. **Limitando el Alcance de Acceso**: Los miembros `default` no son accesibles desde fuera del paquete, incluso si las clases externas están relacionadas (por ejemplo, en una jerarquía de herencia). Esto permite encapsular partes del código para que solo sean accesibles dentro del mismo módulo.

2. **Permitiendo Interacciones Internas del Paquete**: Las clases dentro del mismo paquete pueden acceder a métodos y atributos `default`, lo que facilita la colaboración entre clases que trabajan juntas sin necesidad de exponer esos elementos públicamente.

## Ejemplos
1. **Atributos y Métodos `default`**: Supongamos que tienes las siguientes clases en un paquete llamado `vehiculos`:
```java
package vehiculos;

public class Vehiculo {
    String tipo; // `default`, solo accesible dentro del paquete `vehiculos`

    void arrancar() { // `default`, solo accesible dentro del paquete `vehiculos`
        System.out.println("El vehículo está arrancando.");
    }
}
```
Ahora, creamos otra clase dentro del mismo paquete:
```java
package vehiculos;

public class Coche extends Vehiculo {
    public Coche() {
        tipo = "Coche"; // Acceso permitido gracias al modificador `default`
    }

    public void mostrarTipo() {
        System.out.println("Tipo de vehículo: " + tipo);
        arrancar(); // Acceso permitido
    }
}
```
El atributo `tipo` y método `arrancar` nNo tienen un modificador de acceso explícito, por lo que son `default` y, por tanto, accesibles para todas las clases dentro del paquete `vehiculos`.

2. **Acceso desde un Paquete Diferente**: Supongamos que ahora queremos acceder a tipo desde una clase en otro paquete:
```java
package taller;

import vehiculos.Vehiculo;

public class Mecanico {
    public void revisarVehiculo() {
        Vehiculo v = new Vehiculo();
        v.tipo = "Moto"; // ERROR: No se puede acceder a `tipo` porque es `default`
        v.arrancar(); // ERROR: No se puede acceder a `arrancar` porque es `default`
    }
}
```
**Explicación**: La clase `Mecanico` no puede acceder ni al atributo `tipo` ni al método `arrancar` porque están definidos como `default` en el paquete `vehiculos`. Esto demuestra cómo el modificador `default` limita el acceso a las clases dentro del mismo paquete.

# Non-Access Modifiers
Los Non-Access Modifiers son modificadores que se utilizan para definir comportamientos adicionales o propiedades especiales para clases, métodos, variables, y otros elementos del código. A diferencia de los modificadores de acceso (`public`, `private`, `protected`, `default`), que controlan quién puede acceder a un miembro, los Non-Access Modifiers especifican cómo funcionan estos miembros.

## ¿Para Qué Sirven?
1. **Modificar el Comportamiento de Clases y Miembros**: Permiten alterar la forma en que las clases, métodos y variables se comportan, como definir constantes (`final`), indicar que un método o clase no debe ser sobrescrito (`final`), o habilitar la concurrencia (synchronized).

2. **Mejorar la Gestión de Recursos**: Modificadores como `static` ayudan a gestionar recursos al definir miembros compartidos por todas las instancias de una clase.

3. **Optimización del Rendimiento**: Modificadores como `volatile` y `synchronized` ayudan en el contexto de aplicaciones concurrentes y multihilo.

# `final`
El modificador `final` en Java se utiliza para definir constantes, métodos inmutables o clases que no pueden ser heredadas. Su propósito principal es impedir la modificación de ciertos elementos del código, asegurando que no puedan ser cambiados, sobrescritos o extendidos después de haber sido definidos.

## ¿Para Qué Sirve el Modificador final?
1. **Inmutabilidad**: Garantiza que el valor de una variable no se pueda cambiar después de ser asignado.

2. **Integridad del Comportamiento**: Previene que los métodos sean sobrescritos por subclases, manteniendo la implementación original.

3. **Seguridad de la Clase**: Evita que una clase sea extendida, lo que es útil para asegurar que la clase no se comporte de forma inesperada si alguien intenta heredarla.

## ¿Qué Resuelve?
El uso de final resuelve problemas relacionados con la modificación no intencional del comportamiento del código. Por ejemplo:

* **Variables inmutables**: Asegura que los valores críticos (como constantes) no cambien accidentalmente.

* **Métodos críticos**: Previene que subclases alteren la lógica esencial de un método.

* **Clases selladas**: Impide que una clase se extienda, asegurando que su comportamiento no sea modificado de manera no controlada.

## ¿Cómo Lo Resuelve?
1. **Variables `final`**: Cuando una variable es declarada como `final`, se comporta como una constante. Esto significa que debe ser inicializada una vez y su valor no puede cambiarse después.

```java
final int MAX_USERS = 100; // Constante
MAX_USERS = 200; // Error: No se puede reasignar una variable final
```
**¿Qué Resuelve?**
* Evita la re-asignación accidental de valores a variables que deberían ser constantes.

* Facilita la comprensión del código, ya que los valores final indican de forma clara que algo no debe cambiarse.

2. **Métodos `final`**: Cuando se declara un método como `final`, significa que no se puede sobrescribir en una subclase. Esto asegura que la implementación del método se mantenga sin cambios.
```java
public class Animal {
    public final void hacerSonido() {
        System.out.println("Sonido de animal");
    }
}

public class Perro extends Animal {
    @Override
    public void hacerSonido() { // Error: No se puede sobrescribir un método final
        System.out.println("Ladrar");
    }
}
```
**¿Qué resuelve?**
* **Protección del Comportamiento**: Garantiza que las subclases no puedan alterar métodos importantes, manteniendo la lógica original intacta.

* **Seguridad y Estabilidad**: Asegura que los métodos clave no sean alterados, previniendo posibles errores o inconsistencias.

3. **Clases `final`**: Una clase declarada como `final` no puede ser extendida. Esto significa que no se pueden crear subclases a partir de ella.
```java
public final class Calculadora {
    public int sumar(int a, int b) {
        return a + b;
    }
}

// Error: No se puede extender la clase final
public class CalculadoraAvanzada extends Calculadora {
    // No es posible heredar de Calculadora
}
```
**¿Qué Resuelve?**
* **Protección de la Implementación**: Evita que el comportamiento de la clase sea alterado a través de la herencia.

* **Integridad de la Lógica**: Útil para clases que deben comportarse de una manera muy específica y no deben ser modificadas.

## Consideraciones al Usar `final`
1. **Variables Referenciales**: Cuando una variable de tipo objeto es declarada como `final`, no significa que el objeto sea inmutable. Significa que la referencia a ese objeto no puede cambiar, pero el contenido del objeto aún puede ser modificado. Ejemplo:
```java
final List<String> nombres = new ArrayList<>();
nombres.add("Juan"); // Permitido
nombres = new ArrayList<>(); // Error: No se puede cambiar la referencia
```

2. **Rendimiento**: Marcar un método como `final` puede permitir a la JVM optimizar el rendimiento. Esto se debe a que la JVM sabe que el método no será sobrescrito y, por lo tanto, puede aplicar optimizaciones que no serían posibles si el método fuera sobreescribible.

3. **Herencia y Clases `final`**: Usar `final` en clases puede parecer útil para proteger el código, pero debe ser usado con precaución. Sellar clases evita la extensión futura, lo que puede limitar la flexibilidad si en algún momento se desea modificar el comportamiento de la clase.

# `static`
El modificador `static` se utiliza para indicar que un miembro (campo o método) de una clase pertenece a la clase en sí, en lugar de a instancias individuales de esa clase. Esto significa que solo hay una copia de ese miembro, y todas las instancias de la clase comparten esa copia.

## ¿Para qué sirve static?
* **Gestión de memoria**: Los miembros static se almacenan en la memoria de la clase, lo que puede ser más eficiente en términos de uso de memoria cuando se necesita compartir datos entre instancias.

* **Acceso sin instancia**: Los métodos y campos estáticos pueden ser accedidos sin crear una instancia de la clase, lo que puede ser útil para funciones utilitarias o constantes.

## ¿Qué resuelve?
* **Reducción de duplicación**: Ayuda a evitar la duplicación de datos y comportamiento, ya que solo hay una copia de un miembro `static` que es compartida entre todas las instancias de la clase.

* **Acceso global**: Facilita el acceso a datos que son comunes a todas las instancias, como contadores, configuraciones globales o constantes.

## ¿Cómo lo resuelve?
1. **Campo `static`**: Cuando declares un campo como `static`, cualquier cambio realizado en ese campo a través de una instancia se reflejará en todas las demás instancias. Esto es útil para mantener valores que deben ser consistentes a través de todas las instancias.

```java
public class Contador {
    private static int cuenta = 0;

    public Contador() {
        cuenta++;
    }

    public static int getCuenta() {
        return cuenta;
    }
}

public class Main {
    public static void main(String[] args) {
        new Contador();
        new Contador();
        System.out.println(Contador.getCuenta()); // Salida: 2
    }
}
```
2. **Método `static`**: Puedes definir métodos como `static` para que puedan ser llamados sin crear una instancia de la clase. Esto es útil para métodos que no dependen de la instancia, como métodos de utilidad.
```java
public class Utilidad {
    public static int sumar(int a, int b) {
        return a + b;
    }
}

public class Main {
    public static void main(String[] args) {
        int resultado = Utilidad.sumar(5, 3);
        System.out.println(resultado); // Salida: 8
    }
}
```

##  Consideraciones
* **No pueden acceder a miembros de instancia**: Los métodos estáticos no pueden acceder directamente a los miembros de instancia (no estáticos) de la clase, ya que no tienen referencia a una instancia específica.

```java
public class Ejemplo {
    private int valor = 10;

    public static void mostrarValor() {
        // System.out.println(valor); // Error: no puede acceder a 'valor'
    }
}
```

* **Uso en clases anidadas**: Las clases anidadas pueden ser declaradas como `static`, lo que significa que no necesitan una referencia a una instancia de la clase contenedora.

## `static class`
El uso de static en las clases en Java tiene implicaciones importantes que afectan cómo se estructuran y utilizan las clases y sus miembros.

1. **Clases Anidadas Estáticas**: En Java, puedes definir clases dentro de otras clases. Estas se llaman clases anidadas. Si una clase anidada se declara como static, se comporta de manera diferente a una clase anidada no estática.

**Características de una clase anidada estática:**
* No puede acceder directamente a los miembros no estáticos de la clase externa.

* Se puede instanciar sin necesidad de una instancia de la clase externa.

* Se utiliza comúnmente para agrupar funcionalidad relacionada.

**Ejemplo**
```java
public class Externa {
    private static String mensajeEstatico = "Mensaje de la clase externa.";

    // Clase anidada estática
    public static class AnidadaEstatica {
        public void mostrarMensaje() {
            // Puede acceder a los miembros estáticos de la clase externa
            System.out.println(mensajeEstatico);
        }
    }
    
    public static void main(String[] args) {
        Externa.AnidadaEstatica anidada = new Externa.AnidadaEstatica();
        anidada.mostrarMensaje(); // Salida: Mensaje de la clase externa.
    }
}
```

2. **Uso de `static` en Miembros de Clase**: Los miembros de clase, ya sean campos o métodos, pueden ser declarados como `static`. Esto significa que pertenecen a la clase en sí y no a instancias específicas de la clase.

* **Campos estáticos**: Útiles para almacenar datos que deben ser compartidos entre todas las instancias de la clase.

**Ejemplo**
```java
public class Contador {
    private static int cuenta = 0; // Campo estático

    public Contador() {
        cuenta++; // Incrementa cada vez que se crea una instancia
    }

    public static int getCuenta() { // Método estático
        return cuenta;
    }
    
    public static void main(String[] args) {
        new Contador();
        new Contador();
        System.out.println(Contador.getCuenta()); // Salida: 2
    }
}
```

3. **Métodos Estáticos**: Los métodos estáticos no requieren una instancia para ser invocados. Son útiles para operaciones que no dependen del estado de una instancia.

**Características de los métodos estáticos:**
* Pueden ser llamados directamente a través del nombre de la clase.

* No pueden acceder a miembros de instancia no estáticos.

**Ejemplo**:
```java
public class MathUtil {
    public static int sumar(int a, int b) {
        return a + b; // Método estático que suma dos números
    }
}

public class Main {
    public static void main(String[] args) {
        int resultado = MathUtil.sumar(5, 10);
        System.out.println("Resultado: " + resultado); // Salida: Resultado: 15
    }
}
```

4. **Constantes Estáticas**: Puedes utilizar campos estáticos para definir constantes que son compartidas a través de todas las instancias.

**Ejemplo**:
```java
public class Constantes {
    public static final double PI = 3.14159; // Constante estática

    public static void main(String[] args) {
        System.out.println("Valor de PI: " + Constantes.PI); // Salida: Valor de PI: 3.14159
    }
}
```

## Ventajas y Desventajas del Uso de static
**Ventajas**:
* **Reducción de duplicación**: Evita la duplicación de datos y métodos en cada instancia.

* **Facilita la organización**: Agrupa métodos utilitarios o constantes en una clase.

**Desventajas**:
* **Menos flexibilidad**: Dificulta la sobrecarga de métodos y la extensión de comportamiento en clases derivadas.

* Puede llevar a un diseño pobre si se abusa del uso de miembros estáticos, haciendo que el código sea menos modular.

# `abstract`
El modificador `abstract` se utiliza en dos contextos en Java:

* **Clases abstractas**: Son clases que no se pueden instanciar directamente. Pueden contener métodos abstractos (sin implementación) y métodos concretos (con implementación).

* **Métodos abstractos**: Son métodos declarados sin un cuerpo; es decir, no tienen una implementación en la clase donde se declaran. Las subclases deben implementar estos métodos.

## ¿Para qué sirve abstract?
* **Definición de un contrato**: Al declarar un método abstracto, estás creando un contrato que las subclases deben cumplir. Esto asegura que cualquier subclase que extienda la clase abstracta proporcionará una implementación para esos métodos.

* **Herencia**: Permite definir una estructura común para un grupo de clases relacionadas sin forzar la implementación de todos los métodos en la clase base.

* **Polimorfismo**: Facilita el uso del polimorfismo, permitiendo que diferentes subclases implementen sus versiones de métodos abstractos.

## ¿Qué resuelve?
* **Flexibilidad** en la implementación: Permite que las subclases tengan la libertad de definir sus propias implementaciones mientras siguen un esquema común.

* **Reutilización de código**: Proporciona una forma de reutilizar código común en una clase base, mientras que las subclases pueden implementar comportamientos específicos.

* **Organización de código**: Ayuda a organizar el código al separar la definición de una interfaz de su implementación.

## ¿Cómo lo resuelve?
* **Definición de una clase abstracta**: Se declara usando el modificador `abstract` en la definición de la clase. Puedes incluir métodos abstractos y concretos.

**Ejemplo**
```java
abstract class Animal {
    // Método abstracto
    public abstract void hacerSonido();
    
    // Método concreto
    public void dormir() {
        System.out.println("El animal está durmiendo.");
    }
}
```

**Implementación en subclases**: Las subclases que extienden la clase abstracta deben implementar todos los métodos abstractos.

```java
class Perro extends Animal {
    @Override
    public void hacerSonido() {
        System.out.println("El perro ladra.");
    }
}

class Gato extends Animal {
    @Override
    public void hacerSonido() {
        System.out.println("El gato maulla.");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal miPerro = new Perro();
        Animal miGato = new Gato();
        
        miPerro.hacerSonido(); // Salida: El perro ladra.
        miGato.hacerSonido();  // Salida: El gato maulla.
        miPerro.dormir();      // Salida: El animal está durmiendo.
    }
}
```

# `synchronized`
El modificador synchronized se utiliza para controlar el acceso concurrente a recursos compartidos en un entorno multihilo. Se asegura de que solo un hilo a la vez pueda ejecutar un bloque de código o un método específico que esté marcado como synchronized, evitando así condiciones de carrera y problemas de inconsistencia de datos.

# `volatile`
El modificador volatile se aplica a variables para indicar que su valor puede ser modificado por múltiples hilos. Esto asegura que los cambios realizados por un hilo a una variable volatile sean visibles para otros hilos inmediatamente.

# `transient`
El modificador transient se aplica a campos de una clase para indicar que no deben ser serializados. En otras palabras, cuando se guarda el estado de un objeto en un archivo (o se transmite a través de la red), los campos marcados como transient no se incluirán en el proceso de serialización.
