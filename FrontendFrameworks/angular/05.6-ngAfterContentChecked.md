# `ngAfterContentChecked`
ngAfterContentChecked es un hook del ciclo de vida de un componente o directiva en Angular. Este método se ejecuta después de que Angular verifica el contenido proyectado (`<ng-content>`) de un componente, y se llama cada vez que Angular realiza un ciclo de detección de cambios (change detection).

El hook forma parte de la interfaz AfterContentChecked, que puede implementarse en cualquier clase de componente o directiva.

## ¿Para qué sirve?
Este hook se utiliza para:

* Ejecutar lógica personalizada después de que Angular verifica los cambios en el contenido proyectado. Es útil para realizar tareas que dependen del contenido proyectado o para reaccionar a cualquier modificación en ese contenido.

* Detectar cambios en el contenido proyectado dinámicamente en un componente.

* Ejecutar lógica personalizada después de que Angular haya evaluado y actualizado el contenido proyectado.

* Depurar o realizar validaciones relacionadas con el contenido proyectado y las actualizaciones de datos.

Es útil para manejar escenarios donde el contenido dentro del `<ng-content>` cambia debido a eventos externos o asíncronos.

## ¿Qué resuelve?
Resuelve la necesidad de:

* Detectar cambios en el contenido proyectado dinámico dentro de un componente.

* Ejecutar lógica adicional o realizar ajustes después de que el contenido proyectado ha sido procesado.

**Por ejemplo:**
* Validar que el contenido proyectado cumple con ciertos criterios.

* Ajustar estilos o propiedades según cambios en el contenido dinámico.

## ¿Cómo lo resuelve?
Angular llama automáticamente al método ngAfterContentChecked después de cada detección de cambios que involucra el contenido proyectado. Esto permite al desarrollador escribir lógica personalizada en este punto del ciclo de vida del componente.

## Sintaxis
El hook `ngAfterContentChecked` es un método opcional que puede implementarse en un componente o directiva que implemente la interfaz `AfterContentChecked`.

**Ejemplo de implementación**
```ts
import { Component, AfterContentChecked } from '@angular/core';

@Component({
  selector: 'app-ejemplo',
  template: `
    <div>
      <ng-content></ng-content>
    </div>
  `,
})
export class EjemploComponent implements AfterContentChecked {
  ngAfterContentChecked(): void {
    console.log('El contenido proyectado ha sido verificado');
  }
}
```

## Flujo en el ciclo de vida del componente
El hook `ngAfterContentChecked` se llama:

1. Después de que Angular proyecta el contenido en el componente.

2. Después de cada ciclo de detección de cambios, si se detectan cambios en el contenido proyectado.

**Orden en el ciclo de vida:**
* `ngOnInit`: Inicialización del componente.

* `ngDoCheck`: Detección de cambios personalizada.

* `ngAfterContentInit`: Inicialización del contenido proyectado.

* `ngAfterContentChecked`: Verificación del contenido proyectado.

## Casos de uso
* **Validación del contenido proyectado**, Si necesitas validar que el contenido proyectado cumple con ciertos criterios.
```ts
import { Component, AfterContentChecked, ContentChild, ElementRef } from '@angular/core';

@Component({
  selector: 'app-validador',
  template: `
    <div>
      <ng-content></ng-content>
    </div>
  `,
})
export class ValidadorComponent implements AfterContentChecked {
  @ContentChild('validar') contenido!: ElementRef;

  ngAfterContentChecked(): void {
    if (!this.contenido) {
      console.error('El contenido proyectado no contiene un elemento con la referencia #validar');
    }
  }
}
```
**Uso**
```
<app-validador>
  <!-- Esto causará un error porque no hay un elemento con #validar -->
  <p>Contenido inválido</p>
</app-validador>
```

* **Ajustes dinámicos de estilos o propiedades**, Puedes modificar estilos o propiedades del componente dependiendo de cambios en el contenido proyectado.
```ts
@Component({
  selector: 'app-ajustador',
  template: `
    <div [style.color]="color">
      <ng-content></ng-content>
    </div>
  `,
})
export class AjustadorComponent implements AfterContentChecked {
  @ContentChild('texto') contenido!: ElementRef;
  color: string = 'black';

  ngAfterContentChecked(): void {
    if (this.contenido) {
      this.color = this.contenido.nativeElement.innerText.includes('alerta') ? 'red' : 'black';
    }
  }
}
```
**Uso**
```html
<app-ajustador>
  <p #texto>Este texto contiene una alerta</p>
</app-ajustador>
```

## Consideraciones importantes
* **Evita operaciones costosas**, Como este hook se ejecuta frecuentemente (en cada ciclo de detección de cambios), evita realizar operaciones intensivas (e.g., cálculos complejos, solicitudes HTTP) para no afectar el rendimiento.

* **Diferencia con otros hooks**
  * `ngAfterContentInit`: Se llama una sola vez, cuando el contenido proyectado se inicializa por primera vez.

  * `ngAfterContentChecked`: Se llama cada vez que Angular verifica cambios en el contenido proyectado.

* **No modificar el DOM directamente**, Aunque puedes acceder al contenido proyectado, no debes modificar directamente el DOM dentro de este hook, ya que esto puede causar problemas de detección de cambios.

## Buenas prácticas
* **Usa `ngDoCheck` para lógica compleja**: Si necesitas una verificación personalizada más general, considera usar `ngDoCheck`.

* **Minimiza la lógica en este hook**: Realiza tareas simples, como validaciones o cambios menores en propiedades.

* **Combina con `@ContentChild` y `@ContentChildren`**: Utiliza estos decoradores para interactuar eficientemente con el contenido proyectado.
