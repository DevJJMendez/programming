# `resolvers`
Un resolver en Angular es una clase que implementa la interfaz Resolve y que se utiliza para obtener datos necesarios antes de que un componente sea cargado por una ruta. Funciona como un intermediario que resuelve y entrega la información necesaria para una vista específica, asegurando que los datos estén disponibles al momento de renderizar el componente asociado.

## ¿Para qué sirve un Resolver?
Los resolvers sirven para:

* Cargar datos previamente a la navegación: Garantizan que un componente no se muestre hasta que los datos requeridos estén disponibles.

* Evitar estados incompletos: Protegen al usuario de ver componentes sin datos cargados, evitando errores visuales o funcionales.

* Mantener la lógica de carga separada: Desacoplan la lógica de obtención de datos del componente, facilitando su mantenimiento.

* Optimizar la experiencia de usuario: Al cargar los datos antes de mostrar la vista, se evitan cargas progresivas que puedan interrumpir la experiencia.

## ¿Qué problema resuelve un Resolver?
* Evita la carga progresiva: Los resolvers permiten que todos los datos necesarios estén listos antes de que el componente se cargue. Esto elimina la necesidad de mostrar placeholders o loaders dentro del componente.

* Reduce la complejidad del componente: Mueve la lógica de obtención de datos fuera del componente, haciéndolo más simple y enfocado en la presentación.

* Centraliza el manejo de datos: Mantiene la lógica de carga asociada a la configuración de rutas, promoviendo la consistencia.

## ¿Cómo lo resuelve?
Un resolver intercepta la navegación hacia una ruta específica y realiza operaciones asíncronas (como una solicitud HTTP) para recuperar datos. El enrutador espera a que el resolver termine su tarea antes de cargar el componente.

**Flujo de trabajo típico:**
* El usuario intenta navegar hacia una ruta.

* Angular verifica si hay resolvers definidos en la configuración de la ruta.

* Si existen resolvers, estos se ejecutan y recuperan los datos.

* Cuando los datos están listos, el componente es cargado con la información proporcionada.

## Implementación de un Resolver en Angular
* **Creando un `Resolver`**, Un resolver es una clase que implementa la interfaz Resolve y sobreescribe el método resolve.
```ts
import { Injectable } from '@angular/core';
import { Resolve } from '@angular/router';
import { Observable } from 'rxjs';
import { ProductService } from './product.service';
import { Product } from './product.model';

@Injectable({
  providedIn: 'root'
})
export class ProductResolver implements Resolve<Product[]> {
  constructor(private productService: ProductService) {}

  resolve(): Observable<Product[]> {
    return this.productService.getAllProducts();
  }
}
```
En este ejemplo:
* El resolver llama al servicio `ProductService` para obtener una lista de productos antes de cargar el componente.

* **Asociando el Resolver a una Ruta**, En el archivo de configuración de rutas (`app-routing.module.ts`), se asocia el resolver a la ruta correspondiente.
```ts
import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { ProductListComponent } from './product-list/product-list.component';
import { ProductResolver } from './product.resolver';

const routes: Routes = [
  {
    path: 'products',
    component: ProductListComponent,
    resolve: { products: ProductResolver } // Asociar el resolver
  }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule]
})
export class AppRoutingModule {}
```
En esta configuración:
  * La ruta products está vinculada al componente `ProductListComponent`.

  * El resolver `ProductResolver` se ejecuta antes de cargar el componente y el resultado se almacena en la clave **`products`**.

* **Accediendo a los Datos en el Componente**, Los datos obtenidos por el resolver se acceden a través de `ActivatedRoute`.
```ts
import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';
import { Product } from '../product.model';

@Component({
  selector: 'app-product-list',
  template: `
    <ul>
      <li *ngFor="let product of products">{{ product.name }}</li>
    </ul>
  `
})
export class ProductListComponent implements OnInit {
  products: Product[] = [];

  constructor(private route: ActivatedRoute) {}

  ngOnInit(): void {
    this.products = this.route.snapshot.data['products']; // Acceder a los datos resueltos
  }
}
```

* **Manejo de Errores en un Resolver**, Un resolver puede manejar errores devolviendo un valor predeterminado o redirigiendo al usuario.

Ejemplo con valor predeterminado:
```ts
import { Resolve } from '@angular/router';
import { Observable, of } from 'rxjs';
import { catchError } from 'rxjs/operators';

@Injectable({
  providedIn: 'root'
})
export class ProductResolver implements Resolve<Product[]> {
  constructor(private productService: ProductService) {}

  resolve(): Observable<Product[]> {
    return this.productService.getAllProducts().pipe(
      catchError(() => {
        console.error('Error al cargar productos');
        return of([]); // Devolver un array vacío en caso de error
      })
    );
  }
}
```
Ejemplo con redirección:
```ts
resolve(): Observable<Product[]> {
  return this.productService.getAllProducts().pipe(
    catchError(() => {
      this.router.navigate(['/error']); // Redirigir a una página de error
      return of([]);
    })
  );
}
```

## Buenas Prácticas con Resolvers
* Usa resolvers para datos críticos: Carga únicamente la información esencial para el componente.

* Mantén la lógica de resolución clara: Evita incluir lógica compleja o procesamiento innecesario en el resolver.

* Evita bloquear la navegación: Maneja errores y devoluciones rápidas para no interrumpir al usuario.

* Optimiza el rendimiento: Si los datos ya están en caché o no son necesarios, considera evitarlos.
