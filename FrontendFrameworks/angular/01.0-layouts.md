# Layouts
El directorio layouts es una carpeta donde se definen y gestionan las estructuras principales o plantillas de diseño de la aplicación. Estas estructuras pueden incluir encabezados, pies de página, barras laterales, y espacios para el contenido dinámico.

Por ejemplo:

* Un diseño de panel administrativo con una barra lateral.

* Un diseño de página pública sin barra de navegación.

* Un diseño de autenticación exclusivo para login y registro.

## ¿Cuáles son las características del directorio layouts?
* **Centralización de diseños**: Define y organiza las plantillas de diseño de toda la aplicación.

* **Reutilización de estructura**: Permite reutilizar un diseño común en múltiples vistas sin duplicar código.

* **Integración dinámica**: Usa directivas como `<router-outlet>` para cargar contenido dinámico dentro de las plantillas.

* **Modularidad**: Cada diseño suele estar encapsulado en su propio componente, por ejemplo:
```plaintext
src/
 └── app/
      ├── layouts/
      │    ├── admin-layout/
      │    │    ├── admin-layout.component.ts
      │    │    ├── admin-layout.component.html
      │    │    └── admin-layout.component.scss
      │    ├── auth-layout/
      │    │    ├── auth-layout.component.ts
      │    │    ├── auth-layout.component.html
      │    │    └── auth-layout.component.scss
      │    ├── layouts.module.ts
```
* **Compatibilidad con rutas**: Los diseños suelen asociarse a rutas específicas para que Angular cargue automáticamente el diseño correcto según la URL.

* **Flexibilidad**: Se adapta fácilmente a las necesidades de diseño de la aplicación, desde estructuras simples hasta interfaces complejas.

## ¿Para qué sirve el directorio layouts?
El directorio layouts sirve para:

* Definir estructuras de página comunes para mantener consistencia en el diseño de la aplicación.

* Reducir duplicación de código al reutilizar componentes de diseño.

* Facilitar el mantenimiento al centralizar cambios en los diseños.

* Separar la lógica del diseño de la lógica funcional, siguiendo principios de separación de responsabilidades.

Ejemplo de uso práctico:

* Un diseño de autenticación para login, registro y recuperación de contraseñas.
* Un diseño administrativo para manejar el panel de control con una barra lateral.

## ¿Qué resuelve el directorio layouts?
* Duplicación de código: Evita repetir estructuras de diseño comunes en múltiples componentes o módulos.

* Desorganización del diseño: Centraliza los diseños en un solo lugar, facilitando la gestión.

* Falta de consistencia visual: Asegura que todas las vistas compartan la misma estructura según su propósito (por ejemplo, todas las páginas de administración tienen el mismo encabezado).

* Dificultad para escalar diseños: Permite agregar, modificar o eliminar diseños fácilmente sin afectar otras partes de la aplicación.

## ¿Cómo lo resuelve?
* Componentes especializados: Cada diseño se implementa como un componente único que encapsula su estructura.

* Uso de rutas anidadas: Define rutas que utilizan diferentes diseños según el módulo o la sección.

* Carga dinámica de contenido: Usa `<router-outlet>` en los diseños para insertar dinámicamente el contenido basado en la ruta activa.

* Configuración modular: Agrupa todos los diseños en un módulo específico (LayoutsModule), lo que facilita su importación y uso en otras partes de la aplicación.

## ¿Qué NO es un layouts?
* No es un lugar para lógica funcional: Los layouts solo deben manejar la estructura visual y elementos de diseño.

* No es un lugar para componentes reutilizables genéricos: Esos elementos deben ir al directorio shared.

* No es un lugar para manejar datos o servicios: La lógica de negocio debe residir en servicios o componentes específicos de las funcionalidades.

## Ejemplo de implementación de un diseño con layouts
1. Crear el directorio layouts: Organiza los diseños en subdirectorios según el propósito:
```plaintext
src/
 └── app/
      ├── layouts/
           ├── admin-layout/
           ├── auth-layout/
           └── public-layout/
```

2. Implementar un diseño básico (`AdminLayout`): Archivo: `admin-layout.component.html`
```html
<div class="admin-container">
  <app-sidebar></app-sidebar>
  <div class="main-content">
    <app-header></app-header>
    <router-outlet></router-outlet>
    <app-footer></app-footer>
  </div>
</div>
```

3. Asociar el diseño a rutas: Archivo: `app-routing.module.ts`
```ts
const routes: Routes = [
  {
    path: 'admin',
    component: AdminLayoutComponent,
    children: [
      { path: 'dashboard', loadChildren: () => import('./dashboard/dashboard.module').then(m => m.DashboardModule) },
      { path: 'settings', loadChildren: () => import('./settings/settings.module').then(m => m.SettingsModule) },
    ],
  },
  {
    path: 'auth',
    component: AuthLayoutComponent,
    children: [
      { path: 'login', loadChildren: () => import('./auth/login/login.module').then(m => m.LoginModule) },
      { path: 'register', loadChildren: () => import('./auth/register/register.module').then(m => m.RegisterModule) },
    ],
  },
];
```
