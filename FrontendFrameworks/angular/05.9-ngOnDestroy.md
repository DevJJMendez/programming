# `ngOnDestroy`
`ngOnDestroy` es un hook del ciclo de vida en Angular que se ejecuta justo antes de que un componente, directiva o servicio sea destruido por Angular.

Este método forma parte de la interfaz `OnDestroy`, que se puede implementar en clases para ejecutar lógica de limpieza necesaria al destruir el objeto.

## ¿Para qué sirve?
El hook ngOnDestroy sirve para realizar tareas de limpieza y liberación de recursos cuando un componente o directiva está a punto de ser eliminado del DOM o su contexto de ejecución.

**Tareas comunes que se realizan en `ngOnDestroy`:**
* Desuscribirse de Observables para prevenir fugas de memoria.

* Limpiar **`event listeners`**.

* Cancelar temporizadores (e.g., `setInterval`, `setTimeout`).

* Liberar recursos compartidos o servicios específicos.

* Eliminar referencias a objetos globales (e.g., `window`, `document`).

## ¿Qué resuelve?
Resuelve problemas relacionados con:

* **Fugas de memoria**: Ocurren si no se liberan correctamente suscripciones, manejadores de eventos o recursos compartidos.

* **Eventos no deseados**: Pueden producirse si quedan listeners activos después de que el componente haya sido destruido.

* **Eficiencia del sistema**: Asegura que no queden procesos o recursos consumiendo memoria o CPU innecesariamente.

## ¿Cómo lo resuelve?
Angular invoca automáticamente el hook `ngOnDestroy` justo antes de eliminar un componente o directiva del DOM o destruir su instancia. Esto proporciona un punto de entrada para ejecutar la lógica de limpieza.

El desarrollador define qué recursos liberar o tareas realizar en el método `ngOnDestroy`, lo que asegura que:

* Se liberen recursos ocupados por el componente.

* Se eviten suscripciones activas o procesos innecesarios.

* No ocurran comportamientos inesperados debido a referencias "zombies".

## Sintaxis
Para usar `ngOnDestroy`, debes implementar la interfaz `OnDestroy` y definir el método en tu componente o directiva.
```ts
import { Component, OnDestroy } from '@angular/core';

@Component({
  selector: 'app-ejemplo',
  template: `<p>Ejemplo de ngOnDestroy</p>`,
})
export class EjemploComponent implements OnDestroy {
  ngOnDestroy(): void {
    console.log('El componente ha sido destruido.');
  }
}
```

## Casos de uso comunes
* **Desuscripción de `Observables`**, Si un componente tiene suscripciones a Observables, es importante desuscribirse para evitar que continúen ejecutándose.
```ts
import { Component, OnDestroy } from '@angular/core';
import { Subscription, interval } from 'rxjs';

@Component({
  selector: 'app-observable',
  template: `<p>Componente con Observable</p>`,
})
export class ObservableComponent implements OnDestroy {
  private subscription!: Subscription;

  constructor() {
    this.subscription = interval(1000).subscribe(value => {
      console.log(`Valor emitido: ${value}`);
    });
  }

  ngOnDestroy(): void {
    console.log('Desuscribiendo el Observable...');
    this.subscription.unsubscribe();
  }
}
```

* **Limpiar `Event Listeners`**, Si un componente utiliza `listeners` añadidos manualmente, deben eliminarse en `ngOnDestroy`.
```ts
import { Component, OnDestroy, HostListener } from '@angular/core';

@Component({
  selector: 'app-listener',
  template: `<p>Componente con listener</p>`,
})
export class ListenerComponent implements OnDestroy {
  private clickListener!: () => void;

  constructor() {
    this.clickListener = () => console.log('Click detectado!');
    window.addEventListener('click', this.clickListener);
  }

  ngOnDestroy(): void {
    console.log('Eliminando listener de click...');
    window.removeEventListener('click', this.clickListener);
  }
}
```

* **Cancelar Temporizadores**, Si un componente inicia temporizadores (e.g., `setTimeout`, `setInterval`), deben limpiarse para evitar procesos innecesarios.
```ts
import { Component, OnDestroy } from '@angular/core';

@Component({
  selector: 'app-temporizador',
  template: `<p>Componente con temporizador</p>`,
})
export class TemporizadorComponent implements OnDestroy {
  private intervalId!: any;

  constructor() {
    this.intervalId = setInterval(() => {
      console.log('Ejecutando intervalo...');
    }, 1000);
  }

  ngOnDestroy(): void {
    console.log('Limpiando intervalo...');
    clearInterval(this.intervalId);
  }
}
```

* **Liberar Recursos Globales**, Si un componente interactúa con elementos globales como `document` o `window`, debe limpiar esas referencias.
```ts
import { Component, OnDestroy, Renderer2 } from '@angular/core';

@Component({
  selector: 'app-global',
  template: `<p>Componente con referencia global</p>`,
})
export class GlobalComponent implements OnDestroy {
  private listener!: () => void;

  constructor(private renderer: Renderer2) {
    this.listener = this.renderer.listen('window', 'resize', () => {
      console.log('Ventana redimensionada.');
    });
  }

  ngOnDestroy(): void {
    console.log('Eliminando listener de resize...');
    this.listener();
  }
}
```

## Buenas prácticas
* **Desuscríbete siempre de los `Observables`**: Usa un patrón como `takeUntil` o una variable de tipo `Subject` para automatizar desuscripciones.

* **Elimina temporizadores y listeners manuales**: Siempre limpia temporizadores, listeners y referencias globales.

* **Evita lógica pesada**: `ngOnDestroy` debería centrarse solo en tareas de limpieza, evitando lógica compleja que pueda bloquear el proceso de destrucción.

* **Usa herramientas automatizadas**: Librerías como **`rxjs-operators`** (e.g., `takeUntil`) pueden simplificar la gestión de suscripciones.
