# Child Routes
Las child routes (rutas hijas) en Angular son rutas anidadas dentro de una ruta principal (o padre). Permiten definir jerarquías de navegación y estructurar la aplicación en módulos o secciones más pequeñas y organizadas.

## ¿Para qué sirve?
Las child routes se utilizan para:

* Crear rutas anidadas: Cuando una sección tiene varias subsecciones, como un panel administrativo con configuraciones y estadísticas.

* Organizar la navegación: Mantener el código más limpio y modular al separar la configuración de rutas hijas de las rutas principales.

* Reutilizar componentes: Utilizar un diseño de componentes que se adapten a contextos diferentes dependiendo de la ruta hija activa.

## ¿Qué resuelve?
Las child routes resuelven problemas como:

* Navegación jerárquica: Facilitan la creación de aplicaciones con subpáginas relacionadas.

* Modularidad: Ayudan a dividir la configuración de rutas en múltiples niveles, lo que simplifica el mantenimiento y escalabilidad del código.

* Rutas específicas: Permiten cargar componentes diferentes dependiendo de la ruta hija seleccionada, mejorando la personalización.

## ¿Cómo lo resuelve?
Angular resuelve la navegación jerárquica mediante el uso de la propiedad **`children`** en la configuración de rutas. Cada ruta padre puede tener una lista de rutas hijas que se cargarán dependiendo de la navegación del usuario.

## Ejemplo Básico
**Estructura de Rutas**

Supongamos una aplicación con una sección de "**`Administración`**" que tiene dos subsecciones: "**`Usuarios`**" y "**`Configuraciones`**".
```ts
const routes: Routes = [
  {
    path: 'admin',
    component: AdminComponent, // Componente contenedor
    children: [
      { path: 'users', component: UsersComponent },
      { path: 'settings', component: SettingsComponent },
    ],
  },
];
```
Configuración en el módulo de enrutamiento
```ts
@NgModule({
  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule],
})
export class AppRoutingModule {}
```
### Visualización en la Aplicación
El componente `AdminComponent` tendrá un `<router-outlet>` para mostrar los componentes correspondientes a las rutas hijas.

**`AdminComponent`**
```ts
<h1>Panel Administrativo</h1>
<nav>
  <a routerLink="users">Usuarios</a>
</nav>
<router-outlet></router-outlet>
```
Cuando el usuario navegue a `/admin/users`, el componente `UsersComponent` se cargará dentro del `<router-outlet>` del `AdminComponent`. Similarmente, para `/admin/settings`.

## Parámetros en Rutas Hijas
Las rutas hijas también pueden manejar parámetros, tanto params como queryParams.

Configuración con Parámetros
```ts
const routes: Routes = [
  {
    path: 'admin',
    component: AdminComponent,
    children: [
      { path: 'users/:id', component: UserDetailComponent }, // Parámetro dinámico
    ],
  },
];
```
Uso en un Componente Hijo
```ts
export class UserDetailComponent implements OnInit {
  userId: string | null = null;

  constructor(private route: ActivatedRoute) {}

  ngOnInit(): void {
    this.userId = this.route.snapshot.paramMap.get('id');
  }
}
```
Si el usuario navega a `/admin/users/123`, el valor **123** será capturado por el `UserDetailComponent`.

## Carga Diferida (Lazy Loading) con Child Routes
Para aplicaciones grandes, se pueden combinar rutas hijas con la carga diferida para optimizar el rendimiento.

Configuración
```ts
const routes: Routes = [
  {
    path: 'admin',
    loadChildren: () =>
      import('./admin/admin.module').then((m) => m.AdminModule), // Módulo cargado diferido
  },
];
```
En el módulo cargado (e.g., `AdminModule`):
```ts
const adminRoutes: Routes = [
  {
    path: '',
    component: AdminComponent,
    children: [
      { path: 'users', component: UsersComponent },
      { path: 'settings', component: SettingsComponent },
    ],
  },
];
```

## Buenas Prácticas
* Utiliza jerarquías claras: Define rutas hijas únicamente cuando sea necesario, para evitar una estructura de navegación compleja.

* Agrupa rutas relacionadas: Mantén las rutas hijas relacionadas en un mismo módulo o archivo para facilitar el mantenimiento.

* Incluye guards si es necesario: Protege rutas específicas con CanActivate o CanActivateChild.

* Usa carga diferida: Para módulos grandes con muchas rutas hijas, implementa lazy loading.
