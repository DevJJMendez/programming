# Observer
En el contexto de la programación reactiva y el uso de RxJS (Reactive Extensions for JavaScript), un Observer es un objeto que define cómo reaccionar a las notificaciones de un Observable. Es el receptor de los datos emitidos por el Observable, y puede manejar tres tipos de notificaciones:

* **`next`**: Notificación de un nuevo valor emitido por el Observable.

* **`error`**: Notificación de que ocurrió un error durante el flujo de datos.

* **`complete`**: Notificación de que el flujo de datos ha finalizado correctamente.

## ¿Para qué sirve un Observer?
* Consumir datos emitidos por un Observable.

* Definir comportamientos específicos para manejar valores, errores y la finalización del flujo.

* Implementar la lógica reactiva en aplicaciones, permitiendo que los componentes reaccionen a cambios o eventos de manera asíncrona.

## ¿Qué resuelve un Observer?
* Manejo de flujos de datos asíncronos: Permite reaccionar a valores emitidos en diferentes momentos, como eventos del usuario, datos de una API o temporizadores.

* Gestión centralizada de errores: Simplifica el manejo de excepciones en flujos asíncronos.

* Limpieza y finalización controlada: Ayuda a liberar recursos al definir comportamientos en la fase de complete.

## ¿Cómo lo resuelve?
Un Observer resuelve estos problemas interactuando con un Observable de la siguiente manera:

* Definiendo las funciones de manejo de cada tipo de notificación (next, error, complete).

* Suscribiéndose al Observable mediante el método subscribe: Esto conecta el Observer con el Observable para recibir emisiones.

## Estructura de un Observer
Un Observer es simplemente un objeto con tres métodos opcionales:

* **`next(value: any): void`** Se ejecuta cuando el Observable emite un valor.

* **`error(err: any): void`** Se ejecuta cuando el Observable emite un error y detiene el flujo.

* **`complete(): void`** Se ejecuta cuando el Observable finaliza correctamente.

## Ejemplo básico de Observer
```ts
const observer = {
  next: (value: any) => console.log('Valor emitido:', value),
  
  error: (err: any) => console.error('Error:', err),
  
  complete: () => console.log('Flujo completado'),
};
```
```ts
import { Observable } from 'rxjs';

const observable = new Observable(observer => {
  observer.next('Primer valor'); // Emite un valor
  observer.next('Segundo valor');
  observer.complete(); // Finaliza el flujo
});

observable.subscribe({
  next: value => console.log(value),
  error: err => console.error(err),
  complete: () => console.log('Flujo completado'),
});
```

## Tipos de notificaciones manejadas por un Observer
1. **`next`**:
   * Representa un valor que el Observable emite.

  * Puede haber múltiples emisiones de next.
```ts
observer.next('Hola');
observer.next('Mundo');
```

2. **`error`**:
   * Se ejecuta cuando ocurre un error en el Observable.

   * El flujo se detiene inmediatamente.
```ts
observer.error('Ocurrió un error');
```

3. **`complete`**:
   * Se ejecuta cuando el Observable ha terminado de emitir valores.

   * Indica que no habrá más emisiones ni errores.
```ts
observer.complete();
```

## Uso práctico en Angular
En Angular, los Observers se utilizan comúnmente en servicios, componentes y directivas para manejar flujos de datos asíncronos.

1. Manejo de datos de servicios HTTP: Un Observer puede manejar las respuestas de peticiones HTTP realizadas con [HttpClient](010-HTTPMODULE.md).
```ts
import { HttpClient } from '@angular/common/http';
import { Component } from '@angular/core';

@Component({
  selector: 'app-example',
  template: `<p>{{ data }}</p>`,
})
export class ExampleComponent {
  data: string | undefined;

  constructor(private http: HttpClient) {
    this.http.get('https://api.example.com/data').subscribe({
      next: (response: any) => (this.data = response),
      error: err => console.error('Error:', err),
      complete: () => console.log('Petición completada'),
    });
  }
}
```

2. Uso con AsyncPipe: En lugar de manejar manualmente las suscripciones, Angular ofrece el AsyncPipe, que gestiona automáticamente las suscripciones.
```html
<div *ngIf="data$ | async as data">
  {{ data }}
</div>
```

3. Desuscribirse cuando sea necesario: Usar el método unsubscribe o patrones como takeUntil para limpiar observables.

4. Evitar lógica compleja en Observers: Delegar la lógica pesada a operadores de transformación (como map, filter, etc.) antes de la suscripción.
