# Component
Los Components (componentes) son la unidad fundamental de las aplicaciones Angular. Cada componente representa una parte específica de la interfaz de usuario (UI) y controla un fragmento del DOM, manejando tanto la lógica como la visualización.

## ¿Qué es un componente en Angular?
Un componente en Angular es una clase TypeScript que está asociada a una plantilla **HTML** y un conjunto de estilos **CSS**. Los componentes son responsables de la visualización y el comportamiento de una parte específica de la aplicación.

## Estructura básica de un componente
Cada componente Angular está compuesto por los siguientes elementos principales:

* **Decorador `@Component`**: Es un decorador que convierte una clase TypeScript en un componente Angular. Este decorador incluye metadatos como la plantilla HTML, los estilos, el selector, etc.

* **Clase del componente**: Contiene la lógica del componente. Es donde se definen las propiedades y métodos que la plantilla puede usar.

* **Plantilla HTML (template)**: Es el HTML que define la estructura de la vista del componente.

* **Estilos (styles o styleUrls)**: Son los estilos CSS o SCSS específicos del componente.

## Ejemplo básico
```ts
// app.component.ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-root', // Selector CSS que identifica este componente en un template
  
  templateUrl: './app.component.html', // Ruta al archivo HTML del componente
  
  styleUrls: ['./app.component.css'] // Ruta a los archivos de estilo del componente
})

export class AppComponent {
  title = 'Mi Proyecto Angular';

  constructor() {}

  // Método del componente
  sayHello() {
    console.log('¡Hola desde el componente!');
  }
}
```
```html
<!-- app.component.html -->
<div>
  <h1>{{ title }}</h1>  <!-- Interpolación para mostrar la propiedad 'title' -->
  <button (click)="sayHello()">Click me</button> <!-- Vinculación de evento -->
</div>
```
```css
/* app.component.css */
h1 {
  color: blue;
}
```
### Explicación de los elementos clave:
1. **selector**: Define cómo se invoca este componente en la plantilla de otro componente. En este caso, `<app-root></app-root>` sería la forma de incluir este componente en otra parte de la aplicación.

2. **templateUrl y template**: Se puede usar **templateUrl** para referenciar un archivo HTML separado, o template para escribir el HTML directamente en el decorador (útil para componentes muy pequeños).

* **styleUrls y styles**: Similar al template, styleUrls se usa para referenciar archivos CSS externos, mientras que styles permite definir estilos en línea.

* **Clase `AppComponent`**: La clase contiene propiedades y métodos que definen el comportamiento del componente. Angular enlaza automáticamente la lógica de la clase con la vista (template).

## Características de un componente en Angular
1. **Encapsulación**: Cada componente tiene su propio contexto, lo que permite que los estilos y la lógica estén aislados.

   * Angular utiliza la propiedad `ViewEncapsulation` para manejar esta encapsulación.

2. **Reutilización**: Los componentes pueden ser reutilizados en diferentes partes de la aplicación.

3. **Comunicación**:
   * De entrada: Usa `@Input` para recibir datos de un componente padre.

   * De salida: Usa `@Output` para enviar eventos o datos al padre.

4. **Ciclo de vida**: Los componentes tienen métodos de ciclo de vida como:
   * `ngOnInit`: Se ejecuta al inicializar el componente.

   * `ngOnDestroy`: Se ejecuta antes de destruir el componente.

5. **Selector**: Cada componente tiene un selector único que actúa como etiqueta personalizada en el HTML.

## ¿Para qué sirven los componentes?
* División de la UI: Dividen la interfaz de usuario en partes manejables y reutilizables.

* Modularidad: Facilitan la separación de responsabilidades y la escalabilidad del código.

* Reutilización: Se pueden usar en múltiples lugares, ahorrando esfuerzo y reduciendo duplicación.

* Mantenimiento: Al separar la lógica y la vista por componentes, el código es más legible y fácil de mantener.

## ¿Qué problemas resuelven?
* Complejidad de la UI: Sin componentes, gestionar una aplicación con una interfaz rica y dinámica sería caótico.

* Reutilización del código: Permiten evitar la duplicación de elementos similares en la UI.

* Escalabilidad: Organizan el código en partes pequeñas, permitiendo agregar nuevas funcionalidades sin romper la aplicación.

## ¿Cómo resuelven estos problemas?
* Encapsulación de lógica y vista: Cada componente maneja su propio comportamiento y visualización, haciendo que las partes sean independientes.

* Comunicación clara: Mediante @Input y @Output, se establece cómo los componentes interactúan entre sí.

* Directivas y Data Binding: Angular permite manipular el DOM y enlazar datos dinámicamente, haciendo que los componentes sean flexibles.

# `@Component`
El decorador `@Component` es una función en Angular que marca una clase como un componente y proporciona metadatos esenciales para configurarlo. Es parte del núcleo del framework y pertenece al paquete `@angular/core`.

En términos simples, @Component actúa como una "declaración" que le indica a Angular:
* Qué selector usará para identificar este componente en el DOM.

* Qué template HTML define su vista.

* Qué estilos CSS/SCSS se aplican a este componente.

* Cómo se comportará el componente durante su ciclo de vida.

Ejemplo
```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-hello-world',
  templateUrl: './hello-world.component.html',
  styleUrls: ['./hello-world.component.css']
})
export class HelloWorldComponent {
  message = '¡Hola Mundo!';
}
```

## Características del decorador @Component
1. **Es configurable**: Permite personalizar cómo se comportará el componente mediante propiedades clave, como:
   * selector

   * template o templateUrl

   * styles o styleUrls

   * encapsulation

   * changeDetection

* **Enlaza la clase con su vista**: Asocia la clase TypeScript con su template HTML y estilos.

* Es reutilizable: Un componente decorado con `@Component` puede ser llamado en cualquier parte de la aplicación usando su selector.

* Admite directivas y bindings: Facilita el uso de directivas, interpolación de datos y binding de eventos dentro del template.
