# `queryParams`
Los Query Params (parámetros de consulta) son valores adicionales que se anexan a una URL después del signo `?`. Se utilizan para transmitir datos opcionales a través de una URL en formato **clave-valor**.

Por ejemplo
```bash
https://example.com/products?category=electronics&sort=price
```
En esta URL:
  * `category=electronics` y `sort=price` son Query Params.

En Angular, los Query Params son gestionados por el módulo de enrutamiento, lo que permite que estos parámetros sean utilizados para controlar el comportamiento de una página o pasar información opcional.

## ¿Para qué sirven?
* Pasar datos opcionales entre rutas: Por ejemplo, filtrar o ordenar una lista de productos.

* Configurar el estado de la aplicación: Como seleccionar pestañas, cambiar vistas o mantener preferencias de usuario.

* Crear URLs compartibles: Permite generar enlaces que otros usuarios pueden usar para acceder a un estado específico de la aplicación.

* Compatibilidad con estándares web: Los Query Params son ampliamente soportados por navegadores y herramientas externas.

## ¿Qué resuelven?
* Transmisión de datos sin modificar la estructura de la ruta: En lugar de modificar dinámicamente la ruta principal, los Query Params permiten añadir datos a la URL sin afectar la navegación base.

* Facilidad para compartir estados: Al incluir datos opcionales en la URL, puedes compartir un enlace que preserve el estado de la página.

* Evitar estados almacenados en memoria: Permite evitar el uso de servicios o almacenamiento local para datos temporales, ya que los datos están presentes en la URL.

## ¿Cómo lo resuelven?
Angular facilita el uso de Query Params con:

* Navegación programática: Usa el servicio Router para añadir o modificar Query Params.

* Captura de parámetros desde la URL: Utiliza ActivatedRoute para acceder a los parámetros actuales.

* Sincronización automática: Al usar RouterLink, Angular permite construir URLs con Query Params de forma declarativa.

## Uso básico de Query Params en Angular
* **Definiendo Query Params en una URL**, No necesitas modificar tus rutas para aceptar Query Params. Son aceptados automáticamente por cualquier ruta.

Ejemplo de URL con Query Params:
```bash
https://example.com/products?category=books&page=2
```

* **Navegación declarativa con RouterLink**, Usa RouterLink para navegar con Query Params desde el HTML.
```html
<a [routerLink]="['/products']" [queryParams]="{ category: 'books', page: 2 }">
  View Books
</a>
```
Este enlace generará una URL como:
```bash
https://example.com/products?category=books&page=2
```

* **Navegación programática con Router**, Usa el método navigate del servicio Router para añadir Query Params desde el código TypeScript.
```ts
import { Component } from '@angular/core';
import { Router } from '@angular/router';

@Component({
  selector: 'app-products',
  template: `<button (click)="filterByCategory('electronics')">Filter Electronics</button>`
})
export class ProductsComponent {
  constructor(private router: Router) {}

  filterByCategory(category: string): void {
    this.router.navigate(['/products'], { queryParams: { category } });
  }
}
```

### Acceso a Query Params con `ActivatedRoute`
El servicio ActivatedRoute permite leer los Query Params de la URL actual.
```ts
import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';

@Component({
  selector: 'app-products',
  template: `<p>Selected Category: {{ category }}</p>`
})
export class ProductsComponent implements OnInit {
  category: string | null = null;

  constructor(private route: ActivatedRoute) {}

  ngOnInit(): void {
    this.route.queryParams.subscribe(params => {
      this.category = params['category'] || 'All';
    });
  }
}
```

* **Actualización de Query Params sin recargar la página**, Para cambiar Query Params sin recargar toda la página, usa la opción `queryParamsHandling`.
```ts
this.router.navigate([], { 
  relativeTo: this.route,
  queryParams: { page: 2 },
  queryParamsHandling: 'merge' // Mantiene los parámetros existentes y agrega los nuevos
});
```
Opciones para queryParamsHandling:
  * merge: Combina los nuevos Query Params con los existentes.

  * preserve: Mantiene los Query Params existentes y no agrega nuevos.

## Buenas prácticas al usar Query Params
* Evita datos sensibles: Los Query Params son visibles y pueden ser manipulados fácilmente por el usuario.

* Usa Query Params para datos temporales u opcionales: No uses Query Params para datos obligatorios. En su lugar, usa parámetros de ruta.

* Manejo de valores por defecto: Siempre define valores por defecto si los Query Params no están presentes.

* Validación de parámetros: Asegúrate de validar y sanitizar los valores recibidos desde los Query Params para evitar errores.
