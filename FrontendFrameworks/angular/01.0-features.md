# Features
El directorio features es una carpeta que agrupa los módulos y componentes relacionados con funcionalidades específicas de la aplicación. En un diseño modular, cada feature se encapsula en un módulo independiente.

Estructura típica del directorio features:
```plaintext
src/
 └── app/
     ├── features/
     │    ├── auth/
     │    │    ├── auth.module.ts
     │    │    ├── login/
     │    │    │    ├── login.component.ts
     │    │    │    ├── login.component.html
     │    │    │    └── login.component.scss
     │    │    ├── register/
     │    │         ├── register.component.ts
     │    │         ├── register.component.html
     │    │         └── register.component.scss
     │    ├── products/
     │    │    ├── products.module.ts
     │    │    ├── product-list/
     │    │    ├── product-detail/
     │    └── ...
```

## ¿Cuáles son las características del directorio features?
* Encapsulación por funcionalidad: Cada carpeta en features representa una funcionalidad independiente de la aplicación, organizada como un módulo Angular.

* Modularidad: Cada módulo es autónomo y puede importar otros recursos (como componentes, servicios o pipes) solo si los necesita.

* Reutilización controlada: Los módulos de features están diseñados para ser usados en su contexto específico y no como elementos reutilizables genéricos (a diferencia de shared).

* Escalabilidad: Facilita el crecimiento de la aplicación al permitir agregar nuevas funcionalidades sin afectar las existentes.

* Lazy Loading: Los módulos de features son ideales para implementar lazy loading, mejorando el rendimiento al cargar solo las funcionalidades necesarias.

## ¿Qué NO es un features?
* No es una carpeta para recursos compartidos: Recursos genéricos que pueden usarse en múltiples lugares, como pipes o componentes reutilizables, deben estar en shared, no en features.

* No es una carpeta desorganizada: No debe ser un lugar donde se agrupe código arbitrariamente. Cada subcarpeta en features debe tener una funcionalidad clara.

* No es una carpeta monolítica: Aunque encapsula funcionalidades, cada módulo debe mantenerse modular y evitar depender innecesariamente de otros.

## ¿Para qué sirve el directorio features?
* Organización lógica: Agrupa funcionalidades específicas de forma que sea más fácil entender y mantener la estructura del proyecto.
 
* Separación de responsabilidades: Facilita que cada parte de la aplicación sea independiente y autónoma, alineándose con principios de diseño como SOLID.
 
* Facilitar la carga diferida: Al dividir funcionalidades en módulos, permite implementar lazy loading, cargando funcionalidades solo cuando se necesitan.
 
* Escalabilidad del proyecto: Una estructura modular permite agregar o modificar funcionalidades sin afectar otras partes de la aplicación.
