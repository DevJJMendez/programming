# `ngOnInit`
Es un hook (método de ciclo de vida) de Angular que pertenece a la interfaz `OnInit`. Se ejecuta una vez después de que Angular haya inicializado todas las propiedades de entrada `@Input()` vinculadas a un componente o directiva.

Es el lugar ideal para inicializar lógica o datos en un componente después de haber recibido todos los valores necesarios.

## ¿Para qué sirve?
ngOnInit sirve para:

* Inicializar datos o configuraciones necesarias para el componente.

* **Ejecutar lógica que depende de las propiedades de entrada**: Garantiza que las propiedades de entrada hayan sido inicializadas antes de usarlas.

* **Realizar suscripciones o invocar servicios**: Es el lugar para realizar llamadas a servicios externos o suscribirse a datos observables.

## ¿Qué resuelve?
ngOnInit resuelve los siguientes problemas:

* **Desincronización de inicialización**: Garantiza que todas las propiedades decoradas con @Input() estén listas antes de ejecutar la lógica del componente.

* **Separación de lógica de inicialización del constructor**: Permite mantener el constructor limpio y enfocado en inyecciones de dependencias.

* **Inicio controlado del componente**: Centraliza la inicialización para facilitar el mantenimiento y la escalabilidad del código.

## ¿Cómo lo resuelve?
* Angular llama automáticamente al método `ngOnInit` después de que el componente o directiva es instanciado y sus propiedades de entrada están configuradas.

* Se utiliza la interfaz `OnInit`, **que es opcional pero recomendada**, ya que ayuda a documentar claramente que el hook está implementado.

## Implementación
1. **Interfaz `OnInit`**: Angular proporciona una interfaz llamada `OnInit` para declarar y documentar el uso del método `ngOnInit`.

```ts
import { Component, OnInit } from '@angular/core';

@Component({
  selector: 'app-example',
  template: `<p>Componente inicializado</p>`,
})
export class ExampleComponent implements OnInit {
  ngOnInit(): void {
    console.log('ngOnInit ejecutado');
  }
}
```
Aunque no es obligatorio implementar la interfaz, es una buena práctica, ya que hace explícito que el componente utiliza el hook.

## Casos de uso
1. **Inicialización de datos**, Cargar datos necesarios para el componente:

```ts
ngOnInit(): void {
  this.loadData();
}

private loadData(): void {
  console.log('Datos cargados');
}
```

2. **Llamadas a servicios**, Realizar peticiones HTTP para inicializar datos:

```ts
import { HttpClient } from '@angular/common/http';

export class ExampleComponent implements OnInit {
  data: any;

  constructor(private http: HttpClient) {}

  ngOnInit(): void {
    this.http.get('https://api.example.com/data').subscribe((response) => {
      this.data = response;
    });
  }
}
```

3. **Configuración inicial basada en propiedades de entrada**, Usar valores de entrada para configurar el estado del componente:

```ts
@Input() isActive!: boolean;

ngOnInit(): void {
  if (this.isActive) {
    console.log('El componente está activo');
  } else {
    console.log('El componente está inactivo');
  }
}
```

4. **Suscripción a `Observables`**, Iniciar la suscripción a un observable que provea datos:

```ts
import { Observable } from 'rxjs';

export class ExampleComponent implements OnInit {
  @Input() dataStream!: Observable<any>;

  ngOnInit(): void {
    this.dataStream.subscribe((data) => {
      console.log('Datos recibidos:', data);
    });
  }
}
```

## Limitaciones
* **No se ejecuta en cada cambio de entrada**: Solo se ejecuta una vez durante la inicialización del componente. Para manejar cambios posteriores, debes usar `ngOnChanges`.

* **No sustituye a `ngOnChanges`**: Si necesitas reaccionar cada vez que una propiedad `@Input()` cambia, debes implementar `ngOnChanges`.

## 1. **Mantén la Lógica Separada**: Para mejorar la legibilidad y el mantenimiento, evita colocar demasiada lógica directamente en **ngOnInit**. En su lugar, delega tareas a métodos privados o servicios externos.

    ```ts
    ngOnInit(): void {
      this.setupData();
      this.subscribeToEvents();
    }

    private setupData(): void {
      // Lógica para inicializar datos
    }

    private subscribeToEvents(): void {
      // Lógica para suscripciones
    }
    ```

2. **Evita la Inicialización en el Constructor**: La lógica de inicialización, especialmente la que depende de propiedades `@Input`, debería estar en **`ngOnInit`** y no en el constructor. Esto garantiza que todos los datos necesarios estén disponibles cuando se ejecuta la lógica.

3. **Gestión de Subscripciones**: Si realizas suscripciones en `ngOnInit`, asegúrate de gestionarlas correctamente, por ejemplo, limpiándolas en el hook **`ngOnDestroy`** para evitar fugas de memoria.

    ```ts
    private subscription: Subscription;

    ngOnInit(): void {
      this.subscription = this.someService.getData().subscribe(data => {
        this.data = data;
      });
    }

    ngOnDestroy(): void {
      this.subscription.unsubscribe();
    }
    ```

4. **Carga de Datos Asíncrona**: **ngOnInit** es el lugar ideal para realizar llamadas a servicios asíncronos para cargar datos que el componente necesita al ser renderizado.

    ```ts
    ngOnInit(): void {
      this.loadData();
    }

    private loadData(): void {
      this.dataService.getData().subscribe(data => {
        this.data = data;
      });
    }
    ```

5. **Inicialización Solo una Vez**: A diferencia de **`ngOnChanges`**, que puede ejecutarse múltiples veces, **`ngOnInit`** se ejecuta una sola vez cuando se inicializa el componente. Úsalo para lógica que solo necesita ejecutarse una vez durante la vida del componente.
