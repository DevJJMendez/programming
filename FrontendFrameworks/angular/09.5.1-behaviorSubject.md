# `BehaviorSubject`
Un BehaviorSubject es una extensión del Subject en RxJS que:

* Mantiene un estado actual y lo emite inmediatamente a cualquier suscriptor nuevo.

* Requiere un valor inicial cuando se crea, y siempre tiene un valor actual disponible.

A diferencia de un Subject "básico", que no almacena ningún estado, un BehaviorSubject recuerda el último valor emitido y lo proporciona a los nuevos suscriptores inmediatamente después de suscribirse.

```ts
import { BehaviorSubject } from 'rxjs';

const behaviorSubject = new BehaviorSubject<number>(0); // Valor inicial

behaviorSubject.subscribe(value => console.log('Subscriber 1:', value));

behaviorSubject.next(1); // Cambia el estado actual a 1

behaviorSubject.subscribe(value => console.log('Subscriber 2:', value)); // Obtiene el valor actual (1)

behaviorSubject.next(2); // Ambos suscriptores reciben el valor 2
```
salida
```bash
Subscriber 1: 0
Subscriber 1: 1
Subscriber 2: 1
Subscriber 1: 2
Subscriber 2: 2
```

## ¿Para qué sirve?
El BehaviorSubject se utiliza cuando necesitas:

* Mantener y compartir un estado: Mantener un valor actual accesible y emitirlo a nuevos suscriptores automáticamente.

* Iniciar con un valor predeterminado: A diferencia de otros Subjects, siempre debe tener un valor inicial y garantiza que todos los suscriptores reciban algo incluso si se suscriben tarde.

* Crear flujos de datos reactivos que dependan del estado más reciente: Ideal para sistemas donde los datos cambian dinámicamente y varios componentes dependen de ellos.

## ¿Qué resuelve?
* Acceso inmediato al estado actual: Los nuevos suscriptores pueden obtener inmediatamente el valor más reciente sin esperar a que se emita un nuevo dato.

* Problemas con suscriptores tardíos en Subjects normales: En un Subject básico, los suscriptores que llegan tarde no reciben valores anteriores; en un BehaviorSubject sí.

* Centralizar estados dinámicos en aplicaciones reactivas: Ideal para patrones como el State Management, donde múltiples componentes necesitan acceder y reaccionar a un estado compartido.

## ¿Cómo lo resuelve?
* Almacena internamente un valor actual: Cada vez que se emite un valor con next(), el BehaviorSubject actualiza este valor.

* Emite automáticamente el último valor: Si un nuevo suscriptor se conecta, el BehaviorSubject inmediatamente emite su valor actual antes de esperar nuevos valores.

* Proporciona un valor inicial obligatorio: Esto garantiza que siempre haya un valor accesible, incluso si no se han emitido datos adicionales.

## Casos de uso
Gestión de estado compartido en Angular: BehaviorSubject es una excelente opción para servicios que manejan estados globales, como datos del usuario autenticado, configuraciones o estados de UI.

```ts
import { BehaviorSubject } from 'rxjs';

export class AuthService {
  private isLoggedIn = new BehaviorSubject<boolean>(false);

  // Observable para los componentes
  isLoggedIn$ = this.isLoggedIn.asObservable();

  login() {
    this.isLoggedIn.next(true); // Actualiza el estado a "logeado"
  }

  logout() {
    this.isLoggedIn.next(false); // Actualiza el estado a "no logeado"
  }
}
```
Uso en un componente
```ts
authService.isLoggedIn$.subscribe(isLogged => {
  console.log('Estado de sesión:', isLogged);
});
```

2. Formulario reactivo con estado inicial: Puedes usar BehaviorSubject para almacenar los valores iniciales de un formulario y actualizarlos dinámicamente.

3. Cacheo de datos: Almacenar los datos obtenidos de una API para evitar solicitudes redundantes.
```ts
import { BehaviorSubject } from 'rxjs';
import { HttpClient } from '@angular/common/http';

export class DataService {
  private dataCache = new BehaviorSubject<any[]>([]);

  getData() {
    if (this.dataCache.value.length === 0) {
      this.http.get<any[]>('https://api.example.com/data').subscribe(data => {
        this.dataCache.next(data); // Actualiza el caché
      });
    }
    return this.dataCache.asObservable();
  }
}
```

4. Comunicación entre componentes independientes: Un BehaviorSubject en un servicio compartido puede actuar como un puente entre componentes.

5. Sistemas de notificaciones: BehaviorSubject permite que todos los componentes interesados reciban notificaciones de eventos importantes (por ejemplo, nuevos mensajes o actualizaciones).

## Ventajas
* Último valor accesible: Siempre garantiza que haya un estado actual disponible.

* Suscripciones tardías seguras: No importa cuándo se suscriba, siempre obtendrá el valor más reciente.

* Ideal para manejar estados: Es perfecto para situaciones en las que el estado es crítico y varios componentes necesitan reaccionar a él.

## Limitaciones
* Obligación de un valor inicial: Puede no ser ideal si no tienes un estado inicial lógico.

* Memoria: Almacena el último valor en memoria hasta que se elimine explícitamente.

* Complejidad: Puede ser confuso si no se maneja correctamente, especialmente con múltiples suscriptores o actualizaciones frecuentes.
