# Core
El directorio **core** en Angular es una convención utilizada para almacenar elementos esenciales y de propósito único que son fundamentales para toda la aplicación, pero que no deberían compartirse como elementos genéricos (como ocurre con el directorio shared). Este patrón de organización ayuda a centralizar y gestionar aspectos críticos de la aplicación de manera eficiente.

## ¿Qué es el directorio core?
El directorio **core** es una carpeta que contiene recursos esenciales para la aplicación que:

* No son reutilizables entre componentes o módulos como los de `shared`.

* Son utilizados globalmente, como servicios singleton, interceptores **HTTP**, guardias de rutas, configuraciones globales y clases base.

## ¿Cuáles son las características del directorio core?
1. **Centralización**: Agrupa elementos esenciales y únicos en un solo lugar, como:

   * Servicios globales.

   * Interceptores HTTP.

   * Guardias de rutas.

   * Configuración de la aplicación.

2. **Singletons**: Los servicios en **core** suelen ser singleton (instancia única) debido a que se declaran en el `AppModule`.

3. **Uso global**: Contiene recursos que afectan o gestionan toda la aplicación (por ejemplo, un servicio de autenticación).

4, **No reutilizable directamente**: Los elementos en **core** no están diseñados para ser compartidos entre componentes o módulos como los recursos de shared.

5. **Estructura común del directorio**: Aunque puede variar según el proyecto, una estructura típica es:
```plaintext
src/
 └── app/
      ├── core/
      │    ├── guards/
      │    │    └── auth.guard.ts
      │    ├── interceptors/
      │    │    └── auth.interceptor.ts
      │    ├── services/
      │    │    └── auth.service.ts
      │    ├── models/
      │    │    └── user.model.ts
      │    ├── config/
      │    │    └── app.config.ts
      │    ├── core.module.ts
```

6. **Evita reimportaciones**: Incluye un CoreModule para registrar estos recursos de manera centralizada y prevenir problemas como múltiples instancias de servicios.

## ¿Para qué sirve el directorio core?
* **Gestión de recursos esenciales**: Sirve como el punto único de acceso para elementos que son fundamentales para la aplicación.

* **Mantener modularidad**: Evita sobrecargar otros módulos con responsabilidades globales.

* **Definición de configuraciones globales**: Agrupa configuraciones importantes como las constantes del entorno.

* **Encapsular lógica crítica**: Ayuda a organizar y centralizar la lógica crítica que no pertenece a una funcionalidad específica.

## ¿Qué resuelve el directorio core?
* **Desorganización de recursos esenciales**: Centraliza la lógica fundamental, evitando que los recursos globales estén dispersos.

* **Multiplicación de instancias de servicios**: Declara servicios singleton que se instancian solo una vez.

* **Sobrecarga de `AppModule`**: Mantiene el `AppModule` limpio al delegar la gestión de recursos esenciales al CoreModule.

* **Confusión entre recursos reutilizables y esenciales**: Diferencia claramente entre elementos globales (**core**) y compartidos (**shared**).

## ¿Cómo lo resuelve?
1. **Creando un `CoreModule`**: Encapsula recursos globales y se importa una sola vez en el `AppModule`.
```ts
@NgModule({
  providers: [
    AuthService,
    { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true },
  ]
})
export class CoreModule {
  constructor() {
    if (CoreModule.instance) {
      throw new Error('CoreModule is already loaded. Import it in the AppModule only.');
    }
  }
}
```

2. **Evitando múltiples instancias de servicios**: Servicios como AuthService se declaran en el `CoreModule` y no en módulos secundarios.

3. **Implementando patrones comunes**: Recursos como interceptores HTTP o guardias de rutas se agrupan en carpetas como `interceptors/` o `guards/`.

4. **Definiendo configuraciones globales**: Usa el directorio `config/` para administrar variables globales:
```ts
export const APP_CONFIG = {
  apiUrl: 'https://api.example.com',
  version: '1.0.0',
};
```
5. **Facilitando testing y mantenimiento**: Los elementos globales tienen un lugar centralizado, lo que simplifica el testing y las actualizaciones.

## ¿Qué NO es un core?
* **No es un lugar para componentes reutilizables**: Los componentes o elementos que se pueden usar en múltiples lugares deben ir al directorio shared.

* **No es para recursos específicos de funcionalidades**: Los elementos relacionados con una funcionalidad específica deben estar en features.

* **No es un repositorio genérico de código**: Todo lo que se coloca en core debe tener un propósito claro y global.

## Buenas prácticas con el directorio core
1. **Mantén la unicidad**: Importa el CoreModule solo en el AppModule.

2. **Usa nombres descriptivos**: Organiza las subcarpetas (como `guards`, `interceptors`, `services`) para una mejor comprensión.

3. **Evita la duplicidad**: No declares recursos globales en otros módulos fuera de core.

4. **Minimiza la lógica en el `CoreModule`**: Usa el módulo para configurar y registrar servicios, no para implementar lógica.

5. **Documenta los recursos globales**: Añade comentarios claros sobre el propósito y el alcance de cada recurso.
