# `setup()`
El método setup() es el punto de entrada principal para definir la lógica de un componente en la Composition API de Vue 3. Se ejecuta antes de que el componente sea montado y reemplaza las opciones tradicionales de la Option API (como data(), methods(), computed(), etc.), agrupando toda la lógica reactiva y funcional en un solo lugar.

## ¿Cuál es su estructura?
El método setup() es una función que puede recibir dos parámetros opcionales:

* props: Contiene las propiedades pasadas al componente desde su padre.

* context: Es un objeto que incluye attrs, slots y emit.

Estructura básica:
```ts
setup(props, context) {
  // Lógica reactiva aquí
  return {
    // Variables, métodos y propiedades computadas expuestas al template
  };
}
```
Ejemplo:
```ts
<script lang="ts">
import { defineComponent, ref } from 'vue';

export default defineComponent({
  props: {
    mensajeInicial: {
      type: String,
      required: true,
    },
  },
  setup(props, { emit }) {
    // Variable reactiva
    const contador = ref(0);

    // Método para actualizar el contador
    const incrementar = () => {
      contador.value++;
      emit('contador-actualizado', contador.value);
    };

    return {
      contador,
      incrementar,
      mensaje: props.mensajeInicial,
    };
  },
});
</script>

<template>
  <div>
    <p>{{ mensaje }}</p>
    <p>Contador: {{ contador }}</p>
    <button @click="incrementar">Incrementar</button>
  </div>
</template>
```

## ¿Para qué sirve?
* Definir lógica del componente: Es el lugar donde se declara y organiza toda la lógica reactiva (estado, métodos, propiedades computadas, observadores, etc.) del componente.

* Acceder a props y contexto del componente: Puedes manejar propiedades (props) y utilizar el contexto del componente (attrs, slots, emit).

* Reutilización y modularidad: Facilita la separación de lógica en funciones reutilizables (composables).

* Integración con TypeScript: Ofrece un entorno robusto para definir tipos y mejorar la seguridad del código.

## ¿Qué resuelve?
* Fragmentación de la lógica: En la Option API, la lógica relacionada podía estar dispersa en diferentes secciones (como data, methods, computed). Con setup(), puedes agrupar toda la lógica en un solo lugar.

* Reutilización de lógica: Antes de la Composition API, se dependía de mixins, que podían ser difíciles de depurar y entender. Ahora, puedes usar funciones composables.

* Compatibilidad limitada con TypeScript: La Option API tenía soporte limitado para TypeScript. setup() permite un mejor uso del tipado y de herramientas de desarrollo.

## ¿Cómo lo resuelve?
* Centralizando la lógica: Con setup(), todas las variables, métodos y propiedades computadas se definen en el mismo lugar, mejorando la legibilidad y mantenibilidad.

* Aprovechando reactividad: Usa utilidades reactivas como ref() y reactive() para crear estados reactivos fácilmente.

* Creación de composables: Encapsula la lógica en funciones reutilizables para usar en varios componentes.

* Integración directa con TypeScript: Al usar Composition API, puedes definir explícitamente los tipos de props y variables.

## Pilares clave de setup()
1. Reactividad con ref() y reactive():
   * ref(): Crea un estado reactivo para valores primitivos.

   * reactive(): Convierte un objeto en reactivo.

Ejemplo:
```ts
const contador = ref(0);
const estado = reactive({ nombre: 'Juan', edad: 30 });
```

2. Propiedades computadas con computed(): Crea propiedades derivadas basadas en variables reactivas.
```ts
const mensaje = computed(() => `Contador actual: ${contador.value}`);
```

3. Efectos con watch() y watchEffect(): Observa cambios en las variables reactivas y ejecuta funciones.
```ts
watch(contador, (nuevoValor, viejoValor) => {
  console.log(`Contador cambió de ${viejoValor} a ${nuevoValor}`);
});
```

4. Interacción con el contexto del componente:
   * **`props`**: Las propiedades pasadas desde el padre.

   * **`emit`**: Para emitir eventos personalizados.

   * **`attrs`**: Para acceder a atributos no declarados en props.

   * **`slots`**: Para acceder a los slots del componente.
```ts
setup(props, { emit, attrs, slots }) {
  emit('mi-evento', 'Hola');
  console.log(attrs, slots);
}
```

# `<script setup>`
Con `<script setup>`, se elimina la necesidad de declarar explícitamente el método `setup()`. Todo el código dentro del bloque `<script setup>` se considera parte de la función setup.

## ¿Qué resuelve?
* Redundancia de código: Elimina la necesidad de escribir setup() explícitamente.

* Reduce la cantidad de código necesario para declarar props y métodos.

* Estructura inconsistente: Con la Composition API, puedes mantener toda la lógica relacionada en un mismo lugar, en lugar de separarla en métodos, datos y ciclos de vida (como en la Option API).

* Mayor claridad y mantenibilidad: Proporciona una estructura más sencilla y limpia.

* Mejor integración con TypeScript: Permite una integración directa de tipos y validaciones en tiempo de desarrollo.

```ts
<script setup lang="ts">
import { ref } from 'vue';

// Props
defineProps({
  mensaje: {
    type: String,
    required: true,
  },
});

// Estado reactivo
const contador = ref(0);

// Métodos
const incrementar = () => {
  contador.value++;
};
</script>

<template>
  <div>
    <h1>{{ mensaje }}</h1>
    <p>Contador: {{ contador }}</p>
    <button @click="incrementar">Incrementar</button>
  </div>
</template>
```
