# `unmounted`
El hook unmounted es parte del ciclo de vida de un componente en Vue.js 3. Se ejecuta después de que un componente ha sido completamente desmontado del DOM.
En este punto, el componente ya no está disponible en el DOM y cualquier referencia asociada a él se ha eliminado.

Es el último hook en el ciclo de vida de un componente, utilizado principalmente para realizar tareas finales después del desmontaje.

## ¿Cuál es su estructura?
El hook unmounted se define dentro de la sección de script de un componente.

Estructura básica:
```ts
export default {
  unmounted() {
    console.log('El componente ha sido desmontado.');
  }
};
```
Ejemplo en un componente completo:
```ts
<template>
  <div>
    <p>Este componente será desmontado.</p>
  </div>
</template>

<script>
export default {
  unmounted() {
    console.log('El componente ya no está en el DOM.');
  }
};
</script>
```

## ¿Para qué sirve el hook unmounted?
El hook unmounted se utiliza para:

Confirmar que el componente ha sido eliminado por completo del DOM.
Realizar tareas finales de limpieza, aunque normalmente esto se realiza en el hook beforeUnmount.
Registrar o notificar en un sistema externo que el componente ya no está disponible.
4. ¿Qué resuelve el hook unmounted?
El hook unmounted resuelve:

Confirmar la finalización del desmontaje:

Garantiza que cualquier recurso pendiente relacionado con el componente se haya completado.
Integraciones externas:

Permite notificar a sistemas externos o registros que el componente ya no está disponible.
Registro de acciones finales:

Ayuda a realizar tareas como enviar logs o métricas relacionadas con el ciclo de vida del componente.
Aunque menos utilizado que beforeUnmount, este hook puede ser útil en escenarios donde necesitas confirmación post-desmontaje.

5. ¿Cómo lo resuelve?
El hook unmounted se ejecuta automáticamente después de que Vue ha eliminado completamente el componente del DOM, proporcionando un punto seguro para realizar tareas finales.

6. Ejemplo práctico del hook unmounted
Ejemplo 1: Confirmar el desmontaje en consola
```ts
<template>
  <div>
    <p>Componente desmontable</p>
  </div>
</template>

<script>
export default {
  unmounted() {
    console.log('El componente ha sido eliminado completamente del DOM.');
  }
};
</script>
```
Explicación:

Este es un ejemplo básico para confirmar que el componente ha sido desmontado.

Ejemplo 2: Notificar a un sistema externo
Imagina que tienes un sistema de analíticas para rastrear el estado de los componentes.
```ts
<template>
  <div>
    <p>Componente con integración externa</p>
  </div>
</template>

<script>
export default {
  unmounted() {
    // Notificar al sistema de analíticas
    console.log('Notificando al sistema externo: componente desmontado.');
  }
};
</script>
```
Explicación:

Cuando el componente se desmonta, envía una notificación al sistema externo para registrar el evento.

Ejemplo 3: Registro final de actividad
Si necesitas realizar un seguimiento de las acciones de los usuarios y limpiar al final.
```ts
<template>
  <div>
    <p>Interacción registrada</p>
  </div>
</template>

<script>
export default {
  data() {
    return {
      actividad: 'Navegando por el componente'
    };
  },
  unmounted() {
    console.log(`Actividad registrada: ${this.actividad}`);
  }
};
</script>
```
Explicación:

Al desmontarse, el componente registra la actividad final realizada por el usuario.


## Buenas prácticas
Usa beforeUnmount para la mayoría de las limpiezas:

Normalmente, es mejor liberar recursos como intervalos, eventos o servicios en beforeUnmount.
Confirma desmontajes importantes:

Si necesitas confirmar en sistemas externos o logs, usa unmounted.
No modifiques datos reactivos:

En este punto, el componente ya no existe en el DOM, por lo que no tiene sentido modificar datos reactivos.
Evita dependencias pesadas:

Las tareas realizadas aquí deberían ser ligeras, ya que es el último paso del ciclo de vida del componente.
