# Eventos
Los eventos (events) son una parte fundamental de la programación orientada a eventos (event-driven programming), un paradigma en el que el flujo del programa está determinado por la ocurrencia de acciones o cambios conocidos como eventos. Un evento puede ser cualquier cosa que suceda en un sistema, como un clic del mouse, la pulsación de una tecla, la llegada de un nuevo mensaje de red, la lectura de datos o un cambio en el estado de una aplicación.

Un evento es una acción o suceso reconocido por un programa que puede ser manejado o procesado. Estos eventos son generados por una fuente y luego capturados o escuchados por **event listeners** (escuchadores de eventos) que realizan alguna acción en respuesta.

**Ejemplos de eventos:**
* Un usuario hace clic en un botón de una interfaz gráfica.

* Un archivo es modificado o guardado en el sistema de archivos.

* Una solicitud HTTP llega a un servidor web.

* Un sensor de IoT envía una lectura de temperatura.

## ¿Para qué sirven los eventos?
Los eventos sirven para disparar acciones dentro de un programa en respuesta a interacciones del usuario, cambios en el estado del sistema o entradas externas. La programación basada en eventos es particularmente útil en aplicaciones que requieren interacción en tiempo real, como interfaces gráficas de usuario (GUI), servidores web, aplicaciones de IoT, entre otros.

**Usos comunes de los eventos:**
* **Interfaces gráficas**: Capturar clics de botones, movimiento del ratón, entrada de texto.

* **Aplicaciones web**: Escuchar solicitudes HTTP o cambios en websockets.

* **Sistemas distribuidos**: Detectar cuando llega un mensaje o cuando cambia el estado de un componente en otro nodo del sistema.

* **Manejo de hardware o sensores**: Reaccionar cuando un sensor registra datos o cuando un dispositivo se conecta.

## ¿Qué problemas resuelven los eventos?
Los eventos resuelven el problema de tener que preguntar continuamente (polling) si algo ha cambiado o si ha ocurrido una acción. En lugar de tener un sistema que revisa repetidamente si hay una actualización (lo cual es ineficiente), los eventos notifican al sistema o programa cuando ocurre un cambio, lo que permite que el código reaccione de manera más eficiente y en el momento adecuado.

**Problemas que resuelven:**
1. **Eficiencia**: No es necesario que el sistema esté revisando continuamente el estado de una acción, lo que reduce el uso innecesario de recursos.

2. **Interactividad**: Permite crear aplicaciones más reactivas y dinámicas, que responden a la interacción del usuario o eventos del sistema en tiempo real.

3. **Modularidad**: Facilita la separación de responsabilidades en componentes, ya que cada componente puede emitir y escuchar eventos de manera independiente.

## ¿Cómo lo resuelven?
El manejo de eventos sigue un patrón de emisor y receptor. La fuente del evento genera o emite el evento, mientras que un receptor o manejador (handler) escucha y responde a ese evento cuando ocurre. Esto permite una ejecución asíncrona, donde el flujo del programa no se detiene mientras espera a que ocurra un evento.

**El ciclo básico de un evento:**
1. **Generación del evento**: Algo desencadena un evento, como un clic del usuario, una solicitud de red o un cambio de estado.

2. **Propagación del evento**: El evento es capturado o propagado por el sistema de eventos.

3. **Escuchador de eventos**: Un componente, denominado event listener o handler, escucha el evento y ejecuta una función o acción cuando el evento ocurre.

4. **Manejo del evento**: El manejador ejecuta una acción predefinida en respuesta al evento.

## Ejemplo en Java: Uso de Eventos en una Interfaz Gráfica
En Java, la programación orientada a eventos es comúnmente utilizada en interfaces gráficas (GUI) mediante librerías como Swing o JavaFX. Aquí un ejemplo simple donde un botón emite un evento de clic:

```java
import javax.swing.JButton;
import javax.swing.JFrame;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;

public class EjemploEvento {
    public static void main(String[] args) {
        // Crear ventana
        JFrame ventana = new JFrame("Evento Ejemplo");
        ventana.setSize(300, 200);
        ventana.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

        // Crear botón
        JButton boton = new JButton("Haz clic aquí");

        // Añadir el listener al botón (escuchar el evento de clic)
        boton.addActionListener(new ActionListener() {
            @Override
            public void actionPerformed(ActionEvent e) {
                // Acción cuando se hace clic en el botón
                System.out.println("¡Botón clickeado!");
            }
        });

        // Añadir el botón a la ventana y mostrarla
        ventana.add(boton);
        ventana.setVisible(true);
    }
}
```
En este ejemplo:

* El botón es la fuente del evento.

* Al hacer clic en el botón, se genera un evento de acción.

* El `ActionListener` escucha el evento y ejecuta una acción (imprime un mensaje en la consola) cuando se produce el evento.

## ¿Qué se necesita para trabajar con eventos?
1. **Fuente de eventos**: El origen que genera los eventos (por ejemplo, un botón, una solicitud de red).

2. **Listener o manejador de eventos**: Un componente que escucha los eventos y realiza una acción cuando el evento ocurre.

3. **Registro del listener**: Proceso mediante el cual se asocia el listener con la fuente del evento, permitiendo que el listener sea notificado cuando ocurra un evento.

## Ventajas de la Programación Orientada a Eventos
* **Desacoplamiento**: Los emisores y receptores de eventos están desacoplados, lo que facilita la modularidad y el mantenimiento del código.

* **Escalabilidad**: Este patrón es ideal para sistemas distribuidos o aplicaciones concurrentes.

* **Reactividad**: Las aplicaciones pueden responder de manera inmediata a los cambios, lo que mejora la experiencia del usuario.

## Desventajas de la Programación Orientada a Eventos
* **Complejidad**: El manejo de eventos en aplicaciones grandes puede volverse complejo, especialmente cuando hay muchos eventos sucediendo al mismo tiempo.

* **Depuración difícil**: Debido a la naturaleza asincrónica de los eventos, rastrear errores puede ser más complicado que en un flujo de control secuencial.

* **Condiciones de carrera**: Si no se manejan adecuadamente, los eventos concurrentes pueden causar errores de sincronización en aplicaciones multihilo.

## Patrones Comunes en la Programación Orientada a Eventos
1. **Observer Pattern**: Permite que un objeto (el observador) escuche los cambios en otro objeto (el sujeto). Es útil para la notificación de eventos.

2. **Callback Pattern**: Se utiliza cuando una función pasa una segunda función que se ejecutará cuando ocurra un evento específico.

3. **Pub/Sub (Publicar/Suscribir)**: Es un patrón en el que los emisores (publicadores) generan eventos sin conocer a los receptores (suscriptores), y viceversa. Muy común en sistemas distribuidos.
