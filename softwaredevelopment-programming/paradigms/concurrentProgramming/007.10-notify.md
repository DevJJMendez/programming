# `notify()` y `notifyAll()`
Los métodos `notify()` y `notifyAll()` son utilizados para manejar la comunicación entre hilos en Java. Estos métodos pertenecen a la clase base `Object`, ya que todos los objetos en Java tienen la capacidad de actuar como monitores. Se utilizan comúnmente junto con el método `wait()` para coordinar la ejecución de hilos en escenarios de sincronización.

* `notify()`: Despierta un único hilo que esté esperando en el monitor del objeto (es decir, un hilo que haya llamado previamente al método `wait()` en ese objeto). El hilo que es despertado se elige de manera arbitraria (no hay garantía de cuál se seleccionará si hay varios hilos esperando).

* `notifyAll()`: Despierta todos los hilos que estén esperando en el monitor del objeto. Todos los hilos despiertos pasan a estar en estado bloqueado, y solo uno de ellos podrá adquirir el monitor y continuar la ejecución cuando el monitor se libere.

## ¿Para Qué Sirven notify() y notifyAll()?
Estos métodos permiten a un hilo notificar a otros hilos que una condición de sincronización ha cambiado, permitiendo que estos continúen su ejecución. Sirven para:

1. **Coordinar Tareas Concurrentes**: Permitir que diferentes hilos se sincronicen para completar tareas en orden o de forma secuencial.

2. **Despertar Hilos que Esperan Condiciones Específicas**: Un hilo que realiza tareas críticas puede notificar a otros hilos para que continúen su ejecución cuando se cumplan ciertas condiciones.

## ¿Qué Problemas Resuelven `notify()` y `notifyAll()`?
1. **Evitar Bloqueos Eternos**: Si un hilo está en espera (`wait()`) porque espera que una condición cambie, los métodos `notify()` o `notifyAll()` permiten despertar a estos hilos cuando la condición se cumple.

2. **Controlar la Ejecución de Múltiples Hilos**: Ayudan a coordinar el acceso a recursos compartidos y garantizar que los hilos no entren en conflicto entre sí cuando intentan usar el mismo recurso.

3. **Comunicación entre Hilos**: Proveen un mecanismo para la comunicación directa entre hilos, permitiendo que un hilo notifique a otro cuando una tarea está completa o cuando se puede proceder.

## ¿Cómo Resuelven estos Problemas?
* **Liberando el Monitor y Despertando Hilos**: Cuando un hilo llama a `wait()`, libera el monitor del objeto y entra en un estado de espera. Otro hilo puede entonces llamar a `notify()` o `notifyAll()` para despertar al hilo en espera, permitiéndole reintentar adquirir el monitor y continuar la ejecución.

* **Controlando la Cantidad de Hilos que Despiertan**: `notify()` permite despertar a un solo hilo, lo que puede ser útil cuando solo un hilo necesita realizar una tarea. notifyAll() se utiliza cuando todos los hilos en espera deben ser notificados para intentar continuar su ejecución.

## Ejemplo de Uso: `wait()`, `notify()`, y `notifyAll()`
**Escenario de Productor-Consumidor**: En este ejemplo, vamos a mostrar cómo usar `wait()`, `notify()`, y `notifyAll()` para coordinar dos hilos: uno actuando como productor (que produce datos) y otro como consumidor (que consume esos datos).

```java
class Almacen {
    private int producto;
    private boolean disponible = false;

    public synchronized void producir(int valor) {
        while (disponible) {
            try {
                wait(); // Esperar hasta que el producto sea consumido
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        producto = valor;
        disponible = true;
        System.out.println("Producido: " + valor);
        notify(); // Notificar al consumidor que el producto está disponible
    }

    public synchronized int consumir() {
        while (!disponible) {
            try {
                wait(); // Esperar hasta que el producto esté disponible
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        disponible = false;
        System.out.println("Consumido: " + producto);
        notify(); // Notificar al productor que el producto ha sido consumido
        return producto;
    }
}

public class EjemploProductorConsumidor {
    public static void main(String[] args) {
        Almacen almacen = new Almacen();

        // Hilo productor
        Thread productor = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                almacen.producir(i);
            }
        });

        // Hilo consumidor
        Thread consumidor = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                almacen.consumir();
            }
        });

        productor.start();
        consumidor.start();
    }
}
```
**Explicación del Ejemplo**
1. **Productor**:

   * Llama a `wait()` si el producto ya está disponible (porque el consumidor aún no ha consumido el anterior).

   * Una vez que el consumidor ha consumido el producto y el hilo productor es notificado, produce un nuevo producto y llama a `notify()` para despertar al consumidor.

2. **Consumidor**:

   * Llama a `wait()` si no hay un producto disponible.

   * Cuando el productor produce un nuevo producto, el consumidor es notificado, consume el producto y llama a `notify()` para que el productor pueda producir otro.

## Diferencias Clave entre notify() y notifyAll()
| Característica              | notify()                                                   | notifyAll()                                                  |
| --------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| Número de Hilos Despertados | Solo un hilo es despertado.                                | Todos los hilos en espera son despertados.                   |
| Selección del Hilo          | El hilo despertado se elige arbitrariamente.               | No garantiza el orden de los hilos despertados.              |
| Uso Común                   | Cuando solo un hilo necesita ejecutar la siguiente acción. | Cuando múltiples hilos pueden procesar tras la notificación. |


## Consejos para Usar notify() y notifyAll()
1. **Usar notify()** Cuando Sea Posible: Si puedes resolver el problema con notify(), úsalo en lugar de notifyAll(). Esto es más eficiente ya que evita despertar a hilos innecesarios, que luego deberán volver a esperar.

2. **Evitar Problemas de Desempeño con notifyAll()**: El uso de notifyAll() puede despertar muchos hilos, de los cuales solo uno podrá proceder. Esto puede causar problemas de rendimiento, especialmente si hay una gran cantidad de hilos involucrados.

3. **Siempre Usar Dentro de un Bloque synchronized**: Tanto notify() como notifyAll() deben ser llamados dentro de bloques sincronizados. Si no se usan dentro de un bloque synchronized, lanzarán una IllegalMonitorStateException.
