# Procesos
Un proceso es una instancia de un programa en ejecución. Es una entidad aislada que tiene su propio espacio de memoria y recursos. Cada proceso en un sistema operativo es independiente y tiene las siguientes características:

* **Espacio de Memoria Propio**: Un proceso tiene su propio segmento de memoria que contiene el código del programa, los datos y las variables. No comparte memoria con otros procesos a menos que se implemente explícitamente.

* **Independencia**: Los procesos son generalmente independientes entre sí. La falla de un proceso no afecta directamente a otros procesos.

* **Recursos**: Un proceso tiene recursos asignados por el sistema operativo, como archivos abiertos, memoria y permisos.

* **Ejemplo en la vida real**: Abrir varias aplicaciones en tu computadora (por ejemplo, un navegador web y un editor de texto). Cada aplicación representa un proceso independiente.

**Procesos en Programación Concurrente**
* **Ventaja**: Aislamiento fuerte. La ejecución de un proceso no puede afectar a otro directamente, lo que mejora la estabilidad del sistema.

* **Desventaja**: Comunicar datos entre procesos puede ser más complejo y costoso, ya que requieren mecanismos de comunicación específicos como pipes, sockets o memoria compartida.

# Rutinas
Las rutinas son bloques de código que pueden ser invocados para ejecutar una tarea específica. También son conocidas como funciones o métodos en la mayoría de los lenguajes de programación. Las rutinas se llaman para realizar operaciones específicas y pueden devolver resultados.

**Tipos de Rutinas**:
* **Rutinas Síncronas**: Se ejecutan de manera secuencial. El flujo del programa se detiene y espera hasta que la rutina termine de ejecutarse antes de continuar.

* **Rutinas Asíncronas**: Se ejecutan de forma que no bloquean el flujo del programa principal. El programa puede continuar ejecutando otras operaciones mientras la rutina asíncrona se completa.

**Rutinas en Programación Concurrente**
* En el contexto de concurrencia, las rutinas asíncronas son esenciales, ya que permiten que el programa realice múltiples tareas sin esperar que una sola operación termine.

* Las rutinas también forman la base para crear hilos, ya que el código que define la tarea de un hilo es, esencialmente, una rutina.

# Tareas
Una tarea es una unidad de trabajo o acción que debe realizarse como parte de un programa. A diferencia de un proceso o una rutina, el término "tarea" es más abstracto y puede referirse a cualquier trabajo que deba completarse, ya sea pequeño o grande.

**En Contextos de Concurrencia:**
* En sistemas concurrentes, las tareas son fragmentos de trabajo que pueden ejecutarse de forma independiente y, a menudo, se ejecutan simultáneamente para mejorar la eficiencia.

* Un hilo puede ejecutar una tarea. En programación concurrente moderna, en lugar de gestionar hilos manualmente, se prefiere definir tareas y dejar que un sistema de ejecutor (Executor) administre los hilos que ejecutan esas tareas.

**Ejemplo de Tareas en Programación Concurrente**
* `Runnable` y `Callable` en Java: Cuando defines una implementación de Runnable o Callable, estás definiendo una tarea que puede ejecutarse en un hilo. El sistema de Executor puede tomar múltiples tareas y ejecutarlas de manera concurrente.

* **Frameworks de Ejecución**: Plataformas como `Fork/Join`, `ExecutorService` o `CompletableFuture` gestionan la ejecución concurrente de tareas para mejorar el rendimiento.
