# `ReentrantLock`
es una clase que forma parte del paquete `java.util.concurrent.locks` y proporciona una forma más flexible de controlar el acceso sincronizado a recursos compartidos en comparación con el uso de la palabra clave `synchronized`. Es un tipo de bloqueo explícito que ofrece características adicionales y mayor control sobre la sincronización de hilos.

## ¿Qué es ReentrantLock?
Un ReentrantLock es un bloqueo que permite a un hilo adquirir el bloqueo de forma repetida sin que se bloquee a sí mismo. Esto significa que si un hilo ya tiene el bloqueo, puede volver a adquirirlo sin quedar bloqueado. Esto es similar al comportamiento de un método o bloque synchronized, que también permite la reentrancia.

## ¿Para Qué Sirve ReentrantLock?
* **Sincronización Explícita**: Ofrece un mecanismo de bloqueo explícito que es más flexible que los bloques sincronizados (synchronized).

* **Control Avanzado**: Permite operaciones adicionales, como tratar de adquirir el bloqueo sin quedarse bloqueado, establecer límites de tiempo para la adquisición del bloqueo y liberar el bloqueo de manera segura.

* **Reentrancia**: Permite a un hilo volver a adquirir el bloqueo si ya lo posee, sin quedarse atascado.

## ¿Qué Problemas Resuelve ReentrantLock?
1. **Control de Acceso a Recursos Compartidos**: Ayuda a coordinar el acceso a recursos compartidos por múltiples hilos, evitando condiciones de carrera y asegurando que solo un hilo pueda acceder a un recurso crítico a la vez.

2. **Evitar Bloqueos No Intencionados**: Proporciona métodos que permiten adquirir el bloqueo de forma no bloqueante, es decir, los hilos pueden intentar adquirir el bloqueo sin quedar bloqueados indefinidamente.

3. **Evitar Problemas de Desempeño**: Ofrece la posibilidad de bloqueo justo (fair locking), donde los hilos obtienen el bloqueo en el orden en que lo solicitaron, ayudando a evitar problemas de injusticia (hilos que nunca obtienen el bloqueo).

## ¿Cómo Resuelve Estos Problemas?
* **Métodos Flexibles de Bloqueo**: Ofrece métodos como `lock()`, `tryLock()`, y `unlock()`, que brindan una mayor flexibilidad sobre la sincronización.

* **Reentrancia**: Permite que un mismo hilo adquiera el bloqueo varias veces sin bloquearse, lo que facilita la programación de código recursivo o métodos que se llaman entre sí y requieren acceso exclusivo al recurso.

* **Bloqueo Justo (Fair Locking)**: Permite crear un bloqueo justo, que garantiza que los hilos obtengan el bloqueo en el orden en que lo solicitaron.

## Métodos
Los métodos de ReentrantLock proporcionan una forma más flexible de manejar el control de sincronización que el uso tradicional de synchronized.

1. `lock()`: Adquiere el bloqueo. Si el bloqueo no está disponible, el hilo se bloqueará hasta que pueda adquirirlo. Este método es equivalente a un bloque synchronized, pero se debe liberar el bloqueo manualmente usando `unlock()`.

```java
ReentrantLock lock = new ReentrantLock();

lock.lock(); // Adquirir el bloqueo
try {
    // Código crítico
} finally {
    lock.unlock(); // Liberar el bloqueo
}
```
**Importante**: Siempre debes liberar el bloqueo dentro de un bloque `finally` para asegurar que no se quede bloqueado si ocurre una excepción.

2. `unlock()`: Libera el bloqueo que el hilo actual posee. Si otros hilos están esperando el bloqueo, uno de ellos podrá adquirirlo una vez que se haya liberado.

**Uso**: Debe llamarse siempre después de `lock()` para liberar el bloqueo.

3. `tryLock()`: Intenta adquirir el bloqueo de forma no bloqueante. Si el bloqueo está disponible, lo adquiere y retorna true. Si no lo está, retorna false inmediatamente.

```java
if (lock.tryLock()) {
    try {
        // Código crítico
    } finally {
        lock.unlock();
    }
} else {
    System.out.println("El bloqueo no estaba disponible");
}
```
Cuándo Usarlo: Útil cuando deseas que tu hilo continúe trabajando en otras tareas si el recurso no está disponible, en lugar de bloquearse esperando.

4. `tryLock(long time, TimeUnit unit)`: ntenta adquirir el bloqueo durante el tiempo especificado. Si el bloqueo se adquiere dentro del tiempo límite, retorna true. Si no, retorna false.

```java
try {
    if (lock.tryLock(5, TimeUnit.SECONDS)) {
        try {
            // Código crítico
        } finally {
            lock.unlock();
        }
    } else {
        System.out.println("No se pudo adquirir el bloqueo en 5 segundos");
    }
} catch (InterruptedException e) {
    e.printStackTrace();
}
```
Cuándo Usarlo: Si necesitas un comportamiento de espera más controlado y deseas que tu hilo continúe después de un tiempo específico si no puede adquirir el bloqueo.

5. `lockInterruptibly()`: Adquiere el bloqueo a menos que el hilo sea interrumpido mientras está esperando. Si el hilo es interrumpido, lanza una InterruptedException y deja de intentar adquirir el bloqueo.

```java
try {
    lock.lockInterruptibly();
    try {
        // Código crítico
    } finally {
        lock.unlock();
    }
} catch (InterruptedException e) {
    e.printStackTrace();
}
```
Cuándo Usarlo: Útil cuando deseas que un hilo pueda salir de un intento de adquisición de bloqueo si otro hilo decide interrumpirlo.

6. `newCondition()`: Crea una instancia de Condition asociada con el ReentrantLock. Las condiciones permiten que los hilos esperen y se despierten de manera más controlada que con wait(), notify() y notifyAll() de los bloques synchronized.

```java
Condition condition = lock.newCondition();

lock.lock();
try {
    condition.await(); // El hilo espera hasta que se le notifique
    // Código que se ejecuta después de que se despierta el hilo
} catch (InterruptedException e) {
    e.printStackTrace();
} finally {
    lock.unlock();
}
```
Métodos Importantes de Condition:

* await(): Hace que el hilo actual espere hasta que se le notifique o se interrumpa.

* signal(): Despierta un hilo que está esperando en la condición.

* signalAll(): Despierta a todos los hilos que están esperando en la condición.

7. isLocked()
Descripción: Verifica si el bloqueo está actualmente ocupado por algún hilo. Retorna true si el bloqueo está siendo utilizado y false si no.

```java
if (lock.isLocked()) {
    System.out.println("El bloqueo está ocupado.");
}
```

8. isHeldByCurrentThread()
Descripción: Retorna true si el hilo actual posee el bloqueo. Esto es útil para verificar si el hilo que está ejecutando el código tiene control del recurso bloqueado.

```java
if (lock.isHeldByCurrentThread()) {
    System.out.println("El hilo actual posee el bloqueo.");
}
```

9. getHoldCount()
Descripción: Devuelve el número de veces que el hilo actual ha adquirido el bloqueo. Esto es útil para saber cuántas veces un hilo ha entrado en una sección de código bloqueada que requiere reentrancia.

```java
int count = lock.getHoldCount();
System.out.println("El bloqueo se ha adquirido " + count + " veces.");
```

10. getQueueLength()
Descripción: Devuelve una estimación del número de hilos que están esperando para adquirir el bloqueo. Esto puede ser útil para monitorear el rendimiento de las operaciones de concurrencia.

```java
int queueLength = lock.getQueueLength();
System.out.println("Hay " + queueLength + " hilos esperando para adquirir el bloqueo.");
```


## Bloqueo Justo (Fair Lock)
Por defecto, ReentrantLock no es justo. Esto significa que no garantiza el orden en que los hilos obtendrán el bloqueo. Sin embargo, puedes crear un bloqueo justo así:

```java
ReentrantLock fairLock = new ReentrantLock(true); // Creación de un bloqueo justo
```
Un bloqueo justo garantiza que los hilos obtendrán el bloqueo en el orden en el que lo solicitaron, ayudando a evitar situaciones en las que un hilo nunca recibe el recurso.

## Buenas Prácticas al Usar ReentrantLock
1. **Liberar Siempre el Bloqueo**: Asegúrate de llamar a `unlock()` en un bloque finally para evitar situaciones de deadlock.

2. **Considerar el Uso de `tryLock()`**: Si es posible que tu hilo haga otra cosa mientras espera el recurso, `tryLock()` es una opción más flexible.

3. **Usar Bloqueo Justo con Cuidado**: Aunque el bloqueo justo puede evitar la inanición, es generalmente menos eficiente porque implica más sobrecarga en la gestión del orden.
