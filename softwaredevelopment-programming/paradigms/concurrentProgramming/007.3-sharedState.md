# Estado Compartido
El estado compartido se refiere a cualquier dato o recurso que puede ser accedido y modificado por múltiples hilos o procesos concurrentemente. Este concepto es fundamental en la programación concurrente y puede ser una fuente importante de errores si no se maneja adecuadamente. Entender cómo gestionar el estado compartido es clave para desarrollar aplicaciones que sean robustas, seguras y eficientes.

## ¿Qué es el Estado Compartido?
El estado compartido es el conjunto de datos que es accesible y modificable por múltiples hilos o procesos en una aplicación concurrente. Esto puede incluir:

* Variables globales o estáticas que son accesibles desde diferentes partes de un programa.

* Objetos que se pasan entre hilos y que pueden ser leídos y escritos por más de un hilo.

* Datos almacenados en estructuras compartidas como listas, mapas, colas, etc.

## ¿Para Qué Sirve el Estado Compartido?
El estado compartido permite que los hilos o procesos puedan comunicarse y colaborar al tener acceso a los mismos datos. En aplicaciones concurrentes, es común que varios hilos necesiten leer o actualizar la misma información para realizar su trabajo. Por ejemplo:

* **Servidores web**: Múltiples hilos pueden estar manejando solicitudes de clientes simultáneamente, accediendo a recursos compartidos como bases de datos o archivos.

* **Aplicaciones gráficas**: Hilos diferentes pueden estar procesando eventos de usuario, actualizando la interfaz o realizando cálculos en segundo plano, todos accediendo a un estado compartido.

* **Juegos en tiempo real**: Los hilos pueden compartir información sobre el estado del juego, como las posiciones de los personajes o los recursos del mundo.

## Problemas que Resuelve el Estado Compartido
El estado compartido permite la coordinación y comunicación entre hilos, haciendo posible que una aplicación distribuya el trabajo entre múltiples partes de manera eficiente. Sin embargo, es una fuente común de problemas en aplicaciones concurrentes si no se gestiona adecuadamente. Algunos problemas que se deben resolver cuando se trabaja con estado compartido incluyen:

1. **Condiciones de Carrera (Race Conditions)**: Ocurren cuando dos o más hilos acceden al estado compartido al mismo tiempo y al menos uno de ellos está escribiendo. Esto puede llevar a inconsistencias de datos.

2. **Inconsistencias de Datos**: Cuando múltiples hilos escriben en el mismo estado compartido sin la coordinación adecuada, los datos pueden quedar en un estado incorrecto o inesperado.

3. **Interbloqueos (Deadlocks)**: Situaciones en las que dos o más hilos se bloquean mutuamente al esperar indefinidamente por recursos que el otro posee.

4. **Starvation (Hambre)**: Cuando un hilo nunca obtiene acceso a un recurso porque otros hilos están monopolizándolo.

## ¿Cómo Se Resuelve el Problema del Estado Compartido?
El manejo adecuado del estado compartido implica aplicar técnicas y mecanismos que aseguren que los datos sean consistentes y seguros incluso cuando se accede a ellos concurrentemente. Algunas de las técnicas clave incluyen:

1. **Exclusión Mutua (Mutexes y Bloqueos)**: Para evitar que múltiples hilos modifiquen el estado compartido al mismo tiempo, se utilizan bloqueos (locks). Un bloqueo asegura que solo un hilo pueda acceder a una sección crítica del código a la vez.

* **Bloqueo Implícito**: En Java, se puede usar la palabra clave `synchronized` para asegurarse de que solo un hilo a la vez puede ejecutar un bloque de código.

* **Bloqueo Explícito**: Clases como `ReentrantLock` permiten tener un control más fino sobre los bloqueos.

Ejemplo
```java
public class SharedResource {
    private int counter = 0;

    public synchronized void increment() {
        counter++;
    }

    public int getCounter() {
        return counter;
    }
}
```
En este ejemplo, el método `increment` está sincronizado, lo que significa que solo un hilo a la vez puede incrementarlo.

2. **Inmutabilidad**: Otra forma efectiva de manejar el estado compartido es evitar que los datos cambien después de ser creados, es decir, hacer que sean inmutables. Los objetos inmutables son aquellos cuyos valores no pueden cambiar después de la creación. Al usar objetos inmutables, se elimina la necesidad de sincronización ya que los datos no pueden ser modificados concurrentemente.

* **Ejemplo**: Strings en Java son inmutables, lo que significa que si dos hilos acceden al mismo objeto String, no habrá problemas de concurrencia.

3. **Clases Concurrentes**: Las clases concurrentes en Java, como `ConcurrentHashMap`, proporcionan mecanismos internos de sincronización que permiten el acceso seguro y eficiente al estado compartido sin que el desarrollador tenga que gestionar manualmente los bloqueos.

* **Ejemplo**: Si necesitas que múltiples hilos escriban y lean de un mapa al mismo tiempo, puedes usar `ConcurrentHashMap` en lugar de HashMap para evitar problemas de concurrencia.

4. `Volatile`: La palabra clave `volatile` en Java asegura que cualquier cambio hecho a una variable por un hilo sea visible inmediatamente para otros hilos. Esto es útil cuando se trabaja con variables simples que pueden ser leídas y escritas por múltiples hilos.

* **Limitación**: volatile no proporciona exclusión mutua, por lo que no es adecuado para situaciones donde múltiples hilos necesitan modificar el estado compartido.

Ejemplo
```java
private volatile boolean running = true;

public void stop() {
    running = false;
}
```

## Ejemplos de Problemas de Estado Compartido
Para ilustrar los problemas que pueden ocurrir con el estado compartido, consideremos el siguiente ejemplo:

**Condición de Carrera**: Supongamos que tienes un contador que los hilos deben incrementar:
```java
public class Counter {
    private int count = 0;

    public void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}
```
Si dos hilos ejecutan el método `increment` al mismo tiempo, ambos pueden leer el mismo valor de `count`, incrementar el mismo número y escribir el mismo valor de vuelta, resultando en una actualización incorrecta.

**Solución con Sincronización**: Para evitar la condición de carrera, puedes hacer que el método `increment` sea sincronizado:
```java
public synchronized void increment() {
    count++;
}
```
