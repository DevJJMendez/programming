# `syncronized`
La palabra clave `synchronized` en Java se utiliza para asegurar que solo un hilo pueda ejecutar una sección de código o un método a la vez. Es una forma de sincronización implícita que facilita el control de acceso a recursos compartidos en un entorno multihilo, evitando problemas de concurrencia como las race conditions.

## ¿Para Qué Sirve `synchronized`?
El propósito principal de `synchronized` es garantizar la exclusión mutua, lo que significa que cuando un hilo está ejecutando un bloque de código `synchronized`, ningún otro hilo puede acceder a ese mismo bloque o método hasta que el primero haya terminado. Esto es útil para proteger recursos compartidos y datos críticos que podrían ser corrompidos si se accediera a ellos de forma simultánea por múltiples hilos.

## ¿Qué Problemas Resuelve `synchronized`?
1. **Race Conditions**: Situaciones donde el resultado de una operación depende del orden en que se ejecutan los hilos. `synchronized` asegura que solo un hilo pueda acceder a un recurso compartido a la vez, eliminando posibles conflictos.

2. **Inconsistencia de Datos**: Al bloquear el acceso concurrente a secciones críticas del código, evita que los datos se modifiquen de manera inconsistente o incorrecta.

3. **Coherencia en la Lectura y Escritura de Datos**: Garantiza que las operaciones de lectura y escritura se realicen de manera ordenada y predecible.

## ¿Cómo Resuelve synchronized estos Problemas?
* **Bloqueando Secciones Críticas**: Un bloque `synchronized` o un método **synchronized** asegura que una sección crítica del código solo pueda ser ejecutada por un hilo a la vez. Los demás hilos que intenten entrar en esa sección deben esperar hasta que el hilo actual termine.

* **Utilizando Monitores o Locks**: Cada objeto en Java tiene un monitor (o cerrojo implícito). Cuando un hilo entra en una sección **synchronized**, adquiere el monitor del objeto, y otros hilos quedan bloqueados. Una vez que el hilo termina la ejecución de la sección, libera el monitor, permitiendo que otro hilo entre.

## Tipos de `synchronized` en Java
1. **Métodos Sincronizados (`Synchronized Methods`)**: Cuando se declara un método como `synchronized`, significa que el método completo está protegido por el monitor del objeto.

   * **Métodos de Instancia**: Al sincronizar un método de instancia, se utiliza el monitor del objeto al que pertenece el método.
```java
public class CuentaBancaria {
    private double saldo;

    public synchronized void depositar(double monto) {
        saldo += monto;
    }

    public synchronized void retirar(double monto) {
        if (saldo >= monto) {
            saldo -= monto;
        }
    }
}
```
Aquí, si dos hilos intentan llamar a `depositar` o `retirar` en el mismo objeto `CuentaBancaria`, solo uno podrá ejecutar el método a la vez.

   * **Métodos Estáticos**: Si se declara un método estático como **synchronized**, el monitor que se adquiere es el del **Class Object**. Esto significa que el bloqueo se aplica a todos los objetos de esa clase.

```java
public static synchronized void log(String mensaje) {
    // Sección crítica para todos los hilos
}
```

2. **Bloques Sincronizados (`Synchronized Blocks`)**: Los bloques sincronizados permiten una sincronización más precisa, ya que se puede sincronizar solo una parte específica del método. Esto mejora el rendimiento, ya que el resto del código del método no queda bloqueado si no es necesario.

   * Bloque Synchronized Usando `this`:
```java
public void actualizarSaldo(double monto) {
    synchronized (this) {
        // Solo esta sección está sincronizada
        saldo += monto;
    }
}
```

   * **Bloque Synchronized Usando Otros Objetos**: También se puede sincronizar usando otros objetos como cerrojos.
```java
private final Object bloqueo = new Object();

public void realizarTransferencia(double monto) {
    synchronized (bloqueo) {
        // Código protegido por el objeto `bloqueo`
        saldo -= monto;
    }
}
```

## Funcionamiento Interno: Monitor y Bloqueos
1. **Monitor**: Es un mecanismo de sincronización que controla el acceso a un bloque sincronizado. Cada objeto en Java tiene un monitor asociado. Cuando un hilo adquiere el monitor, los demás hilos deben esperar.

2. **Bloqueo Implícito**: Cuando un hilo entra en un bloque synchronized, adquiere el monitor del objeto. El hilo mantiene este bloqueo hasta que sale del bloque, lo que garantiza que ningún otro hilo pueda entrar hasta que se libere el monitor.

## Problemas y Consideraciones al Usar synchronized
1. **Deadlocks**: Si dos o más hilos esperan de forma indefinida para acceder a recursos bloqueados por otros hilos, ocurre un deadlock. Esto puede suceder si los hilos adquieren múltiples bloqueos en diferentes órdenes.

2. **Desempeño**: El uso excesivo de synchronized puede afectar el rendimiento de la aplicación, ya que impide el acceso concurrente a recursos que podrían no necesitar sincronización.

3. **No se Puede Interrumpir**: Los bloques sincronizados no son interrumpibles, lo que significa que si un hilo queda bloqueado esperando un monitor, no puede ser interrumpido. Para resolver esto, se pueden usar otros mecanismos como ReentrantLock.
