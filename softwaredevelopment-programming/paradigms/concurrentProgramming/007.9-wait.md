# `wait()`
El método `wait()` es una parte fundamental de la programación concurrente en Java y se utiliza para manejar la sincronización entre hilos. Es especialmente importante cuando varios hilos necesitan coordinarse y comunicarse entre sí para evitar problemas como condiciones de carrera (race conditions) o deadlocks.

##  ¿Qué es el método wait()?
* **Definición**: `wait()` es un método nativo de la clase `Object` en Java que se utiliza para pausar temporalmente la ejecución de un hilo y liberarlo del monitor o bloqueo que mantiene sobre un objeto. Esto permite que otros hilos puedan acceder al recurso compartido.

* **Dónde se utiliza**: Como `wait()` es parte de Object, puede ser invocado en cualquier objeto. Sin embargo, debe ser llamado dentro de un bloque sincronizado (`synchronized`), ya que el hilo debe poseer el bloqueo del objeto sobre el que se invoca `wait()`.

## ¿Para qué sirve `wait()`?
* **Sincronización y comunicación entre hilos**: `wait()` permite que los hilos se comuniquen entre sí. Se utiliza en situaciones donde un hilo necesita esperar hasta que otro hilo complete una acción antes de continuar. Por ejemplo, si un hilo está esperando a que se generen datos por otro hilo, puede invocar `wait()` hasta que los datos estén listos.

* **Coordinación de hilos**: En escenarios donde se trabaja con múltiples hilos que dependen unos de otros, `wait()` permite que un hilo se "suspenda" hasta que otro hilo lo "despierte" con `notify()` o `notifyAll()`.

## ¿Qué resuelve wait()?
1. **Problemas de sincronización**:
   * Cuando tienes múltiples hilos accediendo a un recurso compartido, es crucial coordinar su acceso para evitar errores como datos inconsistentes o resultados inesperados.

   * `wait()` ayuda a evitar estas situaciones permitiendo que un hilo se detenga hasta que otro hilo esté listo para proceder.

2. **Evita condiciones de carrera**:
   * Las condiciones de carrera ocurren cuando dos o más hilos acceden a recursos compartidos al mismo tiempo y el resultado depende del orden en el que se ejecutan. Usar `wait()` con `notify()` o `notifyAll()` ayuda a gestionar estos casos.

* **Eficiencia en el uso de recursos**:
  * Sin `wait()`, podrías necesitar un "busy waiting" (esperar activamente) que consume recursos del CPU. `wait()` pone el hilo en un estado de espera eficiente, sin consumir recursos hasta que sea notificado.

## ¿Cómo lo resuelve wait()?
* **Liberación de bloqueo**: Cuando se llama a wait() en un objeto, el hilo que lo invoca libera el bloqueo que tiene sobre el objeto y entra en el estado de espera. Esto permite que otros hilos puedan acceder al recurso compartido.

* **Estado de espera**: El hilo queda suspendido hasta que otro hilo invoque notify() o notifyAll() en el mismo objeto, lo que permite que el hilo que estaba esperando se despierte y continúe con su ejecución.

* **Comunicación mediante notify() y notifyAll()**:
  * notify(): Despierta un solo hilo que está esperando en el monitor del objeto.

  * notifyAll(): Despierta a todos los hilos que están esperando en el monitor del objeto. Los hilos despiertos deben volver a adquirir el bloqueo antes de continuar.

## Ejemplo de uso del método wait()
Aquí hay un ejemplo que muestra cómo `wait()`, `notify()` y synchronized trabajan juntos para coordinar la ejecución de hilos.

**Escenario**: Supongamos que tenemos un hilo productor que produce datos y un hilo consumidor que consume los datos. El consumidor debe esperar a que el productor genere los datos antes de poder consumirlos.

```java
class SharedResource {
    private int data;
    private boolean hasData = false;

    public synchronized void produce(int value) {
        while (hasData) {
            try {
                wait(); // Espera a que el consumidor consuma los datos
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                e.printStackTrace();
            }
        }
        this.data = value;
        hasData = true;
        System.out.println("Producido: " + data);
        notify(); // Notifica al consumidor que los datos están listos
    }

    public synchronized int consume() {
        while (!hasData) {
            try {
                wait(); // Espera a que el productor genere los datos
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                e.printStackTrace();
            }
        }
        hasData = false;
        System.out.println("Consumido: " + data);
        notify(); // Notifica al productor que los datos han sido consumidos
        return data;
    }
}

public class ProducerConsumerExample {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        Thread producer = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                resource.produce(i);
            }
        });

        Thread consumer = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                resource.consume();
            }
        });

        producer.start();
        consumer.start();
    }
}
```

## Puntos clave a considerar al usar wait()
1. **Solo se puede usar en un contexto sincronizado**:
   * `wait()` debe ser llamado dentro de un bloque `synchronized`. Esto se debe a que el hilo necesita tener el bloqueo del objeto antes de liberar el monitor.

2. **Liberación y adquisición de bloqueos**:
   * Cuando se llama a `wait()`, el hilo libera el bloqueo del objeto, lo que permite que otros hilos puedan adquirir ese bloqueo. Cuando el hilo es notificado, vuelve a adquirir el bloqueo antes de continuar.

3. **Manejo de excepciones**:
   * `wait()` puede lanzar InterruptedException, por lo que se debe manejar esta excepción correctamente. Es importante saber que cuando un hilo es interrumpido mientras espera, deja de estar en espera y lanza esta excepción.

## Alternativas y Mejores Prácticas
* **Evitar el uso directo de wait() y notify() en aplicaciones complejas**:
  * Aunque `wait()` y `notify()` son poderosos, su uso puede volverse difícil de manejar en aplicaciones complejas. Para manejar la sincronización de manera más fácil y segura, se recomienda usar clases de la biblioteca de concurrencia de Java, como `ReentrantLock`, `Condition`, `BlockingQueue`, y otros mecanismos que proporcionan una sincronización más avanzada y menos propensa a errores.
