# `Runnable`
La interfaz Runnable en Java es uno de los mecanismos más importantes para crear y gestionar tareas concurrentes. Es esencial para desarrollar aplicaciones multihilo porque proporciona una forma de definir el código que se ejecutará en un hilo sin tener que extender la clase `Thread`. Veamos en detalle todo lo que debes saber sobre `Runnable`.

## ¿Qué es Runnable?
* **Definición**: Runnable es una interfaz funcional en Java (desde Java 8), lo que significa que tiene un único método abstracto: run().

* **Uso principal**: La interfaz Runnable se utiliza para definir la lógica de una tarea que se ejecutará en un hilo. En lugar de extender la clase Thread, puedes implementar esta interfaz para crear objetos que contienen el código a ejecutar en un hilo.

## ¿Para qué sirve?
* **Separar la lógica del control del hilo**: **Runnable** permite definir la lógica de una tarea de forma independiente, sin tener que preocuparse por los aspectos del control del hilo (como iniciarlo o detenerlo). Esto significa que puedes crear múltiples tareas que implementen **Runnable** y luego usar diferentes instancias de **Thread** para ejecutarlas.

* **Reutilización**: Como **Runnable** es una interfaz, puedes implementarla en clases que ya extienden otras clases, lo que permite una mayor flexibilidad y reutilización del código (a diferencia de extender Thread, ya que Java no soporta herencia múltiple).

## Qué resuelve?
1. **Flexibilidad en la programación concurrente**:
   * **Separación de responsabilidades**: Permite separar la definición de una tarea (la lógica del código) del control del hilo, haciendo que el código sea más modular y flexible.

   * **Reutilización del código**: Puedes reutilizar el código de una tarea sin tener que preocuparte por cómo se ejecutará el hilo que la contiene.

2. **Limitaciones de la herencia**:
   * En Java, solo puedes extender una clase a la vez. Si necesitas que una clase sea concurrente pero ya estás extendiendo otra clase, implementar `Runnable` es la mejor opción.

   * Al usar `Runnable`, puedes aprovechar las capacidades concurrentes sin tener que heredar de `Thread`, lo que hace que el diseño sea más flexible.

## ¿Cómo lo resuelve?
* **Implementación sencilla**: Para usar `Runnable`, solo necesitas implementar el método `run()`, que contendrá la lógica de la tarea que deseas ejecutar en un hilo. Luego, puedes pasar una instancia de esta clase a un objeto Thread y usar `start()` para iniciar la ejecución de la tarea en un nuevo hilo.

* **Separación del código**: `Runnable` separa el comportamiento (definido en `run()`) de la gestión del hilo (`Thread`), lo que facilita la creación de programas concurrentes más limpios y modulares.

## Ejemplo básico
```java
public class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println("Hilo en ejecución: " + Thread.currentThread().getName() + " - Mensaje " + i);
            try {
                Thread.sleep(1000); // Pausa el hilo durante 1 segundo
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }

    public static void main(String[] args) {
        MyRunnable runnable = new MyRunnable();
        Thread hilo = new Thread(runnable); // Se pasa el Runnable al Thread
        hilo.start(); // Se inicia el hilo
    }
}
```
Salida
```plaintext
Hilo en ejecución: Thread-0 - Mensaje 0
Hilo en ejecución: Thread-0 - Mensaje 1
Hilo en ejecución: Thread-0 - Mensaje 2
Hilo en ejecución: Thread-0 - Mensaje 3
Hilo en ejecución: Thread-0 - Mensaje 4
```

## Ventajas de Usar Runnable
1. **Mayor Flexibilidad**:
   * Puedes implementar `Runnable` en una clase que ya hereda de otra clase, lo que no sería posible si estuvieras extendiendo Thread.

2. **Separación de Lógica y Control**:
   * Mantiene la lógica de la tarea separada del control del hilo, lo que facilita la reutilización del código y mejora la organización del software.

3. **Uso con APIs Concurrentes**:
   * `Runnable` se usa ampliamente en APIs concurrentes, como ExecutorService, que permite la gestión avanzada de hilos sin tener que controlar directamente los objetos Thread.
