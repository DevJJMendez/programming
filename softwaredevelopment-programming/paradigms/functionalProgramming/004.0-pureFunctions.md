# Funciones Puras
Las funciones puras son un concepto fundamental en la programación funcional. Son aquellas que, al recibir un conjunto de entradas, siempre devuelven el mismo resultado sin modificar el estado global ni tener efectos secundarios. En otras palabras, el resultado de una función pura depende solo de sus argumentos de entrada y no interactúa con el mundo externo, lo que las hace predecibles y fáciles de probar.

## Características de una Función Pura:
* **Determinismo**: Dado el mismo conjunto de argumentos, una función pura siempre devolverá el mismo resultado. No depende de variables externas que puedan cambiar.

* **Sin efectos secundarios**: No modifica variables globales, archivos, bases de datos, ni interactúa con el entorno externo de ninguna forma. Solo calcula y devuelve un valor.

* **Transparencia referencial**: Se refiere a que una función pura puede ser reemplazada por su valor de retorno sin alterar el comportamiento del programa.

## ¿Para qué sirven las funciones puras?
1. **Predecibilidad**: Al ser determinísticas, es fácil predecir su comportamiento. Si pruebas la función con ciertos datos, siempre dará el mismo resultado, lo que facilita la depuración.

2. **Testabilidad**: Dado que no dependen de estados externos, las funciones puras son fáciles de probar unitariamente. No es necesario preparar el entorno para verificar su comportamiento.

3. **Composición**: Las funciones puras pueden combinarse fácilmente para crear funciones más complejas. Esto es clave en la programación funcional, donde se busca construir el software a partir de funciones pequeñas y reutilizables.

## ¿Qué resuelven las funciones puras?
Las funciones puras ayudan a reducir la complejidad de un sistema al eliminar la necesidad de manejar estados mutables o efectos secundarios no controlados. Esto mejora la legibilidad, la mantenibilidad y reduce la cantidad de errores. También resuelven problemas relacionados con la concurrencia, ya que no hay estados compartidos que puedan generar condiciones de carrera.

## ¿Cómo se implementan las funciones puras?

* Ejemplo en `Java`, una función pura simplemente toma argumentos, lo procesa y devuelve un valor sin alterar el estado externo.

  ```java
  public class FuncionesPuras {

      // Función pura: dado dos números, siempre devolverá la suma sin efectos secundarios
      public static int sumar(int a, int b) {
          return a + b;
      }

      public static void main(String[] args) {
          System.out.println(sumar(3, 5)); // Salida: 8
      }
  }
  ```
  Aquí, la función sumar es pura porque:
    * No modifica ningún estado externo.

    * Dado los mismos valores de entrada, siempre devuelve el mismo resultado.

    * No tiene efectos secundarios.

## Ejemplo de una función impura
```java
public class FuncionesImpuras {

    private static int contador = 0;

    // Esta función es impura porque modifica una variable externa (estado global)
    public static int incrementarContador() {
        return ++contador;
    }

    public static void main(String[] args) {
        System.out.println(incrementarContador()); // Resultado: 1
        System.out.println(incrementarContador()); // Resultado: 2 (diferente resultado para la misma llamada)
    }
}
```
Esta función es impura porque modifica una variable global (`contador`), lo que significa que su comportamiento depende de ese estado externo. Si la llamamos varias veces, devolverá resultados diferentes, lo que no ocurre con una función pura.

**Función Pura equivalente**
```java
public class FuncionesPuras {

    // Ahora esta función es pura porque no modifica ningún estado externo
    public static int incrementar(int valor) {
        return valor + 1;
    }

    public static void main(String[] args) {
        int contador = 0;
        System.out.println(incrementar(contador)); // Resultado: 1
        System.out.println(incrementar(contador)); // Resultado: 1, contador no ha cambiado
    }
}
```
En esta versión, `incrementar` es una función pura. No depende de una variable externa ni la modifica, simplemente recibe un valor y devuelve el incremento de ese valor, haciendo el código más predecible y fácil de razonar.

## Ventajas de las funciones puras
1. **Fácil depuración**: Dado que el resultado de una función pura depende únicamente de sus parámetros, puedes probar fácilmente su salida para cualquier entrada específica sin preocuparte por el estado del programa.

2. **Concurrencia segura**: Dado que no hay modificación del estado global ni efectos secundarios, las funciones puras son seguras para ejecutarse en entornos concurrentes, lo que las hace útiles en aplicaciones multihilo.

3. **Reutilización**: Las funciones puras son independientes de estados externos, lo que significa que pueden reutilizarse en diferentes contextos sin riesgo de alterar otros aspectos del programa.

4. **Transparencia referencial**: Puedes reemplazar una función pura por su resultado en cualquier punto del programa sin afectar la lógica, lo que facilita optimizaciones y simplifica el análisis.

## Desventajas
1. **Limitaciones en ciertas aplicaciones**: No todas las operaciones pueden implementarse con funciones puras. Por ejemplo, interactuar con bases de datos, hacer llamadas de red o modificar archivos requiere efectos secundarios.

2. **Curva de aprendizaje**: Aunque el concepto de funciones puras es sencillo, aplicar un enfoque puramente funcional en todo el sistema puede ser desafiante si estás acostumbrado a otros paradigmas de programación, como la orientación a objetos.

# Transparencia Referencial
La transparencia referencial es un concepto clave en la programación funcional, que se refiere a la capacidad de reemplazar una **expresión** por su **valor** sin cambiar el comportamiento del programa. Dicho de otra manera, una expresión es "transparentemente referencial" si siempre que se evalúa produce el mismo resultado, y por lo tanto, puede ser sustituida por ese valor en cualquier parte del programa.

## ¿Qué significa la transparencia referencial?
* **Consistencia**: Si una expresión (como una llamada a una función) siempre devuelve el mismo resultado cuando se le pasa el mismo conjunto de argumentos, esa expresión es referencialmente transparente.

* **Inmutabilidad del resultado**: El valor que devuelve no cambia en el tiempo ni depende de factores externos que puedan alterarlo, como estados globales o variables que cambian de valor.

## Ejemplo
Una función pura es referencialmente transparente porque su salida depende únicamente de sus entradas. 

```java
public class TransparenciaReferencial {

    // Función pura
    public static int sumar(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int resultado = sumar(2, 3); // Siempre será 5
        System.out.println(resultado); // Resultado: 5

        // Transparencia referencial: podemos reemplazar "sumar(2, 3)" por su valor 5
        System.out.println(5); // Esto sería equivalente a la línea anterior
    }
}
```
Aquí, la función `sumar(2, 3)` es referencialmente transparente, porque siempre que se invoque con los mismos argumentos `(2 y 3)`, devolverá el mismo resultado `(5)`. Podemos reemplazar todas las instancias de `sumar(2, 3)` por **5** sin alterar el comportamiento del programa.

## ¿Para qué sirve la transparencia referencial?
1. **Facilita el razonamiento**: Al saber que una expresión siempre produce el mismo valor, puedes predecir el comportamiento del código con mayor facilidad. Esto simplifica la comprensión y depuración del código.

2. **Optimización**: Los compiladores pueden realizar optimizaciones como la memoización (guardar el resultado de una función para evitar cálculos repetidos) si las funciones involucradas son referencialmente transparentes. Esto puede mejorar el rendimiento.

3. **Facilita el testing**: Debido a que una función referencialmente transparente siempre devuelve el mismo valor para los mismos argumentos, puedes probarla fácilmente en aislamiento sin preocuparte por estados externos.

## ¿Qué resuelve la transparencia referencial?
* **Evita la complejidad de estados mutables**: En lenguajes orientados a objetos o imperativos, el estado de un programa puede cambiar constantemente, lo que hace difícil predecir el comportamiento de una función. Con la transparencia referencial, no tienes que preocuparte por estados mutables o efectos secundarios inesperados.

* **Concurrente seguro**: Al no depender de estados globales ni mutables, las funciones referencialmente transparentes pueden ejecutarse de manera segura en entornos concurrentes sin riesgo de condiciones de carrera.

## Ejemplo de función No referencialmente transparente
Un ejemplo de una función que no es referencialmente transparente es una que depende de variables externas o modifica el estado global.

```java
public class NoTransparenciaReferencial {

    private static int contador = 0;

    // Función no pura, depende de una variable externa (contador)
    public static int incrementarContador() {
        return ++contador;
    }

    public static void main(String[] args) {
        System.out.println(incrementarContador()); // El resultado cambia cada vez que la llamamos
        System.out.println(incrementarContador());
    }
}
```
Aquí, la función `incrementarContador` no es referencialmente transparente porque depende del valor de `contador`, que es una variable global. Si llamamos a esta función varias veces, no obtendremos el mismo resultado, porque su comportamiento depende del estado de contador en cada momento.

## Ventajas de la transparencia referencial
1. **Código más predecible**: El código que sigue el principio de la transparencia referencial es más fácil de leer y entender, porque sabes que las funciones siempre devolverán los mismos resultados para las mismas entradas.

2. **Fácil de probar**: Puedes probar funciones puras y referencialmente transparentes de manera aislada, ya que no dependen de estados globales o externos.

3. **Refactorización segura**: Si una función es referencialmente transparente, puedes mover, reutilizar o refactorizar el código sin preocuparte de alterar su comportamiento.

4. **Optimización por parte del compilador**: Los compiladores pueden realizar optimizaciones automáticas, como eliminar llamadas a funciones redundantes o reemplazar llamadas a funciones por sus valores calculados previamente.
