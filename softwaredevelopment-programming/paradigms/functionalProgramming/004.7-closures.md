# Closures
Las closures son un concepto importante en programación funcional y también se encuentran en algunos lenguajes orientados a objetos, como Java desde la versión 8 en adelante, gracias a las expresiones lambda. Aunque Java no utiliza explícitamente el término "closures", el concepto está presente cuando trabajamos con lambdas y referencias a variables locales en un contexto exterior.

## ¿Qué son las closures?
Una closure es una función o bloque de código que:

1. Captura y retiene el acceso a las variables de su entorno o contexto externo, incluso después de que ese entorno haya dejado de existir o no sea accesible.

2. Mantiene ese acceso sin necesidad de que las variables capturadas sean explícitamente pasadas como parámetros.

Este comportamiento permite que una función anidada "recuerde" las variables que estaban en su contexto cuando fue definida, y las siga utilizando más tarde, incluso si esas variables ya no están en el alcance normal.

## ¿Para qué sirven las closures?
Las closures se utilizan principalmente para:

1. Retener estados o valores entre diferentes invocaciones de funciones, permitiendo que una función "recuerde" variables del contexto donde fue creada.

2. Crear funciones más dinámicas que pueden modificar su comportamiento dependiendo del entorno.

3. Evitar el uso excesivo de variables globales al proporcionar una forma de encapsular estados o valores.

4. Facilitar el uso de patrones funcionales como el uso de funciones de alto orden, programación asíncrona y callbacks.

## ¿Qué resuelven las closures?
Las closures resuelven varios problemas en el desarrollo de software, como:

1. **Mantener el estado**: A veces, necesitamos que una función conserve un estado entre ejecuciones. En lugar de usar variables globales (lo cual puede ser problemático por cuestiones de concurrencia y mantenimiento), las closures permiten mantener el estado dentro de la función de una manera controlada.

2. **Modularidad y encapsulación**: Las closures permiten definir funciones que operan sobre un estado "interno" sin necesidad de exponerlo al mundo exterior. Esto favorece la encapsulación, lo cual es crucial en el desarrollo de software robusto y mantenible.

3. **Funciones de alto orden**: En el paradigma funcional, las closures son esenciales para implementar funciones que devuelven otras funciones o reciben funciones como argumento.

4. **Simplificación de código asíncrono**: En programación asíncrona, las closures permiten que las callbacks accedan a datos que estaban en el entorno donde fueron definidas, incluso si esos datos ya no están en el contexto actual.

## ¿Cómo lo resuelven?
Las closures resuelven estos problemas capturando el entorno léxico (las variables locales que están en el alcance cuando se crea la función) y asociándolo a la función misma. Esto permite que la función tenga acceso a esas variables incluso si el entorno original ya no existe.

En Java, una lambda o expresión lambda puede comportarse como una closure cuando captura variables de su contexto exterior. Estas variables deben ser efectivamente finales para poder ser capturadas, lo que significa que no deben cambiar su valor una vez asignado.

## Ejemplo en Java
En Java, aunque no se use el término "closure" directamente, las expresiones lambda y las clases anónimas pueden capturar el estado de variables locales. A continuación te muestro un ejemplo de cómo una lambda actúa como una closure:

```java
import java.util.function.Supplier;

public class EjemploClosure {
    public static void main(String[] args) {
        String mensaje = "Hola, soy una variable local";

        // Creamos una closure usando una expresión lambda
        Supplier<String> closure = () -> {
            return mensaje;
        };

        // Ejecutamos la closure
        System.out.println(closure.get()); // Imprime: "Hola, soy una variable local"
    }
}
```
En este ejemplo:

* La lambda `() ->` mensaje captura la variable mensaje del entorno exterior.

* Incluso si no estamos en el contexto donde la variable mensaje fue definida, la lambda tiene acceso a ella cuando se ejecuta la función `closure.get()`.

## Closures y Variables "Efectivamente Finales"
En Java, para que una variable local sea capturada en una closure, debe ser efectivamente final. Esto significa que su valor no puede cambiar después de su asignación inicial. Esto garantiza que no haya comportamientos inesperados cuando se capturan variables dentro de lambdas o clases anónimas.

Por ejemplo, si intentas modificar una variable capturada dentro de una lambda, el compilador te dará un error:

```java
public class EjemploClosureError {
    public static void main(String[] args) {
        int contador = 10;

        // Error: No se puede modificar una variable capturada dentro de una lambda
        Runnable runnable = () -> {
            // contador++; // Error: Variable local debe ser final o efectivamente final
        };

        runnable.run();
    }
}
```
El compilador necesita que las variables capturadas sean finales o efectivamente finales para evitar posibles inconsistencias en su valor cuando se ejecutan en diferentes hilos o contextos.
