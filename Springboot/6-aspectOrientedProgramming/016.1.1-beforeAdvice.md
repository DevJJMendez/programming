## @Before Advice
En el contexto de Aspect-Oriented Programming (AOP), específicamente en frameworks como AspectJ o Spring AOP, un @Before advice es un tipo de advice que se ejecuta antes de la ejecución de un método objetivo (target method). Este tipo de advice es útil para ejecutar lógica previa, como validaciones, autenticaciones, o logging, antes de que el método principal se ejecute.

### ¿Qué es un @Before Advice?
Es un tipo de advice en AOP que se ejecuta antes de la ejecución de un **join point**. Un **join point** es un punto en el flujo de ejecución de un programa, como la invocación de un método o la manipulación de un campo.

En **AspectJ** o **Spring AOP**, el **@Before** advice se declara utilizando la anotación `@Before` seguida de una expresión de **pointcut** que define cuándo debe aplicarse el **advice**.

```java
@Before("execution(* com.example.service.*.*(..))")
public void beforeAdvice(JoinPoint joinPoint) {
    // Lógica que se ejecuta antes del método objetivo
    System.out.println("Antes de la ejecución del método: " + joinPoint.getSignature().getName());
}
```

### ¿Cómo Funciona @Before Advice?
* **Pointcut Expression**: La expresión dentro de `@Before` define el pointcut, que es una expresión que selecciona uno o más **join points** donde se debe aplicar el advice. En el ejemplo anterior, el pointcut `"execution(* com.example.service.*.*(..))"` selecciona todos los métodos en cualquier clase del paquete `com.example.service`.

* **Ejecución Previa**: Cuando el join point definido en el pointcut es alcanzado en la ejecución del programa, el advice anotado con `@Before` se ejecuta automáticamente antes de que el método objetivo se ejecute.

* **Uso de JoinPoint**: El parámetro JoinPoint (opcional) puede ser inyectado en el método de advice para acceder a detalles sobre el join point actual, como el nombre del método, los argumentos pasados, y el objeto objetivo.

### ¿Para qué se Usa @Before Advice?
El `@Before` advice es ideal para tareas que deben realizarse justo antes de la ejecución de un método. Algunos casos de uso comunes incluyen:

* **Logging**: Registrar la entrada de métodos, incluyendo los argumentos pasados y el nombre del método.

* **Validación**: Realizar validaciones preliminares sobre los argumentos del método.

* **Autenticación/Autorización**: Verificar si el usuario está autenticado o tiene los permisos necesarios antes de ejecutar el método.

* **Preparación de Recursos**: Inicializar recursos necesarios para la ejecución del método, como abrir conexiones a bases de datos.
