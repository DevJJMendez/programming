## @Around Advice
El `@Around` advice es uno de los tipos más poderosos y flexibles de advice en Aspect-Oriented Programming (AOP). Permite interceptar la ejecución de un método y controlarla completamente, lo que significa que puedes ejecutar lógica antes y después del método objetivo, modificar el valor de retorno, o incluso evitar que el método original se ejecute.

El @Around advice envuelve la ejecución de un método objetivo. Proporciona un control completo sobre la invocación del método, permitiendo realizar tareas antes y después de la ejecución del método, o reemplazar completamente la lógica del método.

Se utiliza en situaciones donde necesitas realizar operaciones tanto antes como después de un método, como logging detallado, manejo de transacciones, seguridad, o incluso modificar el comportamiento del método (como cambiar sus argumentos o el valor de retorno).

### Cómo Funciona el @Around Advice
El **`@Around` advice** recibe un objeto del tipo ProceedingJoinPoint, que representa el método objetivo. Este objeto permite controlar la ejecución del método, incluyendo:

* **Ejecutar el método objetivo**: Mediante el método `proceed()` del **ProceedingJoinPoint**.

* **Modificar los argumentos**: Puedes cambiar los argumentos antes de ejecutar el método.

* **Modificar el valor de retorno**: Puedes interceptar y cambiar el valor de retorno del método objetivo.

* **Evitar la ejecución del método**: Si no llamas a `proceed()`, el método objetivo no se ejecutará.

### Ejemplo Básico de @Around Advice
```java
@Aspect
@Component
public class PerformanceAspect {

    @Around("execution(* com.example.service.*.*(..))")
    public Object measureExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        
        // Ejecutar el método objetivo
        Object result = joinPoint.proceed();
        
        long executionTime = System.currentTimeMillis() - start;
        System.out.println(joinPoint.getSignature() + " ejecutado en " + executionTime + "ms");
        
        return result;
    }
}
```
**Explicación del Ejemplo**
* **Antes de la ejecución**: Se registra el tiempo de inicio.

* **Ejecución del método objetivo**: Se llama a proceed(), lo que ejecuta el método que fue interceptado.

* **Después de la ejecución**: Se calcula el tiempo total de ejecución y se imprime.

* **Valor de retorno**: Finalmente, se retorna el resultado del método original.

### 
Modificación de Argumentos y Valor de Retorno
El @Around advice también permite modificar los argumentos antes de la ejecución y cambiar el valor de retorno:

```java
@Around("execution(* com.example.service.UserService.findUser(..))")
public Object modifyArgumentsAndReturnValue(ProceedingJoinPoint joinPoint) throws Throwable {
    Object[] args = joinPoint.getArgs();

    // Modificar los argumentos (por ejemplo, cambiar el primer argumento)
    if (args.length > 0 && args[0] instanceof String) {
        args[0] = ((String) args[0]).toUpperCase();
    }

    // Ejecutar el método con los argumentos modificados
    Object result = joinPoint.proceed(args);

    // Modificar el valor de retorno
    if (result instanceof String) {
        result = ((String) result).toLowerCase();
    }

    return result;
}
```
### Cuándo Utilizar @Around Advice
* **Casos Complejos**: Cuando necesitas una flexibilidad total para controlar la ejecución del método.

* **Medición de Rendimiento**: Para medir tiempos de ejecución o para implementar patrones como el de Circuit Breaker.

* **Modificación de Argumentos o Retorno**: Cuando es necesario alterar el comportamiento del método, como cambiar sus parámetros de entrada o su valor de retorno.

### Ventajas de @Around Advice
* **Control Total**: Permite controlar completamente la ejecución del método interceptado, incluyendo modificar argumentos y valores de retorno.

* **Versatilidad**: Es útil para casos complejos donde se necesita lógica antes y después del método, o cuando se desea reemplazar o condicionar la ejecución del método original.

* **Optimización**: Puede utilizarse para medir y optimizar el rendimiento de los métodos, como en el ejemplo de medir tiempos de ejecución.

### Desventajas de @Around Advice
* **Complejidad**: Dado que envuelve la lógica completa de la ejecución del método, puede hacer que el código sea más difícil de entender y mantener.

* **Rendimiento**: Debido a que puede modificar cada aspecto de la ejecución de un método, un uso excesivo o inapropiado puede introducir un overhead significativo y potencialmente degradar el rendimiento de la aplicación.

* **Errores Potenciales**: Si el `proceed()` no se llama en el **`@Around` advice**, el método interceptado no se ejecutará, lo que podría causar errores o comportamientos inesperados en la aplicación.
