## Java Archive
Un **JAR (Java ARchive)** es un formato de archivo que agrupa muchos archivos en uno solo, similar a un archivo **ZIP**. Se usa principalmente para agrupar archivos de clase Java, metadatos y recursos (como imágenes y archivos de texto) en un solo archivo para su distribución y uso.

**Características de un JAR**
* **Agrupación**: Permite agrupar múltiples archivos en un solo archivo comprimido.

* **Portabilidad**: Facilita la distribución de bibliotecas Java y aplicaciones completas.

* **Metadatos**: Contiene un archivo `META-INF/MANIFEST.MF` que puede incluir información sobre el archivo JAR, como la clase principal para aplicaciones ejecutables.

**Estructura**:
Un **JAR** agrupa múltiples archivos en un solo archivo comprimido. La estructura interna de un archivo JAR puede variar dependiendo del propósito, pero generalmente incluye lo siguiente:

- **Directorio raíz**: Contiene los archivos de clase compilados y otros recursos.

- `META-INF/`: Contiene metadatos sobre el archivo JAR, incluyendo el archivo `MANIFEST.MF`.

Ejemplo:
```bash
miapp.jar
├── META-INF/
│   └── MANIFEST.MF
├── com/
│   └── ejemplo/
│       ├── Main.class
│       ├── Util.class
│       └── Modelo.class
└── recursos/
    ├── config.properties
    └── imagen.png
```
* `META-INF/MANIFEST.MF`: El archivo de manifiesto que puede incluir información sobre la versión, las dependencias y la clase principal para ejecutar (si es un JAR ejecutable).

* **Archivos de clase y recursos**: Los archivos de clase compilados (.class) y otros recursos necesarios para la aplicación.
  
## Web Application Archive
Un WAR (Web Application ARchive) es un archivo que agrupa una colección de recursos web (archivos JSP, servlets, archivos HTML, imágenes, etc.) y archivos de configuración necesarios para implementar una aplicación web en un servidor de aplicaciones Java, como **Apache Tomcat**.

**Características de un WAR**
* **Estructura**: Sigue una estructura específica con directorios como **WEB-INF**, **META-INF**, y archivos de recursos.

* **Configuración**: Contiene un archivo `web.xml` en el directorio **WEB-INF** que configura la aplicación web.

* **Portabilidad**: Facilita la distribución y despliegue de aplicaciones web Java.

**Estructura**:
Sigue una estructura más estricta que un archivo JAR y está destinado a ser desplegado en un servidor de aplicaciones.

Ejemplo:
```bash
miapp.war
├── META-INF/
│   └── MANIFEST.MF
├── WEB-INF/
│   ├── web.xml
│   ├── classes/
│   │   ├── com/
│   │   │   └── ejemplo/
│   │   │       ├── Controlador.class
│   │   │       └── Servicio.class
│   ├── lib/
│   │   ├── biblioteca1.jar
│   │   └── biblioteca2.jar
│   └── src/
│       ├── script.sql
│       └── data.json
├── index.jsp
└── recursos/
    ├── css/
    │   └── estilo.css
    └── js/
        └── script.js
```
* `META-INF/`: Contiene metadatos sobre el archivo WAR, similar a los archivos JAR.

* `MANIFEST.MF`: Archivo de manifiesto que puede contener información adicional sobre el archivo **WAR**.

* `WEB-INF/`: Contiene archivos y directorios que no están accesibles directamente desde el navegador web.

* `web.xml`: Archivo de configuración que define los servlets, filtros y otros componentes de la aplicación web.

* `classes/`: Contiene las clases Java compiladas utilizadas por la aplicación web.

* `lib/`: Contiene bibliotecas adicionales (archivos JAR) que la aplicación web necesita.

* `src/`: Archivos de origen y datos de la aplicación web.

* **Archivos en la raíz del archivo WAR**: Contienen archivos accesibles públicamente como archivos **JSP**, **HTML**, imágenes, etc.
  
* `recursos/`: Subdirectorios que contienen recursos estáticos como CSS y JavaScript.

## Diferencias
1. **Propósito**:
   * **JAR**: Se usa para agrupar bibliotecas y aplicaciones Java que no necesariamente son aplicaciones web.
   
   * WAR: Se usa específicamente para aplicaciones web Java.

2. **Estructura**:
    * **JAR**: No sigue una estructura específica, más allá de incluir un archivo MANIFEST.MF.
    * **WAR**: Sigue una estructura específica con directorios WEB-INF y META-INF, y puede incluir web.xml.

3. **Despliegue**:
   * **JAR**: Se ejecuta directamente con la máquina virtual Java.
   * **WAR**: Se despliega en un servidor de aplicaciones o contenedor web.
