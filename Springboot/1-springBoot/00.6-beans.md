# Beans
En Spring, un **`Bean`** es un objeto que es **instanciado**, **ensamblado** y **gestionado** por el contenedor `IoC` de Spring. 

Los **`Beans`** son los **componentes centrales** en la arquitectura de Spring y representan los objetos que forman la base de una aplicación Spring.

- **Definición de `Beans`**

* **Mediante Anotaciones**

`MyBean.java`
```java
import org.springframework.stereotype.Component;

@Component
public class MyBean {
    public void doSomething() {
        System.out.println("Doing something");
    }
}
```
En este ejemplo, la anotación `@Component` indica que `MyBean` es un **Bean** gestionado por el contenedor `IoC` de Spring.

* **Mediante `XML`**

`applicationContext.xml`
```xml
<Beans xmlns="http://www.springframework.org/schema/Beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/Beans
       http://www.springframework.org/schema/Beans/spring-Beans.xsd">

    <Bean id="myBean" class="com.example.MyBean"/>
</Beans>
```

* **Mediante `JavaConfig`**

`AppConfig.java`
```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {
    @Bean
    public MyBean myBean() {
        return new MyBean();
    }
}
```
## Ciclo de Vida
El ciclo de vida de un Bean en Spring es el proceso completo que abarca desde la creación del Bean hasta su destrucción, gestionado por el contenedor `IoC` de Spring. 

**Ciclo de Vida de un Bean en Spring**

1. **Instanciación**: El contenedor `IoC` de Spring crea una instancia del Bean utilizando el constructor por defecto o un constructor específico.

2. **Inyección de Dependencias**: Spring inyecta las dependencias necesarias en el Bean utilizando la inyección de dependencias (`DI`). Esto puede incluir la inyección de valores de propiedades, dependencias de otros Beans, etc.

  * **Seteo de la Fábrica de Beans** (`BeanNameAware`, `BeanFactoryAware`, `ApplicationContextAware`):
    
    * Si el Bean implementa alguna de las interfaces `BeanNameAware`, `BeanFactoryAware` o `ApplicationContextAware`, los métodos correspondientes se llaman para proporcionar información al Bean sobre su nombre, la fábrica de Beans o el contexto de la aplicación.
      ```java
      public class MyBean implements BeanNameAware, BeanFactoryAware, ApplicationContextAware {
          @Override
          public void setBeanName(String name) {
              System.out.println("Bean Name: " + name);
          }

          @Override
          public void setBeanFactory(BeanFactory BeanFactory) {
              System.out.println("Bean Factory set");
          }

          @Override
          public void setApplicationContext(ApplicationContext applicationContext) {
              System.out.println("Application Context set");
          }
      }
      ```
   *  **Configuración de `BeanPostProcessor` (Antes de Inicialización)**:
   
      * Los `BeanPostProcessor` son Beans especiales que pueden interceptar el ciclo de vida de otros Beans. El método `postProcessBeforeInitialization` se llama antes de la inicialización del Bean.
        ```java
        public class MyBeanPostProcessor implements BeanPostProcessor {
            @Override
            public Object postProcessBeforeInitialization(Object Bean, String BeanName) {
                System.out.println("Before Initialization : " + BeanName);
                return Bean;
            }

            @Override
            public Object postProcessAfterInitialization(Object Bean, String BeanName) {
                System.out.println("After Initialization : " + BeanName);
                return Bean;
            }
        }
        ```
3. **Inicialización del Bean**: Si se especifica un método de inicialización (mediante anotaciones como `@PostConstruct` o configuraciones específicas en `XML/JavaConfig`), se llama a este método. 
    
    ```java
    @Component
    public class MyBean {
        @PostConstruct
        public void init() {
            System.out.println("Bean is going through init.");
        }

        @PreDestroy
        public void destroy() {
            System.out.println("Bean will destroy now.");
        }

        public void doSomething() {
            System.out.println("Doing something");
        }
    }
    ```

   * **Configuración de `BeanPostProcessor` (Después de Inicialización)**: Después de la inicialización, el método `postProcessAfterInitialization` de cualquier `BeanPostProcessor` se llama.

4. **Uso del Bean**: El **Bean** está listo para ser utilizado en la aplicación. En este punto, el **Bean** puede servir sus propósitos en la lógica de la aplicación.

5. **Destrucción del Bean**: Antes de que el contenedor IoC destruya el **Bean**, se llama al método de destrucción si está configurado (mediante anotaciones como @PreDestroy o configuraciones específicas en `XML/JavaConfig`).

### @PostConstruct
se utiliza para marcar un método que debe ser ejecutado después de que el **Bean** haya sido creado y sus dependencias inyectadas. Es útil para realizar cualquier inicialización necesaria después de la construcción del Bean.

**Características Clave**
* **Inicialización**: Se ejecuta una vez que el **Bean** ha sido completamente creado y sus dependencias han sido inyectadas.

* **Un solo método**: Solo un método en una clase Bean debe estar anotado con `@PostConstruct`.

* **Método sin argumentos**: El método anotado con `@PostConstruct` no debe tener argumentos.

**Ejemplo**
```java
import javax.annotation.PostConstruct;
import org.springframework.stereotype.Component;

@Component
public class MyBean {

    @PostConstruct
    public void init() {
        // Código de inicialización
        System.out.println("Bean ha sido inicializado.");
    }
}
```
En este ejemplo, el método `init` se ejecutará después de que `MyBean` haya sido creado y sus dependencias inyectadas.

### @PreDestroy
se utiliza para marcar un método que debe ser ejecutado justo antes de que el Bean sea destruido. Es útil para realizar tareas de limpieza, como cerrar recursos o liberar conexiones.

**Características Clave**

* **Limpieza**: Se ejecuta justo antes de que el **Bean** sea destruido.

* **Un solo método**: Solo un método en una clase **Bean** debe estar anotado con `@PreDestroy`.

* **Método sin argumentos**: El método anotado con `@PreDestroy` no debe tener argumentos.

**Ejemplo**
```java
import javax.annotation.PreDestroy;
import org.springframework.stereotype.Component;

@Component
public class MyBean {

    @PreDestroy
    public void cleanup() {
        // Código de limpieza
        System.out.println("Bean va a ser destruido.");
    }
}
```
En este ejemplo, el método `cleanup` se ejecutará justo antes de que `MyBean` sea destruido.

### Integración con Spring

Estas anotaciones funcionan perfectamente en Spring Framework, tanto en configuraciones basadas en anotaciones como en **XML**. No requieren configuración adicional cuando se utilizan en combinación con `@Component`, `@Service`, `@Repository`, o cualquier otra anotación de estereotipo de Spring.

## Scopes
El alcance (scope) de un **Bean** en Spring define el ciclo de vida y la visibilidad del B**e**an dentro del contenedor `IoC`. Los diferentes alcances determinan cómo y cuándo se crean las instancias de los **Beans**. Spring ofrece varios tipos de scopes que permiten un control granular sobre cómo se gestionan los **Beans**.

**Tipos**

1. **`Singleton`**: Un único **Bean** por contenedor IoC. Es el alcance por defecto en Spring.
   
   * Es cacheado en memoria.
   
   * Sera referenciado en todas la inyecciones de dependencia que se le hagan.

   * Opcionalmente, podemos especificar el alcance: `@Scope(ConfigurableBeanFactory.SCOPE_SINGLETON)`
  **Ejemplo**
  ```java
  @Component
  // @Scope(ConfigurableBeanFactory.SCOPE_SINGLETON)
  public class MySingletonBean {
      // Este Bean es único en el contenedor IoC
  }
  ```

1. **`Prototype`**: Un nuevo **Bean** es creado cada vez que se solicita. Este **Bean** es adecuado para casos en los que se necesita un nuevo estado en cada uso.

  **Ejemplo** 
  ```java
  @Component
  @Scope("prototype")
  public class MyPrototypeBean {
      // Este Bean es una nueva instancia cada vez que se solicita
  }
  ```

3. **`Request`**: Un único **Bean** por petición HTTP. (Solo en aplicaciones web) Este **Bean** vive solo durante la duración de una petición HTTP.
  
  **Ejemplo**
  ```java
  @Component
  @Scope(value = WebApplicationContext.SCOPE_REQUEST, proxyMode = ScopedProxyMode.TARGET_CLASS)
  public class MyRequestBean {
      // Este Bean es único por cada petición HTTP
  }
  ```

4. Session: Un único **Bean** por sesión HTTP. (Solo en aplicaciones web). Este **Bean** vive durante toda la sesión HTTP del usuario.

  **Ejemplo**
  ```java
  @Component
  @Scope(value = WebApplicationContext.SCOPE_SESSION, proxyMode = ScopedProxyMode.TARGET_CLASS)
  public class MySessionBean {
      // Este Bean es único por cada sesión HTTP
  }
  ```

5. **`Global Session`**: Un único **Bean** por sesión global HTTP. (Solo en aplicaciones web con portlets). Este **Bean** vive durante toda la sesión global.

  **Ejemplo**
  ```java
  @Component
  @Scope(value = WebApplicationContext.SCOPE_GLOBAL_SESSION, proxyMode = ScopedProxyMode.TARGET_CLASS)
  public class MyGlobalSessionBean {
      // Este Bean es único por cada sesión global HTTP
  }
  ```

6. Application: Un único **Bean** por el ciclo de vida de un ServletContext. Este **Bean** vive durante toda la vida del ServletContext.

  **Ejemplo**
  ```java
  @Component
  @Scope(value = WebApplicationContext.SCOPE_APPLICATION)
  public class MyApplicationBean {
      // Este Bean es único por el ciclo de vida del ServletContext
  }
  ```

### Configuración del Scope en Beans

* **Mediante Anotaciones**

El alcance de un **Bean** se puede configurar utilizando la anotación `@Scope` junto con la anotación `@Component`.

**Ejemplo**
```java
import org.springframework.context.annotation.Scope;
import org.springframework.stereotype.Component;

@Component
@Scope("prototype")
public class MyPrototypeBean {
    // Este Bean será una nueva instancia cada vez que se solicite
}
```

* **Mediante `XML`**

El alcance de un **Bean** también se puede configurar en un archivo de configuración XML.

**Ejemplo**
```xml
<Beans xmlns="http://www.springframework.org/schema/Beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/Beans
       http://www.springframework.org/schema/Beans/spring-Beans.xsd">

    <Bean id="myPrototypeBean" class="com.example.MyPrototypeBean" scope="prototype"/>
</Beans>
```

* **Mediante `JavaConfig`**

El alcance de un **Bean** se puede configurar en una clase de configuración Java utilizando la anotación `@Bean` y `@Scope`.

**Ejemplo**
```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Scope;

@Configuration
public class AppConfig {
    @Bean
    @Scope("prototype")
    public MyPrototypeBean myPrototypeBean() {
        return new MyPrototypeBean();
    }
}
```

### Proxies para Scopes Personalizados
Para ciertos scopes como request y session, es necesario usar proxies debido a la naturaleza de estos scopes en aplicaciones web. Esto se hace configurando `proxyMode` en la anotación `@Scope`.

**Ejemplo**
```java
import org.springframework.context.annotation.Scope;
import org.springframework.context.annotation.ScopedProxyMode;
import org.springframework.stereotype.Component;
import org.springframework.web.context.WebApplicationContext;

@Component
@Scope(value = WebApplicationContext.SCOPE_REQUEST, proxyMode = ScopedProxyMode.TARGET_CLASS)
public class MyRequestBean {
    // Este Bean es único por cada petición HTTP
}
```

## Configuración 
La configuración de **Beans** en Spring es un aspecto fundamental para el manejo de la inversión de control (`IoC`) y la inyección de dependencias (`DI`). Los **Beans** representan los componentes y servicios de la aplicación que Spring gestiona.

### Métodos para Definir Beans

1. **Configuración basada en XML**:
   * Utiliza un archivo XML para definir y configurar beans.

2. **Configuración basada en anotaciones**:
   * Utiliza anotaciones como `@Component`, `@Service`, `@Repository`, y `@Controller`.

3. **Configuración basada en Java (Java Configuration)**:
   * Utiliza clases Java anotadas con `@Configuration` y métodos anotados con `@Bean`.

### Configuración basada en XML
La configuración basada en XML es la forma tradicional de definir **Beans** en Spring. Se utiliza un archivo de configuración XML para declarar los beans y sus dependencias.

`beans.mxl`
```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
                           http://www.springframework.org/schema/beans/spring-beans.xsd">

    <bean id="myService" class="com.example.MyService">
        <property name="repository" ref="myRepository"/>
    </bean>

    <bean id="myRepository" class="com.example.MyRepository"/>
</beans>
```

### Configuración basada en Anotaciones
Spring permite la configuración mediante anotaciones, lo que hace que el código sea más conciso y fácil de leer. Las anotaciones comunes incluyen `@Component`, `@Service`, `@Repository`, `@Controller`, y `@Autowired`.

**Clases con `Annotations`**
```java
import org.springframework.stereotype.Service;
import org.springframework.beans.factory.annotation.Autowired;

@Service
public class MyService {
    private final MyRepository repository;

    @Autowired
    public MyService(MyRepository repository) {
        this.repository = repository;
    }
}

@Repository
public class MyRepository {
    // ...
}
```
**Habilitar el Escaneo de Componentes:**
```java
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;

@Configuration
@ComponentScan(basePackages = "com.example")
public class AppConfig {
    // ...
}
```

### Configuración basada en Java (Java Configuration)
Spring también permite configurar **Beans** mediante clases Java anotadas con `@Configuration`. Los métodos en estas clases, anotados con `@Bean`, definen y configuran los **Beans**.

**Clase de configuracion Java**
```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

    @Bean
    public MyService myService() {
        return new MyService(myRepository());
    }


    @Bean("customName")
    public MyRepository myRepository() {
        return new MyRepository();
    }
}
```
Una vez que los **Beans** están definidos, se pueden configurar varios aspectos de su comportamiento, tales como el ciclo de vida, el alcance (scope), y las dependencias.

**Ciclo de Vida de los Beans**

Spring permite personalizar el ciclo de vida de los **Beans** mediante las siguientes técnicas:

1. **Métodos de inicialización y destrucción**:

   * Definir métodos personalizados para la inicialización y destrucción de **Beans**.

2. **Interfaces `InitializingBean` y `DisposableBean`**:

   * Implementar estas interfaces para realizar acciones específicas durante la inicialización y destrucción de los **Beans**.

3. **Anotaciones `@PostConstruct` y `@PreDestroy`**:

   * Utilizar estas anotaciones para marcar métodos que se ejecutan después de la inicialización y antes de la destrucción del **Bean**.
