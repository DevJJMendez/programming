## Spring Container
El Spring Container es uno de los componentes fundamentales del framework Spring. Su principal función es gestionar los objetos de una aplicación, incluyendo su creación, configuración y ciclo de vida completo. Este contenedor es responsable de la `Inversión de Control`  (IoC, por sus siglas en inglés) y de la `Inyección de Dependencias` (`DI`, por sus siglas en inglés) en Spring.

### Funciones Principales del Spring Container

1. **Inversión de Control (`IoC`)**:

   * El contenedor Spring controla la creación de objetos y su gestión, lo que significa que los objetos no se crean y gestionan directamente en el código de la aplicación. En lugar de eso, el contenedor Spring es responsable de crear y mantener estos objetos, lo que libera al desarrollador de esta tarea.

2. **Inyección de Dependencias (`DI`)**:

   * `DI` es un patrón en el que el contenedor Spring inyecta las dependencias de un objeto en lugar de que el objeto mismo sea responsable de crear o buscar sus dependencias. Esto se traduce en un código más limpio y fácil de mantener, ya que las dependencias se definen en un archivo de configuración (`XML`, `Annotations` o `JavaConfig`).

3. **Configuración y Ensamblado de `Beans`**:

   * El contenedor configura y ensambla los beans de la aplicación a partir de la configuración proporcionada. Los beans son los objetos gestionados por el contenedor.

### Tipos de Spring Containers
Spring ofrece varios tipos de contenedores, cada uno adecuado para diferentes necesidades. Los dos más comunes son:

1. **`BeanFactory`**:

   * Es el contenedor más básico de Spring, que proporciona la configuración básica para la inyección de dependencias. BeanFactory es adecuado para aplicaciones ligeras y cuando se necesita un contenedor con bajo consumo de memoria.
    
    **Ejemplo**
    ```java
    BeanFactory factory = new XmlBeanFactory(new ClassPathResource("applicationContext.xml"));
    MyBean myBean = (MyBean) factory.getBean("myBean");
    ```

2. **`ApplicationContext`**:

   * Es una extensión de **`BeanFactory`** con funcionalidades adicionales, como soporte para eventos del ciclo de vida, resolución de mensajes, y soporte para AOP. ApplicationContext es el contenedor más utilizado en aplicaciones empresariales debido a sus características avanzadas.
    
    **Ejemplo**
    ```java
    ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");
    MyBean myBean = (MyBean) context.getBean("myBean");
    ```

### Configuración del Spring Container
El contenedor Spring se puede configurar de diferentes maneras:

1. **Archivos `XML`**:

   * Una forma tradicional de configuración donde los beans y sus dependencias se definen en archivos XML.
    
    `applicationContext.xml`
    ```xml
    <beans>
        <bean id="myBean" class="com.example.MyBean">
            <property name="dependency" ref="myDependency" />
        </bean>
        <bean id="myDependency" class="com.example.MyDependency" />
    </beans>
    ```

2. **`Annotations`**:

   * Spring permite configurar los `beans` mediante anotaciones en el código Java, lo que puede hacer la configuración más clara y menos propensa a errores.
    
    **Ejemplo**
    ```java
    @Component
    public class MyBean {
        @Autowired
        private MyDependency myDependency;
    }

    @Component
    public class MyDependency {
    }
    ```

3. **`JavaConfig`**:

   * Configuración basada en clases Java, utilizando la anotación @Configuration para definir beans.

    **Ejemplo**
    ```java
    @Configuration
    public class AppConfig {
        @Bean
        public MyBean myBean() {
            return new MyBean(myDependency());
        }

        @Bean
        public MyDependency myDependency() {
            return new MyDependency();
        }
    }
    ```

### Ciclo de Vida de un Bean
El ciclo de vida de un bean en el contenedor Spring incluye varias etapas:

* **Instanciación**: El contenedor crea una instancia del bean utilizando el constructor definido.

* **Inyección de Dependencias**: El contenedor inyecta las dependencias del bean según la configuración.

* **Configuración de Propiedades**: El contenedor configura las propiedades del bean.

* **Inicialización**: Si el bean implementa la interfaz `InitializingBean` o define un método de inicialización con `@PostConstruct` o en la configuración `XML`, estos métodos se llaman después de la inyección de dependencias.

* **Uso del `Bean`**: El `bean` está listo para ser usado en la aplicación.

* Destrucción: Si el `bean` implementa la interfaz `DisposableBean` o define un método de destrucción con `@PreDestroy` o en la configuración `XML`, estos métodos se llaman antes de que el contenedor destruya el `bean`.
