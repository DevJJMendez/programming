## Thymeleaf
Thymeleaf es un motor de plantillas para Java que se utiliza para generar vistas en aplicaciones web. Es especialmente popular en el ecosistema de Spring debido a su integración directa con Spring Boot y su capacidad para renderizar HTML, XML, JavaScript, CSS, entre otros.

1. **Motor de Plantillas:** Thymeleaf permite definir plantillas HTML que contienen etiquetas y atributos especiales. Estas plantillas se procesan en el servidor para generar el HTML final que se enviará al navegador.

2. **Soporte para HTML5**: Thymeleaf está diseñado para trabajar con HTML5. Las plantillas Thymeleaf son HTML válido, lo que significa que pueden ser visualizadas en cualquier navegador sin necesidad de ser procesadas primero.

3. **Sintaxis Natural**: Uno de los objetivos de Thymeleaf es que las plantillas sean legibles incluso antes de ser procesadas. Esto es útil para diseñadores que trabajan con archivos HTML sin necesidad de conocer Java o la lógica de backend.

4. **Expresiones y Atributos de Thymeleaf**: Thymeleaf introduce atributos específicos (como th:text, th:if, th:each) que se utilizan para insertar datos dinámicos, realizar iteraciones, condicionales, entre otros.

5. **Integración con Spring**: Thymeleaf se integra estrechamente con el modelo y los controladores de Spring MVC, permitiendo la inyección de datos en las vistas y el uso de funcionalidades como mensajes internacionales, fragmentos reutilizables de HTML, y gestión de formularios.

6. **Soporte para Fragmentos**: Thymeleaf permite la reutilización de componentes de una página, como encabezados, pies de página, menús, entre otros, a través de fragmentos de plantillas.

### ¿Cómo se utiliza en Spring Boot?
En un proyecto Spring Boot, Thymeleaf se utiliza principalmente para crear la capa de vista en aplicaciones MVC. Los datos generados en los controladores se inyectan en las plantillas Thymeleaf para crear una respuesta HTML completa que se enviará al cliente.

Por ejemplo, en un controlador Spring MVC, puedes tener algo como esto:

```java
@Controller
public class MyController {

    @GetMapping("/greeting")
    public String greeting(Model model) {
        model.addAttribute("message", "Hola, Thymeleaf!");
        return "greeting";
    }
}
```
Y en la plantilla greeting.html, puedes acceder al modelo utilizando la sintaxis de Thymeleaf:

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <title>Saludo</title>
</head>
<body>
    <h1 th:text="${message}">Mensaje por defecto</h1>
</body>
</html>
```
### Etiquetas
Thymeleaf Ofrece una serie de atributos (o "etiquetas") personalizadas que se usan en el HTML para enlazar datos del backend, controlar la estructura y contenido de las vistas, y manejar interacciones dinámicas. Estas etiquetas son la base de cómo Thymeleaf interactúa con Spring MVC para renderizar contenido dinámico en aplicaciones web.

### Principales Etiquetas (Atributos)
1. `th:text` - Reemplazo de Texto

   * Utilizado para reemplazar el contenido textual de un elemento HTML con un valor dinámico.

      ```html
      <span th:text="${variable}">Texto predeterminado</span>

      <span th:text="${user.name}">Nombre del usuario</span>
      ```
2. `th:utext` - Reemplazo de Texto sin Escapar

   * Similar a `th:text`, pero no escapa caracteres HTML. Se usa para contenido que puede incluir HTML.

      ```html
      <span th:utext="${htmlContent}">Contenido HTML</span>
      ```

3. `th:each` - Iteración

   * Utilizado para iterar sobre colecciones o arrays, similar a un bucle `for-each`.

      ```html
      <tr th:each="user : ${users}">
      <td th:text="${user.name}">Nombre</td>
      </tr>

      <ul>
      <li th:each="user : ${users}" th:text="${user.name}">Nombre del usuario</li>
      </ul>
      ```

4. `th:if / th:unless` - Condicionales

   * `th:if` se utiliza para mostrar un elemento solo si la condición es verdadera.

   * `th:unless` muestra el elemento solo si la condición es falsa.

      ```html
      <div th:if="${user.isAdmin()}">Contenido para administradores</div>
      <div th:unless="${user.isAdmin()}">Contenido para usuarios regulares</div>
      ```

5. `th:attr` - Modificación de Atributos

   * Permite establecer valores dinámicos a uno o varios atributos HTML.

      ```html
      <a th:attr="href=@{/user/profile/{id}(id=${user.id})}">Perfil</a>

      <img th:src="@{${user.profilePicture}}" alt="Foto de perfil">
      ```

6. `th:href / th:src` - URLs Dinámicas

   * `th:href` para establecer URLs dinámicas en enlaces (<a>).

   * `th:src` para URLs dinámicas en imágenes (`<img>`) o scripts.

      ```html
      <a th:href="@{/home}">Inicio</a>

      <img th:src="@{/images/logo.png}" alt="Logo">
      ```

7. `th:include / th:replace` - Inclusión de Fragmentos

   * `th:include` incluye el contenido de un fragmento HTML.

   * `th:replace` reemplaza el elemento con el contenido del fragmento

      ```html
      <div th:include="fragments/header :: header"></div>

      <div th:replace="fragments/header :: header"></div>
      ```

8. `th:fragment` - Definición de Fragmentos

   * Define un fragmento reutilizable de HTML.

      ```html
      <div th:fragment="header">
      <h1>Bienvenido</h1>
      </div>
      ```

9. `th:remove` - Eliminación de Elementos

   * Permite eliminar elementos del **DOM** bajo ciertas condiciones.

      ```html
      <div th:remove="all">Este contenido se eliminará</div>
      ```
      * `all`: Elimina el elemento y su contenido.
      * `tag`: Elimina solo la etiqueta, dejando su contenido.
      * `body`: Elimina solo el contenido, dejando la etiqueta.
      
10. `th:value` - Valores de Inputs

    * Establece el valor de los campos de formulario.

      ```html
      <input type="text" th:value="${user.name}">
      ```

11. `th:object` y `th:field` - Formularios con Binding de Objetos

    * `th:object` vincula un formulario completo a un objeto.
    
    * `th:field` vincula campos individuales a propiedades del objeto.

      ```java
      <form th:object="${user}">
      <input th:field="*{name}" />
      </form>
      ```

12. `th:class` / `th:style` - Clases y Estilos Dinámicos

    * Permite establecer clases CSS o estilos en función de condiciones dinámicas.

      ```html
      <div th:class="${isActive} ? 'active' : 'inactive'">Contenido</div>
      ```

13. `th:action`
    
    *  Se utiliza para especificar la URL a la que debe enviarse un formulario cuando se envía. Es el equivalente de action en HTML puro, pero con la ventaja de que permite utilizar la sintaxis de expresión de Thymeleaf para generar URLs dinámicas.

      ```html
      <form th:action="@{/registrar}" method="post">
         <!-- Campos del formulario -->
         <button type="submit">Registrar</button>
      </form>
      ```

14. `th:object`
    
    * Se utiliza para especificar el objeto del modelo que será utilizado para poblar los campos del formulario y para recibir los datos de la solicitud cuando el formulario sea enviado. Este objeto es el que se vincula a través de `th:field`.

      ```html
      <form th:action="@{/registrar}" th:object="${usuario}" method="post">
      </form>
      ```
      * `th:object="${usuario}"` indica que el formulario está vinculado al objeto usuario que viene del modelo.
      
      * Los campos del formulario (`th:field`) se enlazan automáticamente a las propiedades de este objeto.

15. `th:field`
    * Se utiliza dentro de un formulario para vincular un campo de entrada (input, textarea, select, etc.) a una propiedad específica del objeto definido en th:object. Este atributo se encarga de gestionar el valor inicial del campo (para la vista) y el nombre del campo (para el envío).

      ```html
      <form th:action="@{/registrar}" th:object="${usuario}" method="post">
         <label for="nombre">Nombre:</label>
         <input type="text" th:field="*{nombre}" id="nombre" />
         
         <label for="email">Email:</label>
         <input type="email" th:field="*{email}" id="email" />
         
         <button type="submit">Registrar</button>
      </form>
      ```
      * `th:field="*{nombre}" `indica que este campo de entrada está vinculado a la propiedad nombre del objeto usuario.
      
      * Thymeleaf genera automáticamente el valor de name y id para el campo basado en la propiedad del objeto.
      
      * El campo mostrará el valor actual de nombre y, al enviar el formulario, los datos se mapearán de vuelta a la propiedad nombre del objeto usuario.

### Flujo de Proceso de Thymeleaf
Thymeleaf es un motor de plantillas que trabaja principalmente en la capa de presentación de una aplicación web. Su flujo de trabajo dentro de una aplicación Spring MVC es el siguiente:

1. **Solicitud HTTP del Cliente**:

   * El cliente (navegador) envía una solicitud HTTP a la aplicación web.

2. **Controlador de Spring MVC**:

   * La solicitud es manejada por el `DispatcherServlet`, que delega el procesamiento a un controlador específico. Este controlador es responsable de manejar la lógica de negocio y preparar los datos necesarios para la vista.

3. **Preparación del Modelo en el Controlador**:

   * Dentro del método del controlador, se crea o se obtiene un modelo (`Model`) que contiene los datos que se desean mostrar en la vista. Estos datos se añaden al objeto Model mediante métodos como model.addAttribute("nombreAtributo", valor).

4. **Selección de la Vista**:

   * El controlador devuelve el nombre de la vista que se debe renderizar (por ejemplo, "greeting"). Este nombre se resuelve en un archivo de plantilla Thymeleaf (greeting.html) mediante un ViewResolver.

5. **Procesamiento de la Plantilla Thymeleaf**:

   * Thymeleaf toma la plantilla HTML y la procesa utilizando los datos proporcionados en el `Model`. Durante este proceso, Thymeleaf reemplaza las expresiones Thymeleaf en el archivo HTML con los valores correspondientes del Model.

   * **Ejemplo**: Si en la plantilla tienes `th:text="${message}"`, y el `Model` contiene un atributo `message` con el valor `"Hola, Thymeleaf!"`, el texto en la vista final será `"Hola, Thymeleaf!"`.

6. **Generación de la Vista Final**:

   * Una vez que Thymeleaf ha procesado la plantilla, se genera el HTML final que será enviado al cliente. Este HTML final contiene todos los datos renderizados y es un documento HTML estándar.

7. **Respuesta HTTP al Cliente**:

   * El HTML generado es enviado de vuelta al cliente como respuesta HTTP, y el navegador del usuario renderiza la página web.

### Model
En Spring MVC, el `Model` es un objeto que se utiliza para transportar datos desde el controlador hacia la vista. Actúa como un contenedor que almacena los datos que se desean mostrar en la interfaz de usuario.

* **Uso del Model en el Controlador**:

  * El controlador utiliza el `Model` para agregar datos. Estos datos luego son accesibles desde la plantilla Thymeleaf.

* **Funcionalidad del Model**:

  * El `Model` permite agregar múltiples atributos que pueden ser utilizados en la vista.

  * Es una abstracción que oculta los detalles de cómo se almacenan los datos y proporciona una API sencilla para trabajar con ellos.

* **Relación con Thymeleaf**:

  * Cuando Thymeleaf procesa una plantilla, utiliza los datos del Model para reemplazar las expresiones dentro del HTML. Esto permite que la vista sea dinámica y refleje los datos actuales de la aplicación.

### Métodos de Model
1. `addAttribute(String attributeName, Object attributeValue)`

   * Agrega un atributo al modelo utilizando un nombre específico.

   * **Parámetros**:
      * `attributeName`: El nombre con el que se identificará el atributo en la vista.
      
      * `attributeValue`: El valor del atributo.

   * **Retorna**: Una referencia al mismo Model para permitir el encadenamiento de métodos.

      ```java
      model.addAttribute("user", new User());
      ```
2. `addAttribute(Object attributeValue)`

   * Agrega un atributo al modelo sin especificar un nombre. El nombre del atributo será el nombre de la clase del objeto en notación camel case.

   * **Parámetro**:
     
     * `attributeValue`: El valor del atributo. Su nombre en la vista será derivado de la clase del objeto (por ejemplo, `new User()` se convertirá en `user`).

   * **Retorna**: Una referencia al mismo Model.

      ```java
      model.addAttribute(new User());
      // Esto agregará un atributo con el nombre 'user'
      ```

3. `addAllAttributes(Collection<?> attributeValues)`

   * Agrega todos los atributos de una colección al modelo. Los nombres de los atributos serán derivados de las clases de los objetos, similar a addAttribute(Object attributeValue).

   * **Parámetro**:
     
     * `attributeValues`: Una colección de objetos que serán agregados al modelo.

   * **Retorna**: Una referencia al mismo Model.

      ```java
      List<User> users = Arrays.asList(new User(), new User());
      model.addAllAttributes(users);
      // Esto agregará atributos 'user' al modelo, uno por cada objeto en la lista.
      ```

4. `addAllAttributes(Map<String, ?> attributes)`

   * Agrega todos los atributos de un Map al modelo. Las claves del Map se usan como nombres de los atributos, y los valores del Map se usan como los valores de los atributos.

   * **Parámetro**:

     * `attributes`: Un Map que contiene pares de nombre-valor que serán agregados al modelo.

   * **Retorna**: Una referencia al mismo Model.

      ```java
      Map<String, Object> map = new HashMap<>();
      map.put("user", new User());
      map.put("role", "admin");
      model.addAllAttributes(map);
      ```

5. `mergeAttributes(Map<String, ?> attributes)`

   * Agrega todos los atributos de un Map al modelo solo si no hay un atributo existente con el mismo nombre. Este método no sobrescribe atributos existentes.

   * **Parámetro**:

     * `attributes`: Un Map con pares de nombre-valor.

   * **Retorna**: Una referencia al mismo Model.

      ```java
      Map<String, Object> map = new HashMap<>();
      map.put("user", new User());
      model.mergeAttributes(map);
      ```

6. `containsAttribute(String attributeName)`

   * Verifica si el modelo contiene un atributo con el nombre especificado.

   * **Parámetro**:

     * `attributeName`: El nombre del atributo que se va a verificar.

   * **Retorna**: `true` si el modelo contiene el atributo; `false` en caso contrario.

      ```java
      if (model.containsAttribute("user")) {
         // Do something if 'user' is present in the model
      }
      ```

7. `Map<String, Object> asMap()`

   * Devuelve el contenido del modelo como un Map. Las claves del Map son los nombres de los atributos y los valores son los objetos correspondientes.

   * Retorna: Un Map que representa el contenido del modelo.

      ```java
      Map<String, Object> modelMap = model.asMap();
      ```
