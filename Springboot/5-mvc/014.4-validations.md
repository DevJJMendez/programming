## Validations
La Bean Validation API es una especificación en Java que proporciona un marco estándar para la validación de datos en los componentes de una aplicación. Introducida por primera vez en Java EE 6 como JSR 303 y luego actualizada como JSR 380 en Java EE 8, esta API permite que los desarrolladores definan restricciones o reglas de validación directamente en los modelos de datos usando **anotaciones**.

### Características Principales
* **Anotaciones de Validación**: Las reglas de validación se definen utilizando anotaciones en los campos o métodos de las clases de los modelos.

* **Interoperabilidad**: La API puede ser utilizada en diferentes capas de la aplicación, como en la capa de presentación, servicios o persistencia.

* **Personalización y Extensibilidad**: Es posible definir validaciones personalizadas y reutilizables.

* **Integración con Frameworks**: Se integra fácilmente con frameworks como Spring, JPA, y otros para validar datos de forma automática.

### Anotaciones Comunes
* `@NotNull`: El campo no puede ser nulo.

* `@Null`: Asegura que el campo sea null.

* `@Size`: Define un tamaño mínimo y/o máximo para cadenas o colecciones.

* `@Min` y `@Max`: Establecen un valor mínimo y/o máximo numérico.

* `@Pattern`: Verifica si un string coincide con una expresión regular.

* `@Email`: Valida que el campo tenga un formato de correo electrónico válido.

* `@NotEmpty`: El campo no puede ser nulo ni vacío (aplicable a strings y colecciones).

* `@Past`, `@PastOrPresent`, `@Future`, `@FutureOrPresent`: Valida que una fecha sea pasada, presente o futura.

* `@NotBlank`: Similar a `@NotEmpty`, pero se aplica solo a cadenas de texto. Asegura que la cadena no sea null y que contenga al menos un carácter que no sea espacio en blanco.
java

* `@DecimalMin` y `@DecimalMax`: Valida que un valor numérico (como BigDecimal o double) sea mayor o igual a un valor mínimo (@DecimalMin) o menor o igual a un valor máximo (@DecimalMax).

* `@Digits`: Restringe el número de dígitos enteros y fraccionarios que puede tener un número.

* `@Positive` y `@PositiveOrZero`: Valida que un número sea positivo (@Positive) o no negativo (@PositiveOrZero).

* `@Negative` y `@NegativeOrZero`: Valida que un número sea negativo (@Negative) o no positivo (@NegativeOrZero)

* `@Future` y `@FutureOrPresent`: Valida que una fecha sea en el futuro (@Future) o en el futuro o presente (@FutureOrPresent).

* `@AssertTrue` y `@AssertFalse`: Valida que un campo booleano sea true (@AssertTrue) o false (@AssertFalse)

* `@Pattern`: Valida que una cadena de texto coincida con una expresión regular.

* `@CreditCardNumber` (de Hibernate Validator): Valida que un campo contenga un número de tarjeta de crédito válido

* `@URL` (de Hibernate Validator): Valida que un campo contenga una URL válida.

### Ejemplo Básico
Supongamos que tienes una clase Usuario y quieres aplicar validaciones sobre algunos de sus campos:

```java
import javax.validation.constraints.*;

public class Usuario {

    @NotNull
    @Size(min = 2, max = 30)
    private String nombre;

    @NotNull
    @Email
    private String email;

    @Min(18)
    private int edad;

    // Getters y setters
}
```
* `nombre` debe tener entre 2 y 30 caracteres y no puede ser nulo.

* `email` debe ser un formato de correo electrónico válido y no puede ser nulo.

* `edad` debe ser mayor o igual a 18.

### Validación de Objetos
Para validar un objeto, puedes usar un `Validator` proporcionado por la API. A continuación, un ejemplo de cómo se hace:

```java
import javax.validation.*;
import java.util.Set;

public class UsuarioService {

    private Validator validator;

    public UsuarioService() {
        ValidatorFactory factory = Validation.buildDefaultValidatorFactory();
        validator = factory.getValidator();
    }

    public void registrarUsuario(Usuario usuario) {
        Set<ConstraintViolation<Usuario>> violations = validator.validate(usuario);

        if (!violations.isEmpty()) {
            for (ConstraintViolation<Usuario> violation : violations) {
                System.out.println(violation.getMessage());
            }
        } else {
            // Lógica de registro
        }
    }
}
```
* `validator.validate(usuario)` verifica que todas las restricciones en la clase Usuario se cumplan.

* Si hay violaciones (violations), se pueden manejar de acuerdo con las necesidades de la aplicación.

### Integración con Spring Boot
En Spring Boot, la integración con la Bean Validation API es muy sencilla. Spring automáticamente valida los datos antes de ejecutar los métodos de los controladores, si las anotaciones de validación están presentes.

Ejemplo con Spring Boot:

```java
import javax.validation.Valid;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.PostMapping;

@Controller
public class UsuarioController {

    @PostMapping("/registrar")
    public String registrarUsuario(@Valid Usuario usuario, Model model) {
        // Si hay errores de validación, se manejarán automáticamente
        // Si no hay errores, se procederá con el registro
        return "usuarioRegistrado";
    }
}
```
* La anotación `@Valid` antes de Usuario usuario indica que Spring debe validar este objeto antes de continuar.

* Si hay violaciones de las restricciones, Spring las manejará automáticamente, generalmente devolviendo una respuesta de **error 400**.

## @Valid
La anotación `@Valid` en Spring se utiliza para **activar** la validación automática de los objetos de modelo. Esta anotación es parte de la **Bean Validation API** y se puede aplicar tanto en los métodos del controlador para validar datos de entrada, como en los atributos de un modelo para validar objetos anidados. ## Custom Validations
Las Custom Validations o validaciones personalizadas en Java, especialmente dentro del contexto de la Bean Validation API, permiten definir reglas de validación que no están cubiertas por las anotaciones estándar como `@NotNull`, `@Size`, `@Email`, etc. Esto es útil cuando tienes reglas de negocio específicas que no se pueden expresar con las validaciones predefinidas.

### Pasos para Crear una Validación Personalizada
1. **Definir la Anotación Personalizada**: Crear una nueva anotación que describa la validación.

2. **Implementar la Lógica de Validación**: Crear una clase que implemente la interfaz `ConstraintValidator` y contenga la lógica de validación.

3. **Aplicar la Anotación**: Utilizar la nueva anotación en los modelos de datos donde sea necesario.

### Ejemplo Completo de Validación Personalizada
Supongamos que tienes una regla de negocio que requiere que un campo de texto solo contenga letras mayúsculas.

1. **Definir la Anotación Personalizada**: Primero, defines una anotación que se puede aplicar a los campos que deseas validar.

```java
@Documented
@Constraint(validatedBy = UpperCaseValidator.class)
@Target({ ElementType.METHOD, ElementType.FIELD })
@Retention(RetentionPolicy.RUNTIME)
public @interface UpperCase {

    String message() default "El texto debe estar en mayúsculas";

    Class<?>[] groups() default {};

    Class<? extends Payload>[] payload() default {};
}
```
* `@Constraint`: Indica que esta anotación es una restricción de validación y especifica la clase `UpperCaseValidator` como la que realizará la validación.

* `message`: Especifica el mensaje de error que se devolverá si la validación falla.

* `groups` y `payload`: Se utilizan para la agrupación y el transporte de información adicional en la 
validación, aunque a menudo no se necesitan en validaciones básicas.

2. **Implementar la Lógica de Validación**: Ahora, implementas la clase `UpperCaseValidator` que contiene la lógica para verificar si el texto está en mayúsculas.

```java
public class UpperCaseValidator implements ConstraintValidator<UpperCase, String> {

    @Override
    public void initialize(UpperCase constraintAnnotation) {
        // Aquí se puede realizar la inicialización si es necesario
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null) {
            return true; // Permitir nulo, usa @NotNull si el campo no puede ser nulo
        }
        return value.equals(value.toUpperCase());
    }
}
```
* `initialize`: Método opcional para realizar cualquier configuración inicial.

* `isValid`: Aquí se define la lógica de validación. Si value es nulo, se devuelve true para permitir nulos (se puede controlar con @NotNull). Si no es nulo, se verifica que el texto esté en mayúsculas.

3. **Aplicar la Anotación**: Una vez definida la anotación y su validador, puedes usarla en tus modelos de datos.

```java
public class Usuario {

    @UpperCase
    private String nombreUsuario;

    // Otros campos y métodos
}
```
En este ejemplo, el campo `nombreUsuario` ahora debe contener solo letras mayúsculas, de lo contrario, la validación fallará.

## @InitBinder
La anotación `@InitBinder` en Spring MVC se utiliza para inicializar y configurar un WebDataBinder, que es responsable de vincular los datos de la solicitud HTTP a los objetos del modelo. `@InitBinder` es especialmente útil cuando necesitas personalizar cómo se transforman y validan los datos de la solicitud antes de que se asignen a los objetos del modelo.

### Usos Comunes de @InitBinder
1. **Registro de Editores Personalizados**: Puedes utilizar @InitBinder para registrar editores de propiedades personalizados que transformen los datos de un tipo a otro durante el proceso de enlace.

2. **Configuración de Validadores**: Se puede usar para configurar validadores específicos que se aplicarán a un objeto antes de procesar la solicitud.

3. **Configuración de Formateadores**: También es posible registrar formateadores específicos para tipos de datos, como fechas o números.

### Ejemplo de Uso de @InitBinder
Supongamos que tienes una aplicación que maneja fechas y quieres asegurarte de que cualquier fecha enviada desde el formulario se convierta en un objeto Date en un formato específico.

1. **Registro de un Editor Personalizado para Fechas**

```java
@Controller
public class UsuarioController {

    @InitBinder
    public void initBinder(WebDataBinder binder) {
        SimpleDateFormat dateFormat = new SimpleDateFormat("yyyy-MM-dd");
        dateFormat.setLenient(false);
        binder.registerCustomEditor(Date.class, new CustomDateEditor(dateFormat, false));
    }

    @RequestMapping(value = "/registrar", method = RequestMethod.POST)
    public String registrarUsuario(Usuario usuario) {
        // Aquí, la fecha en el objeto Usuario ya estará formateada
        return "usuarioRegistrado";
    }
}
```
* `@InitBinder` marca un método que se ejecutará antes de cualquier método de controlador que procese una solicitud.

* `registerCustomEditor(Date.class, new CustomDateEditor(...))` registra un editor personalizado que convierte una cadena de fecha en un objeto Date usando el formato **yyyy-MM-dd**.

2. **Uso de Validadores Específicos**: Puedes usar `@InitBinder` para aplicar un validador específico a un objeto del modelo.

```java
import org.springframework.validation.Validator;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.ModelAttribute;

@Controller
public class UsuarioController {

    private final UsuarioValidator usuarioValidator;

    public UsuarioController(UsuarioValidator usuarioValidator) {
        this.usuarioValidator = usuarioValidator;
    }

    @InitBinder
    public void initBinder(WebDataBinder binder) {
        binder.addValidators(usuarioValidator);
    }

    @RequestMapping(value = "/registrar", method = RequestMethod.POST)
    public String registrarUsuario(@Validated @ModelAttribute Usuario usuario) {
        // Si hay errores de validación, estos se manejarán automáticamente
        return "usuarioRegistrado";
    }
}
```
* `usuarioValidator` es un validador personalizado que se aplica al objeto Usuario.

* El validador se agrega al `WebDataBinder` usando `binder.addValidators(usuarioValidator)`.

### Ejemplo con Formateadores Personlizados
En lugar de un editor de propiedades, podrías usar un formateador personalizado para convertir cadenas en objetos complejos.

```java
public class MiCustomFormatter implements Formatter<MiTipoPersonalizado> {

    @Override
    public MiTipoPersonalizado parse(String text, Locale locale) throws ParseException {
        // Lógica para convertir el texto en MiTipoPersonalizado
        return new MiTipoPersonalizado(text.toUpperCase());
    }

    @Override
    public String print(MiTipoPersonalizado object, Locale locale) {
        // Lógica para convertir MiTipoPersonalizado en String
        return object.toString();
    }
}
```
Luego, podrías registrar este formateador en `@InitBinder`.

```java
@Controller
public class MiController {

    @InitBinder
    public void initBinder(WebDataBinder binder) {
        binder.addCustomFormatter(new MiCustomFormatter());
    }

    @RequestMapping(value = "/procesar", method = RequestMethod.POST)
    public String procesarFormulario(MiTipoPersonalizado miObjeto) {
        // Aquí, miObjeto se ha procesado usando MiCustomFormatter
        return "resultado";
    }
}
```
