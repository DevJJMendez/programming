## JDBC Authentication
La autenticación JDBC en Spring Security es un mecanismo que permite autenticar usuarios a través de una base de datos relacional. Utiliza **JDBC (Java Database Connectivity)** o **JPA** para consultar y verificar las credenciales de los usuarios almacenadas en tablas de base de datos.

1. **DataSource**:

   * Se requiere un **DataSource** configurado para conectarse a la base de datos. Spring Security usará este **DataSource** para ejecutar consultas SQL que autentican a los usuarios y obtienen sus roles.

2. **Tablas de Usuarios y Roles**:

   * **Usuarios (users)**: Almacena la información de los usuarios, como nombres de usuario, contraseñas y si las cuentas están habilitadas o no.

   * **Roles (authorities)**: Almacena los roles o privilegios asociados con los usuarios.

3. Consultas SQL Predeterminadas:

   * Spring Security usa consultas SQL predeterminadas para autenticar a los usuarios y obtener sus roles.
   
   * Puedes personalizar estas consultas si tu esquema de base de datos es diferente del predeterminado.

### Configuración Básica de JDBC Authentication

1. **Dependencia en `pom.xml`**: Primero, asegúrate de que tienes las dependencias necesarias en tu proyecto Maven para Spring Security y JDBC:

    ```xml
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-security</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-jdbc</artifactId>
    </dependency>
    <dependency>
        <groupId>com.h2database</groupId>
        <artifactId>h2</artifactId>
        <scope>runtime</scope>
    </dependency>
    ```

2. **Configurar el DataSource**: Define el DataSource en tu archivo de configuración `application.properties` o mediante una configuración manual en una clase de configuración.

    ```properties
    spring.datasource.url=jdbc:h2:mem:testdb
    spring.datasource.driverClassName=org.h2.Driver
    spring.datasource.username=sa
    spring.datasource.password=password
    spring.datasource.schema=classpath:schema.sql
    ```

3. **Crear las Tablas `users` y `authorities`**: Spring Security espera que las tablas de usuarios y roles tengan la siguiente estructura predeterminada:

    ```sql
    CREATE TABLE users (
        username VARCHAR(50) NOT NULL PRIMARY KEY,
        password VARCHAR(100) NOT NULL,
        enabled BOOLEAN NOT NULL
    );

    CREATE TABLE authorities (
        username VARCHAR(50) NOT NULL,
        authority VARCHAR(50) NOT NULL,
        FOREIGN KEY (username) REFERENCES users(username)
    );
    ```
    * `username`: El nombre de usuario del usuario.
    * `password`: La contraseña codificada del usuario.
    * `enabled`: Un campo booleano que indica si el usuario está habilitado.
    * `authority`: El rol o autoridad del usuario (por ejemplo, **ROLE_USER**, **ROLE_ADMIN**).

4. **Configurar la Seguridad en `SecurityConfig`**: Configura Spring Security para usar autenticación **JDBC** en tu clase de configuración:

    ```java
    @Configuration
    @EnableWebSecurity
    public class SecurityConfig {

        @Bean
        public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
            http
                .authorizeRequests()
                    .antMatchers("/admin/**").hasRole("ADMIN")
                    .antMatchers("/user/**").hasRole("USER")
                    .antMatchers("/public/**").permitAll()
                    .anyRequest().authenticated()
                    .and()
                .formLogin()
                    .permitAll()
                    .and()
                .logout()
                    .permitAll();
            
            return http.build();
        }

        @Bean
        public JdbcUserDetailsManager jdbcUserDetailsManager(DataSource dataSource) {
            JdbcUserDetailsManager manager = new JdbcUserDetailsManager(dataSource);
            manager.setUsersByUsernameQuery("SELECT username, password, enabled FROM users WHERE username = ?");
            manager.setAuthoritiesByUsernameQuery("SELECT username, authority FROM authorities WHERE username = ?");
            return manager;
        }
    }
    ```

5.  **Personalización de Consultas SQL** Si tu esquema de base de datos es diferente del predeterminado, puedes personalizar las consultas SQL usadas por `JdbcUserDetailsManager`:

    ```java
    manager.setUsersByUsernameQuery("SELECT user_id AS username, user_password AS password, is_active AS enabled FROM my_users WHERE user_id = ?");

    manager.setAuthoritiesByUsernameQuery("SELECT user_id AS username, role_name AS authority FROM my_roles WHERE user_id = ?");
    ```

### Flujo de Trabajo de la Autenticación JDBC

1. **Formulario de Inicio de Sesión**:

   * El usuario ingresa sus credenciales en un formulario de inicio de sesión.
   
   * Las credenciales son enviadas al servidor.

2. **Consulta de la Base de Datos**:

   * Spring Security utiliza el **DataSource** configurado para conectarse a la base de datos.

   * Ejecuta una consulta SQL para verificar las credenciales del usuario `(SELECT username, password, enabled FROM users WHERE username = ?)`.

3. **Verificación de Roles**:

   * Si la autenticación es exitosa, Spring Security ejecuta otra consulta para obtener los roles del usuario `(SELECT username, authority FROM authorities WHERE username = ?)`.

4. **Autorización**: Con base en los roles obtenidos, Spring Security autoriza o deniega el acceso a los recursos solicitados.

5. **Redirección**: Si la autenticación y autorización son exitosas, el usuario es redirigido a la página solicitada o a una página predeterminada.

## Encriptación
Spring Security utiliza el concepto de **PasswordEncoder** para codificar (o encriptar) contraseñas antes de almacenarlas en una base de datos. Esta codificación asegura que las contraseñas no se almacenen en texto plano, lo que mejoraría la seguridad del sistema.

El formato **`{encoder_id}password`** se usa para almacenar una contraseña con un identificador de codificador. Esto permite a Spring Security saber qué tipo de codificación se ha utilizado y cómo debe decodificarse o verificarse cuando se autentica un usuario.

**Ejemplo**
```bash
{bcrypt}$2a$10$7Q.jhFJYB9c5QsHqGVdKwe4AsgnJeTFL.GOl7Ahs1S9MN9cy1bf3K
```
* `{bcrypt}`: Indica que la contraseña ha sido codificada usando BCrypt, que es un algoritmo de hash seguro.

* `$2a$10$...`: Es la cadena codificada que representa la contraseña encriptada usando BCrypt.

## JdbcUserDetailsManager
Es una implementación de la interfaz UserDetailsManager en Spring Security que gestiona usuarios y sus roles utilizando una base de datos relacional a través de JDBC. Esta clase se encarga de todas las operaciones relacionadas con la autenticación y autorización, como crear, actualizar, eliminar, y consultar usuarios y roles, todo almacenado en una base de datos.

### Principales Características de JdbcUserDetailsManager
1. **Autenticación Basada en Base de Datos**:

   * `JdbcUserDetailsManager` permite autenticar a los usuarios contra los registros almacenados en una base de datos relacional.

2. **Gestión de Usuarios**:

   * Ofrece métodos para gestionar el ciclo de vida completo de los usuarios (crear, actualizar, eliminar, etc.).

3. **Gestión de Roles**:

   * Permite asignar roles a los usuarios y verificarlos durante el proceso de autenticación.

4. **Consultas SQL Personalizables**:

   * Puedes personalizar las consultas SQL que utiliza JdbcUserDetailsManager para adaptarlas a la estructura de tu base de datos.

### Configuración de JdbcUserDetailsManager
Para utilizar JdbcUserDetailsManager, necesitas configurar un **DataSource** que apunte a tu base de datos y asegurarte de que la estructura de la base de datos esté alineada con las consultas SQL predeterminadas o personalizadas.

1. **Configuración Básica**: Aquí tienes un ejemplo básico de cómo configurar `JdbcUserDetailsManager`:

```java
        @Configuration
        @EnableWebSecurity
        public class SecurityConfig extends WebSecurityConfigurerAdapter {

            @Autowired
            private DataSource dataSource;

            @Bean
            public JdbcUserDetailsManager jdbcUserDetailsManager() {
                JdbcUserDetailsManager jdbcUserDetailsManager = new JdbcUserDetailsManager();
                jdbcUserDetailsManager.setDataSource(dataSource);
                return jdbcUserDetailsManager;
            }

            @Override
            protected void configure(AuthenticationManagerBuilder auth) throws Exception {
                auth.userDetailsService(jdbcUserDetailsManager());
            }
        }
```

* `DataSource`: Se utiliza para conectar con la base de datos.
        
* `JdbcUserDetailsManager`: Es el componente principal que gestiona los usuarios en la base de datos.
  
### Ejemplo de Uso
Supongamos que tienes una aplicación que necesita gestionar usuarios y roles a través de una base de datos. Puedes usar JdbcUserDetailsManager para esta tarea. Aquí tienes un ejemplo de cómo agregar un usuario:

```java
@Autowired
private JdbcUserDetailsManager jdbcUserDetailsManager;

public void createUser() {
    UserDetails user = User.withDefaultPasswordEncoder()
                           .username("john")
                           .password("password")
                           .roles("USER")
                           .build();

    jdbcUserDetailsManager.createUser(user);
}
```

### Métodos Clave de JdbcUserDetailsManager
* `createUser(UserDetails user)`: Crea un nuevo usuario en la base de datos.

* `updateUser(UserDetails user)`: Actualiza un usuario existente.

* `deleteUser(String username)`: Elimina un usuario por su nombre de usuario.

* `changePassword(String oldPassword, String newPassword)`: Cambia la contraseña del usuario autenticado actualmente.

* `userExists(String username)`: Verifica si un usuario existe en la base de datos.
