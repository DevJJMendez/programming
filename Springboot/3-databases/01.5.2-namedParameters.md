# Named Parameters
Los Named Parameters o parámetros nombrados son una forma de definir parámetros en consultas de JPQL o SQL utilizando nombres en lugar de posiciones en la consulta. Este enfoque aporta claridad, facilita el mantenimiento de código y reduce el riesgo de errores que pueden ocurrir al emplear múltiples parámetros en una consulta.

## ¿Qué es un Named Parameter?
Un Named Parameter en JPQL o SQL es un parámetro identificado por un nombre en lugar de un índice. Se representa precediendo el nombre del parámetro con dos puntos (`:`). Por ejemplo, en una consulta JPQL podríamos tener `:nombre` o `:precio`.

**Ejemplo**
```java
@Query("SELECT p FROM Producto p WHERE p.nombre = :nombre")
List<Producto> findByNombre(@Param("nombre") String nombre);
```

## ¿Para qué sirve?
Los Named Parameters sirven para:

* **Hacer las consultas más legibles**: Al utilizar nombres descriptivos para los parámetros, las consultas son más fáciles de entender y mantener.

* **Evitar errores de orden**: Con parámetros nombrados, no es necesario recordar el orden de los parámetros, lo cual es especialmente útil en consultas largas.

* **Reutilización de parámetros**: Un mismo parámetro puede ser usado múltiples veces en la consulta sin repetir valores en el código.

## ¿Qué resuelve?
* **Confusión en el orden de parámetros**: Al usar parámetros posicionales, es fácil equivocarse al pasar valores en el orden correcto, especialmente en consultas largas. Los Named Parameters eliminan esta preocupación.

* **Claridad en el código**: Con parámetros nombrados, los nombres mismos documentan la finalidad de cada valor en la consulta.

* **Repetición de código**: Si un mismo valor debe utilizarse en varias partes de la consulta, se puede hacer referencia al mismo Named Parameter, lo que reduce la repetición de código.

## ¿Cómo lo resuelve?
Los Named Parameters se resuelven en el momento de ejecutar la consulta, asociando el nombre del parámetro en la consulta con el valor provisto en el código. En Spring Data JPA, los Named Parameters son asociados al parámetro del método con la anotación @Param, lo que le permite al framework insertar automáticamente el valor del parámetro en la consulta.

## Ejemplo de uso
Supongamos que tenemos una entidad Producto y deseamos buscar productos en una tienda en base a su nombre y a un rango de precio.

```java
@Entity
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    private String nombre;
    private double precio;

    // Getters y Setters
}
```
Luego, definimos el repositorio usando parámetros nombrados en la consulta:
```java
@Repository
public interface ProductoRepository extends JpaRepository<Producto, Long> {

    @Query("SELECT p FROM Producto p WHERE p.nombre = :nombre AND p.precio BETWEEN :precioMin AND :precioMax")
    List<Producto> findByNombreAndPrecioRange(
            @Param("nombre") String nombre,
            @Param("precioMin") double precioMin,
            @Param("precioMax") double precioMax);
}
```
**En este ejemplo:**
* **Parámetros nombrados**: `:nombre`, `:precioMin`, y `:precioMax` se asignan a las variables en el método.

* **`@Param`**: La anotación @Param enlaza los parámetros del método con los nombres de los parámetros en la consulta.

* **Flexibilidad en el uso**: Puedes modificar el orden de los parámetros en el método sin afectar la consulta, ya que Spring Data usa los nombres para hacer la asignación, no la posición.

## Ventajas de los Named Parameters
* Código más claro y fácil de mantener: Ayuda a que las consultas sean autodescriptivas y más fáciles de leer.

* Evita problemas de posicionamiento: Reduce el riesgo de errores en el orden de los parámetros, lo cual es común en consultas complejas.

* Múltiples referencias: Un mismo parámetro nombrado puede usarse en varias partes de la consulta sin duplicación de valores en el código.

* Compatible con Spring Data JPA: Permite una integración perfecta y fácil de manejar.

## Buenas Prácticas con Named Parameters
* Usar nombres descriptivos: Nombres como nombreCliente son mejores que solo nombre, ya que dan contexto.

* Evitar nombres ambiguos: Asegúrate de que el nombre del parámetro sea lo suficientemente específico para evitar confusiones.

* Mantener consistencia: Usar nombres consistentes entre consultas para los mismos valores hace que el código sea más fácil de entender.
