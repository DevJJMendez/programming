# `Statement`
En JDBC, Statement es una de las interfaces fundamentales que permite ejecutar sentencias SQL directamente en una base de datos y obtener los resultados. Existen varias formas de crear sentencias en JDBC, siendo `Statement`, `PreparedStatement` y `CallableStatement` las tres más comunes, cada una diseñada para diferentes necesidades.

## ¿Qué es Statement?
`Statement` es una interfaz de JDBC que se utiliza para ejecutar sentencias SQL sin parámetros y de una manera directa. Este tipo de sentencias se utilizan principalmente para operaciones **SQL** simples, como `SELECT`, `INSERT`, `UPDATE` y `DELETE`, donde no se necesita precompilar ni reutilizar la sentencia.

## ¿Para qué sirve Statement?
La interfaz `Statement` es útil para ejecutar SQL en una base de datos sin parámetros y obtener resultados en caso de que se trate de una consulta `SELECT`. Esto permite:

* Crear y ejecutar consultas SQL en la base de datos.

* Recibir datos de la base de datos y procesarlos en la aplicación.

* Realizar operaciones de modificación de datos (`INSERT`, `UPDATE`, `DELETE`).

## ¿Qué resuelve Statement?
`Statement` resuelve la necesidad básica de ejecutar sentencias SQL en una base de datos directamente desde una aplicación Java, sin tener que utilizar instrucciones complejas o datos parametrizados. Proporciona una forma rápida de ejecutar SQL, ideal para consultas o modificaciones que no se ejecutan de forma repetida o con datos variables.

Sin `Statement`, los desarrolladores tendrían que usar comandos específicos de cada base de datos, lo cual sería menos eficiente y portátil.

## ¿Cómo lo resuelve?
`Statement` resuelve el problema mediante un conjunto de métodos que:

* **Ejecutan comandos SQL**: Con `executeQuery` para consultas `SELECT` y executeUpdate para sentencias `INSERT`, `UPDATE` o `DELETE`.

* **Obtienen resultados**: Devuelve un objeto `ResultSet` cuando la sentencia ejecutada es una consulta `SELECT`, permitiendo procesar los datos obtenido

## Métodos principales de Statement
1. `executeQuery(String sql)`: Ejecuta una consulta SELECT y devuelve un ResultSet con los datos obtenidos.

**Ejemplo**
```java
String query = "SELECT * FROM productos";
ResultSet resultSet = statement.executeQuery(query);
```

2. `executeUpdate(String sql)`:
   * Ejecuta una sentencia de actualización, como `INSERT`, `UPDATE` o `DELETE`.
   
   * Devuelve un número entero que indica la cantidad de filas afectadas.

**Ejemplo**
```java
String insert = "INSERT INTO productos (nombre, precio) VALUES ('Producto1', 100)";
int rowsAffected = statement.executeUpdate(insert);
```

3. `execute(String sql)`:

   * Puede ejecutar cualquier sentencia **SQL**, incluyendo `SELECT`, `INSERT`, `UPDATE` y `DELETE`.

   + Si la sentencia es una consulta `SELECT`, devuelve `true` y el `ResultSet` debe recuperarse usando `getResultSet()`.

**Ejemplo**:
```java
String query = "SELECT * FROM productos";
boolean hasResultSet = statement.execute(query);
if (hasResultSet) {
    ResultSet resultSet = statement.getResultSet();
}
```

## Limitaciones y Buenas Prácticas de `Statement`
1. **Inyección SQL**:

   * Las sentencias `Statement` son vulnerables a ataques de inyección SQL porque el SQL es ensamblado directamente en el código.

   * **Recomendación**: Usar `PreparedStatement` en lugar de `Statement` cuando sea necesario incluir parámetros en la consulta.

2. **Reutilización y Precompilación**:

   * `Statement` no es eficiente para consultas repetidas, ya que no es precompilado.

   * **Recomendación**: Usar `PreparedStatement` para consultas que se ejecutarán muchas veces con diferentes valores, ya que mejora el rendimiento al precompilar la consulta.

3. **Control de Transacciones**:

   * Cuando se usan varias sentencias en una sola transacción, se recomienda manejar explícitamente las transacciones y evitar la `autocommit`.
