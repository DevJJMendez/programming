# Uso de EntityManager
1. **Entidad**: Define una entidad JPA

```java
import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;

@Entity
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String nombre;
    private double precio;

    // Getters y setters
}
```

2. **Uso del `EntityManager`**: Inyecta y utiliza `EntityManager` en un repositorio personalizado o servicio:

```java
import org.springframework.stereotype.Repository;
import javax.persistence.EntityManager;
import javax.persistence.PersistenceContext;
import javax.transaction.Transactional;
import java.util.List;

@Repository
public class ProductoRepositoryCustom {

    @PersistenceContext
    private EntityManager entityManager;

    @Transactional
    public void insertar(Producto producto) {
        entityManager.persist(producto);
    }

    public Producto obtenerPorId(Long id) {
        return entityManager.find(Producto.class, id);
    }

    public List<Producto> obtenerTodos() {
        return entityManager.createQuery("SELECT p FROM Producto p", Producto.class).getResultList();
    }

    @Transactional
    public void actualizar(Producto producto) {
        entityManager.merge(producto);
    }

    @Transactional
    public void eliminar(Long id) {
        Producto producto = obtenerPorId(id);
        if (producto != null) {
            entityManager.remove(producto);
        }
    }
}
```

4. **Servicio**: Usa el repositorio personalizado en tu capa de servicio

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class ProductoService {

    @Autowired
    private ProductoRepositoryCustom productoRepositoryCustom;

    public List<Producto> listarProductos() {
        return productoRepositoryCustom.obtenerTodos();
    }

    public Producto obtenerProducto(Long id) {
        return productoRepositoryCustom.obtenerPorId(id);
    }

    public void agregarProducto(Producto producto) {
        productoRepositoryCustom.insertar(producto);
    }

    public void actualizarProducto(Producto producto) {
        productoRepositoryCustom.actualizar(producto);
    }

    public void eliminarProducto(Long id) {
        productoRepositoryCustom.eliminar(id);
    }
}
```

5. **Controlador**: El controlador expone las operaciones a través de una API REST

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/productos")
public class ProductoController {

    @Autowired
    private ProductoService productoService;

    @GetMapping
    public List<Producto> listarProductos() {
        return productoService.listarProductos();
    }

    @GetMapping("/{id}")
    public Producto obtenerProducto(@PathVariable Long id) {
        return productoService.obtenerProducto(id);
    }

    @PostMapping
    public void agregarProducto(@RequestBody Producto producto) {
        productoService.agregarProducto(producto);
    }

    @PutMapping("/{id}")
    public void actualizarProducto(@PathVariable Long id, @RequestBody Producto producto) {
        producto.setId(id);
        productoService.actualizarProducto(producto);
    }

    @DeleteMapping("/{id}")
    public void eliminarProducto(@PathVariable Long id) {
        productoService.eliminarProducto(id);
    }
}
```




## `@PersistenceContext`

La anotación `@PersistenceContext` se utiliza en **JPA (Java Persistence API)** para inyectar una instancia de `EntityManager` en un **Bean** gestionado por el contenedor de dependencia (como Spring). `EntityManager` es el API principal para interactuar con el contexto de persistencia en JPA.

### Función de `@PersistenceContext`
`@PersistenceContext` se usa para definir un punto de inyección para una instancia de EntityManager. Esto permite a los desarrolladores utilizar el `EntityManager` sin tener que crear manualmente una instancia o manejar su ciclo de vida. En aplicaciones basadas en Spring, el contenedor de Spring administra la creación y la configuración del EntityManager.

### Parámetros de `@PersistenceContext`

* `unitName`: El nombre de la unidad de persistencia a la que se asocia este `EntityManager`. Se utiliza cuando hay múltiples unidades de persistencia definidas.

    ```java
    @PersistenceContext(unitName = "miUnidadDePersistencia")
    private EntityManager entityManager;
    ```

* `type`: Define el tipo de `PersistenceContext`, que puede ser `PersistenceContextType.TRANSACTION` (por defecto) o `PersistenceContextType.EXTENDED`.
  
  * `TRANSACTION` significa que el `EntityManager` se asocia con el ciclo de vida **de una transacción JTA**, mientras que `EXTENDED` significa que el `EntityManager` puede vivir más allá de una transacción.

## `@Transactional`
La anotación `@Transactional` en Spring se utiliza para gestionar transacciones de manera declarativa. Esto significa que puedes marcar métodos o clases enteras como transaccionales, y Spring se encargará de iniciar, comprometer (`commit`) o revertir (`rollback`) la transacción según sea necesario.

### Función de `@Transactional`

**La anotación `@Transactional` permite:**

1. **Gestión Automática de Transacciones**: Spring se encarga de iniciar y finalizar las transacciones de manera automática.

2. **Declaración de Propagación y Aislamiento**: Puedes definir el comportamiento de propagación y el nivel de aislamiento de las transacciones.

3. **Manejo de Rollback**: Puedes especificar qué excepciones deben causar un rollback automático de la transacción.

4. **Optimización del Rendimiento**: Mejora el rendimiento al reducir la cantidad de código necesario para manejar transacciones de manera explícita.

### Parámetros de `@Transactional`
La anotación `@Transactional` tiene varios parámetros que permiten personalizar el comportamiento de las transacciones:

* `propagation`: Define cómo debe propagarse una transacción existente. Los valores incluyen **REQUIRED**, **SUPPORTS**, **MANDATORY**, **REQUIRES_NEW**, **NOT_SUPPORTED**, **NEVER**, **NESTED**.

    ```java
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void nuevoMetodoTransaccional() {
        // Código del método
    }
    ```

* `isolation`: Define el nivel de aislamiento de la transacción. Los valores incluyen **DEFAULT**, **READ_UNCOMMITTED**, **READ_COMMITTED**, **REPEATABLE_READ**, **SERIALIZABLE**.

    ```java
    @Transactional(isolation = Isolation.SERIALIZABLE)
    public void metodoConAislamientoSerializable() {
        // Código del método
    }
    ```

* `timeout`: Define el tiempo de espera en segundos para la transacción antes de que sea abortada.

    ```java
    @Transactional(timeout = 5)
    public void metodoConTimeout() {
        // Código del método
    }
    ```

* `readOnly`: Indica si la transacción es solo de lectura. Esto puede optimizar el rendimiento de las consultas.

    ```java
    @Transactional(readOnly = true)
    public void metodoSoloLectura() {
        // Código del método
    }
    ```

* `rollbackFor`: Define qué excepciones causarán un rollback de la transacción.

    ```java
    @Transactional(rollbackFor = Exception.class)
    public void metodoConRollback() throws Exception {
        // Código del método
        if (true) {
            throw new Exception("Error");
        }
    }
    ```

## Consultas Personalizadas con JPQL
**JPQL (Java Persistence Query Language)** es el lenguaje de consultas utilizado en JPA para realizar consultas sobre las entidades gestionadas por el `EntityManager`. JPQL es similar a SQL, pero opera sobre el **modelo** de entidades en lugar de directamente sobre las tablas de la base de datos.

### Características de JPQL
1. **Orientado a Objetos**: Las consultas se hacen sobre entidades y sus relaciones.

2. **Compatibilidad con JPA**: JPQL es parte del estándar JPA, asegurando portabilidad entre diferentes implementaciones.

3. **Flexibilidad**: Permite realizar consultas complejas utilizando sintaxis similar a SQL.

### Ejemplo de Consultas Personalizadas con JPQL
Supongamos que tenemos una entidad Producto y queremos realizar una consulta personalizada para encontrar todos los productos con un precio superior a un valor específico.

1. **Definición de la Entidad**

    ```java
    import javax.persistence.Entity;
    import javax.persistence.GeneratedValue;
    import javax.persistence.GenerationType;
    import javax.persistence.Id;

    @Entity
    public class Producto {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long id;
        private String nombre;
        private double precio;

        // Getters y setters
    }
    ```

2. **Repositorio Personalizado con JPQL**

```java
import org.springframework.stereotype.Repository;

import javax.persistence.EntityManager;
import javax.persistence.PersistenceContext;
import javax.persistence.TypedQuery;
import java.util.List;

@Repository
public class ProductoRepositoryCustom {

    @PersistenceContext
    private EntityManager entityManager;

    public List<Producto> findProductosByPrecioGreaterThan(double precio) {

        // Definicion de la consulta
        String jpql = "SELECT p FROM Producto p WHERE p.precio > :precio";

        // Creacion de la consulta
        TypedQuery<Producto> query = entityManager.createQuery(jpql, Producto.class);
        
        // Establecimiento del parametro
        query.setParameter("precio", precio);
        
        // ejecuta la consulta
        return query.getResultList();
    }
}
```
**Sintaxis de la consulta**

* `SELECT p`

  * Esta parte de la consulta especifica que queremos seleccionar instancias de la entidad `Producto`. Aquí, `p` es un alias que se asigna a la entidad `Producto`.

* `FROM Producto p`

  * Esta cláusula indica la entidad de la cual estamos seleccionando datos, en este caso, `Producto`. El alias `p` se utiliza para referirse a la entidad `Producto` en el resto de la consulta.

1. **Uso en el Servicio**

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class ProductoService {

    @Autowired
    private ProductoRepositoryCustom productoRepositoryCustom;

    public List<Producto> obtenerProductosConPrecioMayorA(double precio) {
        return productoRepositoryCustom.findProductosByPrecioGreaterThan(precio);
    }
}
```

### Cuándo Utilizar Consultas Personalizadas con JPQL
1. **Consultas Específicas**: Cuando necesitas realizar consultas específicas que no pueden ser manejadas por los métodos de repositorio estándar.

2. **Consultas Dinámicas**: Cuando necesitas construir consultas dinámicamente en función de criterios de búsqueda variados.

3. **Optimización**: Cuando necesitas optimizar las consultas para un rendimiento específico o casos de uso complejos.

## Query Objects
Es un patrón de diseño utilizado para encapsular las consultas a la base de datos en un objeto separado. Este patrón ayuda a separar la lógica de acceso a datos de la lógica de negocio, facilitando la mantenibilidad y prueba del código.

### Ventajas de Query Objects

1. **Encapsulamiento**: Las consultas están encapsuladas en objetos dedicados, lo que mejora la modularidad.

2. **Reutilización**: Las consultas comunes pueden ser reutilizadas en diferentes partes de la aplicación.

3. **Mantenibilidad**: Facilita la actualización y mantenimiento de las consultas sin afectar la lógica de negocio.

4. **Legibilidad**: Mejora la legibilidad del código al separar las consultas SQL o JPQL del código de negocio.

### Ejemplo de Query Object
Supongamos que tenemos una entidad Producto y queremos encontrar todos los productos por nombre.

```java
import javax.persistence.EntityManager;
import javax.persistence.PersistenceContext;
import javax.persistence.TypedQuery;
import java.util.List;

public class ProductoQuery {

    @PersistenceContext
    private EntityManager entityManager;

    public List<Producto> findByName(String nombre) {
        String jpql = "SELECT p FROM Producto p WHERE p.nombre = :nombre";
        TypedQuery<Producto> query = entityManager.createQuery(jpql, Producto.class);
        query.setParameter("nombre", nombre);
        return query.getResultList();
    }
}
```
El `ProductoQuery` encapsula la lógica de la consulta, permitiendo que el código de negocio simplemente llame a este objeto para obtener los resultados.

### Cuándo Utilizar Query Objects
1. **Consultas Complejas**: Cuando las consultas son complejas y se reutilizan en múltiples lugares de la aplicación.

2. **Separación de Preocupaciones**: Para mantener la lógica de consultas separada de la lógica de negocio.

3. **Mantenimiento**: Para facilitar el mantenimiento y actualización de las consultas sin afectar el código de negocio.

## Parámetros
En JPQL (Java Persistence Query Language), los parámetros en las consultas se utilizan para evitar la concatenación de cadenas para crear consultas dinámicas, lo cual mejora la seguridad contra inyecciones SQL y facilita la reutilización de las consultas. Hay dos tipos principales de parámetros en JPQL: parámetros posicionales y parámetros con nombre.

### Parámetros Posicionales
Los parámetros posicionales están marcados con un signo de interrogación seguido de un número que indica su posición en la consulta. Estos parámetros se establecen en el mismo orden en que aparecen en la consulta.

**Ejemplo**
```java
String jpql = "SELECT p FROM Producto p WHERE p.precio > ?1 AND p.categoria = ?2";

TypedQuery<Producto> query = entityManager.createQuery(jpql, Producto.class);

query.setParameter(1, 100.0);

query.setParameter(2, "Electrónica");

List<Producto> resultados = query.getResultList();
```
En este ejemplo, `?1` se reemplaza por **100.0** y `?2` se reemplaza por "**Electrónica"**.

### Parámetros con Nombre
Los parámetros con nombre están marcados con un prefijo `:` seguido de un nombre. Estos parámetros se establecen utilizando su nombre, lo que mejora la legibilidad y el mantenimiento de la consulta.

**Ejemplo**
```java
String jpql = "SELECT p FROM Producto p WHERE p.precio > :precio AND p.categoria = :categoria";

TypedQuery<Producto> query = entityManager.createQuery(jpql, Producto.class);

query.setParameter("precio", 100.0);

query.setParameter("categoria", "Electrónica");

List<Producto> resultados = query.getResultList();
```
En este ejemplo, `:precio` se reemplaza por **100.0** y `:categoria` se reemplaza por **"Electrónica"**.

### Ventajas de los Parámetros con Nombre

1. **Legibilidad**: Los parámetros con nombre son más fáciles de leer y entender, especialmente en consultas complejas.

2. **Mantenimiento**: Cambiar el orden de los parámetros en la consulta no afecta el código, ya que los parámetros se refieren por su nombre.

3. **Evitar Errores**: Reduce la probabilidad de errores al establecer parámetros, ya que no depende del orden.

## Usando Parámetros en Consultas con Named Queries
También puedes utilizar parámetros en las `Named Queries` definidas a nivel de entidad.

1. Definición de la `Named Query`

    ```java
    import javax.persistence.*;

    @Entity
    @NamedQuery(name = "Producto.findByCategoriaYPrecio",
                query = "SELECT p FROM Producto p WHERE p.categoria = :categoria AND p.precio > :precio")
    public class Producto {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long id;
        private String nombre;
        private String categoria;
        private double precio;

        // Getters y setters
    }
    ```

2. **Uso de la Named Query**

    ```java
    TypedQuery<Producto> query = entityManager.createNamedQuery("Producto.findByCategoriaYPrecio", Producto.class);

    query.setParameter("categoria", "Electrónica");

    query.setParameter("precio", 100.0);

    List<Producto> resultados = query.getResultList();
    ```

## Parámetros de Fecha
JPQL también admite parámetros de fecha, que se pueden pasar utilizando objetos `java.util.Date` o `java.time.LocalDate`, dependiendo de la versión de JPA/Hibernate que estés utilizando.

**Ejemplo de Parámetros de Fecha**
```java
import java.util.Date;

String jpql = "SELECT p FROM Pedido p WHERE p.fechaEntrega = :fechaEntrega";

TypedQuery<Pedido> query = entityManager.createQuery(jpql, Pedido.class);

query.setParameter("fechaEntrega", new Date());

List<Pedido> resultados = query.getResultList();
```

## Parámetros de Colección
En algunos casos, es posible que desees pasar una colección de valores como parámetro. Esto se hace utilizando el método `setParameter` con una colección.

```java
import java.util.Arrays;
import java.util.List;

String jpql = "SELECT p FROM Producto p WHERE p.categoria IN :categorias";

TypedQuery<Producto> query = entityManager.createQuery(jpql, Producto.class);

List<String> categorias = Arrays.asList("Electrónica", "Hogar", "Juguetes");

query.setParameter("categorias", categorias);

List<Producto> resultados = query.getResultList();
```
