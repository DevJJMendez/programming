# `@OneToOne`
La anotación `@OneToOne` en Hibernate y en JPA se utiliza para definir una relación de **uno a uno** entre dos entidades, es decir, cada instancia de una entidad está asociada con una sola instancia de otra entidad y viceversa. Es común utilizar esta anotación cuando dos entidades tienen una relación en la que una entidad depende directamente de la otra, o donde cada entidad contiene información exclusiva que solo se relaciona con otra entidad específica.

## ¿Qué es `@OneToOne`?
`@OneToOne` es una anotación de JPA que representa una relación de **uno a uno** entre dos entidades. Al aplicar esta anotación, estamos indicando que un registro en la tabla de la primera entidad tiene una relación exclusiva con un único registro en la tabla de la segunda entidad, y viceversa. Un ejemplo típico es la relación entre **una persona y un pasaporte: cada persona tiene un único pasaporte, y cada pasaporte pertenece a una única persona**.

## ¿Para qué sirve `@OneToOne`?
La anotación `@OneToOne` se usa para establecer y mapear relaciones **uno a uno** en el modelo de datos de la aplicación. Sirve para:

* Modelar asociaciones **uno a uno** en el código de la aplicación.

* Mantener la integridad relacional entre entidades asociadas.

* Facilitar la navegación bidireccional de las entidades (si la relación está configurada como bidireccional).

* Permitir que Hibernate gestione las relaciones de manera eficiente al realizar operaciones de CRUD.

## ¿Qué problemas resuelve `@OneToOne`?
* **Mantenimiento de relaciones exclusivas**: Define y mantiene relaciones en las que dos entidades tienen una asociación exclusiva, sin riesgo de que una entidad tenga varias instancias relacionadas de la otra.

* **Simplificación de la consulta**: Al tener una relación establecida, las entidades se pueden cargar juntas o de manera selectiva, según la estrategia de carga configurada (FetchType), mejorando el rendimiento y reduciendo la necesidad de consultas adicionales.

* **Manejo automático de restricciones**: Con `@OneToOne`, se puede gestionar automáticamente las restricciones en la base de datos, como llaves foráneas y referencias cruzadas, sin necesidad de realizar la administración manual.

## ¿Cómo lo resuelve `@OneToOne`?
Hibernate y JPA usan esta anotación para manejar la relación en dos sentidos posibles:

* **Bidireccional**: Ambas entidades están conscientes de la relación. Esto significa que, al navegar de una entidad a otra, podemos hacerlo en ambos sentidos.

* **Unidireccional**: Solo una de las entidades tiene información sobre la otra, simplificando la relación.

La configuración de `@OneToOne` también permite definir aspectos como:

* **`Cascade`**: Controla cómo las operaciones realizadas en una entidad afectan la entidad relacionada.

* **`FetchType`**: Determina si la entidad relacionada se carga de manera diferida (**`LAZY`**) o de inmediato (**`EAGER`**).

* **`JoinColumn`**: Especifica la columna de unión en la base de datos, para mantener la referencia entre ambas entidades.

## Parámetros de `@OneToOne`
Al configurar @OneToOne, se pueden establecer varios parámetros importantes:

* **`cascade`**: Especifica el comportamiento en cascada. Por ejemplo, `CascadeType.ALL` aplica todas las operaciones de cascada (guardar, actualizar, eliminar).

* **`fetch`**: Controla si se debe cargar la entidad relacionada en el momento (`FetchType.EAGER`) o solo cuando se accede a ella (`FetchType.LAZY`).

* **`mappedBy`**: Solo en relaciones bidireccionales. Define el propietario de la relación, especificando cuál de las entidades gestiona la relación en la base de datos.

* **`optional`**: Determina si la entidad relacionada es opcional. Si es `false`, se espera que la entidad relacionada siempre esté presente (valor por defecto: `true`).

## Ejemplo de uso
Supongamos una relación entre `Persona` y `Pasaporte`, donde cada persona tiene un único pasaporte y cada pasaporte pertenece a una sola persona.

**Relación unidireccional**
```java
@Entity
public class Persona {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @OneToOne(cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    @JoinColumn(name = "pasaporte_id", referencedColumnName = "id")
    private Pasaporte pasaporte;

    // Getters y Setters
}

@Entity
public class Pasaporte {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    // Otros atributos y métodos
}
```
Aquí, la clase Persona tiene un campo pasaporte que representa su pasaporte. La columna de unión se especifica en la anotación `@JoinColumn`.

**Relación bidireccional**, Si queremos que el pasaporte también tenga un campo que haga referencia a su persona:

```java
@Entity
public class Persona {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @OneToOne(cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    @JoinColumn(name = "pasaporte_id", referencedColumnName = "id")
    private Pasaporte pasaporte;

    // Getters y Setters
}

@Entity
public class Pasaporte {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @OneToOne(mappedBy = "pasaporte")
    private Persona persona;

    // Getters y Setters
}
```
Aquí, `Persona` sigue siendo el propietario de la relación, y `Pasaporte` tiene un campo persona con la anotación `mappedBy` que indica que pasaporte en `Persona` es el lado de la relación que controla la asociación.

## Buenas prácticas al usar `@OneToOne`
* **Usar `@OneToOne` solo cuando la relación es exclusiva**: Evitar su uso para relaciones donde múltiples instancias de una entidad se puedan asociar a otra.

* **Definir `fetch = FetchType.LAZY` cuando sea posible**: Cargar entidades relacionadas solo cuando sea necesario puede mejorar el rendimiento.

* **Configurar adecuadamente `optional`**: Si la entidad relacionada siempre debe estar presente, establecer `optional = false`.
