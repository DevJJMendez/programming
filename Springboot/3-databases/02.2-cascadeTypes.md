# Cascade Types
Los tipos de Cascade (o CascadeType) en JPA e Hibernate son configuraciones que definen cómo se deben propagar las operaciones de persistencia entre entidades relacionadas. Al definir una relación entre entidades (como @OneToOne, @OneToMany, @ManyToOne o @ManyToMany), los tipos de cascada especifican qué acciones se deben tomar sobre una entidad relacionada cuando se realiza una operación sobre la entidad principal.

## ¿Qué son los CascadeType?
Los CascadeType son opciones que determinan si las operaciones de una entidad (como guardar, actualizar o eliminar) deben aplicarse automáticamente a las entidades asociadas. Este enfoque reduce la necesidad de realizar múltiples operaciones sobre cada entidad manualmente, mejorando la consistencia y el manejo de dependencias.

## ¿Cuáles son los Tipos de Cascada?
* **`CascadeType.PERSIST`**: Propaga la operación de persistencia (`save`) desde la entidad padre a sus entidades relacionadas.

* **`CascadeType.MERGE`**: Propaga la operación de mezcla (`merge`) de los cambios de la entidad padre a sus entidades relacionadas.

* **`CascadeType.REMOVE`**: Propaga la operación de eliminación (`delete`) desde la entidad padre a sus entidades relacionadas.

* **`CascadeType.REFRESH`**: Refresca el estado de las entidades relacionadas para que coincidan con el de la base de datos.

* **`CascadeType.DETACH`**: Desvincula la entidad padre y todas las entidades relacionadas del contexto de persistencia.

* **`CascadeType.ALL`**: Aplica todos los tipos de cascada anteriores (`PERSIST`, `MERGE`, `REMOVE`, `REFRESH` y `DETACH`) sobre las entidades relacionadas.

## ¿Para qué sirven los CascadeType?
Los CascadeType sirven para simplificar y gestionar de forma automática las relaciones entre entidades. Permiten definir qué acciones se deben ejecutar sobre las entidades relacionadas cuando se realiza una operación específica en la entidad principal. Esto facilita la persistencia, sincronización, y eliminación de datos asociados sin necesidad de administrar manualmente cada entidad dependiente.

## ¿Qué resuelven?
Resuelven la necesidad de sincronizar operaciones entre entidades relacionadas, garantizando que las entidades dependientes sigan el mismo ciclo de vida de persistencia que la entidad principal. Esto es esencial para mantener la consistencia de los datos en una base de datos, ya que evita la creación de huérfanos o datos incoherentes entre entidades.

## ¿Cómo lo resuelven?
Los CascadeType resuelven esto propagando las operaciones automáticamente de la entidad principal a sus entidades dependientes. Al especificar el tipo de cascada en la relación, JPA e Hibernate aplican automáticamente las operaciones correspondientes en las entidades relacionadas sin requerir que el desarrollador ejecute operaciones manuales.

## Explicación
1. **`CascadeType.PERSIST`**:

   * Al persistir la entidad padre, también se guardan las entidades relacionadas.

   * **Ejemplo**: Guardar un Cliente guardará también sus Pedidos.

2. **`CascadeType.MERGE`**:

   * Al fusionar cambios en la entidad principal, también se aplican en las entidades relacionadas.

   * **Ejemplo**: Si actualizas el nombre de un Cliente y quieres que sus Pedidos reflejen los cambios, este tipo de cascada lo facilita.

3. **`CascadeType.REMOVE`**:

   * Al eliminar la entidad principal, también se eliminan las entidades relacionadas.

   * **Ejemplo**: Si eliminas un Cliente, sus Pedidos también se eliminarán, evitando datos huérfanos.

4. **`CascadeType.REFRESH`**:

   * Actualiza la entidad principal y las entidades relacionadas con los datos más recientes de la base de datos.

   * **Ejemplo**: Si otra aplicación actualiza los datos de un Cliente, puedes usar REFRESH para sincronizar los datos con la base de datos.

5. **`CascadeType.DETACH`**:

   * Desvincula tanto la entidad principal como sus entidades relacionadas del contexto de persistencia, de forma que ya no están gestionadas por JPA.

   * **Ejemplo**: Si desvinculas un Cliente, sus Pedidos también se desvinculan y cualquier cambio posterior no se reflejará en la base de datos.

6. **`CascadeType.ALL`**:

   * Aplica todos los tipos de cascada anteriores, simplificando la gestión de la relación.

   * **Ejemplo**: Con CascadeType.ALL, cualquier cambio (persistir, fusionar, eliminar, etc.) en un Cliente se aplicará a sus Pedidos automáticamente.

## Consideraciones y Buenas Prácticas
* **Usar con Cuidado**: El uso excesivo o incorrecto de `CascadeType.ALL` puede llevar a operaciones no deseadas en la base de datos, como la eliminación accidental de registros importantes.

* **Operaciones Masivas**: En situaciones donde se manejan relaciones complejas con muchos registros, es importante considerar el rendimiento, ya que las cascadas pueden desencadenar un gran número de operaciones en la base de datos.

* **Sincronización de Estados**: El uso de cascadas ayuda a mantener la coherencia entre las entidades y la base de datos, pero es crucial entender cómo se comportan estas operaciones en cascada para evitar inconsistencias.

# Multiples Cascade Types
Se puede configurar múltiples **CascadeType** en una relación utilizando un `array` en la anotación `@Cascade`. Esto te permite combinar varias operaciones en cascada según lo que necesites para una relación específica.

## Configuración de Múltiples CascadeType
Puedes definir múltiples tipos de cascada utilizando la siguiente sintaxis:

```java
@OneToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
private List<Direccion> direcciones;
```
En este ejemplo, tanto la operación de persistencia (**PERSIST**) como la de fusión (**MERGE**) se propagarán desde la entidad principal a las entidades relacionadas.

## Casos Útiles para Usar Múltiples CascadeType
1. **Propagación Selectiva de Operaciones**

   * Si necesitas que al persistir una entidad principal también se persistan las entidades relacionadas, pero al eliminar la entidad principal no se eliminen las entidades relacionadas, podrías combinar **PERSIST** y **MERGE** sin incluir **REMOVE**.

      ```java
      @OneToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
      private List<Direccion> direcciones;
      ```

   * **Uso**: Cuando deseas que las direcciones se creen y actualicen automáticamente con el usuario, pero no deseas que se eliminen automáticamente si el usuario se elimina.

2. **Sincronización de Entidades Relacionadas**

   * En un escenario donde quieras que las entidades relacionadas se sincronicen con la entidad principal cada vez que se actualiza o se rehidrata desde la base de datos, podrías usar **MERGE** y **REFRESH** juntos.

      ```java
      @OneToMany(cascade = {CascadeType.MERGE, CascadeType.REFRESH})
      private List<Direccion> direcciones;
      ```

   * **Uso**: Útil en aplicaciones donde es crucial que las entidades relacionadas siempre reflejen el estado más reciente desde la base de datos, asegurando que los cambios se apliquen tanto en la actualización como en la recarga.

3. **Persistencia y Eliminación Automática**

   * Si necesitas que las entidades relacionadas se creen y eliminen automáticamente junto con la entidad principal, podrías combinar **PERSIST** y **REMOVE**.

      ```java
      @OneToOne(cascade = {CascadeType.PERSIST, CascadeType.REMOVE})
      private Direccion direccion;
      ```

   * **Uso**: Ideal cuando deseas que una relación uno a uno se mantenga consistente, de manera que la eliminación de la entidad principal también elimine la entidad relacionada, y viceversa.

4. **Manejo de Relaciones Orfanadas**

   * En ciertas configuraciones, como en colecciones de entidades, puedes querer combinar **REMOVE** con **PERSIST** para asegurar que cuando una entidad hija se quita de la colección, también se elimine de la base de datos, mientras que cualquier nueva entidad hija se persista.

      ```java
      @OneToMany(cascade = {CascadeType.PERSIST, CascadeType.REMOVE}, orphanRemoval = true)
      private List<Direccion> direcciones;
      ```

   * **Uso**: Esto es común en relaciones padre-hijo donde la entidad hijo no tiene sentido sin su padre y debe eliminarse si se quita de la relación.
