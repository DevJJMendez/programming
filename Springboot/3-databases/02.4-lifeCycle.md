## Entity
En Hibernate, las entidades son objetos de Java que se mapean directamente a tablas en una base de datos relacional. Cada entidad representa una fila en la tabla, y los campos de la entidad se mapean a las columnas de la tabla. Hibernate permite que estos objetos sean gestionados por el framework, lo que facilita las operaciones de persistencia, actualización, eliminación y consulta en la base de datos.

### Características de las Entidades en Hibernate
1. **Debe ser una clase Java**

   * Una entidad es una clase Java normal (**POJO: Plain Old Java Object**) que sigue ciertas convenciones para ser manejada por Hibernate.

2. **Debe tener un identificador único (Primary Key)**

   * Cada entidad debe tener un campo que funcione como identificador único. Este campo se mapea a la clave primaria en la base de datos.

3. **Debe estar anotada con `@Entity`**

   * La clase debe estar anotada con `@Entity` para que Hibernate la reconozca como una entidad.

4. **Debe tener un constructor sin parámetros**

   * Aunque puede tener otros constructores, es necesario que tenga un constructor público o protegido sin parámetros, ya que Hibernate lo usa para instanciar la entidad.


## Ciclo de Vida de las Entidades
El ciclo de vida de una entidad en Hibernate describe los diferentes estados por los que una entidad puede pasar desde que se crea hasta que se elimina o se deja de gestionar por el framework. Comprender este ciclo de vida es esencial para trabajar eficazmente con Hibernate y evitar problemas comunes, como actualizaciones innecesarias o excepciones inesperadas.

### Estados del Ciclo de Vida de una Entiidad

#### **Transient (Transitorio)**
Una entidad se encuentra en el estado "transient" cuando ha sido creada en memoria, pero no está asociada con ninguna **Session** de Hibernate ni ha sido persistida en la base de datos.

* Características:

  * La entidad no tiene ninguna representación en la base de datos.

  * No está siendo gestionada por Hibernate.

  * Hibernate no realiza ningún seguimiento de esta entidad ni persiste automáticamente sus cambios.

  * **Ejemplo**
  ```java
  Empleado empleado = new Empleado(); // Estado Transient
  empleado.setNombre("Juan");
  ```
  * Cómo pasar al siguiente estado:

    * Llamando a `session.save(empleado)` o `session.persist(empleado)` para mover la entidad al estado **Persistent**.

#### Persistent (Persistente)
Una entidad se encuentra en el estado "persistent" cuando está siendo gestionada activamente por una **Session** de Hibernate y tiene una representación en la base de datos.

* Características:

  * La entidad está asociada a una **Session** de Hibernate.

  * Cualquier cambio en la entidad se sincroniza con la base de datos al finalizar la transacción o al hacer un `flush()` en la **Session**.

  * Hibernate realiza un seguimiento de los cambios en la entidad.
  
  * **Ejemplo**

    ```java
    session.save(empleado); // Estado Persistent
    empleado.setSalario(50000.0); // Hibernate rastrea y sincroniza este cambio
    ```
  
  * Cómo pasar al siguiente estado:
  
    * La entidad permanece en este estado hasta que la **Session** se cierra o la entidad se elimina.

### Detached (Desasociado)
Una entidad entra en el estado "detached" cuando la **Session** que la estaba gestionando se cierra, o cuando la entidad se desasocia de la **Session**.

* Características:

  * La entidad aún existe en la base de datos, pero Hibernate ya no la está gestionando.

  * Los cambios en la entidad no se sincronizan automáticamente con la base de datos.

  * Es útil en aplicaciones distribuidas o en contextos donde se necesita desasociar una entidad para enviarla a través de la red.
  
  * **Ejemplo**

    ```java
    session.evict(empleado); // Empleado pasa a estado Detached
    empleado.setSalario(55000.0); // No se sincronizará a menos que se vuelva a asociar
    ```

  * Cómo pasar al siguiente estado:

    * Para volver a hacer que una entidad desasociada sea gestionada por Hibernate, puedes usar `session.update(empleado)` o session.merge(empleado) para moverla de nuevo al estado **Persistent**.

###  Removed (Eliminado)
Una entidad entra en el estado "removed" cuando se ha marcado para ser eliminada de la base de datos. Esto ocurre al llamar a `session.delete(entidad)`.

* Características:

  * La entidad será eliminada de la base de datos cuando la transacción se complete.
Sigue siendo gestionada por la Session hasta que se confirma la eliminación.

  * **Ejemplo**

    ```java
    session.delete(empleado); // Estado Removed
    ```

  * Cómo pasar al siguiente estado:

    * Después de que se ejecute la eliminación en la base de datos, la entidad ya no tiene representación en la base de datos y no se puede volver a gestionar a menos que se vuelva a insertar (por ejemplo, con `save()` o `persist()`).

### Diagrama del Ciclo de Vida de una Entidad
```plaintext
       +-------------------+
       |                   |
       |   Transient       |
       |                   |
       +---------+---------+
                 |
                 | save() / persist()
                 v
       +-------------------+
       |                   |
       |   Persistent      |
       |                   |
       +---------+---------+
                 |
         +-------+-------+
         |               |

         v               v
   +-------------+  +-------------+
   |             |  |             |

   |             |  |             |
   +-------------+  +-------------+
                        |
                        | update() / merge()
                        v
                 +-------------+
                 |             |
                 |  Persistent |
                 |             |
                 +-------------+
```

## Contexto de Persistencia
El contexto de persistencia es un concepto clave en Hibernate y en otros frameworks ORM (Object-Relational Mapping). Define el entorno en el que se gestionan las entidades, determinando cómo y cuándo Hibernate realiza operaciones sobre la base de datos relacionadas con esas entidades. Entender el contexto de persistencia es fundamental para manejar correctamente el ciclo de vida de las entidades y evitar problemas como inconsistencias en los datos, errores de transacción, o problemas de rendimiento.

El contexto de persistencia es un conjunto de entidades gestionadas por una Session en Hibernate. En términos más simples, es el ambiente donde las entidades están vivas y Hibernate realiza un seguimiento de ellas, asegurando que cualquier cambio en las entidades se sincronice con la base de datos.

En JPA (Java Persistence API), el contexto de persistencia se gestiona a través de la **EntityManager**, que en Hibernate se asocia directamente con la **Session**.

### Características del Contexto de Persistencia
1. **Identidad de Entidades**:

   * Dentro de un contexto de persistencia, una entidad es única por su identificador. Si intentas cargar la misma entidad (con el mismo ID) más de una vez dentro de la misma Session, Hibernate devolverá la misma instancia. Esto asegura que no hay duplicación de objetos en la memoria.

2. **Sincronización Automática**:

   * Cualquier cambio realizado en una entidad gestionada por el contexto de persistencia se sincroniza automáticamente con la base de datos cuando se realiza un flush(), se cierra la transacción o la Session.

3. **Caché de Primer Nivel**:

   * Hibernate mantiene una caché de primer nivel dentro del contexto de persistencia. Todas las entidades cargadas dentro de una Session se almacenan aquí, lo que significa que las consultas repetidas para la misma entidad se satisfacen desde esta caché sin hacer consultas adicionales a la base de datos.

4. **Transacciones**:

   * El contexto de persistencia está estrechamente vinculado con las transacciones. Hibernate se asegura de que todas las operaciones de persistencia (crear, leer, actualizar, eliminar) se realicen dentro de una transacción.

### Ciclo de Vida y el Contexto de Persistencia
El ciclo de vida de las entidades está controlado por el contexto de persistencia. Dependiendo del estado de la entidad y la relación con el contexto de persistencia, Hibernate toma decisiones sobre cómo manejar la entidad.

### Tipos de Contexto de Persistencia
1. **Contexto de Persistencia Transaccional**:

   * Este es el tipo más común, donde el contexto de persistencia se asocia con una única transacción. Una vez que la transacción finaliza (se confirma o se revierte), el contexto de persistencia se cierra.

   * Ideal para aplicaciones que manejan un conjunto limitado de operaciones en un corto período de tiempo.

2. **Contexto de Persistencia Extendido**:

   * En este caso, el contexto de persistencia no se cierra cuando la transacción termina. En su lugar, permanece activo a lo largo de múltiples transacciones.
   
   * Utilizado en aplicaciones de larga duración, como las basadas en interfaces de usuario (por ejemplo, aplicaciones web), donde las entidades necesitan ser gestionadas a lo largo de múltiples interacciones del usuario.

## Eventos del Ciclo de Vida: @PrePersist, @PostPersist, @PreUpdate, @PostUpdate, @PreRemove, @PostRemove.
En Hibernate y JPA, los eventos del ciclo de vida de una entidad permiten ejecutar lógica personalizada en momentos clave del ciclo de vida de la entidad. Estos eventos están asociados con anotaciones específicas que pueden aplicarse a métodos dentro de las entidades o a entidades específicas para realizar acciones antes o después de operaciones como persistir, actualizar o eliminar una entidad. Esto es útil para realizar validaciones, auditorías, registros o cualquier otra lógica que deba ejecutarse en respuesta a cambios en el estado de la entidad.

### @PrePersist
Este evento se dispara antes de que una entidad sea persistida (insertada) en la base de datos por primera vez. Es un buen lugar para realizar inicializaciones o configuraciones que deben ocurrir justo antes de que la entidad se almacene por primera vez.

**Uso Común**: Establecer valores predeterminados, calcular valores derivados, o realizar cualquier lógica que necesite ejecutarse antes de la primera inserción en la base de datos.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    private String nombre;
    
    private LocalDateTime fechaCreacion;
    
    @PrePersist
    protected void onPrePersist() {
        fechaCreacion = LocalDateTime.now(); // Establecer la fecha de creación antes de persistir
    }
}
```

### @PostPersist
Este evento se dispara inmediatamente después de que una entidad ha sido persistida (insertada) en la base de datos por primera vez. Es útil para ejecutar lógica que debe suceder después de que la entidad haya sido guardada.

**Uso Común**: Registrar auditorías, enviar notificaciones, o actualizar entidades relacionadas.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    @PostPersist
    protected void onPostPersist() {
        System.out.println("Empleado " + id + " ha sido persistido en la base de datos.");
    }
}
```

### @PreUpdate
Este evento se dispara antes de que una entidad existente sea actualizada en la base de datos. Es útil para realizar validaciones o ajustar valores antes de que se sincronicen los cambios.

**Uso Común**: Validar datos, ajustar fechas de modificación, o realizar cualquier preparación necesaria antes de la actualización.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    private LocalDateTime fechaUltimaModificacion;
    
    @PreUpdate
    protected void onPreUpdate() {
        fechaUltimaModificacion = LocalDateTime.now(); // Actualizar la fecha de última modificación
    }
}
```

### @PostUpdate
Este evento se dispara después de que una entidad ha sido actualizada en la base de datos. Puedes usarlo para lógica que debe ejecutarse después de que se hayan sincronizado los cambios.

**Uso Común**: Registrar cambios, enviar notificaciones, o realizar acciones dependientes de la confirmación de la actualización.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    @PostUpdate
    protected void onPostUpdate() {
        System.out.println("Empleado " + id + " ha sido actualizado en la base de datos.");
    }
}
```

### @PreRemove
Este evento se dispara antes de que una entidad sea eliminada de la base de datos. Es un buen lugar para manejar relaciones dependientes o realizar cualquier limpieza que deba ocurrir antes de la eliminación.

**Uso Común**: Manejar la eliminación en cascada, validar la eliminación, o limpiar datos relacionados.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    @PreRemove
    protected void onPreRemove() {
        System.out.println("Empleado " + id + " está a punto de ser eliminado.");
    }
}
```

### @PostRemove
Este evento se dispara después de que una entidad ha sido eliminada de la base de datos. Puedes usarlo para realizar acciones que deben ocurrir después de la eliminación.

**Uso Común**: Eliminar datos relacionados, registrar la eliminación, o enviar notificaciones.

**Ejemplo**
```java
@Entity
public class Empleado {
    
    @Id
    private Long id;
    
    @PostRemove
    protected void onPostRemove() {
        System.out.println("Empleado " + id + " ha sido eliminado de la base de datos.");
    }
}
```
