# EntityManager
Es una interfaz que proporciona una serie de métodos para realizar operaciones CRUD, consultas y gestionar el ciclo de vida de las entidades.

## ¿Para qué sirve EntityManager?
El EntityManager es crucial para las siguientes operaciones:

* **Persistencia de entidades**: Permite guardar nuevas entidades en la base de datos.

* **Consulta de entidades**: Proporciona métodos para realizar consultas a la base de datos usando JPQL (Java Persistence Query Language) o consultas SQL nativas.

* **Manejo del ciclo de vida de las entidades**: Permite manejar el estado de las entidades (nueva, gestionada, detachada, eliminada).

* **Transacciones**: Facilita el manejo de transacciones, asegurando que las operaciones en la base de datos sean atómicas.

## ¿Qué problemas resuelve EntityManager?
* **Abstracción del acceso a datos**: Permite a los desarrolladores trabajar con objetos Java en lugar de preocuparse por las complejidades del acceso directo a la base de datos.

* **Gestión del ciclo de vida**: El EntityManager simplifica la gestión del ciclo de vida de las entidades y su estado, lo que facilita el desarrollo de aplicaciones robustas y mantenibles.

* **Manejo de transacciones**: Proporciona un mecanismo para gestionar transacciones de manera efectiva, garantizando la integridad de los datos.
Interoperabilidad: Facilita la comunicación entre la aplicación y diferentes bases de datos, ya que es independiente de la tecnología de almacenamiento.

## ¿Cómo resuelve estos problemas EntityManager?
El EntityManager resuelve estos problemas a través de varias funcionalidades clave:

* **Métodos de persistencia**: Proporciona métodos como `persist()`, `merge()`, y `remove()` para manejar entidades en la base de datos.

* **Consulta de datos**: Con métodos como `createQuery()`, `find()`, y `createNativeQuery()`, el EntityManager permite realizar consultas a la base de datos de manera sencilla.

* **Gestión de transacciones**: A través de EntityTransaction, permite iniciar, confirmar o revertir transacciones, lo que asegura que las operaciones en la base de datos se realicen correctamente.

* **Contexto de persistencia**: Mantiene un contexto de persistencia en el que las entidades pueden ser gestionadas, asegurando que cualquier cambio en la entidad se refleje en la base de datos.

## Métodos Comunes de EntityManager

* `persist(Object entity)`: Inserta una nueva entidad.

* `find(Class<T> entityClass, Object primaryKey)`: Busca una entidad por su clave primaria.

* `merge(Object entity)`: Actualiza una entidad existente.

* `remove(Object entity)`: Elimina una entidad.

* `createQuery(String qlString, Class<T> resultClass)`: Crea una consulta JPQL.

* `createNamedQuery(String name, Class<T> resultClass)`: Crea una consulta nombrada.

* `createNativeQuery(String sqlString)`: Crea una consulta nativa SQL.

+ `getTransaction()`: Obtiene la transacción actual (cuando no se utiliza `@Transactional` de Spring).

## Cuándo Usar `EntityManager`
1. **Consultas Complejas**: Cuando necesitas realizar consultas JPQL o SQL nativas complejas que no se pueden manejar fácilmente con JpaRepository.

2. **Operaciones Avanzadas**: Cuando necesitas realizar operaciones avanzadas como bloqueos, transacciones manuales o uso de cachés.

3. **Optimización**: Cuando necesitas optimizar consultas y operaciones de persistencia para un mejor rendimiento.

4. **Manipulación del Ciclo de Vida**: Cuando necesitas un control detallado sobre el ciclo de vida de las entidades.

## Cuándo No Usar `EntityManager`
1. **Operaciones CRUD Simples**: Para operaciones CRUD simples, `JpaRepository` es suficiente y más fácil de usar.

2. **Prototipos y Desarrollo Rápido**: Cuando necesitas desarrollar aplicaciones rápidamente y con un mínimo de configuración, `JpaRepository` es más conveniente.

3. **Lógica de Negocio Básica**: Si tu lógica de negocio no requiere control detallado del ciclo de vida de las entidades o consultas avanzadas, `JpaRepository` es suficiente.
