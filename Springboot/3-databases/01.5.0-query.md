# Query
La anotación @Query en Spring Data JPA permite definir consultas personalizadas directamente en los métodos de los repositorios. Esta anotación es esencial para los casos en los que la lógica de consulta es más compleja de lo que las convenciones de métodos en Spring Data pueden cubrir, y donde se necesita un control preciso sobre las operaciones de consulta, ya sea usando JPQL o SQL nativo.

## ¿Qué es @Query?
@Query es una anotación en Spring Data que se utiliza para definir consultas directamente en los métodos de un repositorio. Es compatible tanto con JPQL (Java Persistence Query Language) como con consultas SQL nativas.

## ¿Para qué sirve @Query?
@Query se usa para:

* **Especificar consultas personalizadas**: Permite definir consultas directamente en el código sin depender de los nombres de métodos generados por convenciones de Spring Data.

* **Optimizar consultas complejas**: Ideal para consultas que no pueden representarse de manera sencilla usando las convenciones de nombres de métodos de Spring Data.

* **Combinar lógica personalizada**: Permite mezclar lógica de consulta compleja con las funcionalidades de JPA y SQL.

## ¿Qué resuelve @Query?
* **Limitaciones de convenciones de Spring Data**: Si bien Spring Data genera consultas en función de los nombres de métodos, hay ocasiones en las que esto no es suficiente. @Query permite escribir consultas personalizadas cuando la lógica es compleja.

* **Compatibilidad con SQL nativo y JPQL**: Permite realizar consultas específicas del proveedor de la base de datos utilizando SQL nativo o consultas independientes de la base de datos con JPQL.

* **Facilita la reutilización**: Las consultas complejas que suelen definirse en múltiples capas de la aplicación se pueden definir en un solo lugar.

## ¿Cómo lo resuelve @Query?
@Query resuelve estas limitaciones permitiendo incluir la lógica de consulta directamente dentro del repositorio. Esto se realiza de la siguiente manera:

* **Definición de la consulta en la anotación**: Se escribe la consulta dentro de la anotación @Query, en el método que la utilizará.

* **Parámetros de la consulta**: Los parámetros se pueden pasar directamente en la consulta, lo que permite la personalización en tiempo de ejecución.

* **Compatibilidad con SQL nativo**: Si se necesita una consulta SQL nativa específica del proveedor, simplemente se configura el parámetro `nativeQuery` como `true`.

## Ejemplo y Uso de @Query
* Supongamos que tenemos una entidad `Producto`:
```java
@Entity
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    private String nombre;
    private double precio;

    // Getters y Setters
}
```
Ejemplo de @Query con JPQL
```java
@Repository
public interface ProductoRepository extends JpaRepository<Producto, Long> {

    @Query("SELECT p FROM Producto p WHERE p.precio > :precioMinimo")
    List<Producto> findProductosConPrecioMayorA(@Param("precioMinimo") double precioMinimo);
}
```
**En este caso:**
* **Consulta JPQL**: Se seleccionan todos los productos cuyo precio es mayor que el valor pasado como parámetro (`precioMinimo`).

* **Parámetro**: Se utiliza `@Param` para asociar el parámetro `precioMinimo` en la consulta con el valor pasado en el método.

**Ejemplo de @Query con SQL Nativo**
```java
@Repository
public interface ProductoRepository extends JpaRepository<Producto, Long> {

    @Query(value = "SELECT * FROM producto WHERE precio > :precioMinimo", nativeQuery = true)
    List<Producto> findProductosConPrecioMayorA(@Param("precioMinimo") double precioMinimo);
}
```
**En este caso:**
* **Consulta SQL nativa**: Se especifica directamente en SQL la lógica de consulta sobre la tabla producto.

* **`nativeQuery = true`**: Indica a Spring Data que debe tratar la consulta como una consulta SQL nativa.

**Consultas con Operadores**, Puedes realizar consultas más complejas utilizando operadores JPQL:
```java
public interface ProductoRepository extends JpaRepository<Producto, Long> {

    @Query("SELECT p FROM Producto p WHERE p.precio > :precioMinimo AND p.categoria = :categoria")
    List<Producto> findByPrecioAndCategoria(@Param("precioMinimo") BigDecimal precioMinimo, 
                                            @Param("categoria") String categoria);
}
```
En este ejemplo, la consulta selecciona productos cuyo precio es mayor que `precioMinimo` y que pertenecen a una categoría específica.

## Parámetros de @Query
Los parámetros de la anotación @Query permiten personalizar el comportamiento de la consulta:

* **`value`**: Especifica la consulta JPQL o SQL que se ejecutará.

* **`nativeQuery`**: Un valor booleano (true o false) que indica si la consulta es una consulta SQL nativa (true) o una consulta JPQL (false).

* **`countQuery`**: Se utiliza para definir una consulta de conteo personalizada cuando se trabaja con paginación (Pageable).

## Ventajas de Usar @Query
* Flexibilidad: Permite escribir consultas complejas que no se pueden definir con convenciones de nombres de métodos.

* Modularidad: Facilita la organización del código al mantener las consultas en los repositorios.

* Compatibilidad: Soporta tanto JPQL como SQL, lo que permite optimizar el acceso a datos para diferentes bases de datos.

## Buenas Prácticas con @Query
* Evitar lógica de negocio compleja en las consultas: Es recomendable que las consultas no incluyan demasiada lógica de negocio. Esto debería manejarse en el servicio.

* Usar @Param para parámetros nombrados: Siempre es buena práctica utilizar @Param en lugar de depender de los nombres de las variables de método para mejorar la claridad.

* Limitar el uso de consultas SQL nativas: Aunque SQL nativo puede ser útil, es preferible usar JPQL siempre que sea posible para mantener la independencia del proveedor de base de datos.
