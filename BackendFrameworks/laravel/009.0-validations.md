### Validaciones
Laravel proporciona un sistema de validación robusto y fácil de usar para las solicitudes entrantes. Las validaciones se pueden escribir directamente en los **controladores**, pero una práctica recomendada es utilizar **Form Requests**, que encapsulan la lógica de validación en una clase dedicada.

Podemos agrupar validaciones de dos maneras:
```php
use Illuminate\Foundation\Http\FormRequest;

class StoreUserRequest extends FormRequest
{
    public function authorize()
    {
        return true;
    }

    public function rules()
    {
        return [
            'name' => 'required|max:255',
            'email' => ['required','email','unique:users'],
        ];
    }
```
### Reglas de Validación Comunes
Laravel incluye una amplia variedad de reglas de validación listas para usar:

- `accepted`: El campo debe ser "yes", "on", 1, o true.
- `active_url`: El campo debe ser una URL válida.
- `after:date`: El campo debe ser una fecha después de otra fecha.
- `alpha`: El campo solo puede contener letras.
- `alpha_dash`: El campo solo puede contener letras, números, guiones y guiones bajos.
- `alpha_num`: El campo solo puede contener letras y números.
- `array`: El campo debe ser un array.
- `bail`: Deja de validar después del primer error.
- `before:date`: El campo debe ser una fecha antes de otra fecha.
- `between:min,max`: El campo debe tener un tamaño entre min y max.
- `boolean`: El campo debe ser true o false.
- `confirmed`: El campo debe tener un campo de confirmación correspondiente (e.g., password_confirmation).
- `date`: El campo debe ser una fecha válida.
- `date_format`:format: El campo debe coincidir con el formato de fecha especificado.
- `different:field`: El campo debe ser diferente de otro campo.
- `digits:value`: El campo debe ser un valor numérico de exactamente value dígitos.
- `digits_between`:min,max: El campo debe ser un valor numérico entre min y max dígitos.
- `email`: El campo debe ser una dirección de correo electrónico válida.
- `exists`:table,column: El campo debe existir en la tabla de base de datos especificada.
- `file`: El campo debe ser un archivo cargado exitosamente.
- `image`: El campo debe ser una imagen (jpeg, png, bmp, gif, svg, o webp).
- `in:values`: El campo debe estar incluido en los valores proporcionados.
- `integer`: El campo debe ser un número entero.
- `ip`: El campo debe ser una dirección IP válida.
- `json`: El campo debe ser una cadena JSON válida.
- `max:value`: El campo no puede ser mayor que value.
- `min:value`: El campo debe ser al menos value.
- `nullable`: El campo puede ser null.
- `numeric`: El campo debe ser un número.
- `required`: El campo es obligatorio.
- `unique:table,column`: El campo debe ser único en la tabla especificada.

### Validación Condicional
Puedes aplicar validación condicional utilizando métodos en la Form Request.
```php
public function rules()
{
    $rules = [
        'name' => 'required|max:255',
        'email' => 'required|email|unique:users',
        'password' => 'required|min:8|confirmed',
    ];

    if ($this->isMethod('post')) {
        $rules['password'] = 'required|min:8|confirmed';
    }

    return $rules;
}
```
### Validación Personalizada
Si necesitas una validación más específica, puedes crear tus propias reglas de validación.

- **Usar Closure para Validación Personalizada**
```php
public function rules()
{
    return [
        'name' => [
            'required',
            'max:255',
            function ($attribute, $value, $fail) {
                if ($value === 'invalid') {
                    $fail('El nombre no puede ser "invalid".');
                }
            },
        ],
    ];
}
```
### Crear Validación Personalizada 

Laravel proporciona una manera poderosa y flexible para definir reglas de validación personalizadas utilizando la clase `Rule`. Esto es particularmente útil cuando necesitas aplicar una lógica de validación específica que no está cubierta por las reglas de validación incorporadas.
```bash
php artisan make:rule Uppercase
```
Esto genera una clase en `app/Rules/Uppercase.php`.
```php
namespace App\Rules;

use Illuminate\Contracts\Validation\Rule;

class Uppercase implements Rule
{
    public function passes($attribute, $value)
    {
        return strtoupper($value) === $value;
    }

    public function message()
    {
        return 'El :attribute debe estar en mayúsculas.';
    }
}
```
Luego, úsalo en tu **Form Request**:
```php
use App\Rules\Uppercase;

public function rules()
{
    return [
        'name' => ['required', 'max:255', new Uppercase],
    ];
}
```

### ¿Qué es un Closure?
Un Closure es una función anónima que puede capturar variables del ámbito en el que se creó. En PHP, los closures se utilizan a menudo para definir pequeñas funciones sin necesidad de darles un nombre específico. Los closures son útiles para definir funciones de `callback` o lógica de corta duración dentro de otro contexto.

**Sintaxis Básica de un Closure en PHP**
```php
$greet = function($name)
{
    return "Hello, " . $name;
};

// Usar el closure
echo $greet('World'); // Outputs: Hello, World
```

### Conclusión
Laravel ofrece una variedad de métodos para manejar la validación de datos entrantes, desde reglas básicas hasta validaciones condicionales y personalizadas. Al usar Form Requests, puedes mantener tus controladores limpios y organizados, y encapsular la lógica de validación de manera reutilizable y fácil de mantener.
