### API Resources

En Laravel, ApiResource es una herramienta poderosa que facilita la transformación y serialización de modelos y colecciones de modelos para su exposición a través de una API RESTful. Los recursos de API te permiten definir cómo los modelos deben ser presentados en JSON, proporcionando una capa adicional de abstracción y control sobre la salida de tus endpoints.

**¿Como podriamos añadir campos que no contiene el modelo o modificar el formato de respuesta de la API?,** para esto usamos los API Resources, con estos podemos establecer una capa intermedia mediante la cual le indicamos a los modelos como deben construir los datos que retorna.

**Caracteristicas clave de las API Resource en Laravel**

- **Transformación de Datos**: Permiten personalizar y estructurar los datos que serán devueltos como respuestas JSON.

- **Normalización de Respuestas**: Ayudan a normalizar las respuestas JSON proporcionadas por tu API, asegurando consistencia y estructura predefinida en los datos devueltos.

- **Reutilización de Transformaciones**: Puedes definir una transformación específica para un modelo y reutilizarla en varios controladores o rutas para mantener consistencia en la presentación de datos.

- **Control de la Presentación de Datos**: Especifican cómo se presentarán los datos de tu aplicación a través de la API, permitiendo ocultar o exponer ciertos atributos de un modelo según sea necesario.
  
**¿Qué es una ApiResource?**

Una **ApiResource** es una clase que define cómo se debe transformar un modelo o una colección de modelos cuando se convierte a **JSON**. Laravel proporciona dos tipos principales de recursos:

- **Resources**: Para transformar una sola instancia de un modelo.
- **Resource Collections**: Para transformar una colección de instancias de un modelo.

**Creación**
```php
php artisan make:resource UserResource
```
Esto generará una clase en el directorio `app/Http/Resources`.

**Estructura**
```php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;

class UserResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @param  \Illuminate\Http\Request  $request
     * @return array
     */
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'name' => 'el nombre del usuario es: ' . $this->name,
            'email' => $this->email,
            'created_at' => $this->created_at->toDateTimeString(),
            'updated_at' => $this->updated_at->toDateTimeString(),
        ];
    }
}
```

**Creación de una Resource Collection**
```bash
php artisan make:resource UserCollection
```
Esto generará una clase similar en el directorio `app/Http/Resources`, pero puedes extender esta clase para manejar colecciones.

**Estructura**
```php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\ResourceCollection;

class UserCollection extends ResourceCollection
{
    /**
     * Transform the resource collection into an array.
     *
     * @param  \Illuminate\Http\Request  $request
     * @return array
     */
    public function toArray($request)
    {
        return [
            'data' => $this->collection,
            'meta' => [
                'total_users' => $this->collection->count(),
            ],
        ];
    }
}
```

**Implementación**

- **Devolver un Resource**: En el controlador, puedes devolver una instancia del resource para transformar un modelo:
```php
namespace App\Http\Controllers;

use App\Models\User;
use App\Http\Resources\UserResource;
use Illuminate\Http\Request;

class UserController extends Controller
{
    public function show($id)
    {
        $user = User::findOrFail($id);
        return new UserResource($user);
    }
}
```
- **Devolver una Resource Collection**: Para devolver una colección de modelos, usa la resource collection:
```php
namespace App\Http\Controllers;

use App\Models\User;
use App\Http\Resources\UserCollection;
use Illuminate\Http\Request;

class UserController extends Controller
{
    public function index()
    {
        $users = User::all();
        return new UserCollection($users);
    }
}
```
**Incluir Relaciones**

Puedes incluir relaciones en tus recursos para proporcionar datos relacionados. Utiliza las relaciones Eloquent en el resource para incluir información adicional.

**Ejemplo**
```php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;

class UserResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @param  \Illuminate\Http\Request  $request
     * @return array
     */
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'email' => $this->email,
            'posts' => PostResource::collection($this->whenLoaded('posts')),
            'created_at' => $this->created_at->toDateTimeString(),
            'updated_at' => $this->updated_at->toDateTimeString(),
        ];
    }
}
```
**Controlador**
```php
namespace App\Http\Controllers;

use App\Models\User;
use App\Http\Resources\UserResource;
use Illuminate\Http\Request;

class UserController extends Controller
{
    public function show($id)
    {
        $user = User::with('posts')->findOrFail($id);
        return new UserResource($user);
    }
}
```

**Añadir Meta Información**

Puedes añadir meta información a tu respuesta JSON utilizando el método `with` en el resource.
```php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;

class UserResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @param  \Illuminate\Http\Request  $request
     * @return array
     */
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'email' => $this->email,
        ];
    }

    /**
     * Customize the outgoing response for the resource.
     *
     * @param  \Illuminate\Http\Request  $request
     * @return array
     */
    public function with($request)
    {
        return [
            'meta' => [
                'key' => 'value',
            ],
        ];
    }
}
```

### Api Resouce Routes

Las API Resource Routes en Laravel proporcionan una forma conveniente de definir rutas para un controlador que maneja las operaciones CRUD (Crear, Leer, Actualizar, Eliminar) siguiendo las convenciones RESTful. Utilizando las rutas de recursos, puedes definir todas las rutas necesarias para interactuar con tu recurso de forma eficiente y mantener tu código organizado y legible.

**Definición de API Resource Routes**

Para definir las rutas de recursos en Laravel, utiliza el método `Route::apiResource` o `Route::resource` en tu archivo de rutas, típicamente `routes/api.php` para APIs.
```php
use App\Http\Controllers\UserController;

Route::apiResource('users', UserController::class);
```
El ejemplo anterior creará automáticamente las siguientes rutas:

- `GET /users (index)` – Mostrar una lista de recursos.
- `POST /users (store)` – Crear un nuevo recurso.
- `GET /users/{id} (show)` – Mostrar un recurso específico.
- `PUT/PATCH /users/{id} (update)` – Actualizar un recurso específico.
- `DELETE /users/{id} (destroy)` – Eliminar un recurso específico.

**Personalización de API Resource Routes**

- **Exclusión de Métodos**: Si no necesitas todas las rutas generadas, puedes excluir algunas utilizando la opción `except`:
```php
Route::apiResource('users', UserController::class)->except(['create', 'edit']);
```
- **Incluir Sólo Métodos Específicos**: Si solo necesitas ciertas rutas, usa la opción `only`:
```php
Route::apiResource('users', UserController::class)->only(['index', 'show']);
```
**Controlador API**
```bash
php artisan make:controller USerController --api
```

### Métodos Generados por las API Resource Routes

1. `index`: Muestra una lista de recursos
```php
public function index()
{
    return UserResource::collection(User::all());
}
```
2. `store`: Almacena un nuevo recurso en la base de datos.
```php
public function store(Request $request)
{
    $user = User::create($request->all());
    return new UserResource($user);
}
```
3. `show`: Muestra un recurso específico.
```php
public function show($id)
{
    $user = User::findOrFail($id);
    return new UserResource($user);
}
```
4. `update`: Actualiza un recurso específico.
```php
public function update(Request $request, $id)
{
    $user = User::findOrFail($id);
    $user->update($request->all());
    return new UserResource($user);
}
```
5. `destroy`: Elimina un recurso específico.
```php
public function destroy($id)
{
    $user = User::findOrFail($id);
    $user->delete();
    return response()->noContent();
}
```
### Diferencias entre ApiResource y Resource
En Laravel, ApiResource y Resource se utilizan para transformar y serializar modelos y colecciones de modelos a formatos JSON adecuados para la exposición a través de APIs. Sin embargo, existen diferencias clave entre ellos, y entender cuándo y cómo usarlos es crucial para aprovechar al máximo sus beneficios.

- **ApiResource**
  - **Propósito**: Diseñado específicamente para **APIs RESTful**.
  - **Características**: Excluye métodos `create` y `edit` que no son necesarios para APIs.
  - **Rutas Generadas**:
    - `index (GET /resource)`
    - `store (POST /resource)`
    - `show (GET /resource/{id})`
    - `update (PUT/PATCH /resource/{id})`
    - `destroy (DELETE /resource/{id})`
  - **Uso**: Cuando necesitas exponer tu modelo a través de una API, asegurando que todas las rutas sigan las convenciones RESTful.

- **Resource**
  - **Propósito**: Diseñado para aplicaciones web y APIs.
  - **Características**: Incluye métodos `create` y `edit` que son útiles para formularios en aplicaciones web.
  - Rutas Generadas:
    - `index (GET /resource)`
    - `create (GET /resource/create)`
    - `store (POST /resource)`
    - `show (GET /resource/{id})`
    - `edit (GET /resource/{id}/edit)`
    - `update (PUT/PATCH /resource/{id})`
    - destroy (DELETE /resource/{id})
- **Uso**: Cuando necesitas manejar tanto la interfaz de usuario de una aplicación web como las operaciones CRUD a través de formularios y APIs.
