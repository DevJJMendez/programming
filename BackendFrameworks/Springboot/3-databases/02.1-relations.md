# Relations
Las relaciones en Hibernate permiten mapear asociaciones entre entidades que representan las relaciones entre las tablas de una base de datos relacional. Este mapeo es esencial para trabajar con datos de manera relacional, facilitando que las entidades en el código reflejen las relaciones lógicas del modelo de datos.

## ¿Para qué sirven las relaciones en Hibernate?
Las relaciones en Hibernate sirven para:

* Mapear la lógica relacional en las bases de datos dentro del modelo de objetos de una aplicación.

* Facilitar la navegación de los datos asociados entre entidades, respetando las restricciones de integridad.

* Simplificar el acceso y manipulación de datos relacionales en el código, permitiendo trabajar con entidades en lugar de escribir consultas SQL complejas.

## ¿Qué problemas resuelven las relaciones en Hibernate?
* Reducción de redundancia en el código: Se evitan múltiples queries SQL para obtener datos asociados, permitiendo acceder a datos relacionados mediante propiedades.

* Mantenimiento de integridad: Las relaciones ayudan a Hibernate a mantener la coherencia e integridad de los datos.

* Estandarización de acceso a datos: A través de métodos y propiedades en objetos Java, las relaciones proporcionan una manera estándar de acceder a datos, independientemente de la estructura subyacente en la base de datos.

## ¿Cómo resuelven estos problemas?
Hibernate proporciona anotaciones específicas para mapear las relaciones y establecer configuraciones de `fetching`, `cascading`, y `orphan removal`, que controlan cómo se deben recuperar, persistir y eliminar los datos de las entidades relacionadas. Estas anotaciones permiten modelar correctamente las relaciones en el dominio de objetos, eliminando la necesidad de lógica de consulta y manipulación de datos adicionales.

## Relaciones y sus Tipos
En Hibernate, las relaciones permiten definir los vínculos entre distintas entidades de acuerdo con las relaciones de base de datos, como:

* **`One-to-One` (Uno a Uno)**: Cada instancia de una entidad se asocia con una única instancia de otra entidad.

* **`One-to-Many` (Uno a Muchos)**: Una instancia de una entidad se asocia con múltiples instancias de otra entidad.

* **`Many-to-One` (Muchos a Uno)**: Varias instancias de una entidad están relacionadas con una única instancia de otra entidad.

* **`Many-to-Many` (Muchos a Muchos)**: Las instancias de una entidad pueden relacionarse con múltiples instancias de otra entidad y viceversa.

## Configuración de propiedades adicionales en relaciones
Hibernate permite configurar aspectos adicionales en las relaciones para un mejor control.

* **`Cascading`**: Controla cómo las operaciones en una entidad afectan a las entidades relacionadas. Se define con CascadeType (ej., ALL, **`PERSIST`**, **`REMOVE`**).

* **`FetchType`**: Determina cómo Hibernate debe recuperar las entidades relacionadas (**`LAZY`** para cargar bajo demanda y **`EAGER`** para cargar de inmediato).

* **`Orphan Removal`**: Permite eliminar automáticamente las entidades relacionadas si son desvinculadas de la relación principal (utilizado en **`OneToMany`** y **`OneToOne`**).

```java
@OneToMany(mappedBy = "cliente", cascade = CascadeType.ALL, fetch = FetchType.LAZY, orphanRemoval = true)
private List<Orden> ordenes;
```

# Relaciones Bidireccionales
Las relaciones bidireccionales en Hibernate y JPA son aquellas en las que dos entidades están conectadas entre sí, permitiendo la navegación de una entidad hacia la otra en ambos sentidos. Esto significa que si tienes una relación bidireccional entre Persona y Dirección, puedes acceder a la Dirección de una Persona y también acceder a la Persona asociada desde la Dirección.

## ¿Qué es una relación bidireccional?
En términos de ORM (Object-Relational Mapping), una relación bidireccional es un vínculo entre dos entidades que se refleja en ambas clases, con una propiedad de referencia en cada una. Este tipo de relación permite que ambas entidades conozcan y tengan una referencia mutua de la otra.

Ejemplo
Si tenemos dos clases: Persona y Dirección, en una relación bidireccional, cada Persona puede tener una Dirección y cada Dirección puede estar asociada a una Persona.

```java
@Entity
public class Persona {
    @Id
    private Long id;

    @OneToOne(mappedBy = "persona")
    private Direccion direccion;

    // Getters y setters
}

@Entity
public class Direccion {
    @Id
    private Long id;

    @OneToOne
    @JoinColumn(name = "persona_id")
    private Persona persona;

    // Getters y setters
}
```
En este caso, la clase Persona tiene una referencia a Direccion, y Direccion también tiene una referencia de vuelta a Persona.

## ¿Para qué sirve?
Las relaciones bidireccionales permiten acceder a los datos desde ambas entidades de manera natural, facilitando operaciones complejas y brindando mayor flexibilidad en consultas y manipulación de datos. En una relación bidireccional:

* Facilitan la navegación en ambos sentidos, permitiendo operaciones y consultas más intuitivas.

* Mejoran la consistencia de los datos, ya que permiten sincronizar la información de ambas entidades.

## ¿Qué resuelven?
Las relaciones bidireccionales resuelven problemas de navegabilidad y consistencia en los modelos de datos:

Navegabilidad: Al contar con relaciones en ambas entidades, se puede acceder fácilmente a una entidad desde la otra, lo cual es útil en operaciones complejas y consultas que necesitan información de ambas tablas.
Consistencia de datos: Ayudan a que los cambios en una entidad se reflejen en la otra, manteniendo la información sincronizada y minimizando el riesgo de inconsistencia.

## ¿Cómo lo resuelve?
Para resolver estos problemas, Hibernate y JPA permiten especificar relaciones bidireccionales mediante el uso de anotaciones como @OneToOne, @OneToMany, @ManyToOne y @ManyToMany, en combinación con el atributo mappedBy. Este parámetro indica que una de las entidades es propietaria de la relación y la otra es "inversa" o dependiente de esta.

**Propietario y lado inverso de la relación**
En las relaciones bidireccionales, siempre hay un lado propietario de la relación y un lado inverso:

* Lado propietario: Es el que define la clave foránea (foreign key) en la base de datos y controla la persistencia de la relación.

* Lado inverso: Hace referencia al lado propietario usando el atributo mappedBy, lo que permite la sincronización sin duplicar la clave en ambas tablas.

Ejemplo de implementación con `mappedBy`:
```java
@Entity
public class Persona {
    @Id
    private Long id;

    @OneToMany(mappedBy = "persona") // Lado inverso
    private List<Direccion> direcciones;

    // Getters y setters
}

@Entity
public class Direccion {
    @Id
    private Long id;

    @ManyToOne // Lado propietario
    @JoinColumn(name = "persona_id")
    private Persona persona;

    // Getters y setters
}
```
En este ejemplo:

Persona es el lado inverso de la relación, pues tiene mappedBy.
Direccion es el lado propietario y define la clave foránea (persona_id).

## Tipos de relaciones bidireccionales
Dependiendo de la cardinalidad entre las entidades, las relaciones bidireccionales pueden ser:

@OneToOne: Una instancia de una entidad está relacionada con una sola instancia de la otra.
@OneToMany y @ManyToOne: Una entidad contiene una colección de instancias de la otra.
@ManyToMany: Cada entidad puede tener múltiples relaciones con instancias de la otra.
Consideraciones y buenas prácticas
Usar relaciones bidireccionales cuando sea necesario: No todas las relaciones necesitan ser bidireccionales. Evalúa si necesitas acceder a los datos en ambos sentidos.
Control de la sincronización: Asegúrate de mantener la consistencia entre ambos lados de la relación. Por ejemplo, al agregar una Direccion a una Persona, también debes asignar la Persona a la Direccion.
Uso correcto de mappedBy: Es importante definir correctamente el lado propietario e inverso para evitar problemas de rendimiento y de duplicidad en la base de datos.
