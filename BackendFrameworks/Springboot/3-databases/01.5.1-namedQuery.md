# Named Query
La anotación `@NamedQuery` es una característica de JPA (Java Persistence API) que se utiliza para definir consultas predefinidas en un modelo de entidad. Esta anotación permite nombrar y reutilizar consultas JPQL (Java Persistence Query Language) de forma que estén disponibles para usarse en cualquier parte de la aplicación, optimizando el código y favoreciendo el rendimiento.

## ¿Qué es `@NamedQuery`?
`@NamedQuery` es una anotación en JPA que define una consulta JPQL con un nombre único asociado. Esta consulta se puede reutilizar en distintas partes de la aplicación usando su nombre. Es común definir @NamedQuery en la clase de entidad misma, agrupando la lógica de consulta cerca de la definición del modelo de datos.

## ¿Para qué sirve?
La anotación `@NamedQuery` sirve para:

* **Definir consultas reutilizables**: Permite evitar la duplicación de consultas en el código al definir una vez la consulta y reutilizarla en distintos métodos.

* **Mejorar la organización del código**: Centraliza las consultas en las entidades, facilitando la comprensión y el mantenimiento.

* **Optimizar el rendimiento**: En algunos proveedores de JPA, las consultas `@NamedQuery` pueden ser precompiladas al inicio, lo cual reduce el tiempo de procesamiento de las consultas en tiempo de ejecución.

## ¿Qué resuelve?
`@NamedQuery` resuelve varios problemas comunes:

* **Evita consultas duplicadas**: Con `@NamedQuery`, se pueden definir las consultas en un solo lugar, eliminando la duplicación de consultas en diferentes métodos o clases.

* **Facilita el mantenimiento**: Al centralizar las consultas, cualquier cambio necesario en una consulta se puede realizar en un solo lugar, lo cual facilita el mantenimiento.

* **Mejora el rendimiento de las consultas**: Algunos proveedores de JPA precompilan las consultas definidas como `@NamedQuery` cuando se inicia la aplicación, lo cual optimiza el tiempo de ejecución.

## ¿Cómo lo resuelve?
Lo resuelve mediante la definición de la consulta dentro de la clase de entidad usando la anotación `@NamedQuery`. Cada consulta es asociada a un nombre único que luego puede ser utilizado en la aplicación para ejecutar esa consulta sin tener que escribirla de nuevo. Las consultas definidas con `@NamedQuery` se almacenan en la memoria y se pueden recuperar rápidamente, lo cual optimiza la eficiencia.

## Ejemplo de Uso de `@NamedQuery`
Aquí tienes un ejemplo para ilustrar cómo se usa la anotación `@NamedQuery`:

```java
import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.NamedQuery;

@Entity
@NamedQuery(
    name = "Usuario.findByNombre",
    query = "SELECT u FROM Usuario u WHERE u.nombre = :nombre"
)
public class Usuario {
    
    @Id
    private Long id;
    private String nombre;
    private String correo;
    
    // Getters y setters
}
```
**En este ejemplo:**
* Se define una entidad Usuario con un `@NamedQuery` llamado **`"Usuario.findByNombre"`**.

* La consulta JPQL se puede usar para buscar usuarios por su nombre (nombre), usando el parámetro `:nombre`.

## Ejecución de la @NamedQuery
Para ejecutar la consulta, se llama al EntityManager y se recupera la consulta por su nombre:
```java
public Usuario findByNombre(EntityManager em, String nombre) {
    return em.createNamedQuery("Usuario.findByNombre", Usuario.class)
             .setParameter("nombre", nombre)
             .getSingleResult();
}
```

## Parámetros de `@NamedQuery`
La anotación `@NamedQuery` tiene dos parámetros principales:

* **`name`**: Define el nombre de la consulta, que se utilizará para invocarla en el código.

* **`query`**: Especifica la consulta JPQL que se ejecutará cuando se llame al `name`.

## Buenas Prácticas
* Nombrar consultas claramente: El nombre de la consulta debe ser descriptivo para que sea claro lo que realiza, como "Usuario.findByNombre".

* Revisar el rendimiento: Asegúrate de que los `@NamedQuery` se usen en consultas frecuentes y que puedan beneficiarse de la precompilación.

* Centralizar la lógica de consultas: Utilizar `@NamedQuery` ayuda a mantener las consultas en un solo lugar, en la entidad, lo cual facilita el mantenimiento.

## Ventajas
* Facilita la reutilización de consultas.

* Mejora el rendimiento gracias a la posible precompilación.

* Centraliza la lógica de consultas en la entidad.

**Limitaciones:**
* Consultas estáticas: La consulta es fija y no puede cambiarse en tiempo de ejecución. Si necesitas consultas altamente dinámicas, `@NamedQuery` podría no ser la mejor opción.

* Depende del soporte del proveedor JPA: No todos los proveedores JPA optimizan la precompilación de `@NamedQuery`.
