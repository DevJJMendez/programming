# `CallableStatement`
CallableStatement es una interfaz en Java JDBC que se utiliza para ejecutar procedimientos almacenados en bases de datos. Estos procedimientos almacenados pueden incluir consultas complejas y lógicas de negocio, y CallableStatement permite interactuar con ellos de manera eficiente. Es ideal para aplicaciones que requieren operaciones en la base de datos que involucran lógica compleja y reutilizable.

## ¿Qué es CallableStatement?
CallableStatement es una clase en JDBC que permite ejecutar procedimientos almacenados en una base de datos, los cuales son programas predefinidos que se ejecutan en el servidor de la base de datos. Estos procedimientos suelen aceptar parámetros de entrada y salida, permitiendo una mayor flexibilidad y reusabilidad.

## Para qué sirve CallableStatement?
CallableStatement se utiliza principalmente para:

* Ejecutar procedimientos almacenados y funciones en una base de datos.

* Simplificar y optimizar el código SQL, ya que permite encapsular consultas complejas y lógica de negocio en el servidor.

* Facilitar el manejo de operaciones que requieren parámetros de entrada y salida, lo que resulta útil en casos donde se necesitan valores generados o calculados en la base de datos.

## ¿Qué resuelve CallableStatement?
* **Lógica centralizada**: Permite que las operaciones y reglas de negocio residan en la base de datos, mejorando la consistencia y reutilización.

* **Mejor rendimiento**: Al ejecutar lógica compleja en el servidor de base de datos en lugar de en la aplicación, reduce la cantidad de datos transferidos y optimiza el rendimiento.

* **Modularidad**: Los procedimientos almacenados encapsulan la lógica de la base de datos, facilitando la modularización y el mantenimiento.

Sin CallableStatement, se requeriría que la aplicación maneje toda la lógica de negocio, lo cual resultaría en un código más extenso y difícil de mantener.

## ¿Cómo lo resuelve CallableStatement?
CallableStatement permite que la aplicación Java interactúe con procedimientos almacenados utilizando:

* **Parámetros de entrada (`IN`)**: Para pasar valores al procedimiento almacenado.

* **Parámetros de salida (`OUT`)**: Para recibir valores generados o calculados por el procedimiento.

* **Parámetros de entrada y salida (`INOUT`)**: Que permiten pasar un valor inicial y luego recibir un valor modificado por el procedimiento.

## Ejemplo de uso básico de CallableStatement
Supongamos que tienes un procedimiento almacenado llamado `obtenerProducto` en tu base de datos que recibe un `id` y devuelve el `nombre` y el `precio` del producto.

**Creación del procedimiento en SQL:**
```sql
CREATE PROCEDURE obtenerProducto(IN id INT, OUT nombre VARCHAR(50), OUT precio DECIMAL(10, 2))
BEGIN
    SELECT nombre, precio INTO nombre, precio FROM productos WHERE producto_id = id;
END;
```
Código Java con `CallableStatement`:
```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.CallableStatement;
import java.sql.SQLException;

public class CallableStatementDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/mi_basededatos";
        String username = "usuario";
        String password = "contraseña";

        try (Connection connection = DriverManager.getConnection(url, username, password)) {
            String sql = "{CALL obtenerProducto(?, ?, ?)}";
            CallableStatement callableStatement = connection.prepareCall(sql);

            // Asignación de parámetros de entrada y salida
            callableStatement.setInt(1, 1); // Parámetro IN: id del producto
            callableStatement.registerOutParameter(2, java.sql.Types.VARCHAR); // Parámetro OUT: nombre
            callableStatement.registerOutParameter(3, java.sql.Types.DECIMAL); // Parámetro OUT: precio

            // Ejecución del procedimiento
            callableStatement.execute();

            // Recuperación de resultados de parámetros de salida
            String nombreProducto = callableStatement.getString(2);
            double precioProducto = callableStatement.getDouble(3);

            System.out.println("Nombre del Producto: " + nombreProducto);
            System.out.println("Precio del Producto: " + precioProducto);
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}
```
**Explicación del flujo del `CallableStatement`**
1. **Preparación**:

   * `String sql = "{CALL obtenerProducto(?, ?, ?)}";` define la llamada al procedimiento con parámetros de entrada y salida.

2. **Asignación de parámetros**:

   * `callableStatement.setInt(1, 1);` asigna el valor para el parámetro de entrada id.
`registerOutParameter()` especifica los tipos de los parámetros de salida.

3. **Ejecución**:

   * `callableStatement.execute();` ejecuta el procedimiento en la base de datos.

4. **Obtención de resultados**:

   * Se extraen los valores de los parámetros de salida con métodos como `getString` o `getDouble`.

## Ventajas de CallableStatement
* **Encapsulación de lógica de negocio**:

  * Los procedimientos almacenados permiten encapsular la lógica en la base de datos, lo que facilita el mantenimiento y la seguridad de la aplicación.

* **Optimización de rendimiento**:

  * Las operaciones complejas se ejecutan en la base de datos, reduciendo la carga de la red y el tiempo de procesamiento en la aplicación.

* **Reducción de la complejidad del código**:

  * Al centralizar la lógica de negocio en procedimientos almacenados, el código Java es más limpio y manejable.

## Buenas prácticas con `CallableStatement`
* **Manejo adecuado de excepciones**:

  * Los procedimientos almacenados pueden fallar por diversas razones, por lo que se deben capturar y manejar las excepciones correctamente.

* **Liberación de recursos**:

  * Cerrar siempre CallableStatement y cualquier otro recurso JDBC para liberar la memoria y evitar fugas.

* **Modularidad**:

  * Utilizar procedimientos almacenados bien definidos y documentados para modularizar la lógica de la base de datos.

* **Uso de INOUT con precaución**:

  * Evitar el uso excesivo de parámetros INOUT, ya que pueden hacer que el procedimiento sea difícil de leer y mantener.
