# Session
La interfaz Session en Hibernate es una API clave que permite la interacción directa con la base de datos mediante el manejo de operaciones CRUD (Crear, Leer, Actualizar y Eliminar) y la administración de entidades en un contexto de persistencia. Es parte del sistema ORM (Mapeo Objeto-Relacional) de Hibernate, y en ella se gestionan el ciclo de vida de los objetos persistentes y las transacciones en una sesión.

**Características Principales de Session**
* **Unidad de Trabajo**: La Session representa una transacción (o parte de ella) y es responsable de mantener la sincronización entre las entidades en memoria (en el caché de primer nivel) y la base de datos.

* **No es Thread-Safe**: Una instancia de Session no es segura para su uso concurrente por múltiples hilos. Cada Session debería ser usada por un solo hilo y para una única transacción.

* **Ciclo de Vida Corta**: Generalmente, una Session tiene un ciclo de vida corto. Se abre al inicio de una unidad de trabajo y se cierra al finalizarla. Mantener una Session abierta por mucho tiempo puede llevar a problemas de rendimiento y a un manejo ineficiente de recursos.

* **Caché de Primer Nivel**: Hibernate mantiene un caché de primer nivel dentro de la Session, lo que significa que cualquier entidad que sea recuperada de la base de datos durante la misma Session será almacenada en caché, evitando que se hagan consultas redundantes a la base de datos.

## ¿Qué es la interfaz Session?
La interfaz Session representa una conexión "liviana" y "temporal" con la base de datos. En Hibernate, se utiliza para:

* Crear y gestionar entidades en la base de datos.

* Realizar consultas y búsquedas de objetos.

* Administrar el ciclo de vida de los objetos, incluyendo operaciones de persistencia, actualizaciones, eliminaciones y lectura.

Una instancia de Session está asociada a una unidad de trabajo: es decir, el conjunto de operaciones realizadas desde la apertura de la sesión hasta su cierre.

## ¿Para qué sirve Session?
La interfaz Session sirve como el punto principal de interacción entre la aplicación y la base de datos en Hibernate. Sus principales usos incluyen:

* Manejo de transacciones: Realiza y controla transacciones en la base de datos.

* Operaciones CRUD: Permite crear, leer, actualizar y eliminar entidades.

* Consulta de datos: Realiza consultas SQL o HQL (Hibernate Query Language) para recuperar datos.

* Gestión de caché: Administra el primer nivel de caché, lo que optimiza el rendimiento al reducir el número de operaciones directas a la base de datos.

## ¿Qué problemas resuelve Session?
Session resuelve varios problemas al interactuar con la base de datos, como:

* Abstracción de SQL: Simplifica las operaciones de base de datos al permitir el uso de métodos de alto nivel sin escribir SQL explícito.

* Optimización de acceso a datos: Con el manejo de caché y el uso de proxies, minimiza el acceso a la base de datos cuando no es necesario.

* Control de transacciones: Facilita el manejo de transacciones en un contexto seguro y aislado.

* Gestión del ciclo de vida: Permite un control efectivo del ciclo de vida de las entidades en la sesión, asegurando que solo se reflejen en la base de datos los cambios realizados dentro de la sesión activa.

## ¿Cómo Session resuelve estos problemas?
Session resuelve estos problemas proporcionando una API coherente y una serie de métodos para gestionar las operaciones con la base de datos:

* Control de la persistencia: Permite realizar operaciones de persistencia (save, update, delete) y asegura que los cambios se registren en la base de datos en un solo ciclo.

* Ciclo de vida de las entidades: Los métodos de Session como persist, merge, detach permiten controlar el estado de las entidades (transitoria, persistente o separada) de forma explícita.

* Gestión de transacciones: A través de métodos como beginTransaction, commit y rollback, se maneja cada operación de forma atómica, garantizando la consistencia.

* Primer nivel de caché: Hibernate mantiene un caché de primer nivel asociado a la sesión, lo que significa que si se carga un objeto una vez, no es necesario recargarlo en la misma sesión.

## Métodos Comunes
1. **CRUD Operations**:

   * `save(Object entity)`: Guarda la entidad en la base de datos y devuelve el identificador generado si la entidad es nueva.

   * `persist(Object entity)`: Similar a save, pero más alineado con la especificación JPA. No devuelve un valor.

   * `update(Object entity)`: Sincroniza el estado de la entidad en memoria con la base de datos.

   * `saveOrUpdate(Object entity)`: Hace un save si la entidad es nueva, o un update si ya existe.

   * `delete(Object entity)`: Elimina la entidad de la base de datos.

2. **Consultas**:

   * `get(Class<T> entityType, Serializable id)`: Recupera una entidad por su identificador. Devuelve null si no se encuentra.

   * `load(Class<T> entityType, Serializable id)`: Similar a get, pero lanza una excepción si no se encuentra la entidad.

   * `createQuery(String hql)`: Crea una consulta HQL.

   * `createNativeQuery(String sql)`: Crea una consulta SQL nativa.

   * `createCriteria(Class<T> entityType)`: Crea un criterio de consulta para la entidad especificada.

3. **Transacciones**:

   * `beginTransaction()`: Inicia una nueva transacción.

   * `getTransaction()`: Obtiene la transacción asociada con la sesión actual.
  
   * `flush()`: Sincroniza el estado persistente en memoria con la base de datos.
  
   * `clear()`: Limpia el caché de primer nivel, descartando cualquier entidad que no haya sido sincronizada con la base de datos.
  
   * `close()`: Cierra la Session, liberando los recursos asociados.

4. **Gestión de la Sesión**:

   * `isOpen()`: Verifica si la Session está abierta.

   * `isConnected()`: Verifica si la Session está conectada a la base de datos.

   * `evict(Object entity)`: Elimina una entidad específica del caché de primer nivel, haciéndola elegible para ser recogida por el recolector de basura si no hay más referencias a ella.

   * `merge(Object entity)`: Actualiza el estado de una entidad en la base de datos con los cambios realizados en la entidad proporcionada.

## Ventajas de usar Session
* Optimización de recursos: Al usar caché y proxies, Hibernate optimiza la cantidad de interacciones directas con la base de datos.

* Facilita la persistencia: Los métodos de Session permiten administrar las entidades sin requerir SQL explícito.

* Control de transacciones: Simplifica la gestión de transacciones, permitiendo que las operaciones sean consistentes.

* Consistencia en la persistencia: Los cambios se reflejan en la base de datos de forma precisa cuando se confirman las transacciones.

## Consideraciones de Session
* Duración limitada: Las sesiones no están diseñadas para ser persistentes en toda la aplicación; deben abrirse y cerrarse de acuerdo con el ciclo de vida de las operaciones de persistencia específicas.

* Manejo adecuado de transacciones: Es fundamental usar transacciones para evitar inconsistencias.

* Sincronización del contexto: Session no se sincroniza automáticamente con la base de datos; es necesario ejecutar flush() para forzar esta sincronización en algunas situaciones.
