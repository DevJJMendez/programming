## Aspects
Aspects son el núcleo del paradigma de Aspect-Oriented Programming (AOP). Un aspect es un módulo de software que encapsula un comportamiento que afecta a múltiples clases o métodos de una aplicación, pero que no pertenece a la lógica central de ninguna de esas clases o métodos. Los aspects permiten separar las preocupaciones transversales (cross-cutting concerns) del código de negocio principal, facilitando así la modularidad y el mantenimiento del código.

### Componentes Principales de un Aspect
Un aspect generalmente se compone de los siguientes elementos:

1. **Advice**:

   * Es el bloque de código que define lo que debe hacerse en un punto específico del programa. El advice puede ejecutarse antes, después, o alrededor de la ejecución de un método o evento.

2. **Tipos de Advice**:

   * `Before Advice`: Se ejecuta antes de que el método objetivo sea llamado.

   * `After Advice`: Se ejecuta después de que el método objetivo ha sido ejecutado, independientemente de si la ejecución fue exitosa o fallida.

   * `After Returning Advice`: Se ejecuta después de que el método objetivo se ejecuta con éxito y devuelve un valor.

   * `After Throwing Advice`: Se ejecuta si el método objetivo lanza una excepción.

   * `Around Advice`: Es el más potente, ya que rodea la ejecución del método objetivo, permitiendo realizar acciones antes y después de la ejecución, e incluso modificar el flujo de control.

3. **Pointcut**:

   * Es una expresión que define "dónde" se debe aplicar un **advice**. Especifica los **join points (puntos de ejecución específicos en la aplicación, como la invocación de un método o la ejecución de un constructor)** a los que se debe vincular un advice.

   * **Ejemplo**: Un pointcut podría definir que un **advice** se aplique a todos los métodos en un paquete específico o a todos los métodos con una anotación particular.

4. **Join Point**:

   * Es un punto bien definido en la ejecución del programa, como la invocación de un método o el lanzamiento de una excepción. Un pointcut identifica los join points específicos a los que se aplicará un advice.

5. **Aspect**:

   * El **aspect** es una combinación de **pointcuts** y **advice**. Define el comportamiento transversal completo, especificando tanto "dónde" (pointcut) como "qué" (advice) se ejecutará.

### Ejemplo de un Aspect en Spring AOP
En Spring AOP, los aspects suelen definirse mediante anotaciones. Un ejemplo sencillo sería un aspect que registra la ejecución de métodos.

```java
@Aspect
@Component
public class LoggingAspect {

    @Pointcut("execution(* com.example.service.*.*(..))")
    public void loggableMethods() {
        // Pointcut para todos los métodos en el paquete com.example.service
    }

    @Before("loggableMethods()")
    public void logBefore(JoinPoint joinPoint) {
        System.out.println("Antes de ejecutar el método: " + joinPoint.getSignature().getName());
    }

    @AfterReturning(pointcut = "loggableMethods()", returning = "result")
    public void logAfterReturning(JoinPoint joinPoint, Object result) {
        System.out.println("Después de ejecutar el método: " + joinPoint.getSignature().getName() + ", resultado: " + result);
    }
}
```
* **Pointcut**: `execution(* com.example.service.*.*(..))` captura todos los métodos en el paquete `com.example.service`.

* **Before Advice**: `logBefore` se ejecuta antes de cada método capturado por el pointcut.

* **AfterReturning Advice**: `logAfterReturning` se ejecuta después de que el método capturado se ejecuta exitosamente.

## Join Points
En Aspect-Oriented Programming (AOP), un Join Point es un punto específico en el flujo de ejecución de un programa donde se puede aplicar un aspecto. Los Join Points son los puntos de interés en el código, y un aspecto puede interceptar y ejecutar una lógica adicional en esos puntos.

Un Join Point es un punto bien definido en la ejecución de un programa. Puede ser la invocación de un método, la asignación de un valor a un campo, la ejecución de un bloque de código, etc. Los aspectos se aplican en estos Join Points para insertar lógica transversal como logging, manejo de excepciones, seguridad, transacciones, etc.

Un Join Point es el lugar donde la lógica del programa original se cruza con la lógica adicional proporcionada por el aspecto. En AOP, los Join Points son seleccionados y manejados a través de **Pointcut Expressions**.

### Tipos Comunes de Join Points
En la mayoría de las implementaciones de AOP, como Spring AOP o AspectJ, los Join Points más comunes incluyen:

1. **Invocación de Métodos**:

   * El Join Point más común es la invocación de un método. Por ejemplo, cuando un método es llamado, este evento puede ser interceptado por un aspecto.

   * **Ejemplo**: La invocación de cualquier método en una clase de servicio.

      ```java
      @Before("execution(* com.example.service.UserService.createUser(..))")
      public void logBeforeMethodInvocation() {
          // Código que se ejecuta antes de la invocación del método
      }
      ```

2. **Acceso a Campos**:

   * En algunos frameworks como AspectJ, un Join Point puede ser el acceso a un campo de una clase. Esto incluye tanto la lectura como la escritura en el campo.

   * **Ejemplo**: Interceptar el acceso a un campo name en una clase User

      ```java
      @Before("get(String com.example.model.User.name)")
      public void logFieldAccess() {
          // Código que se ejecuta antes de acceder al campo
      }
      ```

3. **Excepciones**:

   * Aunque es menos común en AOP basado en Spring, algunos frameworks permiten que los Join Points sean eventos como la captura o el lanzamiento de excepciones.

   * **Ejemplo**: Manejar la excepción lanzada por un método

      ```java
      @AfterThrowing(pointcut = "execution(* com.example.service.UserService.*(..))", throwing = "ex")
      public void logException(JoinPoint joinPoint, Exception ex) {
          // Código que se ejecuta cuando una excepción es lanzada
      }
      ```

### Relación entre Join Points, Pointcuts, y Advice
* **Join Point**: Es cualquier punto en el flujo de ejecución de un programa donde un aspecto puede ser aplicado.

* **Pointcut**: Especifica un conjunto de Join Points. Es una expresión que define en qué Join Points un aspect debería ser aplicado.

* **Advice**: Es la acción que se toma en un Join Point seleccionado por un Pointcut. El advice es el código que realmente se ejecuta cuando el aspecto es aplicado en un Join Point.

## Pointcut Expression Language
Las Pointcut Expressions son una parte fundamental de Aspect-Oriented Programming (AOP), ya que definen los puntos de ejecución (join points) en el programa donde un aspecto debe ser aplicado. Estas expresiones permiten especificar con precisión cuándo y dónde se deben aplicar los **advices**, como `@Before`, `@After`, `@Around`, entre otros.

Una Pointcut Expression es una expresión que se utiliza para seleccionar uno o más join points. Un join point es un punto en el flujo de ejecución del programa, como la invocación de un método, la modificación de un campo, o la ejecución de un bloque de código.

### Sintaxis Básica de una Pointcut Expression
La sintaxis de una pointcut expression puede variar dependiendo del framework, pero en Java, las pointcut expressions más comunes utilizan la siguiente estructura:

```java
pointcut_expression(modifiers-pattern? ret-type-pattern declaring-type-pattern? name-pattern(param-pattern) throws-pattern?)
```
**Donde:**

* **modifiers-pattern**: Especifica los modificadores de acceso del método (opcional).

* **ret-type-pattern**: Especifica el tipo de retorno del método.

* **declaring-type-pattern**: Especifica el tipo que declara el método (opcional).

* **name-pattern**: Especifica el nombre del método.

* **param-pattern**: Especifica el patrón de parámetros del método.

* **throws-pattern**: Especifica las excepciones lanzadas por el método (opcional).

### Tipos Comunes de Pointcut Expressions
1. `execution`:

   * Este es uno de los tipos más comunes de pointcuts. Se usa para capturar la ejecución de un método.

      ```java
      @Before("execution(public void com.example.service.UserService.createUser(..))")
      public void beforeCreateUser() {
          // Advice logic here
      }
      ```
      Este pointcut se aplica a la ejecución del método `createUser` en la clase `UserService`.

2. `within`:

   * Se usa para limitar el scope del pointcut a un tipo específico o un paquete.

      ```java
      @Before("within(com.example.service.*)")
      public void beforeAnyServiceMethod() {
          // Advice logic here
      }
      ```
      Este pointcut se aplica a todos los métodos dentro del paquete `com.example.service`.

3. `args`:

   * Este pointcut captura los métodos que tienen argumentos que coinciden con el patrón especificado.

      ```java
      @Before("execution(* *(..)) && args(id, name)")
      public void beforeMethodWithArgs(Long id, String name) {
          // Advice logic here
      }
      ```
      Este pointcut se aplica a métodos que tienen un **Long** y un **String** como parámetros.

4. `this` y `target`:

   * `this`: Apunta a los join points donde el objeto proxy implementa una interfaz específica.

   * `target`: Apunta a los join points donde el objeto objetivo es una instancia de un tipo específico.

      ```java
      @Before("this(com.example.service.UserService)")
      public void beforeProxyInvocation() {
          // Advice logic here
      }
      ```

5. `@annotation`:

   * Captura los join points donde el método tiene una anotación específica.

      ```java
      @Before("@annotation(com.example.MyCustomAnnotation)")
      public void beforeAnnotatedMethod() {
          // Advice logic here
      }
      ```
      Este pointcut se aplica a todos los métodos que tienen la anotación `@MyCustomAnnotation`.

6. `@within` y `@target`:

   * `@within`: Apunta a los join points dentro de clases anotadas con una anotación específica.
   
   * `@target`: Similar a target, pero enfocado en la anotación.

      ```java
      @Before("@within(com.example.MyCustomAnnotation)")
      public void beforeMethodInAnnotatedClass() {
          // Advice logic here
      }
      ```

### Combinación de Pointcut Expressions
Las pointcut expressions pueden ser combinadas utilizando operadores lógicos como `&&` (**AND**), `||` (**OR**), y `!` (**NOT**) para formar expresiones más complejas.

**Ejemplo**
```java
@Before("execution(* com.example.service.*.*(..)) && @annotation(com.example.MyCustomAnnotation)")
public void beforeAnnotatedServiceMethod() {
    // Advice logic here
}
```
Este pointcut se aplica a cualquier método en `com.example.service` que también esté anotado con `@MyCustomAnnotation`.
