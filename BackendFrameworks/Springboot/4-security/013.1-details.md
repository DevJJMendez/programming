## UserDetails
Es una interfaz en Spring Security que representa la información del usuario necesario para la autenticación y autorización dentro de una aplicación. Los objetos que implementan esta interfaz contienen detalles como el nombre de usuario, la contraseña, los roles, y otros atributos que son esenciales para el proceso de autenticación.

### Principales Componentes de UserDetails
La interfaz UserDetails define varios métodos clave que Spring Security utiliza durante el proceso de autenticación:

1. `getUsername()`:

   * Devuelve el nombre de usuario del usuario.

   * Es el identificador principal del usuario durante la autenticación.

2. `getPassword()`:

   * Devuelve la contraseña del usuario (normalmente en formato codificado).

   * Se utiliza para verificar la autenticación del usuario.

3. `getAuthorities()`:

   * Devuelve una colección de `GrantedAuthority`, que representa los roles o permisos otorgados al usuario.
   
   * Estos roles determinan qué acciones o recursos puede acceder el usuario.

4. `isAccountNonExpired()`:

   * Devuelve un booleano que indica si la cuenta del usuario ha expirado.

   * Si la cuenta ha expirado, el usuario no puede autenticarse.

5. `isAccountNonLocked()`:

   * Devuelve un booleano que indica si la cuenta del usuario está bloqueada.

   * Si la cuenta está bloqueada, el usuario no puede autenticarse.

6. `isCredentialsNonExpired()`:

   * Devuelve un booleano que indica si las credenciales (contraseña) del usuario han expirado.

   * Credenciales expiradas impiden que el usuario se autentique.

7. `isEnabled()`:

   * Devuelve un booleano que indica si la cuenta del usuario está habilitada.

   * Un usuario deshabilitado no puede autenticarse.

### Ejemplo de Implementación de UserDetails
Cuando creas una aplicación, a menudo necesitarás implementar `UserDetails` para adaptar la información del usuario desde tu base de datos u otra fuente de datos a un formato que Spring Security pueda utilizar.

```java
public class CustomUserDetails implements UserDetails {

    private User user; // Este es un objeto de dominio que representa al usuario en tu aplicación

    public CustomUserDetails(User user) {
        this.user = user;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return user.getRoles().stream()
                .map(role -> new SimpleGrantedAuthority(role.getName()))
                .collect(Collectors.toList());
    }

    @Override
    public String getPassword() {
        return user.getPassword(); // Devuelve la contraseña del usuario
    }

    @Override
    public String getUsername() {
        return user.getUsername(); // Devuelve el nombre de usuario
    }

    @Override
    public boolean isAccountNonExpired() {
        return true; // Puedes personalizar esto para controlar si la cuenta ha expirado
    }

    @Override
    public boolean isAccountNonLocked() {
        return true; // Puedes personalizar esto para controlar si la cuenta está bloqueada
    }

    @Override
    public boolean isCredentialsNonExpired() {
        return true; // Puedes personalizar esto para controlar si las credenciales han expirado
    }

    @Override
    public boolean isEnabled() {
        return user.isEnabled(); // Controla si el usuario está habilitado
    }
}
```
### Integración con UserDetailsService
Una vez que hayas implementado UserDetails, puedes usarlo junto con UserDetailsService para cargar los detalles del usuario durante la autenticación. Por ejemplo:

```java
@Service
public class CustomUserDetailsService implements UserDetailsService {

    @Autowired
    private UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByUsername(username);
        if (user == null) {
            throw new UsernameNotFoundException("User not found");
        }
        return new CustomUserDetails(user);
    }
}
```
### Relación entre `UserDetails`, `GrantedAuthority`, y `Authentication`
* `UserDetails`: Proporciona la información principal del usuario, como el nombre de usuario, la contraseña, y el estado de la cuenta.

* `GrantedAuthority`: Representa los roles o permisos que tiene el usuario.

* `Authentication`: Es el objeto que Spring Security utiliza para representar el estado de autenticación de un usuario en el contexto actual. Este objeto contiene un UserDetails y una lista de `GrantedAuthority`.

## `UserDetailsService`
Es una interfaz central en Spring Security que se utiliza para recuperar los detalles del usuario durante el proceso de autenticación. Su principal responsabilidad es cargar un usuario por su nombre de usuario y devolver un objeto UserDetails que contiene toda la información necesaria para la autenticación y autorización.

### ¿Qué es UserDetailsService?
* **Interfaz Clave en Spring Security**: UserDetailsService es la interfaz que Spring Security utiliza para cargar información del usuario desde una fuente de datos (base de datos, archivo en memoria, etc.).

* **Carga de Usuario por Nombre de Usuario**: La interfaz tiene un solo método llamado `loadUserByUsername(String username)` que se implementa para cargar los datos del usuario.

* **Retorno de `UserDetails`**: El método `loadUserByUsername` devuelve un objeto de tipo `UserDetails`, que incluye información como el nombre de usuario, la contraseña, las autoridades (roles), y si la cuenta está habilitada, bloqueada, etc.

### Definición de la Interfaz

```java
public interface UserDetailsService {
    UserDetails loadUserByUsername(String username) throws UsernameNotFoundException;
}
```

### Método loadUserByUsername
* **Parámetro**: username es el nombre de usuario que el sistema recibe para autenticar.

* **Retorno**: `UserDetails`, que contiene información sobre el usuario.

* **Excepción**: `UsernameNotFoundException` es lanzada si el usuario no se encuentra en la fuente de datos.

### Implementaciones Comunes
* `InMemoryUserDetailsManager`:

  * Utiliza una lista en memoria para almacenar y gestionar usuarios.

  * Ideal para pruebas y entornos de desarrollo.

* `JdbcUserDetailsManager`:

  * Utiliza una base de datos relacional (a través de JDBC) para almacenar y gestionar usuarios.

  * Es la elección común para aplicaciones que necesitan persistencia a largo plazo de los usuarios.

* `Custom UserDetailsService`:

  * Puedes implementar tu propia clase que extienda `UserDetailsService` y personalizar la lógica de carga del usuario desde cualquier fuente de datos (base de datos NoSQL, servicios externos, etc.).

### Ejemplo de Implementación Personalizada
Supongamos que tienes una base de datos relacional y quieres implementar un `UserDetailsService` personalizado que cargue usuarios desde una tabla específica:

```java
@Service
public class CustomUserDetailsService implements UserDetailsService {

    @Autowired
    private UserRepository userRepository; // Un repositorio para interactuar con la base de datos

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByUsername(username);
        if (user == null) {
            throw new UsernameNotFoundException("User not found with username: " + username);
        }

        // Convertimos el objeto User de la base de datos en un objeto UserDetails
        return new org.springframework.security.core.userdetails.User(user.getUsername(),
                user.getPassword(), 
                getAuthorities(user));
    }

    private Collection<? extends GrantedAuthority> getAuthorities(User user) {
        return user.getRoles().stream()
                .map(role -> new SimpleGrantedAuthority(role.getName()))
                .collect(Collectors.toList());
    }
}
```
## UserDetailsManager
Es una interfaz en Spring Security que extiende la interfaz UserDetailsService. Mientras que UserDetailsService se centra únicamente en cargar los detalles del usuario desde un almacenamiento (como una base de datos), UserDetailsManager proporciona operaciones adicionales para manejar el ciclo de vida de un usuario, como crear, actualizar, eliminar y cambiar la contraseña de los usuarios.

### Interfaz UserDetailsManager
`UserDetailsManager` proporciona métodos que permiten gestionar los detalles del usuario de una manera más completa. Aquí están los métodos clave:

1. `createUser(UserDetails user)`: Crea un nuevo usuario en el almacenamiento subyacente.

2. `updateUser(UserDetails user)`: Actualiza un usuario existente en el almacenamiento.

3. `deleteUser(String username)`: Elimina un usuario por su nombre de usuario.

4. `changePassword(String oldPassword, String newPassword)`: Cambia la contraseña del usuario autenticado actualmente.

5. `userExists(String username)`: Verifica si un usuario con el nombre de usuario dado ya existe en el almacenamiento.

### Implementaciones Comunes de UserDetailsManager
1. `InMemoryUserDetailsManager`:
   
   * Una implementación de UserDetailsManager que almacena los detalles de los usuarios en memoria.

   * Útil para pruebas o aplicaciones pequeñas.

        ```java
        @Bean
        public InMemoryUserDetailsManager userDetailsManager() {
            UserDetails user = User.withDefaultPasswordEncoder()
                .username("user")
                .password("password")
                .roles("USER")
                .build();

            UserDetails admin = User.withDefaultPasswordEncoder()
                .username("admin")
                .password("password")
                .roles("ADMIN")
                .build();

            return new InMemoryUserDetailsManager(user, admin);
        }
        ```

2. `JdbcUserDetailsManager`

   * Una implementación que almacena los detalles del usuario en una base de datos relacional usando JDBC.

   * Utiliza un DataSource para conectarse a la base de datos y manejar las operaciones relacionadas con el usuario.

        ```java
        @Bean
        public JdbcUserDetailsManager jdbcUserDetailsManager(DataSource dataSource) {
            JdbcUserDetailsManager manager = new JdbcUserDetailsManager(dataSource);
            // Configurar las consultas SQL si es necesario
            return manager;
        }
        ```

3. `LdapUserDetailsManager`

   * Se usa para gestionar usuarios en un directorio LDAP.

   * Aunque no es tan común como `JdbcUserDetailsManager` o `InMemoryUserDetailsManager`, es crucial en aplicaciones empresariales que utilizan LDAP para la gestión de usuarios.

        ```java
        @Bean
        public JdbcUserDetailsManager jdbcUserDetailsManager(DataSource dataSource) {
            JdbcUserDetailsManager manager = new JdbcUserDetailsManager(dataSource);
            
            if (!manager.userExists("user")) {
                manager.createUser(User.withDefaultPasswordEncoder()
                    .username("user")
                    .password("password")
                    .roles("USER")
                    .build());
            }
            
            if (!manager.userExists("admin")) {
                manager.createUser(User.withDefaultPasswordEncoder()
                    .username("admin")
                    .password("password")
                    .roles("ADMIN")
                    .build());
            }
            
            return manager;
        }
        ```
     * `createUser()` se utiliza para agregar un nuevo usuario al almacenamiento si no existe.
     
     * `userExists()` se utiliza para verificar si un usuario ya está presente antes de crearlo.


## `InMemoryUserDetailsManager`
Es una implementación de la interfaz `UserDetailsService` en Spring Security, que se utiliza para la autenticación **en memoria**. Esto significa que los usuarios y roles se definen directamente en la configuración de la aplicación en lugar de ser cargados desde una base de datos u otro almacenamiento externo.

`InMemoryUserDetailsManager` es un componente que gestiona usuarios y roles en memoria. Es útil para prototipos, pruebas, o aplicaciones pequeñas donde no se necesita persistir los datos de usuario en una base de datos.

### Configuración
Puedes configurar `InMemoryUserDetailsManager` en tu clase de configuración de Spring Security. 

Hablemos de WebSecurityConfigurerAdapter
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {

    @Override
    protected void configure(AuthenticationManagerBuilder auth) throws Exception {
        auth.userDetailsService(inMemoryUserDetailsManager());
    }

    @Bean
    public InMemoryUserDetailsManager inMemoryUserDetailsManager() {
        UserDetails user = User.withDefaultPasswordEncoder()
                .username("user")
                .password("password")
                .roles("USER")
                .build();

        UserDetails admin = User.withDefaultPasswordEncoder()
                .username("admin")
                .password("admin")
                .roles("ADMIN")
                .build();

        return new InMemoryUserDetailsManager(user, admin);
    }

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
            .antMatchers("/admin/**").hasRole("ADMIN")
            .antMatchers("/user/**").hasRole("USER")
            .antMatchers("/").permitAll()
            .and()
            .formLogin()
            .and()
            .logout()
            .permitAll();
    }
}
```
1. **Configuración de Autenticación**:

   * `auth.userDetailsService(inMemoryUserDetailsManager())`;: Configura Spring Security para utilizar el `InMemoryUserDetailsManager` como el UserDetailsService para cargar los detalles de usuario.

2. **Creación de Usuarios**:

   * `User.withDefaultPasswordEncoder()`: Crea un usuario utilizando un codificador de contraseña por defecto. Nota: El uso de withDefaultPasswordEncoder es adecuado solo para fines de prueba. En producción, deberías usar un codificador de contraseñas más seguro.

   * `username("user")`: Establece el nombre de usuario.

   * `password("password")`: Establece la contraseña.

   * `roles("USER")`: Asigna roles al usuario.

3. **Protección de URLs**:

   * `antMatchers("/admin/**").hasRole("ADMIN")`: Solo los usuarios con el rol "ADMIN" pueden acceder a URLs que comiencen con `/admin/`.

   * `antMatchers("/user/**").hasRole("USER")`: Solo los usuarios con el rol "USER" pueden acceder a URLs que comiencen con `/user/`.
   
   * **Login y Logout**:
   
     * `formLogin()`: Habilita el inicio de sesión basado en formulario.
   
     * `logout().permitAll()`: Permite a todos los usuarios cerrar sesión.

### Ventajas y Limitaciones

* **Ventajas**:

   * **Simplicidad**: Fácil de configurar y utilizar para aplicaciones pequeñas o pruebas.

   * **Rápido de configurar**: No requiere de una base de datos ni de un almacén de datos externo.

   * **Útil para Prototipos**: Ideal para crear prototipos de aplicaciones donde la persistencia de datos no es necesaria.

* **Limitaciones**:

  * **No Persistente**: Los usuarios y roles no se almacenan de manera persistente. Cada vez que la aplicación se reinicia, se perderán los datos de usuario.

  * **No Escalable**: No es adecuado para aplicaciones grandes o en producción donde se requiere almacenamiento persistente de datos de usuario.

  * **Seguridad Limitada**: El uso de `withDefaultPasswordEncoder` no es adecuado para entornos de producción debido a la falta de cifrado fuerte de contraseñas.

* **Alternativas**
Para aplicaciones más grandes o de producción, es recomendable usar una implementación de UserDetailsService más robusta, como:

  * **JDBC Authentication**: Cargar usuarios y roles desde una base de datos.

  * **LDAP Authentication**: Integración con un servidor LDAP.

  * **Custom UserDetailsService**: Implementación personalizada que carga usuarios y roles desde cualquier fuente (base de datos, servicio web, etc.).
