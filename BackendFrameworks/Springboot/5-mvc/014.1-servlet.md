### Servlet

Un Servlet es una clase Java que se ejecuta en un servidor web o de aplicaciones y actúa como un intermediario entre una solicitud de un cliente (generalmente un navegador web) y el backend de una aplicación web. Los Servlets son la tecnología base para construir aplicaciones web en Java y son parte de la especificación Java Servlet API.

1. **Interacción Cliente-Servidor**:

   - Un Servlet recibe una solicitud HTTP del cliente (por ejemplo, una solicitud GET o POST), la procesa y genera una respuesta HTTP. Esta respuesta generalmente es una página HTML, aunque también puede ser otro tipo de contenido, como JSON o XML.

2. **Ciclo de Vida de un Servlet**:

   - **Inicialización (`init`)**: El servidor web carga y crea una instancia del Servlet. El método `init()` se llama una vez, cuando el Servlet se carga por primera vez, y se utiliza para realizar la inicialización necesaria.

   - **Procesamiento de Solicitudes (`service`)**: Cada vez que el servidor recibe una solicitud para el Servlet, se llama al método service(), que a su vez llama a métodos específicos como `doGet()` o `doPost()` dependiendo del tipo de solicitud.

   - **Destrucción (`destroy`)**: Cuando el servidor decide destruir el Servlet (por ejemplo, cuando se apaga), se llama al método `destroy()` para liberar recursos.

3. **Métodos Comunes en un Servlet**:

   - `doGet(HttpServletRequest request, HttpServletResponse response)`: Maneja solicitudes **HTTP GET**. Es utilizado principalmente para obtener datos desde el servidor.

   - `doPost(HttpServletRequest request, HttpServletResponse response)`: Maneja solicitudes **HTTP POST**. Se utiliza para enviar datos al servidor, por ejemplo, cuando se envía un formulario.

   - `service(HttpServletRequest request, HttpServletResponse response)`: Este método es el punto de entrada para todas las solicitudes HTTP y decide qué método específico (**GET**, **POST**, etc.) invocar según la solicitud recibida.

4. **Servlet Container**:

   - Un Servlet se ejecuta dentro de un contenedor de Servlets, que es una parte del servidor web que maneja la ejecución de Servlets. Ejemplos de contenedores de Servlets incluyen Apache Tomcat, Jetty y GlassFish. El contenedor es responsable de la creación, gestión del ciclo de vida y seguridad de los Servlets.

5. **Servlet y JSP**:

   - Los Servlets proporcionan la lógica de negocio y manejo de solicitudes, mientras que JSP (JavaServer Pages) se utiliza generalmente para la presentación. JSP se compila en un Servlet en tiempo de ejecución, lo que permite mezclar lógica Java con HTML.

### Dispatcher Servlet

El DispatcherServlet es un componente central en el marco de trabajo Spring MVC, actuando como el front controller para las aplicaciones web desarrolladas con Spring. Su función principal es recibir todas las solicitudes HTTP entrantes y dirigirlas al controlador adecuado para su procesamiento.

1. Front Controller:

   - El `DispatcherServlet` es el punto de entrada único para todas las solicitudes en una aplicación Spring MVC. Este patrón de diseño centraliza el manejo de solicitudes en un solo componente, lo que facilita la coordinación y el flujo de la aplicación.

2. **Configuración de Mapeo**:

   - Cuando se configura una aplicación Spring, el DispatcherServlet se mapea a una o más URL patterns en el archivo de configuración. En la mayoría de las aplicaciones Spring Boot, el DispatcherServlet se mapea por defecto a `"/*"`, lo que significa que maneja todas las solicitudes en el contexto de la aplicación.

3. **Flujo de Trabajo del DispatcherServlet**:

   - **Recepción de Solicitudes**:

     - Cuando una solicitud HTTP llega a la aplicación, el servidor web (como Tomcat) la dirige al DispatcherServlet, que es el encargado de procesarla.

   - **HandlerMapping**:

     - El DispatcherServlet consulta los componentes HandlerMapping para determinar cuál controlador (o handler) debe manejar la solicitud. Los HandlerMapping usan la información de las anotaciones en los controladores (`@RequestMapping`) para resolver el controlador adecuado.

   - `**HandlerAdapter**`:

     - Una vez identificado el controlador, el DispatcherServlet usa un HandlerAdapter para invocar el método adecuado del controlador. Este adaptador se encarga de la ejecución del método del controlador con los parámetros correctos.

   - **Procesamiento de la Solicitud**:

     - El método del controlador se ejecuta y puede interactuar con el modelo, realizar lógica de negocio, acceder a la base de datos, etc. El controlador luego devuelve una vista (generalmente como un ModelAndView) o una respuesta directa.

   - Resolver la Vista:

     - Si el controlador devuelve un nombre de vista, el `DispatcherServlet` delega a un ViewResolver la tarea de localizar la plantilla de la vista correspondiente (por ejemplo, un archivo Thymeleaf o JSP).

   - Renderización de la Vista:

     - Finalmente, la vista se renderiza con los datos proporcionados por el controlador y el resultado (usualmente HTML) se envía como respuesta HTTP al cliente.

4. **Configuración en Spring Boot**:

   - En aplicaciones Spring Boot, la configuración del DispatcherServlet es generalmente automática. Spring Boot crea un DispatcherServlet y lo mapea a la raíz del contexto de la aplicación (/), lo que significa que maneja todas las solicitudes HTTP.

   - Sin embargo, si se necesita una configuración personalizada, se puede modificar en el archivo de configuración de la aplicación (`application.properties` o `application.yml`), o se puede proporcionar un bean personalizado `DispatcherServlet` o `ServletRegistrationBean`.

5. **Flexibilidad y Extensibilidad**:

   - El DispatcherServlet es altamente configurable. Se pueden agregar interceptores para ejecutar lógica antes o después de la llamada al controlador. También permite el uso de excepciones personalizadas para manejar errores y otros eventos durante el procesamiento de la solicitud.
