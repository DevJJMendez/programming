## Spring Core

El core de Spring Framework constituye la base sobre la cual se construyen todos los demás módulos y componentes de Spring. Este núcleo proporciona funcionalidades esenciales que permiten el uso de **Inversión de Control** (IoC) y la **Inyección de Dependencias** (DI), junto con otros servicios básicos que son cruciales para el desarrollo de aplicaciones.

### Componentes del Core de Spring 

1. **`BeanFactory`**:

   * **Descripción**: Es la interfaz fundamental para el contenedor IoC en Spring. Proporciona la configuración básica y la administración de beans.

   * **Uso**: Se utiliza en aplicaciones ligeras o cuando se necesita un bajo consumo de recursos.

    **Ejemplo**
    ```java
    BeanFactory factory = new XmlBeanFactory(new ClassPathResource("applicationContext.xml"));
    MyBean myBean = (MyBean) factory.getBean("myBean");
    ```

2. **`ApplicationContext`**:

   * **Descripción**: Es una extensión de BeanFactory que proporciona funcionalidades adicionales, como la gestión de eventos, resolución de mensajes y soporte para la integración con AOP (Aspect-Oriented Programming).

   * **Uso**: Se utiliza en la mayoría de las aplicaciones empresariales debido a sus capacidades avanzadas.

    **Ejemplo**
    ```java
    ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");
    MyBean myBean = (MyBean) context.getBean("myBean");
    ```

3. **`Resource Interface`**:

   * **Descripción**: Proporciona una manera uniforme de acceder a recursos externos como archivos, URLs, y ubicaciones en el classpath.

   * **Uso**: Facilita la carga de recursos en diferentes formatos y ubicaciones.

    **Ejemplo**
    ```java
    Resource resource = new ClassPathResource("data.txt");
    InputStream is = resource.getInputStream();
    ```

4. **`IoC Container`**:

   * **Descripción**: El contenedor `IoC` es responsable de la gestión del ciclo de vida de los objetos y de las dependencias entre ellos.

   * **Uso**: Centraliza la creación y configuración de los objetos (**beans**) necesarios para la aplicación.

   * **Ejemplo**: Utilizando **ApplicationContext** o **BeanFactory** para cargar beans definidos en configuraciones **XML** o **anotaciones**.

5. **`Spring AOP` (Aspect-Oriented Programming)**:

   * **Descripción**: Permite la separación de preocupaciones transversales (como logging, seguridad y transacciones) mediante la creación de aspectos que pueden ser aplicados a los objetos gestionados por el contenedor Spring.

   * **Uso**: Facilita la adición de funcionalidades transversales sin modificar el código fuente original.
   
   * **Ejemplo**:   Definir un aspecto para logging que se aplica a métodos específicos.

    ```java
    @Aspect
    public class LoggingAspect {
        @Before("execution(* com.example.MyService.*(..))")
        public void logBefore(JoinPoint joinPoint) {
            System.out.println("Method called: " + joinPoint.getSignature().getName());
        }
    }
    ```

5. **Environment Abstraction**:

   * **Descripción**: Proporciona una manera de acceder a propiedades del entorno y perfiles activos.

   * Uso: Permite la configuración dinámica de la aplicación basada en el entorno (desarrollo, prueba, producción).

   * Ejemplo
    ```java
    @Autowired
    private Environment env;

    public void printActiveProfiles() {
        System.out.println(Arrays.toString(env.getActiveProfiles()));
    }
    ```
### Ventajas del Core de Spring
* **Flexibilidad**: Permite diferentes estilos de configuración (XML, anotaciones, JavaConfig).

* **Modularidad**: Facilita la separación de preocupaciones y la modularización de la aplicación.

* **Testabilidad**: Promueve prácticas de diseño que facilitan la escritura de pruebas unitarias.

* **Reusabilidad**: Los beans gestionados por el contenedor pueden ser fácilmente reutilizados y configurados para diferentes entornos.


## 1. Bean Factory

Es una interfaz central en el contenedor de Inversión de Control (IoC) de Spring. Es la implementación más básica del contenedor IoC y se encarga de la configuración, creación y gestión del ciclo de vida de los beans en una aplicación Spring.

### Funciones Principales del BeanFactory

1. **Configuración y Gestión de Beans**:

   * Define los beans y sus dependencias a través de configuraciones (XML, anotaciones o JavaConfig).

   * Gestiona el ciclo de vida de los beans, desde la instanciación hasta la destrucción.

2. **Inyección de Dependencias (DI)**:

   * Inyecta dependencias en los beans según la configuración proporcionada.

3. **Lazy Initialization**:

   * Los **Beans** se crean solo cuando son necesarios, es decir, cuando se solicitan explícitamente por primera vez (lazy loading).


### Uso Básico del BeanFactory

* **Configuración XML** `beans.xml`

    ```xml
    <beans xmlns="http://www.springframework.org/schema/beans"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

        <bean id="myBean" class="com.example.MyBean">
            <property name="name" value="Bean Example"/>
        </bean>
    </beans>
    ```

* **Clase de Bean**

    ```java
    package com.example;

    public class MyBean {
        private String name;

        public void setName(String name) {
            this.name = name;
        }

        public void printName() {
            System.out.println("Bean name: " + name);
        }
    }
    ```

* **Uso del BeanFactory**

    ```java
    package com.example;

    import org.springframework.beans.factory.BeanFactory;
    import org.springframework.beans.factory.xml.XmlBeanFactory;
    import org.springframework.core.io.ClassPathResource;

    public class MainApp {
        public static void main(String[] args) {

            BeanFactory factory = new XmlBeanFactory(new ClassPathResource("beans.xml"));
            
            MyBean myBean = (MyBean) factory.getBean("myBean");
            
            myBean.printName();
        }
    }
    ```
### Diferencias entre BeanFactory y ApplicationContext

Aunque **BeanFactory** es la interfaz más básica para el contenedor IoC de Spring, la mayoría de las aplicaciones modernas utilizan **ApplicationContext**, que es una subinterfaz de **BeanFactory** con funcionalidades adicionales.

## 2. ApplicationContext

Es una interfaz central en el **contenedor IoC (Inversión de Control)** de Spring. Es una extensión del **BeanFactory** y proporciona funcionalidades adicionales para la gestión avanzada de **Beans**, como la gestión de eventos, la integración con **AOP (Programación Orientada a Aspectos)**, la carga de archivos de propiedades y la internacionalización.

#### Funcionalidades

1. **Inyección de Dependencias**:

    * Gestiona la creación y la inyección de dependencias entre **Beans**.

2. **Soporte para eventos**:

   * Permite la publicación y el manejo de eventos de aplicación.

3. **Soporte para AOP**:

   * Integración con aspectos, permitiendo la configuración declarativa de aspectos.

4. **Internacionalización (i18n)**:

   * Soporte para mensajes internacionalizados mediante archivos de propiedades.

5. **Carga de recursos**:

   * Capacidad para cargar archivos externos, como archivos de propiedades, XML, etc.

6. **Herencia de Contextos**:

   * Soporte para la creación de jerarquías de ApplicationContext, permitiendo contextos secundarios que heredan **Beans** y configuraciones del contexto principal.

#### Tipos

1. **`ClassPathXmlApplicationContext`**:

   * Carga el contexto desde un archivo **XML** ubicado en el classpath.
        
        ```java
        ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");
        ```

2. **`FileSystemXmlApplicationContext`**:

   * Carga el contexto desde un archivo **XML** ubicado en el sistema de archivos.
        
        ```java
        ApplicationContext context = new FileSystemXmlApplicationContext("C:/path/to/applicationContext.xml");
        ```

3. **`AnnotationConfigApplicationContext`**:

   * Carga el contexto desde clases Java configuradas con anotaciones.
  
        ```java
        ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
        ```

4. **`WebApplicationContext`**:

   * Especialización del `ApplicationContext` para aplicaciones web. Es típicamente utilizado en aplicaciones **Spring MVC**.

#### Ejemplo Básico de Uso

1. **Configuración XML**

    `applicationContext.xml`
    ```xml
    <beans xmlns="http://www.springframework.org/schema/beans"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

        <bean id="myService" class="com.example.MyService"/>
    </beans>
    ```
* `MyService.java`

    ```java
    package com.example;

    public class MyService {
        public void performTask() {
            System.out.println("Task performed");
        }
    }
    ```
* `MainApp.java`

    ```java
    package com.example;

    import org.springframework.context.ApplicationContext;
    import org.springframework.context.support.ClassPathXmlApplicationContext;

    public class MainApp {

        public static void main(String[] args) {

            ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");

            MyService myService = context.getBean(MyService.class);
            
            myService.performTask();
        }
    }
    ```
2. **Configuración con Anotaciones**
   
   `AppConfig.java`
    
    ```java
    package com.example;

    import org.springframework.context.annotation.Bean;
    import org.springframework.context.annotation.Configuration;

    @Configuration
    public class AppConfig {
        @Bean
        public MyService myService() {
            return new MyService();
        }
    }
    ```
* `MyService.java`
    
    ```java
    package com.example;

    import org.springframework.stereotype.Service;

    @Service
    public class MyService {
        public void performTask() {
            System.out.println("Task performed");
        }
    }
    ```
* `MainApp.java`

    ```java
    package com.example;

    import org.springframework.context.ApplicationContext;
    import org.springframework.context.annotation.AnnotationConfigApplicationContext;

    public class MainApp {
        public static void main(String[] args) {

            ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
            
            MyService myService = context.getBean(MyService.class);
            
            myService.performTask();
        }
    }
    ```
## 3. Resource Interface

La interfaz Resource en Spring Framework es una abstracción que representa un recurso externo. Este recurso puede ser cualquier cosa accesible desde la aplicación, como archivos, URLs, ubicaciones en el classpath, etc. La interfaz Resource proporciona métodos para manejar estos recursos de manera uniforme, independientemente de su origen.

### Propósito de la Interfaz Resource

La interfaz Resource permite a Spring proporcionar una manera consistente y flexible de acceder a recursos externos. Esto es particularmente útil en situaciones donde una aplicación necesita leer archivos de configuración, cargar archivos de propiedades, o acceder a otros tipos de recursos.

### Principales Métodos de la Interfaz Resource

* `exists()`: Devuelve true si el recurso existe.

* `isReadable()`: Devuelve true si el recurso es legible.

* `isOpen()`: Devuelve true si el recurso es un InputStream que se encuentra actualmente abierto.

* `getInputStream()`: Devuelve un InputStream para leer desde el recurso.

* `getDescription()`: Devuelve una descripción del recurso.

## 4. IOC Container

El contenedor **IoC (Inversion of Control)** en Spring es el componente principal que gestiona la **creación, configuración y el ciclo de vida de los objetos (beans)** en una aplicación Spring. El contenedor se encarga de **invertir el control de la creación de objetos desde la aplicación hacia el contenedor**, permitiendo una inyección de dependencias efectiva y una configuración declarativa.

### Principios Básicos

1. **Inversión de Control (IoC)**:

   * La creación de objetos y la inyección de sus dependencias se delega al contenedor IoC en lugar de ser gestionada por el propio código de la aplicación.

2. **Inyección de Dependencias (DI)**:

   * El proceso mediante el cual el contenedor IoC inyecta dependencias en los beans, ya sea a través del constructor, métodos setter o campos.

### Tipos de Contenedores IoC en Spring

1. **BeanFactory**:

   * Es la interfaz raíz para el contenedor IoC. Proporciona las funcionalidades básicas de configuración y gestión de **Beans**.

   * Es perezoso en la inicialización de **Beans** (los beans se crean cuando son solicitados).

2. **ApplicationContext**:

   * Es una subinterfaz de **BeanFactory** que añade más funcionalidades avanzadas.

   * Prepara y configura los **Beans** de manera anticipada (**eager initialization**).

   * Proporciona soporte para eventos de aplicación, internacionalización (i18n), y carga de recursos.

#### Creación y Configuración de Beans

El contenedor IoC de Spring puede crear y gestionar beans a partir de varias configuraciones: **XML**, **Annotations** o **JavaConfig**.

1. **Configuración XML**

    `applicationContext.xml`

    ```java
    <beans xmlns="http://www.springframework.org/schema/beans"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

        <bean id="myService" class="com.example.MyService">
            <property name="repository" ref="myRepository"/>
        </bean>

        <bean id="myRepository" class="com.example.MyRepository"/>
    </beans>
    ```
* Cargar `ApplicationContext`

    ```java
    ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");
    MyService myService = context.getBean(MyService.class);
    ```

2. **Configuración con Anotaciones**

    `AppConfig.java`
    ```java
    package com.example;

    import org.springframework.context.annotation.ComponentScan;
    import org.springframework.context.annotation.Configuration;

    @Configuration
    @ComponentScan(basePackages = "com.example")
    public class AppConfig {
    }
    ```
* **Beans con `Annotations`**

    ```java
    package com.example;

    import org.springframework.stereotype.Service;
    import org.springframework.beans.factory.annotation.Autowired;

    @Service
    public class MyService {
        @Autowired
        private MyRepository myRepository;
    }

    @Repository
    public class MyRepository {
    }
    ```
* Cargar `ApplicationContext`

    ```java
    ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
    MyService myService = context.getBean(MyService.class);
    ```

3. **Configuración con `JavaConfig`**

    `AppConfig.java`

    ```java
    package com.example;

    import org.springframework.context.annotation.Bean;
    import org.springframework.context.annotation.Configuration;

    @Configuration
    public class AppConfig {

        @Bean
        public MyService myService() {
            return new MyService(myRepository());
        }

        @Bean
        public MyRepository myRepository() {
            return new MyRepository();
        }
    }
    ```
* Cargar `ApplicationContext`

    ```java
    ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
    MyService myService = context.getBean(MyService.class);
    ```

#### Ejemplo

* `MyRepository.java`

    ```java

    import org.springframework.stereotype.Repository;

    @Repository
    public class MyRepository {
        public void save() {
            System.out.println("Data saved!");
        }
    }
    ```
* `MyService.java`

### Inversion of Control / IOC

La Inversión de Control (`Inversion of Control`, **IoC**) es un principio de diseño de software que **invierte el control del flujo del programa**, de manera que **el control pasa del propio programa a un contenedor o framework**. En el contexto de Spring, **IoC** es fundamental para gestionar la creación y el ciclo de vida de los objetos (beans) y sus dependencias de forma automática.

En lugar de que un objeto controle sus dependencias y flujo, es el contenedor IoC el que se encarga de crear, configurar y gestionar estos objetos y sus dependencias.

#### Estructura

1. `**Beans**`:

   * Los objetos que son gestionados por el contenedor IoC. Los Beans pueden ser cualquier objeto Java configurado y gestionado por Spring.

2. **Configuración de `Beans`**:

   * Los beans y sus dependencias se definen en archivos de configuración **XML**, clases Java con **anotaciones** o mediante **JavaConfig**.

3. **Contenedor `IoC`**:

   * `BeanFactory` y `ApplicationContext` son los dos tipos principales de contenedores `IoC` en Spring. `ApplicationContext` es una extensión de `BeanFactory` con funcionalidades adicionales.

#### Flujo

1. **Definición de Beans**: Los beans y sus dependencias se definen en la configuración de Spring.

2. **Creación del Contenedor IoC**: Se inicializa el contenedor **IoC**, que lee la configuración y crea los Beans definidos.

3. **Inyección de Dependencias**: El contenedor IoC analiza las dependencias de cada bean y las resuelve, inyectando las instancias apropiadas en los beans.

4. **Inicialización de Beans**: Los Beans se inicializan, incluyendo la llamada a métodos de ciclo de vida como `@PostConstruct`.

5. **Uso de Beans**: Los beans están listos para ser utilizados en la aplicación.

#### Ejemplo de IOC

1. **Configuración mediante `XML`**

    `applicationContext.xml`:
    
    ```xml
    <beans xmlns="http://www.springframework.org/schema/beans"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

        <bean id="myBean" class="com.example.MyBean">
            <property name="myDependency" ref="myDependency"/>
        </bean>

        <bean id="myDependency" class="com.example.MyDependency"/>
    </beans>
    ```
2. **Configuración mediante Anotaciones**

    `MyBean.java`:
    ```java
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.stereotype.Component;

    @Component
    public class MyBean {

        private MyDependency myDependency;

        @Autowired
        public void setMyDependency(MyDependency myDependency) {
            this.myDependency = myDependency;
        }
    }
    ```


* `MyDependency.java`:

    ```java
    import org.springframework.stereotype.Component;

    @Component
    public class MyDependency {
    }
    ```
    `AppConfig.java`
    ```java
    import org.springframework.context.annotation.ComponentScan;
    import org.springframework.context.annotation.Configuration;

    @Configuration
    @ComponentScan(basePackages = "com.example")
    public class AppConfig {
    }
    ```

3. **Configuración mediante `JavaConfig`**

    `AppConfig.java`:

    ```java
    import org.springframework.context.annotation.Bean;
    import org.springframework.context.annotation.Configuration;

    @Configuration
    public class AppConfig {
        @Bean
        public MyBean myBean() {
            return new MyBean(myDependency());
        }

        @Bean
        public MyDependency myDependency() {
            return new MyDependency();
        }
    }
    ```

### Ejemplo

`MyBean.java`

```java

    private final MyDependency myDependency;

    public MyBean(MyDependency myDependency) {
        this.myDependency = myDependency;
    }

    public void doSomething() {
        System.out.println("Doing something with " + myDependency);
    }
}
```
`MyDependency.java`:

```java

    @Override

        return "MyDependency";

```
`MainApp.java`

#### Ventajas de IoC

1. **Desacoplamiento**: Promueve un diseño desacoplado donde las clases no gestionan directamente sus dependencias, lo que facilita el cambio de implementaciones y la prueba unitaria.

2. **Reutilización**: Los **Beans** gestionados por el contenedor **IoC** pueden ser fácilmente reutilizados en diferentes contextos.

3. **Mantenibilidad**: Facilita la gestión y configuración centralizada de los objetos, lo que mejora la mantenibilidad del código.

4. **Modularidad**: Permite la separación de preocupaciones, ya que las dependencias se gestionan externamente.

### Dependecy Injection / DI

La Inyección de Dependencias (`Dependency Injection`, **DI**) es un patrón de diseño que permite gestionar y resolver las dependencias entre los componentes de una aplicación de manera automática. En lugar de que los objetos **creen sus propias dependencias**, éstas son **inyectadas por un contenedor**, como el `Spring Container`. Este enfoque promueve un diseño más modular, desacoplado y fácil de mantener.

#### Conceptos Clave

* **Inversión de Control (`IoC`)**
  
  * Principio por el cual el control de la creación y gestión de los objetos es invertido, es decir, no es el objeto el que controla sus dependencias, sino un contenedor que se encarga de proporcionar esas dependencias.

* **Contenedor `IoC`**
  
  * Un framework o biblioteca que gestiona la creación, configuración y ciclo de vida de los objetos y sus dependencias. En Spring, el contenedor IoC es el núcleo del framework.

* **Beans**
  
  * Los objetos que el contenedor `IoC` gestiona. Estos beans son definidos y configurados en el contexto del contenedor.


### pendencias

1. **Inyección por Constructor**
   
   Las dependencias se proporcionan a través del constructor de la clase. Las dependencias se inyectan al momento de la creación del objeto, lo que permite que el objeto esté completamente inicializado.

    **Ejemplo**
    ```java
    public class MyBean {
        private MyDependency myDependency;

        @Autowired
        public MyBean(MyDependency myDependency) {
            this.myDependency = myDependency;
        }
    }
    ```
2. **Inyección por Setter**
   
   Las dependencias se inyectan mediante métodos setter. Permite la inyección de dependencias opcionales y promueve el uso de métodos de inicialización adicionales.

    **Ejemplo**
    ```java
    public class MyBean {
        private MyDependency myDependency;

        @Autowired
        public void setMyDependency(MyDependency myDependency) {
            this.myDependency = myDependency;
        }
    }
    ```

3. **Inyección por Campo (`Field Injection`)**
   
   Las dependencias se inyectan directamente en los campos de la clase. Simplifica el código al eliminar la necesidad de constructores o métodos setter.

    **Ejemplo**
    ```java
    public class MyBean {
        @Autowired
        private MyDependency myDependency;
    }
    ```

#### Flujo de Inyección de Dependencias en Spring

1. **Definición de Beans**: Los beans y sus dependencias se definen en la configuración de Spring (mediante anotaciones, archivos XML o clases JavaConfig).

2. **Creación del Contenedor `IoC`**: Se inicializa el contenedor IoC, que lee la configuración y crea los beans definidos.

3. **Resolución de Dependencias**: El contenedor IoC analiza las dependencias de cada bean y las resuelve, inyectando las instancias apropiadas en los beans.

4. **Inicialización de Beans**: Los beans se inicializan, incluyendo la llamada a métodos de ciclo de vida como `@PostConstruct`.

5. **Uso de Beans**: Los beans están listos para ser utilizados en la aplicación.

## 5. Spring AOP (Aspect-Oriented Programming)

Spring AOP (Programación Orientada a Aspectos) es una funcionalidad clave de Spring Framework que permite la separación de preocupaciones transversales en módulos independientes llamados aspectos. La programación orientada a aspectos es un paradigma que complementa la programación orientada a objetos, permitiendo la modularización de aspectos que afectan a múltiples clases y métodos.

### Principales Conceptos de Spring AOP

1. **Aspecto (Aspect)**:

   * Un módulo que encapsula un comportamiento transversal que afecta múltiples puntos en una aplicación, como la gestión de transacciones, la auditoría, el logging, etc.

   * En Spring, un aspecto es una clase anotada con `@Aspect`.

2. **Join Point**:

   * Un punto en la ejecución de un programa donde se puede aplicar un aspecto, como la llamada a un método, la creación de un objeto, etc.

   * En Spring AOP, los **join points** son principalmente las invocaciones de **métodos**.

3. **Advice**:

   * La acción que se realiza en un **join point** determinado. Puede ser antes, después, o alrededor de la ejecución de un método.

   * Tipos de advice:
  
     * `Before`: Se ejecuta antes de la ejecución del método.
        
     * `After`: Se ejecuta después de la ejecución del método.
        
     * `AfterReturning`: Se ejecuta después de la ejecución del método si este completa con éxito.
        
     * `AfterThrowing`: Se ejecuta después de la ejecución del método si este lanza una excepción.
        
     * `Around`: Envuelve la ejecución del método, permitiendo realizar acciones antes y después de su ejecución.

4. **Pointcut**:

   * Una expresión que define los **join points** donde se aplica un aspecto.

   * En Spring AOP, las pointcuts se definen usando expresiones **AspectJ**.

5. **Weaving**:

   * El proceso de aplicar aspectos a los objetos del programa. Puede ocurrir en tiempo de compilación, carga de clase, o en tiempo de ejecución.

   * Spring AOP realiza el weaving en tiempo de ejecución utilizando proxies dinámicos.

### Ejemplo Práctico de Spring AOP

* **Paso 1: Dependencias en `pom.xml`**

    ```xml
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-aop</artifactId>
    </dependency>
    ```
* **Paso 2: Definir un Aspecto**

    ```java
    package com.example.aspect;

    import org.aspectj.lang.annotation.Aspect;
    import org.aspectj.lang.annotation.Before;
    import org.springframework.stereotype.Component;

    @Aspect
    @Component
    public class LoggingAspect {

        @Before("execution(* com.example.service.*.*(..))")
        public void logBeforeMethod() {
            System.out.println("Method execution started");
        }
    }
    ```

* **Paso 3: Crear un Servicio para Demostrar el Aspecto**

    ```java
    package com.example.service;

    import org.springframework.stereotype.Service;

    @Service
    public class UserService {

        public void createUser() {
            System.out.println("Creating a new user");
        }
    }
    ```

* **Paso 4: Configuración de Spring Boot Application**

    ```java
    package com.example;

    import org.springframework.boot.SpringApplication;
    import org.springframework.boot.autoconfigure.SpringBootApplication;

    @SpringBootApplication
    public class AopExampleApplication {

        public static void main(String[] args) {
            SpringApplication.run(AopExampleApplication.class, args);
        }
    }
    ```
* **Paso 5: Ejecución de la Aplicación**

    ```java
    package com.example;

    import com.example.service.UserService;
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.boot.CommandLineRunner;
    import org.springframework.stereotype.Component;

    @Component
    public class AppRunner implements CommandLineRunner {

        @Autowired
        private UserService userService;

        @Override
        public void run(String... args) throws Exception {
            userService.createUser();
        }
    }
    ```
* **Resultado Esperado** Al ejecutar la aplicación, la consola debería mostrar el siguiente output:

    ```bash
    Method execution started
    Creating a new user
    ```
